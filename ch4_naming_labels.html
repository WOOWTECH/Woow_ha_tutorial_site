第 4 章

命名與標籤

把 switch.0x00abc123_2 改成「客廳主燈」。改完之後語音助理、儀表板、自動化通通看得懂。再學會「標籤」把同類設備群起來，之後管理省時 10 倍。

為什麼要重新命名

剛配對進來的設備，名字是廠商給的技術代號，例如：

  • light.aqara_light_group_2
  • switch.0x00158d000abcd1234
  • sensor.motion_sensor_ambient_temperature

這些名字有兩個問題：

  1. 語音助理不會念 — 你不會對 Google 說「請打開 aqara_light_group_2」。
  2. 家人看不懂 — 儀表板上一堆天書，沒人敢按。

解法：全部改成「你會脫口而出的名字」。

先分清楚三個名字

HA 有三個層級的名字，容易搞混：

  • 裝置名稱（Device name）：整個設備的名字，例如「客廳吸頂燈」。
  • 實體 ID（Entity ID）：程式用的內部 ID，例如 light.living_room_ceiling。寫自動化時用這個。
  • 友善名稱（Friendly name）：使用者介面顯示的名字，例如「主燈」。顯示、語音用這個。
好習慣：裝置名稱寫全稱（「客廳吸頂燈」），友善名稱寫短版（「主燈」）— 因為友善名稱前面已經會加上區域，變成「客廳 主燈」剛好。

重新命名步驟

版本差異：下面會用到的「設定 → 工具（Settings → Tools）」，在 2026.2 之前是側欄上獨立的一項「開發者工具（Developer tools）」；2026.2 把它收進「設定」裡，2026.8 再把名字從「開發者工具」簡化成「工具」。裡面的分頁名稱（狀態、範本⋯⋯）沒有變，舊版請到側欄的「開發者工具」找同一個東西。

  1. 進「設定 → 裝置與服務 → 實體」

    看到一長串所有 entity，可以用上方搜尋框快速找到某個設備。

  2. 點某個實體 → 齒輪（設定）

    打開實體詳情，右上角齒輪進入設定頁。

  3. 改「名稱」欄位

    這裡改的是友善名稱。實體 ID 不會跟著改，因為 ID 是自動化的 key，改了會壞掉。

  4. 要不要一起改實體 ID？

    建議改。如果這是剛裝的裝置、還沒被任何自動化引用，直接把 ID 改成有意義的英數，例如 light.living_room_main。之後看程式碼會很容易。

    注意：已被自動化、腳本、儀表板引用的實體，改 ID 前先在「設定 → 工具 → 狀態（States）」搜一下有沒有被用到。
驗證：改完後，「設定 → 工具 → 狀態」搜尋新名字應該找得到；舊 entity_id 應該從清單消失。警告：如果這個實體有被自動化用到，改 entity_id 會讓自動化壞掉——第 8 章會講為什麼要一開始就想好命名。

用標籤（Label）分類

區域回答「這個燈在哪裡」，標籤回答「這個燈是哪一類」。例如：

  • 燈類設備都貼 照明 標籤 — 之後「關掉所有照明」一鍵搞定。
  • USB 供電的設備都貼 不斷電 標籤 — 停電時不用擔心。
  • 房客會用到的設備都貼 房客可控 標籤 — 建儀表板時就過濾這個。

  1. 建立標籤：設定 → 標籤 → 新增

  2. 幫實體貼標籤

    實體列表左側勾多個 → 上方「加入標籤」— 一次貼上。

  3. 之後怎麼用

    Labels 可以貼在的東西比你想的多：區域、設備、實體、自動化、腳本、場景、helper 都能貼；一個東西可以有多個 Label（不像區域只能屬於一個）。這是 HA 裡最靈活的分類工具。

    自動化的觸發條件、儀表板篩選、腳本引用，都可以用「標籤」代替一個個列實體。實體換了、標籤不變，維護超省事。

Categories：第四種分類（進階）

2024.04 之後 HA 引入了 Categories（分類），跟 Labels 常常被搞混，這裡幫你分清楚：

維度 Labels 標籤 Categories 分類
能貼在哪區域／設備／實體／自動化／腳本／場景／helper只有自動化／腳本／場景／helper
能當自動化目標嗎可以不行，純粹是後台清單分類
典型用法「所有客廳燈」「所有安全設備」「照明類」「氛圍類」「安全類」（清單好找）
一句話：要在自動化裡用就選 Labels，只是想在後台清單裡收好就選 Categories。

常見問題

改了實體 ID，舊自動化都要重寫嗎？
HA 有「重新命名時同步更新自動化引用」的功能，但只涵蓋 UI 建的自動化。YAML 手寫的、Node-RED 的要自己搜尋替換。
「標籤」和「區域」有什麼區別？
區域是「地點」（在哪裡），標籤是「屬性」（是什麼類型 / 誰能控制 / 什麼用途）。一個設備只能屬於一個區域，但可以有多個標籤。
友善名稱能重複嗎？
可以。同名不同區域不會衝突（HA 顯示時會帶區域前綴）。但語音助理下指令時會分不出來，所以還是建議避免。

常見卡關

改了 entity_id 後某個自動化不動了？
因為那個自動化裡引用的是舊 entity_id。到「設定 → 自動化」逐一檢查，或用「設定 → 工具（舊版側欄叫「開發者工具」）→ 範本」搜尋舊名字。這也是為什麼第 8 章會教「一律用 entity_id 而不是 device_id」——換 entity_id 至少你會馬上發現壞了，device_id 換設備才壞就更難查。
Friendly name 和 entity_id 差在哪？
friendly name 是 UI 顯示的中文名（例：客廳主燈），可以隨便改不會壞任何東西；entity_id 是系統識別碼（例：light.living_room_main），改了會影響所有引用它的自動化、儀表板、腳本。平常只改 friendly name 就好。
可以整批改名字嗎？
HA 本身沒有批次改名 UI。可以直接編輯 .storage/core.entity_registry（不推薦，容易壞）或用 HACS 上的「Bulk Rename」自訂卡片。安全的做法：新設備一次改好再繼續下一個。
