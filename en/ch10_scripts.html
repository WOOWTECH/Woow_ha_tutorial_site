Chapter 10

Scripts

Package a sequence of actions under one name so automations, dashboard buttons, and voice assistants can reuse it. An automation decides when to run; a script is a reusable action sequence that something else calls.

Why scripts matter

Use a script when several automations repeat the same sequence, for example:

  • “Turn off every light, turn off climate devices, start the vacuum, then turn off the entryway light after 30 seconds” — leaving home
  • “Open the covers, set the main lights to 20%, and play a morning playlist” — waking up
  • “Fade the bedroom light to 5%, then turn it off” — going to sleep

Put that sequence in a script such as script.leaving_home. You can then reuse it from:

  • A departure automation → call script.leaving_home
  • A long press on an entryway Zigbee button → call script.leaving_home
  • An Assist command such as “I’m leaving” → call script.leaving_home
  • A dashboard button → call script.leaving_home

If you later decide to turn off another appliance when leaving, edit the script once. Every caller receives the change. Centralized logic is easier to maintain.

Scripts vs. automations vs. scenes

These three Home Assistant features solve different problems:

  • Automation: Has triggers, optional conditions, and actions. It starts when a trigger fires.
  • Script: Contains actions and must be called. It can include delays, loops, and conditional branches.
  • Scene: Captures target states, such as lights at 60%, climate at 26°C, and covers open. It has no delays or branching logic.
Simple decision tree:
  • “Set five lights to fixed levels” → scene
  • “Do A, wait three seconds, do B, and do C only if X is true” → script
  • “Run X automatically at 7:00 AM” → automation
A script often activates a scene: the scene defines a target state, while the script defines the sequence.

Hands-on: The first script "Leaving Home Mode"

Terminology update: Home Assistant now calls a service call an Action; the interface uses “Perform action,” and current YAML uses service: instead of action:. Tools moved under Settings → Tools; in 2026.8 the name became Tools, and its former Services tab is now called action.

  1. Settings → Automations & scenes → Script tab

    "+ Add Script" in the lower right corner → select "Create New Script". (You can also choose "From Blueprint", but start with a blank first.)

  2. Fill in the name and icon

    Name: "Leaving Home Mode"
    Icon: mdi:door-open(Browse pictogrammers.com)
    Home Assistant generates an entity ID such as script.leaving_home. Keep it stable because callers reference it.

  3. Add action: turn off all lights

    "+ New Action" → "Execute Action" (the old version was called "Call Service") → Select light.turn_off.
    target: Use an area or “Lights” label when membership should update automatically. Select entities individually only for deliberate exceptions.

  4. Add action: turn off the air conditioner

    Select Add action → climate.turn_off → Target all climate entities or use the "air conditioning" tag.

  5. Add action: wait 30 seconds

    "+ New action" → "Delay" → 30 seconds. This is where scripts are stronger than scenes, as they can be arranged in sequence.

  6. Add action: Entrance light

    Select Add action → light.turn_off → Target selection Entrance light Single entity. Intention: The lights in the whole house have been turned off in the front, and the entrance light will be turned off with a delay of 30 seconds, giving you time to put on your shoes and go out.

  7. Add action: push notification

    Select Add action → notify.mobile_app_your_phone(see Chapter 7), then enter “Leaving-home mode activated.” This confirmation helps you catch an accidental press.

  8. "Save" in the upper right corner → click Test Run (▶)

    Save, then select Run script. Confirm that each target changes as intended and the phone receives the notification.

    Verify: Call script.leaving_homefrom Settings → Tools → Actions. The script page, a dashboard, and an automation should run the same sequence.

Add fields to make the script reusable

The delay is fixed at 30 seconds. Add a field if different callers need 60 seconds at night and 15 seconds during the day:

  1. Open the script menu and select “Edit in YAML”

    You can also add fields in the visual editor. The YAML representation makes the complete definition easy to inspect:

    fields:
  delay_seconds:
    name: Entryway light delay
    description: Seconds before turning off the entryway light
    default: 30
    selector:
      number:
        min: 5
        max: 300
        unit_of_measurement: seconds

  2. Use the field in the delay action

    - delay:
    seconds: "{{ delay_seconds }}"

    A caller can now invoke script.leaving_home with delay_seconds: 60.

  3. Use fields from the UI

    Supported callers display the “Entryway light delay” input automatically, so users do not have to edit YAML.

Common selectors: number (number), text (text), boolean (toggle), entity (entity picker), area (area picker), and time (time picker). A selector provides validation and a suitable UI control.

Execution mode Single / Restart / Queued / Parallel

A run mode decides what happens when the script is called again before the current run ends:

mode behavior Suitable for the scene
single(Default) Already running and ignoring new calls One-time situations like leaving home and going to bed
restart Stop this time and start again from the beginning The motion sensor lights up (if someone moves again, the delay will be recalculated)
queued Queue execution in sequence Push messages and record events
parallel Open multiple copies at the same time A large number of independent events trigger simultaneously
Choose deliberately: A leaving-home script can use single, so a second press is ignored. For a gradual light fade, single ignores a second press; use restart.

Useful script patterns

1. Sleep fade out (restart mode)

Fade from the current level to 1% over 30 seconds, wait 5 seconds, then turn off. Calling the script again restarts the sequence.

alias: bedroom_fade_out
mode: restart
sequence:
  - action: light.turn_on
    target:
      entity_id: light.bedroom_main
    data:
      brightness_pct: 1
      transition: 30
  - delay: "00:00:35"
  - action: light.turn_off
    target:
      entity_id: light.bedroom_main

2. Loop notification until someone responds (repeat until)

Send a reminder every three minutes after the washer finishes, stopping when a laundry-room motion sensor detects someone.

alias: nag_until_laundry_picked
mode: restart
sequence:
  - repeat:
      until:
        - condition: state
          entity_id: binary_sensor.laundry_motion
          state: "on"
      sequence:
        - action: notify.mobile_app_dad
          data:
            message: The washing machine has finished. Please collect the laundry!
        - delay: "00:03:00"

3. Conditional branch (choose)

Choose a different arrival sequence by time of day: climate before sunset, a night-light after 11:00 PM, or lights and climate during the evening.

alias: arriving_home
sequence:
  - choose:
      - conditions:
          - condition: sun
            before: sunset
        sequence:
          - action: climate.turn_on
            target: { entity_id: climate.livingroom }
      - conditions:
          - condition: time
            after: "23:00:00"
        sequence:
          - action: light.turn_on
            target: { entity_id: light.hallway }
            data: { brightness_pct: 20 }
    default:
      - action: light.turn_on
        target: { area_id: livingroom }
      - action: climate.turn_on
        target: { entity_id: climate.livingroom }

4. Parallel actions

Normal actions run in sequence. Use parallel only when these independent actions are safe to start together:

sequence:
  - parallel:
      - action: light.turn_off
        target: { area_id: livingroom }
      - action: cover.close_cover
        target: { area_id: livingroom }
      - action: media_player.turn_off
        target: { entity_id: media_player.tv }

5. Call other scripts/scenes

sequence:
  - action: scene.turn_on
    target: { entity_id: scene.movie_night }
  - delay: "00:00:02"
  - action: script.turn_on
    target: { entity_id: script.close_all_curtains }

Difference: script.turn_on starts a script without waiting. A direct call such as action: script.other_script waits for that script to finish before continuing.

Four ways to call a script

  1. From an automation action

    Add an action, select script.leaving_home, and complete any fields it exposes.

  2. Card from dashboard

    Add a Button card, set its tap action to perform script.turn_on, and target the script. A Tile card provides another compact option.

  3. From Zigbee remote/scene panel

    Map the remote event exposed by its integration to this script. Short press, long press, and double press can call different scripts when the device supports those events.

  4. Assist from voice assistant

    Expose the script to Assist through its entity settings, then use a clear voice phrase such as “Activate leaving-home mode.” Expose only scripts that are safe for voice control.

Common problems

The script stops in the middle of execution and does not continue?
  • Check whether wait_template or wait_for_trigger has no timeout. Add timeout: "00:00:30" and continue_on_timeout: true.
  • If an action fails to execute, an error will be thrown and aborted. continue_on_error: true Let it skip to continue.
  • Go to "Settings → Tools → Actions" to test the action by itself and identify a missing entity or invalid parameter.
Fields are added, but the fill-in field does not appear on the dashboard button card?
A Button card runs with predefined data and does not prompt for fields. Provide fixed values, use a supported dialog flow, or build a separate helper-based control. Do not assume Mushroom Template card adds script-field prompting.
Nothing happens when I press "Execute Script"?
Open Settings → System → Logs and inspect the script trace. Common causes include a misspelled entity ID, unavailable target, or invalid action data.
in the script {{ variable }} Not replaced?
To wrap it in quotes:value: "{{ my_var }}". Pure numbers or Boolean can be omitted, but strings must be quoted. In addition {{ }} only in data: Working within values, key names cannot use templates.

FAQ

Can the script be triggered by itself?
No, the script does not have a trigger section. If you want to "run by yourself when the conditions are met", write an automation whose action is to call this script.
Can a script call a script? How many layers are there in the nest?
Yes, in practice there is no limit to the number of layers (HA does not officially set a hard upper limit). But each layer you call adds another layer that is difficult to track, and more than 3 layers usually indicates a restructuring. Shared steps can be pulled out, and the parent script only takes care of the process.
After the script is deleted, what happens to the automation that uses it?
It will be broken and the action will fail when executing to that line. Before deleting the script, use "Settings → Automations & scenes → three-dot menu → Traces" or go to "Settings → Tools → Events" to monitor service_registered.
How does a Blueprint relate to a script?
Blueprint is reusable script or automation template, discussed in Chapter 8. After importing one, complete its exposed inputs, such as a light or sensor. See Chapter 8 for the automation workflow.
