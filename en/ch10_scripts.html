Chapter 10

Scripts

Pack up a "series of actions" and give it a name. Then automation, buttons, and voice can all evoke it in one sentence. The automation in Chapter 8 is "a thing that operates independently and completely"; the script is "a called action".

Why do you need a script?

When you find yourself repeating the same action in many automations, for example:

  • "Turn off the lights in the whole house + turn off the air conditioner + start the sweeper + delay turning off the entrance light for 30 seconds" - going out situation
  • "All curtains are drawn + main lights 20% + sound playing good morning playlist" - wake-up situation
  • "The light in the master bedroom slowly fades to 5% and then turns off" - Fade out for sleep

Directly wrap this entire paragraph into a script, for example script.leaving_home, after:

  • Automation away from home → Just "call script.leaving_home"One line
  • Entrance Zigbee button long press → also call script.leaving_home
  • The voice assistant says "I'm going out" → also calls script.leaving_home
  • Put a big button on the dashboard → also call script.leaving_home

Later, if you want to change "Should you turn off the water dispenser when you go out?", you only need to change the script, and all four entrances will be synchronized.This is the value of centralizing logic.

Scripting vs Automation vs Scenarios

There are three nouns that are often confused by novices. Let’s first distinguish them:

  • Automation Automation: Three-stage (trigger/condition/action), it will "start by itself". Example: Triggered at sunset.
  • Script Script: It only has action segments and will not start by itself.to be called. It can have delays, loops, and conditional branches, which is much more capable than scenes.
  • Scene: A group of entity "status snapshots" (lights 60%/air conditioner 26°C/curtains 100%). When called, all entities are instantly switched to the specified state.No delays or logic.
Simple decision tree:
  • "Adjust 5 lights to a fixed brightness at a time" → scene(the simplest)
  • "Do A first, wait 3 seconds, then do B, and only do C if X" → script(logical)
  • "Automatically do X at 7 a.m." → Automation(with trigger)
The scene is often "called" by the script - the scene is the bricks and the script is the method for building the wall.

Hands-on: The first script "Leaving Home Mode"

The name has been changed:The former "Service" is now called "Action"—"Call Service" on the interface becomes "Execute Action", and the "Call Service" in YAML service: to be written as action:(HA 2024.8 onwards). In addition, "Developer Tools" will be moved from the sidebar in 2026.2Settings → Tools, 2026.8 simplified Developer Tools into Tools, the original "Service" tab inside is now called "action”. The old way of writing HA is still understandable, but the old name can no longer be found on the interface.

  1. Settings → Automation and Scenarios → Script tab

    "+ Add Script" in the lower right corner → select "Create New Script". (You can also choose "From Blueprint", but start with a blank first.)

  2. Fill in the name and icon

    Name: "Leaving Home Mode"
    Icon: mdi:door-open(Available from pictogrammers.com find)
    The entity_id will be automatically generated at the bottom of the page:script.leaving_home. This ID is then used to make calls and give it a memorable name.

  3. Add action: turn off all lights

    "+ New Action" → "Execute Action" (the old version was called "Call Service") → Select light.turn_off.
    target: Don't select one by one; use "Area" to select "All", or use "Tag" (taught in Chapter 4) to select "Lights". In this way, newly added lights will be automatically covered.

  4. Add action: turn off the air conditioner

    “＋New action”→ climate.turn_off → Target all climate entities or use the "air conditioning" tag.

  5. Add action: wait 30 seconds

    "+ New action" → "Delay" → 30 seconds. This is where scripts are stronger than scenes, as they can be arranged in sequence.

  6. Add action: Entrance light

    “＋New action”→ light.turn_off → Target selectionEntrance lightSingle entity.Intention: The lights in the whole house have been turned off in the front, and the entrance light will be turned off with a delay of 30 seconds, giving you time to put on your shoes and go out.

  7. Add action: push notification

    “＋New action”→ notify.mobile_app_your mobile phone(See Chapter 7) → Message: "Away from home mode activated ✅". In this way, even if you press the wrong button, your phone will prompt you.

  8. "Save" in the upper right corner → click Test Run (▶)

    After saving, the orange "Save" will appear above and turn green → click "Execute Script" to test. If done correctly, your phone should receive a notification.

    Verify:Go to "Settings → Tools → Actions" to call script.leaving_home, should also be run completely. The same entry is equivalent from the script page, Settings → Tools, Dashboard, and Automation.

Add parameters (Fields) - make the script customizable

The "30-second delay" was written into the script just now. What if I think for 60 seconds at night and 15 seconds during the day? add one Field:

  1. Edit script → upper right "⋮" → "Edit YAML"

    The UI can also add fields (in the "Fields" area at the bottom of the script page), but YAML can be seen clearly at once. Join:

    fields:
  delay_seconds:
    name: Entrance light delay seconds
    description: Turn off the entrance light in a few seconds
    default: 30
    selector:
      number:
        min: 5
        max: 300
        unit_of_measurement: seconds

  2. Change 30 in the action into a variable

    - delay:
    seconds: "{{ delay_seconds }}"

    Then you can pass parameters when calling:script.leaving_home + delay_seconds: 60.

  3. UI calls can also fill in fields

    After adding fields, when calling this script in the dashboard card, automated action, setting → tool, a field that can be filled with "delay seconds" will automatically appear, and non-engineers can also change it.

Commonly used selectors: number(number),text(text),boolean(switch),entity(Select entity),area(select area),time(Select time). If there is a selector UI, it will be rendered into corresponding components, which is friendlier than pure text.

Execution mode Single / Restart / Queued / Parallel

What happens if the script is called again while the script is running? This is determined by the "mode", just like automation:

mode behavior Suitable for the scene
single(Default) Already running and ignoring new calls One-time situations like leaving home and going to bed
restart Stop this time and start again from the beginning The motion sensor lights up (if someone moves again, the delay will be recalculated)
queued Queue execution in sequence Push messages and record events
parallel Open multiple copies at the same time A large number of independent events trigger simultaneously
Pit:Leaving Home Script If You Stay single, if you accidentally click the button twice at the door, the second time will be discarded (correct); but if it is a script of "living room lights slowly fade out" single, if you press it a second time and think "fader it again", it won't move. Change this scenario to restart.

Collection of practical examples

1. Sleep fade out (restart mode)

Fade to 1% within 30 seconds from the current brightness, then turn off after 5 seconds. Pressing it again in the middle will restart.

alias: bedroom_fade_out
mode: restart
sequence:
  - action: light.turn_on
    target:
      entity_id: light.bedroom_main
    data:
      brightness_pct: 1
      transition: 30
  - delay: "00:00:35"
  - action: light.turn_off
    target:
      entity_id: light.bedroom_main

2. Loop notification until someone responds (repeat until)

When the washing machine is finished washing, the broadcast will be pushed every 3 minutes until someone comes to the laundry room (Zigbee motion sensor triggers).

alias: nag_until_laundry_picked
mode: restart
sequence:
  - repeat:
      until:
        - condition: state
          entity_id: binary_sensor.laundry_motion
          state: "on"
      sequence:
        - action: notify.mobile_app_dad
          data:
            message: The washing machine has finished washing, go and get it!
        - delay: "00:03:00"

3. Conditional branch (choose)

When you get home, do different things according to the time of day: only turn on the air conditioner during the day, turn on the lights + air conditioner at night, and only turn on the night light late at night.

alias: arriving_home
sequence:
  - choose:
      - conditions:
          - condition: sun
            before: sunset
        sequence:
          - action: climate.turn_on
            target: { entity_id: climate.livingroom }
      - conditions:
          - condition: time
            after: "23:00:00"
        sequence:
          - action: light.turn_on
            target: { entity_id: light.hallway }
            data: { brightness_pct: 20 }
    default:
      - action: light.turn_on
        target: { area_id: livingroom }
      - action: climate.turn_on
        target: { entity_id: climate.livingroom }

4. Parallel action (parallel) - the fastest version of fully open and fully closed

A normal series of actions is a sequence run, use parallel You can send them at the same time, which is much faster:

sequence:
  - parallel:
      - action: light.turn_off
        target: { area_id: livingroom }
      - action: cover.close_cover
        target: { area_id: livingroom }
      - action: media_player.turn_off
        target: { entity_id: media_player.tv }

5. Call other scripts/scenes

sequence:
  - action: scene.turn_on
    target: { entity_id: scene.movie_night }
  - delay: "00:00:02"
  - action: script.turn_on
    target: { entity_id: script.close_all_curtains }

difference: use script.turn_on The call is "fire and forget", the main script continues to run; write directly action: script.Other scripts(Without turn_on) it means "wait until it finishes running before continuing". If you want to synchronize and wait, use the latter.

How to call a script (4 entries)

  1. from automated action segments

    Automation → Action → Select "Execute Action" → script.leaving_home(Or directly select the script entity). Fields are displayed when fields are present.

  2. Card from dashboard

    Add a Button card → Click on the action and select "Execute Action" → script.turn_on → Target selection script. Want to use it more fancyly Tile card + Custom icon.

  3. From Zigbee remote/scene panel

    Use the "MQTT event" or "ZHA event" mentioned in Chapter 8 to grab the button, and the action section calls this script. Long press, short press, and double-click can all be mapped to different scripts.

  4. Assist from voice assistant

    "Expose" to Assist (Settings → Voice Assistant → Expose Script), and then you can say "Hey, away from home mode" to call directly. This is a built-in function, no need to write any integration.

Common stuck levels

The script stops in the middle of execution and does not continue?
  • Check if it is a wait_template or wait_for_trigger No timeout — add timeout: "00:00:30" + continue_on_timeout: true.
  • If an action fails to execute, an error will be thrown and aborted. continue_on_error: true Let it skip to continue.
  • Go to "Settings → Tools → Actions" to test that action individually to see if the entity does not exist or the parameters are wrong.
Fields are added, but the fill-in field does not appear on the dashboard button card?
The button card defaults to "press and run" and does not ask for fields. If you want to pop up a dialog box, please use "Entity card" or set "hold_action → more-info", the fields will be displayed; or use Mushroom Template card(HACS) Draw it yourself.
Nothing happens when I press "Execute Script"?
Go to "Settings → System → Log" to see if there is anything wrong. Common script failures include: misspelled entity ID, offline target device, insufficient permissions (non-administrator account running administrator script).
in the script {{ variable }} Not replaced?
To wrap it in quotes:value: "{{ my_var }}". Pure numbers or Boolean can be omitted, but strings must be quoted. In addition {{ }} only in data: Working within values, key names cannot use templates.

FAQ

Can the script be triggered by itself?
No, the script does not have a trigger section. If you want to "run by yourself when the conditions are met", write an automation whose action is to call this script.
Can a script call a script? How many layers are there in the nest?
Yes, in practice there is no limit to the number of layers (HA does not officially set a hard upper limit). But each layer you call adds another layer that is difficult to track, and more than 3 layers usually indicates a restructuring. Shared steps can be pulled out, and the parent script only takes care of the process.
After the script is deleted, what happens to the automation that uses it?
It will be broken and the action will fail when executing to that line. Before deleting the script, use "Settings → Automation → Three Dots → Tracker" or go to "Settings → Tools → Events" to monitor service_registered Find out who is using it.
What is Blueprint? What does it have to do with the script?
Blueprint isScript or automated templates, discussed in Chapter 8. Commonly used logic is made into a Blueprint. After importing it, anyone only needs to fill in a few parameters (which light, which sensor) to have a usable script, which is suitable for sharing and mass deployment.
