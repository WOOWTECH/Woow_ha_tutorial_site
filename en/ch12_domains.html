Chapter 12

Domain reference

Home Assistant groups entities by domain: lights use light, climate systems use climate, and covers use cover. Entities in the same domain share the same actions and behavior, so learning a domain gives you a reusable control model.

What is a domain, and why does it matter?

Every entity ID follows domain.name. The part before the period is its domain:

  • light.livingroom_main → uses the light
  • climate.bedroom_ac → uses the climate
  • sensor.outdoor_temperature → uses the sensor

Why is it important? Home Assistant actions are organized by domain.light.turn_on can control supported lights across brands and protocols—for example, Hue, IKEA, Yeelight, Zigbee lights, and WLED. This shared interface is the value of Home Assistant’s abstraction.

Buying tip: Before purchasing a device, check which domain its integration exposes. If it becomes light , existing light automations can usually control it without changes. If it becomes switch , it offers only switch behavior, not brightness or color-temperature controls.

light · Lights

Lighting entities may support brightness, color temperature, color, effects, or only on/off. Capabilities depend on the device and integration.

Common actions

  • light.turn_on — Common parameters include brightness_pct: 60, color_temp_kelvin: 3000, rgb_color: [255, 100, 50], transition: 5 (fade duration), effect: "colorloop"
  • light.turn_off — May also support transition for fading
  • light.toggle — Toggle between on and off

Commonly used UI cards

  • Light card: Built in; provides brightness and available color controls
  • Tile card: Compact controls that work well in a grid
  • Mushroom Light card (HACS): Community card with compact sliders and color controls

Common pitfalls

  • Power cut at the wall: A smart bulb goes unavailable when a wall switch removes power. Keep the bulb powered and use a smart wall control, or use a smart relay designed for the installation.
  • Color-temperature units: Current actions use color_temp_kelvin (3000 K warm white / 6500 K cool white). Older examples may use color_temp (mired). Use only parameters supported by the entity.
  • Transitions can be interrupted: transition: 30 fades from the current state to the target over 30 seconds. Another command may interrupt it. A restart script can restart the sequence consistently.

switch · Switches and smart plugs

A switch exposes on/off power control. Smart plugs, relays, and simple wall switches commonly use this domain.

Common actions

  • switch.turn_on / switch.turn_off / switch.toggle — Basic on/off/toggle controls

Common uses

  • Control suitable non-smart appliances such as a dehumidifier, simple fan, or decorative lights
  • Control appropriately rated relays; use dedicated safety-rated equipment for water, heating, or gas
  • Control a simple motor, although an integration that exposes cover for a better cover interface.

Common pitfalls

  • Power-on behavior: A plug may remain off after an outage. Configure its supported power-on state deliberately; choosing On can be unsafe for heaters or motors.
  • Energy entities: Some smart plugs expose sensor.*_power, sensor.*_energy, which can feed the Energy dashboard or indicate that an appliance cycle has ended.
Example: Detect a completed washer or dryer cycle. Use a correctly rated smart plug to measure power. Trigger when sensor.washer_power remains below 5 W for three minutes after previously running, then send a notification. Tune the thresholds from actual history.

climate · Heating, cooling, and thermostats

Common actions

  • climate.turn_on / climate.turn_off
  • climate.set_temperature — Use temperature: 26 for one target, or target_temp_high / target_temp_low for a range
  • climate.set_hvac_mode — Set hvac_mode: cool / heat / auto / dry / fan_only / off
  • climate.set_fan_mode — fan_mode: auto / low / medium / high / on / off (values depend on the device)
  • climate.set_preset_mode — Manufacturer presets such as eco, sleep, or away
  • climate.set_swing_mode — Set a supported swing mode

UI card

  • Thermostat card: Built-in thermostat control
  • Tile card: Compact control for several climate entities
  • simple-thermostat (HACS): Community card with additional layout options

Common pitfalls

  • Infrared state can be optimistic: With an IR blaster, Home Assistant may know only which command it sent, not whether the appliance received it. Use an independent temperature sensor to verify the result.
  • Presets can override temperature: A manufacturer’s Eco or Sleep preset may control the setpoint. Return to none before changing temperature when the integration requires it.
  • Units: Confirm the unit system from Chapter 2 before sending a numeric setpoint. A value such as temperature: 26 must match the entity’s configured temperature unit.

cover · Curtains / Garage Doors / Blinds

Common actions

  • cover.open_cover / cover.close_cover / cover.stop_cover / cover.toggle
  • cover.set_cover_position — Parameters position: 50(0 fully closed, 100 fully open)
  • cover.set_cover_tilt_position —Louvre blade angle
  • cover.open_cover_tilt / cover.close_cover_tilt

Common pitfalls

  • The direction is reversed: Some motors “turn on” contrary to your intuition. Go to the device page "Reconfigure" or calibrate directly in the device App. Do not use it in HA. position: 100 - x Write backwards.
  • No position support: Cheap curtain motors only have three stages: open/close/stop. set_cover_position It will fail directly. Check the device page to see supported_features.
  • Add lock safeguards for a garage door: An automation that calls cover.open_cover without adequate conditions may open the garage in the middle of the night If you write the wrong automation. use input_boolean When switch + condition is checked.

media_player · TVs, speakers, and streamers

Common actions

  • media_player.turn_on / turn_off / toggle
  • media_player.volume_set (volume_level: 0.3, 0-1), volume_up / volume_down / volume_mute
  • media_player.media_play / media_pause / media_stop / media_next_track / media_previous_track
  • media_player.play_media — Play specific content (media_content_id plus media_content_type)
  • media_player.select_source — Select an input or source (HDMI1, Netflix, Spotify)
  • media_player.select_sound_mode — Select a supported sound mode

Capabilities vary by integration

  • Google Cast: Can play supported media on Cast targets
  • Apple TV / Sonos / HEOS: Capabilities may include playlists and groups
  • Samsung / LG TV: Power-on may require Wake-on-LAN or a vendor-specific setting
  • Spotify / Plex:May use play_media for supported playlists or videos

Common pitfalls

  • A TV may need several seconds after power-on before accepting another command. Add an appropriate delay.
  • A Cast speaker group is a separate media-player entity, not an attribute of an individual speaker.

lock · Smart locks

Common actions

  • lock.lock / lock.unlock
  • lock.open (opens a supported latch)

Common pitfalls

  • Safety first: Lock automations need independent safeguards. Check door state and occupancy, and never use only a clock time to unlock an entry.
  • Cloud latency: Cloud integrations can respond more slowly or become unavailable during an outage. Prefer a supported local integration when reliability is critical.
  • Unavailable means no remote control: If Home Assistant cannot reach the lock, it cannot operate it. Always retain a local entry method.
Warning: Automatic locking can lock you out. Keep a tested mechanical key, keypad code, or other independent entry method.

vacuum · Robot vacuums

Common actions

  • vacuum.start / vacuum.pause / vacuum.stop
  • vacuum.return_to_base — Return to the dock
  • vacuum.locate — Make the vacuum identify its location
  • vacuum.set_fan_speed — Set a supported fan-speed value
  • vacuum.send_command — Send vendor-specific commands; payloads vary by integration

Common usage

  • Everyone has been away for 30 minutes → start cleaning
  • No motion for 15 minutes on a weekday afternoon → start cleaning
  • A calendar event says guests are coming → clean the living room beforehand

Common pitfalls

  • Cloud rate limits: Some vendor APIs limit calls. Rely on entity updates instead of polling from an automation every minute.
  • Room IDs are vendor-specific: Map rooms in the vendor app first, then follow the integration documentation before using send_command with a room identifier. Do not guess values.

fan · Fans and air purifiers

Common actions

  • fan.turn_on / fan.turn_off / fan.toggle
  • fan.set_percentage (0–100% speed)
  • fan.set_preset_mode (auto / sleep / turbo, depending on the device)
  • fan.oscillate (enable or disable oscillation)
  • fan.set_direction (set a supported direction)

Common pitfalls

  • An air purifier may expose fan (fan speed), sensor (air quality), and switch (an optional feature) as separate entities.
  • set_percentage: 0 may turn some fans off. Call turn_on.

camera · Camera

Common actions

  • camera.snapshot — Take a chart and save it (parameters filename: /media/snap_{{ now().timestamp() }}.jpg)
  • camera.turn_on / turn_off(supported by some cameras)
  • camera.enable_motion_detection / disable_motion_detection
  • camera.record — Record a video

UI card

  • Picture entity: Built-in, the simplest
  • Picture glance: Image + small icon above to display related entities (door locks, lights)
  • WebRTC card (HACS): Low latency streaming, perfect for doorbells

Common pitfalls

  • Cloud camera (Ring, Wyze, TP-Link Kasa): Picture delay of 5-30 seconds is normal. If you want to get real-time streaming, you need to use ONVIF/RTSP local streaming.
  • Snapshot file location:Default /config/www/ can be read by the dashboard; save /media/ To configure additional media_source.

sensor / binary_sensor · Sensor

A sensor reports a value, such as 25.3°C or 87%. A binary_sensor reports one of two states, such as open/closed or detected/clear.

They do not accept control actions

Sensors are read-only. You cannot turn on a temperature sensor. Use its value in a trigger or condition:

  • Trigger: When binary_sensor.motion_livingroom turns on → turn on a light
  • Condition: At sunset, continue only If binary_sensor.someone_home is on
  • Value: When sensor.pm25 exceeds 35 → turn on an air purifier

Common device classes (which influence names, icons, and behavior)

  • sensor: temperature / humidity / pressure / illuminance / power / energy / battery / co2 / pm25
  • binary_sensor: motion / occupancy / door / window / smoke / moisture / opening / battery / connectivity
Tip: If an integration assigns the wrong device class, the entity settings may let you override it. Choose only a class that matches the value’s actual meaning.

Common pitfalls

  • Binary-sensor chatter: Rapid on/off changes can repeatedly toggle an automation. Require the off state to remain stable for five minutes before turning off a light.
  • Battery level is usually a sensor: A low-battery reminder uses sensor.*_battery with a numeric-state trigger.

Domain tools

Concept: This area was formerly called Developer Tools. It moved under Settings and in 2026.8 became Tools . The current path is Settings → Tools. Its former Services tab is now called Actions. Older screenshots may show Developer Tools → Services for the equivalent controls.

Use Tools to test actions

Open Settings → Tools → Actions. Select an action, choose a safe target, provide valid parameters, and run it. This isolates an action from automation triggers and conditions.

Use States to inspect attributes

Settings → Tools → “States” tab → Paste entity ID → See what it has attributes. For example light.livingroom properties will have supported_color_modes, min_color_temp_kelvin, max_color_temp_kelvin, these determine what parameters you can set.

Choose integrations by capability

Check the domain before buying: Devices exposed as light / switch / cover / climate usually provide a consistent control model. A device exposed only as several sensor + switch may require more custom logic. Read the official integration page and confirm the exact model before buying.

FAQ

Why does Home Assistant expose my lamp as a switch? Can I change it to light ?

The device reports only power on/off, as with a smart plug or relay. The integration cannot know whether the load is a lamp or another appliance, so it exposes a switch.

Use Home Assistant’s built-in “Change device type of a switch” helper under Settings → Devices & services → Helpers → Create helper. Select one switch entity and expose it as light, cover, fan, lock, siren or valve . Home Assistant creates a new entity such as light.desk_lamp and hides the original switch to avoid duplicate dashboard controls.

Warning: Changing the domain does not create hardware capabilities. After conversion to light, you can call light.turn_on, but you still Can'tadjust brightness or color temperature when the hardware lacks those features. Dimming requires a dimmable lamp or module.
My light only has brightness and no color temperature and color options. Is it an HA problem?

Start by checking the entity’s actual capabilities under Settings → Tools → States. supported_color_modes lists the modes reported by the integration:

color modeWhat you will see on the UI
onoffOnly on/off, not even a brightness slider
brightnessBrightness slider only (monotone light)
color_tempBrightness plus Color Temperature (warm white to cool white)
hs / rgb / rgbw / rgbwwBrightness plus Color Wheel (rgbww This kind also has an additional white light channel)

There is in the list color_temp lights will appear simultaneously in the properties min_color_temp_kelvin and max_color_temp_kelvin, that is, how warm or cold the color temperature of this lamp can be adjusted. If the hardware does not support it, no helpers or HACS cards can change the color temperature.

If supported_color_modes Obviously less than what is written in the product specifications (for example, I bought a colored light bulb but only brightness), that is the key to integration: first update the bulb firmware, re-pair, or go to the integrated GitHub to see If there are reports of the same model.

The opening and closing direction of the curtain is reversed. Press "Open" to close it. The positions 0 and 100 are also reversed. How to fix it?

First remember that the definition of HA is dead:position: 0 means Completely closed, position: 100 means Fully open. This rule doesn't change based on your motor setup.

Correct the direction at the motor or integration: Fix the motor calibration at its source. Avoid putting 100 - x arithmetic into every automation because the dashboard slider will remain reversed. Use the appropriate setup method:

  1. Zigbee2MQTT motor

    Go to the settings area of the device page to find motor_reversal(Reverse the direction of the motor) or invert_cover(Reverse the position value, false is open=100 / close=0). Taking common curtain modules such as Tuya TS130F as an example, these two options are among the device's configurable items.

  2. Motor paired with the original app

    Most electric curtains have "motor direction" or "travel calibration" in the original app. Re-setting the upper and lower limits is usually correct. After calibrating the HA, there is no need to change anything.

  3. Device page reset

    Some integrations provide "Reconfigure" on the device page to rerun the calibration process.

  4. There really is no choice, last resort

    Use a template cover to reverse values only as a last resort, because it adds another layer to maintain.

I call climate.set_temperature with 26°C, but the climate device does not respond. Why?

Check these causes in order:

  • The air conditioner is off. Assume that the target temperature is not equal to power on.climate.set_temperature can also accept hvac_mode. Set both fields together:hvac_mode: cool add temperature: 26.
  • Trapped by preset. When switching to manufacturer-preset modes such as "eco" and "sleep", the target temperature is often determined by the manufacturer. first climate.set_preset_mode Set back none, and then set the temperature.
  • Out of settable range. Each machine has its own min_temp / max_tempand target_temp_step. A device may accept only fixed increments. Inspect these attributes under Settings → Tools → States.
  • It is actually a zone thermostat. Use target_temp_high and target_temp_low; the integration may ignore a single temperature value.
  • Infrared air conditioner. As mentioned earlier in this article, HA only sends commands, and no one knows whether there are any hits when sent out - is the air conditioner facing the remote control? Is there any obstruction in the middle?

The quickest way to determine what happened is to Settings → Tools → Actions Execute it directly and see If it reports success or skips an error message.

Why does select_source not list or select the source I want?

media_player.select_source accepts only strings reported by the device, and The capitalization and spaces must be exactly the same.. In Settings → Tools → States, inspect the media player’s source_list attribute. Use an exact listed value; HDMI 1 fails If the list says HDMI1.

Two common situations:

  • The list is empty or has only one or two items. Many TVs will not report the complete source list to HA until they are turned on and connected to the Internet. When automatically writing "power on → change source", please leave a few seconds in between. delay, otherwise the list will not be generated at all when the command is sent out.
  • The integration does not support changing sources at all. Not every media_player has this capability (pure speakers and some streaming boxes do not). I can’t see the source drop-down menu on the device page, nor in the status. source_list, that is, no, use the brand's App macro or IR/HDMI-CEC bypass instead.
Why is the camera slow on my dashboard?

Identify whether the delay comes from the camera source, stream format, or dashboard load:

  1. First make sure it is not an inherent delay in cloud integration

    Cloud-camera latency is determined largely by the provider. Use a supported local ONVIF or RTSP stream when low latency is required.

  2. Make sure you are using WebRTC

    Home Assistant has built-in go2rtc starting from 2024.11, which provides WebRTC streaming for the camera, which is significantly more real-time than the old HLS. If you are running Home Assistant OS or Home Assistant container, it will be enabled by default after the update; cameras that do not support WebRTC will automatically fall back to the old method.

  3. Use substream (substream)

    Most IP cameras provide both a high-definition main stream and a low-resolution sub-stream. The small grid on the dashboard uses the sub-stream, and the main stream is used when you click to open it. The machine burden is much different.

  4. Limit concurrent live streams

    Each live stream consumes CPU and bandwidth. Put cameras on a dedicated view and load only the streams you need.

  5. Use “Preload stream” selectively

    Preloading keeps a stream connected for faster opening but consumes resources continuously. Enable it only for priority cameras that the host can support.

Sensor display unknown and unavailable, what’s the difference between these two?

The two states indicate different problems:

Statusmeaningtypical situation
unavailableThe integration cannot provide a current state—for example, a disconnected device or unavailable cloud service.The Zigbee sensor has no battery, the Wi-Fi socket is disconnected, and the host has just been restarted and is still not connected.
unknownThe entity exists, but its current value is unknownThe system has not received the first update, a field was omitted, or a new helper has no initial value.

In plain language, unavailable means “the integration cannot currently provide this entity”;unknown means “the entity exists, but its current value is not known.”

Numeric-state triggers ignore both states. In templates, convert values safely and add availability checks so an invalid value does not stop the automation. Confirm that the state is neither unknownnor unavailablebefore calculating.

Tip: If a sensor often change unavailable, that is a signal or battery problem, which cannot be solved by writing a program - go to the device page troubleshooting in Chapter 11, or add a Zigbee router (plugged-in device) relay for it.
