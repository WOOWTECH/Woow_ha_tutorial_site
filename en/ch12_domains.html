Chapter 12

Domain reference

HA classifies everything according to "Domain": the light is light, air conditioning is climate, curtains are cover. All devices in the same domainAccept the same set of actions (Action, the old version was called "Service"), if you learn one, you will know them all. This chapter is a cheat sheet for each commonly used domain.

What is Domain? why to understand it

Each entity_id grows into domain.name, the first half is domain:

  • light.livingroom_main → domain is light
  • climate.bedroom_ac → domain is climate
  • sensor.outdoor_temperature → domain is sensor

Why is it important?Because the "execution action" of HA (called "call service" in the old version) is based on domain.light.turn_on can be openedAny brand of lamps of any agreement—Philips Hue, IKEA Tradfri, Xiaomi Yeelight, Zigbee universal lights, DIY WLED light strips—all eating the same thing. This is the power of HA abstraction.

Mental method:Before buying a new device, check which domain it will be recognized by HA. If recognized light, you will know that all existing lamp automation can eat it directly without rewriting. recognize switch There is no brightness or color temperature adjustment.

light · lamp

Lighting equipment with adjustable brightness, color temperature and color. Switch types (only on/off) may also be classified as light, depending on the integration.

Common actions

  • light.turn_on —Supported parameters:brightness_pct: 60, color_temp_kelvin: 3000, rgb_color: [255, 100, 50], transition: 5(fade seconds),effect: "colorloop"
  • light.turn_off — also supports transition(fading)
  • light.toggle — switch toggle

Commonly used UI cards

  • Light card: Built-in, slide to adjust brightness, press and hold to open color palette
  • Tile card: Small picture tiles, suitable for arranging a whole tile
  • Mushroom Light card(HACS): more beautiful, slider + color palette integration

Common pitfalls

  • The light is powered off by a physical switch: Zigbee lights will go offline when the power is cut off, and the automation of turning on the lights will not work. Solution: pretendUninterrupted power supplySmart switch, or tie the wall switch to turn it on.
  • color temperature unit: For new version color_temp_kelvin(3000K warm white / 6500K cool white); for older versions color_temp(mired, the smaller the number, the colder it is). Which UI to choose depends on integration. When writing YAML, kelvin is more intuitive.
  • Be careful with transitions: transition: 30 Let the light fade to the target brightness from the current 30 seconds. If another turn_on comes at the same time, it will be interrupted. Use restart The script package of the mode is relatively stable.

switch · Switch/Smart Socket

Pure power on and off. Sockets, relays, and simple wall switches all fall into this category.

Common actions

  • switch.turn_on / switch.turn_off / switch.toggle — There are no other parameters, it’s just that simple.

Common uses

  • Control non-smart appliances: water dispenser, dehumidifier, fan (old style), Christmas lights
  • Control solenoid valves: water heaters, sprinkler systems, gas
  • Control the electric curtain motor (but it is more recommended to recognize cover)

Common pitfalls

  • Power off memory: Many sockets do not have a "restore to previous state after power on" feature and are turned off after a power trip. Prioritize setting "Power on state = Last / On" in App or HA.
  • Energy consuming entity: Many smart sockets have sensor.*_power, sensor.*_energy, can be used as an energy dashboard, or as a signal that "the washing machine is finished" (see example).
Magic example: Detection of washing machine/dryer completed. Use smart sockets to measure power and write automated "when sensor.washer_power Dropped from >10W to <5W for 3 minutes → Push." Easier to use than the original app.

climate · Heating/Cooling/Air Conditioner/Thermostat

Common actions

  • climate.turn_on / climate.turn_off
  • climate.set_temperature — Parameters:temperature: 26(single target temperature), or target_temp_high / target_temp_low(range, thermostat)
  • climate.set_hvac_mode — Parameters hvac_mode: cool / heat / auto / dry / fan_only / off
  • climate.set_fan_mode — fan_mode: auto / low / medium / high / on / off(Value depends on the brand)
  • climate.set_preset_mode —Manufacturer preset modes (energy saving, sleep, away from home)
  • climate.set_swing_mode — Sweep direction

UI card

  • Thermostat card: Built-in circular temperature plate, the most intuitive
  • Tile card: Compact, suitable for multiple air conditioners in parallel
  • simple-thermostat(HACS): More control details

Common pitfalls

  • The status of the infrared air conditioner is incorrect: Using the IR blaster's air conditioner (Broadlink, SwitchBot Hub) HA only knows "what command was sent", but does not know whether the air conditioner was actually received. It is more reliable to add a temperature sensor to compare the actual temperature changes.
  • Preset override temperature: Switching to preset "eco" will usually force the temperature to be set, and return to none preset can be set freely.
  • unit: Confirm that the unit system in Chapter 2 is set to "Celsius", otherwise temperature: 26 Will be treated as Fahrenheit (very cold XD).

cover · Curtains / Garage Doors / Blinds

Common actions

  • cover.open_cover / cover.close_cover / cover.stop_cover / cover.toggle
  • cover.set_cover_position — Parameters position: 50(0 fully closed, 100 fully open)
  • cover.set_cover_tilt_position —Louvre blade angle
  • cover.open_cover_tilt / cover.close_cover_tilt

Common pitfalls

  • The direction is reversed: Some motors “turn on” contrary to your intuition. Go to the device page "Reconfigure" or calibrate directly in the device App. Do not use it in HA. position: 100 - x Write backwards.
  • No position support: Cheap curtain motors only have three stages: open/close/stop. set_cover_position It will fail directly. Check the device page to see supported_features.
  • Garage door to lock insurance: cover.open_cover If you are not foolproof, you may open the garage in the middle of the night if you write the wrong automation. use input_boolean When switch + condition is checked.

media_player · TV / Audio / Streaming Box

Common actions

  • media_player.turn_on / turn_off / toggle
  • media_player.volume_set (volume_level: 0.3, 0-1), volume_up / volume_down / volume_mute
  • media_player.media_play / media_pause / media_stop / media_next_track / media_previous_track
  • media_player.play_media — Broadcast specific content (media_content_id + media_content_type)
  • media_player.select_source — Change input source (HDMI1, Netflix, Spotify)
  • media_player.select_sound_mode — Sound field mode

Integration varies greatly

  • Google Cast: Can push URL to Nest Hub / Chromecast, suitable for broadcasting TTS voice "The washing machine is finished"
  • Apple TV / Sonos / HEOS: Rich support, including playlists and groups
  • Samsung / LG TV: Shutdown is usually OK, startup often requires additional settings of Wake-on-LAN
  • Spotify / Plex:Yes play_media Specified playlist/video

Common pitfalls

  • It takes 3-5 seconds for the TV to accept commands after it is turned on. Automatic writing of "power on + change source" requires adding in the middle. delay.
  • Cast group (several speakers group broadcast) isExtraThe media_player entity is not an attribute of either speaker.

lock · Smart door lock

Common actions

  • lock.lock / lock.unlock
  • lock.open(If it is an electronically controllable door handle, it will actually open)

Common pitfalls

  • Safety first:Door lock automation is a mustdouble insurance. For example: "Automatically lock when leaving home" plus the condition "No one is at home + the door has not been opened in the past 5 minutes". Don't just use time as a trigger.
  • Cloud latency: Brand cloud integrations (Yale, August, Aqara cloud) often experience 5-15 second delays. If you want low latency, use Matter over Thread or Z-Wave.
  • Cannot lock when Unavailable: If the door lock is disconnected from the host, it cannot be operated remotely. Local protocols (Matter, Zigbee, Z-Wave) are more reliable than pure cloud.
Reminder:If the door is automatically locked without a mobile phone or key backup, you will be locked out. Always have a backup mechanical key or PIN.

vacuum · Sweeping robot

Common actions

  • vacuum.start / vacuum.pause / vacuum.stop
  • vacuum.return_to_base — Back to the charging stand
  • vacuum.locate — Ring the bell to find your location
  • vacuum.set_fan_speed —Suction level
  • vacuum.send_command — Send customized instructions (different brands, such as Roborock’s designated room cleaning)

Common usage

  • "Everyone leaves home for 30 minutes → Start cleaning" - Automation of going out
  • "Zigbee motion sensors are all inactive for 15 minutes + weekday afternoon" - conditional trigger
  • "There are visitors coming to the living room (Google Calendar event) → Clean the living room 30 minutes ago" - event driven

Common pitfalls

  • Cloud API current limit: Some brands of cloud APIs have a limit on the number of calls per day. Don’t write automation to check the status every minute.
  • Room ID is hidden: If you want to "scan only the living room", you must first partition the original App and then use it from HA send_command Pass the room ID. The ID is usually found in device properties or integration logs.

fan · Electric fan/ceiling fan/air purifier

Common actions

  • fan.turn_on / fan.turn_off / fan.toggle
  • fan.set_percentage(0-100 wind speed)
  • fan.set_preset_mode (auto / sleep / turbo, depending on the device)
  • fan.oscillate(shaking head left and right)
  • fan.set_direction(ceiling fan clockwise)

Common pitfalls

  • Air purifiers are often fan(air volume) + sensor (PM2.5)+ switch(Negative ions) Three domain-separated entities.
  • set_percentage: 0 Usually it is equivalent to shutting down. Before turning it back on, remember to first turn_on.

camera · Camera

Common actions

  • camera.snapshot — Take a picture and save it (parameters filename: /media/snap_{{ now().timestamp() }}.jpg)
  • camera.turn_on / turn_off(supported by some cameras)
  • camera.enable_motion_detection / disable_motion_detection
  • camera.record — Record a video

UI card

  • Picture entity: Built-in, the simplest
  • Picture glance: Image + small icon above to display related entities (door locks, lights)
  • WebRTC card(HACS): Low latency streaming, perfect for doorbells

Common pitfalls

  • Cloud camera (Ring, Wyze, TP-Link Kasa): Picture delay of 5-30 seconds is normal. If you want to get real-time streaming, you need to use ONVIF/RTSP local streaming.
  • Snapshot file location:Default /config/www/ can be read by the dashboard; save /media/ To configure additional media_source.

sensor / binary_sensor · Sensor

sensor YesHas a numerical valuesensor (temperature 25.3, battery 87%),binary_sensor YesOnly two statesof (door open/closed, someone/nobody, raining/not raining).

They do not accept control actions

The sensor is read-only. You cannot "turn_on" a temperature sensor. The value of the sensor iswhen trigger or condition:

  • Trigger: "When binary_sensor.motion_livingroom "turn on → turn on the light"
  • Condition: "When the sun sets, if binary_sensor.someone_home Do things only when you are on"
  • Value: "When sensor.pm25 > 35 → Turn on the purifier"

Commonly used device_class (determines icons and behaviors)

  • sensor: temperature / humidity / pressure / illuminance / power / energy / battery / co2 / pm25
  • binary_sensor: motion / occupancy / door / window / smoke / moisture / opening / battery / connectivity
Skill:If a sensor determines that the device_class is wrong (for example, opening is determined as door), the physical gear page can overwrite the device_class, and the dashboard icon will change accordingly.

Common pitfalls

  • Binary sensor jitter: The motion sensor is always "on → off in seconds → on", and automatically writing "on → turn on the light" and "off → turn off the light" will shake to the point of dizziness. Use the "for: 5 minutes" condition instead, and it will take action after 5 minutes of stable status.
  • battery is sensor not binary_sensor: Want to use "Battery lower than 20% reminder" sensor.*_battery + numeric_state trigger.

Common Tools and Mindsets

Concept:This tool has had its name changed twice. It used to be an independent project "Developer Tools" in the sidebar, and was included in it starting from 2026.2SettingsInside, 2026.8 simplified the name toTools—The current path isSettings → Tools. The "Services" tab inside will also be renamed in 2024.8Actions. So where it says "Settings → Tools → Actions" in this chapter, if your HA is still an old version, please go to the sidebar "Developer Tools → Services", the things are exactly the same.

Use "tools" to try out actions

Side menu "Settings" → "Tools" → "Actions" tab. You can select any action, fill in the parameters, and press execute. This is the fastest way for you to learn a new domain: no need to write automation, just try it.

Use "status" to view entity properties

Settings → Tools → "Status" tab → Paste entity ID → See what it has attributes. For example light.livingroom properties will have supported_color_modes, min_color_temp_kelvin, max_color_temp_kelvin, these determine what parameters you can set.

Summary of mental methods

Buy equipment → Check the domain first:can be recognized light / switch / cover / climate This kind of "named and surnamed" domain usually has the best subsequent experience; if you can only recognize it as a bunch of sensor + switch(such as some copycat Tuya electric curtains), writing automation will be a pain. You can check this by Google "Brand Home Assistant integration" before buying the device.

FAQ

The lamp in my house is obviously a lamp, why does HA think it is a lamp? switch? can be changed to light ?

Because the ability of that device to report back to HA is only "power on/off" - commonly seen in smart sockets connected to desk lamps, relay-type wall switches, and Tuya's one-on-everything module. The integration only knows that it will turn on and off the power, and does not know whether the light or the water dispenser is connected behind it, so it is classified as switch.

HA has a built-in auxiliary component that can help it change its face:Settings → Devices and Services → Accessories → Create Accessories, select "Change device type of a switch" (the old name in English is Switch as X, the Chinese interface will display the corresponding words "Change device type of a switch"). pick one switch entity, you can turn it into light, cover, fan, lock, siren or valve One of a kind. After conversion, there will be one new entity (for example light.desk_lamp), the original one switch It will be automatically hidden to prevent two identical things from appearing on the dashboard.

Warning:This is just a change of classification and will not create capabilities that the hardware does not have. Convert to light Afterwards you can use light.turn_on, but stillCan'tAdjust brightness and color temperature - it doesn't have it. If you want to dim the light, you need to replace it with a truly dimmable lamp or dimming module.
My light only has brightness and no color temperature and color options. Is it an HA problem?

Eighty percent of the time, the problem is not with the HA, but with the lamp itself. ArriveSettings → Tools → StatusPaste the entity ID and see supported_color_modes This attribute will honestly tell you which color modes this lamp supports:

color modeWhat you will see on the UI
onoffOnly on/off, not even a brightness slider
brightnessBrightness slider only (monotone light)
color_tempBrightness + Color Temperature (warm white to cool white)
hs / rgb / rgbw / rgbwwBrightness + Color Wheel (rgbww This kind also has an additional white light channel)

There is in the list color_temp lights will appear simultaneously in the properties min_color_temp_kelvin and max_color_temp_kelvin, that is, how warm or cold the color temperature of this lamp can be adjusted. If the hardware does not support it, no auxiliary components or HACS cards will be able to change the color temperature.

if supported_color_modes Obviously less than what is written in the product specifications (for example, I bought a colored light bulb but only brightness), that is the key to integration: first update the bulb firmware, re-pair, or go to the integrated GitHub to see if there are reports of the same model.

The opening and closing direction of the curtain is reversed. Press "Open" to close it. The positions 0 and 100 are also reversed. How to fix it?

First remember that the definition of HA is dead:position: 0 YesCompletely closed, position: 100 YesFully open. This rule doesn't change based on your motor setup.

The correct approach isGo to the installation end and adjust it, do not write in HA automation 100 - x This kind of math problem - you'll completely forget why this line is there in half a year, and the slider on the dashboard will still be backwards. According to your method:

  1. Zigbee2MQTT motor

    Go to the settings area of the device page to find motor_reversal(Reverse the direction of the motor) or invert_cover(Reverse the position value, false is open=100 / close=0). Taking common curtain modules such as Tuya TS130F as an example, these two options are among the device's configurable items.

  2. Motor paired with the original app

    Most electric curtains have "motor direction" or "travel calibration" in the original app. Re-setting the upper and lower limits is usually correct. After calibrating the HA, there is no need to change anything.

  3. Device page reset

    Some integrations provide "Reconfigure" on the device page to rerun the calibration process.

  4. There really is no choice, last resort

    Only then did I consider using a template cover to wrap a layer and reverse the values. This is the most difficult approach to maintain, so avoid it if you can.

I use climate.set_temperature Set to 26 degrees, but the air conditioner doesn’t respond at all?

Checking in this order, 90% are the first two items:

  • The air conditioner is off.Assume that the target temperature is not equal to power on.climate.set_temperature Eat by itself hvac_mode This field is the safest to write in one go:hvac_mode: cool add temperature: 26.
  • Trapped by preset.When switching to manufacturer-preset modes such as "eco" and "sleep", the target temperature is often determined by the manufacturer. first climate.set_preset_mode Set back none, and then set the temperature.
  • Out of settable range.Each machine has its own min_temp / max_temp(default for HA side is 7 to 35 degrees), and target_temp_step(Some machines can only adjust a few degrees. If you send 25.5, it will be ignored). You can see these properties in Settings → Tools → Status.
  • It is actually a zone thermostat.Use this kind target_temp_high / target_temp_low, get a single temperature will be eaten.
  • Infrared air conditioner.As mentioned earlier in this article, HA only sends commands, and no one knows whether there are any hits when sent out - is the air conditioner facing the remote control? Is there any obstruction in the middle?

The quickest way to determine what happened is toSettings → Tools → ActionsExecute it directly and see if it reports success or skips an error message.

The camera is slow and stuck on the dashboard, is there any way to fix it?

First figure out which section you are stuck in:

  1. First make sure it is not an inherent delay in cloud integration

    The delay of several seconds for cameras running on brand clouds (those types mentioned earlier in this article) is structural and cannot be saved by changing the settings. The only option is to switch to ONVIF / RTSP local streaming.

  2. Make sure you are using WebRTC

    Home Assistant has built-in go2rtc starting from 2024.11, which provides WebRTC streaming for the camera, which is significantly more real-time than the old HLS. If you are running Home Assistant OS or the official container, it will be enabled by default after the update; cameras that do not support WebRTC will automatically fall back to the old method.

  3. Use substream (substream)

    Most IP cameras provide both a high-definition main stream and a low-resolution sub-stream. The small grid on the dashboard uses the sub-stream, and the main stream is used when you click to open it. The machine burden is much different.

  4. Don’t cram eight cameras into one page

    Every live stream consumes CPU and bandwidth. Concentrate the camera on a single tab, and don't open that page normally, so that it won't drag down the entire dashboard.

  5. "Preload streaming" should be considered

    There is a "Preload stream" option in the camera's physical settings. If you turn it on, it will always stay connected. When you click it, it will be faster, but it will continue to consume resources. It is not recommended to turn it all on low-end hosts (like the old Raspberry Pi).

Sensor display unknown and unavailable, what’s the difference between these two?

The official development documents explain the division of labor between these two states very clearly:

Statusmeaningtypical situation
unavailableIntegrateCan't find information—The connection is disconnected, the device is out of power, and the cloud service is down.The Zigbee sensor has no battery, the Wi-Fi socket is disconnected, and the host has just been restarted and is still not connected.
unknownNot even close, butThis value is currently emptyThe computer has just been restarted and the first report has not been received. A certain field has not been returned this time. The value of the auxiliary component has not been set after it was created.

Vernacular version:unavailable It's "no one is here",unknown It's "The person is here, but he can't answer it."

When writing automation, beware of both: Numeric triggers (numeric_state) will not trigger when encountering these two states, but if you use it to perform calculations in conditions or templates, an error will occur and the entire automation will be interrupted. It is customary to add a condition to block it, such as judging that the status is not unknown Neither unavailable Just go down.

Tip:If a sensoroftenchange unavailable, that is a signal or battery problem, which cannot be solved by writing a program - go to the device page troubleshooting in Chapter 11, or add a Zigbee router (plugged-in device) relay for it.
