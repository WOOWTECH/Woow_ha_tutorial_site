Chapter 16

To-do lists and calendars

Move recurring household reminders out of your head and into Home Assistant. Build shared to-do lists and calendars, then use their items and events to send notifications and trigger actions.

Why this matters

Household reminders often end up scattered across sticky notes, phone apps, and paper bills. When information lives in separate places, tasks are easy to miss.

Home Assistant has two built-in tools to cut through this mess:

  • To-do list: a set of pending items that you can complete and, where supported, assign due dates. A shopping list is one example.
  • Calendar: events tied to dates or times, such as a collection schedule, meeting, or payment deadline.

The main advantage is not merely visibility: lists and calendars can drive automations. A 7:30 p.m. collection event can turn on an entry light and notify a phone at 7:10 p.m. Adding a to-do item can notify the household.

Concept: This chapter extends Chapter 7 (Notifications) and Chapter 8 (First automation). The trigger → condition → action model remains the same; only the triggers (calendar events and to-do changes) and actions (todo domain) are new.

By the end, you will have a shared shopping list, a local calendar, at least three calendar-driven automations, and a dashboard view of today’s tasks.

To-do lists vs. calendars

A to-do item does not automatically act like a timed reminder. Choose based on one question: Does the task occur at a specific date or time?

Aspect To-do list (todo) Calendar
Core information Items with completion status Events with start and end times
Time Can have a due date or date/time when the provider supports it Time is central and can be precise to the minute
entity state Number: Number of items not yet completed on(currently in an event) or off
typical content Buy soy sauce, change filters, pay water bills Trash removal 19:30, meeting 14:00–15:00, housework rotation
How to trigger automation When items are added/completed/removed When the event starts or ends (can be earlier)
Tip: Use both together: a calendar determines when something occurs, while a to-do list keeps the work visible until completion. A later example adds a filter-replacement task when its maintenance event begins.

A domain groups entities by function, such as light, switch, or sensor. To-do entities use todo; calendar entities use calendar. You will therefore see entity IDs such as todo.shopping_list and calendar.trash_day. See Chapter 12.

Warning: Entity IDs such as todo.family_chores are examples. Home Assistant generates the actual ID from your list name, and non-Latin names may produce unexpected IDs. Before using an example, copy the real ID from Settings → Tools → States. This area was named Developer tools before 2026.8. See Chapter 4.

Hands-on 1: Create your first local to-do list

Use the Local To-do integration. Its data remains in your Home Assistant installation and does not depend on a cloud service or internet access. A full Home Assistant backup includes it; see Chapter 9.

  1. Open integration page

    Click on the left sidebar Settings → Devices & Services, select the Integrations tab.

  2. Add the integration

    Select Add integration in the lower-right corner, search for “Local” or “To-do,” and choose Local to-do. The integration requires Home Assistant 2023.11 or later.

  3. Name the list

    Enter a clear list name, such as “Household chores” or “Shopping,” then select Submit.

  4. Create additional lists as needed

    Local To-do creates one list per setup flow. Repeat the previous steps for separate lists such as household chores, shopping, and family requests. Each becomes an independent todo. entity.

  5. Go to the sidebar to find the "To-Do List" panel

    The built-in To-do lists panel lets you add items, mark them complete, and set supported due fields without building a custom dashboard.

  6. Confirm entity ID

    Open Settings → Tools → States and filter for todo.. The entity state is the number of incomplete items. Copy the entity ID for later automations.

Concept: A list item can provide a required name, an optional due date or date/time, an optional description, and a status. Provider support varies; Local To-do supports these fields.

Which one to use for Shopping List?

Home Assistant also provides the older Shopping list integration. Choose between them based on list count, due fields, and voice support.

Shopping list Local to-do
Number of lists One fixed shopping list Create as many separate lists as needed
due date No Yes
voice assistant Official documentation clearly states that you can use voice commands such as "Add eggs to my shopping list" to add items. Voice support depends on your voice assistant settings
Exclusive action There is a whole group shopping_list.* old action There are no exclusive actions, only general ones todo.*
Universal todo.* action Can be used (it is also a todo entity) available

Two integrations They are still in Home Assistant documentation and have not been marked for elimination.. It is recommended to choose this:

  • You need one grocery list with built-in voice support → use Shopping list.
  • You need multiple lists, due fields, or more general automations → use Local To-do.
  • You can install both; they use separate entities and data.

Shopping list retains a set of older, dedicated actions. For new automations, prefer the shared todo.* actions in the next section, because that set of actions is common to all to-do lists:

shopping_list.add_item
shopping_list.complete_item
shopping_list.incomplete_item
shopping_list.remove_item
shopping_list.complete_all
shopping_list.incomplete_all
shopping_list.clear_completed_items
shopping_list.sort
Tip: Shopping list creates a todo. entity, so it works with the To-do list card and todo.add_item. Its dedicated legacy actions remain available.

Action quick check for todo domain

Older documentation used the term service and the YAML key service:. Home Assistant now uses action and action:. Older examples may therefore show service: todo.add_item.

action what to do Main parameters
todo.add_item Add a new item item(required),due_date, due_datetime, description
todo.update_item Change an item: change name, check box, change due date item(required, name or UID),rename, status, due_date, due_datetime, description
todo.remove_item Delete an entire item item
todo.get_items Read out the contents of the list for subsequent steps status, match response_variable
todo.remove_completed_items Clear all completed items at once Just specify the list, no other parameters

Add a new item

action: todo.add_item
target:
  entity_id: todo.family_chores
data:
  item: Replace the living-room AC filter
  due_date: "2026-09-01"
  description: Remove it, rinse it with water, let it air-dry for a day, and reinstall it.
Warning:due_date(Only date, e.g. 2026-09-01) and due_datetime(Date plus time, such as 2026-09-01 23:00:00) You can only choose one of the two, not both at the same time., writing two will directly report an error. In addition, the due date and description fields are not supported by every list. Only supported lists can be used.

Tick the item (mark complete)

action: todo.update_item
target:
  entity_id: todo.family_chores
data:
  item: Replace the living-room AC filter
  status: completed

status accepts needs_action or completed. To reopen a completed item, set status to needs_action.

Warning: item can identify an entry by name. If two entries have the same name, use the item’s unique UID instead. Retrieve UIDs with todo.get_items.

Read list contents

This action returns data. Use response_variable to store the response for later steps:

action: todo.get_items
target:
  entity_id: todo.family_chores
data:
  status: needs_action
response_variable: my_items

If omitted, status defaults to needs_action. To retrieve both states, use [needs_action, completed]. The response has this structure:

todo.family_chores:
  items:
    - summary: Replace the living-room AC filter
      uid: "01244b28-e604-11ee-a0a4-e45f0197c057"
      status: needs_action
      due: "2026-09-01"
      description: Remove and rinse it with water
    - summary: Pay the building management fee
      uid: "ae993df4-e604-11ee-a0a4-e45f0197c057"
      status: needs_action

Note the field names for each item:summary(not item), uid, status, and there are two optional due(due date) and description.

Warning: Items without a due value or description omit those fields entirely. A template that assumes every item has due can fail. The payment example first uses selectattr('due', 'defined') to retain only items where the field exists.

Triggered by changes in the to-do list

Newer Home Assistant versions provide three todo triggers in the automation editor:

trigger When does it trigger? What to use it for?
todo.item_added New item added to list When someone adds something to the shopping list, notify the whole family
todo.item_completed Item is ticked The child checked "Take out the trash", notify parents
todo.item_removed Item was deleted Used for auditing to see who deleted something

The YAML writing method is different from the general trigger. It uses target: rather than writing directly entity_id:: 

alias: Notify when an item is added to the shopping list
triggers:
  - trigger: todo.item_added
    target:
      entity_id: todo.shopping_list
actions:
  - action: notify.mobile_app_my_phone
    data:
      title: Shopping list updated
      message: Someone added an item. Remember to check the list before you go out.

Trigger data includes the list entity_id and affected item IDs in item_ids. To obtain item names, call todo.get_items in the actions.

Warning: These triggers require a recent Home Assistant version. If they are unavailable, either upgrade after reviewing release requirements or use a State trigger on the todo. entity. Remember that its numeric state is the count of incomplete items, so multiple changes can produce the same count.
Tip: To check support, add an automation trigger and search for “to-do.” If the trigger types do not appear, consult the documentation for your installed version.

Hands-on 2: Create a local calendar

The official Local Calendar integration, added in Home Assistant 2022.12, stores data in your installation and requires no external account or cloud service.

  1. New integration

    Settings → Devices & Services → + New integration, search Local calendar (local calendar).

  2. Pick a calendar name

    Enter a calendar name. Separate calendars by purpose, such as collection, chore rotation, payments, and maintenance, to simplify triggers.

  3. Why build it separately: Because the trigger is tied to the "entire calendar"

    A calendar trigger fires for any event in that calendar. Separate calendars by purpose to simplify automations. To share one calendar, add a condition that checks trigger.calendar_event.summary.

  4. Go to the "Calendar" panel in the sidebar and add events

    After setup, open the Calendar panel in the sidebar. Select a day to create an all-day or timed event, and optionally set Repeat (weekly, monthly, etc.). If something like taking out the trash is fixed on a weekly basis, set it up as a recurring event, and set it up once for a whole year.

  5. Confirm entity ID and status

    Settings → Tools → States, filter calendar.. A calendar entity has two states: on while an event is in progress and off otherwise.

Concept: Do not rely on the calendar entity changing to on for reminders. That state represents only whether an event is currently active and cannot provide advance notice. Use a calendar trigger with an offset.

An automation can also create calendar events, for example after a reservation is confirmed:

action: calendar.create_event
target:
  entity_id: calendar.family
data:
  summary: Family dinner
  start_date_time: "2026-09-20 18:00:00"
  end_date_time: "2026-09-20 20:00:00"
  location: Grandma’s house

summary(Title) is the only required field. There are three ways to specify time, Choose one from three:

Writing method Where to use Example
start_date_time + end_date_time event with definite moment "2026-09-20 18:00:00"
start_date + end_date all day event "2026-09-20"
in(Including days or weeks) "In a few days/weeks", no need to count the date in: {days: 90}

Connect Google Calendar and CalDAV

Local Calendar is available only through Home Assistant. If your household already uses Google Calendar, connecting it lets events created in Google appear in Home Assistant.

Google Calendar

Google Calendar has the most involved setup in this chapter. Create a Google Cloud project, enable the Google Calendar API, configure OAuth consent, create OAuth client credentials, and enter the Client ID and Client Secret in Home Assistant. Follow the current integration documentation.

Danger: Treat the Client Secret as a credential. Never publish it in a forum, chat, video comment, log, or screenshot. If exposed, revoke it in Google Cloud Console and create a replacement.
Warning: If the OAuth consent screen remains in Testing, the documentation warns that the OAuth token expires every 7 days. If appropriate for your Google project and account type, use Publish app to change the publishing status, then authorize Home Assistant again.

After setup, each calendar under My calendars becomes a calendar. entity. Use google.create_event to add events through the integration.

Tip: Start with Local Calendar to test these automations before completing Google’s OAuth setup. Both integrations expose calendar. entities, so the automation structure remains the same when you replace an entity ID.

CalDAV (Nextcloud, iCloud, Synology…)

For Nextcloud, Baikal, ownCloud, Synology Calendar, or iCloud, use the CalDAV standard. The documentation lists tested servers; other RFC 4791-compliant servers may work.

Setting method how to do Can I get a to-do list?
Interface settings (recommended) Settings → Devices & Services → New integration → CalDAV Yes, todo entities will be generated
Manually write YAML Edit configuration.yaml No, Home Assistant documentation clearly states that YAML does not support to-do lists.

The main fields are url, username, and password. Use calendars or custom_calendars to select calendars. verify_ssl defaults to true; disable verification only for a trusted self-hosted server when you understand the risk. days defaults to 1 and applies only under custom_calendars.

Warning: For iCloud, use an app-specific password. Do not provide your primary Apple Account password to Home Assistant.

Google Tasks (to-do list, not calendar)

By the way, Google’s to-do list also has an official integration called Google Tasks (Added in Home Assistant 2023.11), will turn your Google to-do list into todo. entity. There are two limitations to be aware of first:

  • Only expiration "date" is supported, expiration "time" is not supported—This is a limitation of the Google Tasks API itself, not a problem with HA.
  • The integration polls every 30 minutes. A task created on a phone may not appear in Home Assistant until the next poll.
Tip: The documented 30-minute polling interval applies to Google → Home Assistant updates. Changes made through Home Assistant are sent to Google Tasks immediately. Do not expect a phone-created task to trigger a Home Assistant automation immediately.

The setting method is the same as that of Google Calendar. You need to create your own Google Cloud certificate, but you need to enable the Google Tasks API.

Put lists and calendars on your dashboard

The built-in panels are sufficient for direct use. To show today’s tasks on a dashboard, add To-do list and Calendar cards. See Chapter 6 for dashboard editing.

    Open your dashboard, top right corner pencil icon to enter edit mode, then press "+ Add new card".

  2. Add to-do list card

    Find it in the card list To-do list, choose your todo. entity.

  3. Add calendar card

    Add a Calendar card. It can display several calendars together, distinguished by color.

  4. Fine-tuning with YAML

    In the lower left corner of the card editing window, there is "Show Code Editor", you can paste the following settings by cutting it.

Trigger automation with calendar events

A calendar trigger requires only these fields:

triggers:
  - trigger: calendar
    entity_id: calendar.trash_day
    event: start
    offset: "-00:20:00"
field meaning
entity_id Calendar entity to monitor
event start(event starts) or end(event ends)
offset Time offset. The format is "hour:minute:second". A negative sign in front means advance, without the negative sign means delay. The one above -00:20:00 That's "20 minutes before the event starts"
Warning: Home Assistant reads calendar data every 15 minutes. A newly created event that starts in 5 minutes may not be retrieved before its trigger time. Very short offsets such as -00:02:00 are therefore unreliable for newly added remote events; use a Time trigger when exact timing is required.

The content of the event can be used directly

When the trigger fires, event data is available under trigger.calendar_event for use in notifications and conditions:

variables content
trigger.calendar_event.summary event title
trigger.calendar_event.description Detailed description of the event (only available if filled in)
trigger.calendar_event.location Location (only available if filled in)
trigger.calendar_event.start Text for start time, e.g. 2026-04-10 or 2026-04-10 11:30:00-07:00
trigger.calendar_event.end end time text
trigger.calendar_event.all_day Is it an all-day event?

For an all-day event, start contains a date only; timed events include time-zone information. Extract the date with {{ trigger.calendar_event.start[:10] }}.

Tip: Test templates under Settings → Tools → Templates before adding them to an automation.

Six practical situations you can copy right away

Each of the following paragraphs can be pasted directly into the YAML mode of the automation editor (three dots in the upper right corner → Edit YAML). Remember to replace the entity ID with your own.

1. Trash day reminder

First, create a calendar called "Taking out the Trash" in Local Calendar, and set the garbage truck time as a weekly recurring event.

alias: Garbage collection is approaching
triggers:
  - trigger: calendar
    entity_id: calendar.trash_day
    event: start
    offset: "-00:20:00"
actions:
  - action: notify.mobile_app_my_phone
    data:
      title: Garbage collection in 20 minutes
      message: "{{ trigger.calendar_event.summary }} | Do you have the bag?"
  - action: light.turn_on
    target:
      entity_id: light.entrance
    data:
      brightness_pct: 80
mode: single

The light provides an ambient reminder in addition to the phone notification.

2. Payment date: reminder as soon as the due date arrives

Use a to-do item for a bill because it remains pending until completed. This automation checks each morning at 8:00 for items due today:

alias: Items due today
triggers:
  - trigger: time
    at: "08:00:00"
actions:
  - action: todo.get_items
    target:
      entity_id: todo.family_chores
    data:
      status: needs_action
    response_variable: result
  - variables:
      today: "{{ now().date() | string }}"
      due_today: >-
        {{ result['todo.family_chores']['items']
           | selectattr('due', 'defined')
           | rejectattr('due', 'none')
           | selectattr('due', 'search', today)
           | map(attribute='summary') | list }}
  - if:
      - condition: template
        value_template: "{{ due_today | count > 0 }}"
    then:
      - action: notify.mobile_app_my_phone
        data:
          title: "{{ due_today | count }} items are due today"
          message: "{{ due_today | join(', ') }}"
mode: single

The three filters are essential. selectattr('due', 'defined') keeps items that contain a due field. rejectattr('due', 'none') removes null values. Finally, selectattr('due', 'search', today) keeps due strings containing today’s date. Without the first two filters, an item without a due value can cause a template error.

Warning: Providers can return due as a date such as 2026-09-01 or as a date/time. Test this template under Settings → Tools → Templates with your provider’s actual response before enabling the automation.

3. Air conditioning filter replacement: Calendar creates to-do list

The classic "calendar + to-do" combo. The calendar is responsible for recording time periods. Once the time is up, a to-do item will be automatically added to the list. You can do it whenever you are free and tick it when you are done:

alias: Create to-do items from the maintenance calendar
triggers:
  - trigger: calendar
    entity_id: calendar.maintenance
    event: start
actions:
  - action: todo.add_item
    target:
      entity_id: todo.family_chores
    data:
      item: "{{ trigger.calendar_event.summary }}"
      due_date: "{{ trigger.calendar_event.start[:10] }}"
      description: "{{ trigger.calendar_event.description }}"
mode: queued
max: 10

Set up several full-day events in the "Maintenance" calendar that repeat every three months: "Clean the living room air conditioning filter," "Replace the water purifier filter element," and "Clean the washing machine." Set it up once and it will automatically appear on your to-do list every quarter.

Tip: mode: queued with max: 10 allows multiple maintenance events that start together to run in sequence. With the default single mode, an overlapping run is rejected. See Chapter 10.

4. Housework rotation

In the "Housework Rotation" calendar, write the event title directly as "It's Xiao Ming's turn to wash the dishes this week", and then:

alias: Household chore rotation reminder
triggers:
  - trigger: calendar
    entity_id: calendar.chore_rotation
    event: start
    offset: "-01:00:00"
actions:
  - action: todo.add_item
    target:
      entity_id: todo.family_chores
    data:
      item: "{{ trigger.calendar_event.summary }}"
  - action: notify.family_all
    data:
      title: Chore rotation
      message: "In one hour: {{ trigger.calendar_event.summary }}"
mode: queued
max: 10

notify.family_all is the example notification group configured in Chapter 7.

5. Office conference room: one-panel event tube lights and air conditioning

The most practical one for small offices. Connect the conference room reservation calendar to HA (Google Calendar or CalDAV will work), turn on the lights and air conditioner ten minutes before the meeting, and turn them off when the meeting ends:

alias: Control a meeting room from its bookings
triggers:
  - trigger: calendar
    id: meeting_start
    entity_id: calendar.meeting_room
    event: start
    offset: "-00:10:00"
  - trigger: calendar
    id: meeting_end
    entity_id: calendar.meeting_room
    event: end
actions:
  - choose:
      - conditions:
          - condition: trigger
            id: meeting_start
        sequence:
          - action: light.turn_on
            target:
              entity_id: light.meeting_room
          - action: climate.turn_on
            target:
              entity_id: climate.meeting_room
      - conditions:
          - condition: trigger
            id: meeting_end
        sequence:
          - action: light.turn_off
            target:
              entity_id: light.meeting_room
          - action: climate.turn_off
            target:
              entity_id: climate.meeting_room
mode: queued
max: 10

This example assigns each trigger an id, then branches with choose. This keeps related start and end behavior in one automation. If the climate integration does not support climate.turn_on, use climate.set_hvac_mode, see the domain actions in Chapter 12.

6. Clear the boxes every week

alias: Clear completed items on Sunday night
triggers:
  - trigger: time
    at: "22:00:00"
conditions:
  - condition: time
    weekday:
      - sun
actions:
  - action: todo.remove_completed_items
    target:
      entity_id: todo.family_chores
mode: single
Danger: todo.remove_completed_items permanently deletes completed items; there is no recycle bin. Do not schedule it if you need an audit trail, or use a retention interval appropriate to your records.

Linking notifications with voice assistants

Notifications: Make reminders really visible

Companion App setup, notify.mobile_app_* entity IDs, and notification groups are covered in Chapter 7. Apply these practices to lists and calendars:

  • Put the event title directly into the message—Use {{ trigger.calendar_event.summary }}, one automation can serve all events on the calendar, without writing one for each event.
  • Use conditions to avoid irrelevant or overnight alerts. Add a time or occupancy condition under conditions:.
  • Choose the right output. In a meeting room, a visible light cue or authorized voice announcement may be more effective than a phone notification.

Voice: add shopping list by shouting

Voice assistants are a natural companion for this chapter—it’s much faster to shout than to pull out your phone when your hands are greasy and the refrigerator door is open. The key points of this part:

  • Home Assistant documentation for Shopping list integration clearly mentions You can add things using voice commands, an example sentence is "Add eggs to my shopping list" in English.
  • Sentence support varies by language. Home Assistant does not support every sentence pattern in every language. Your version and your voice assistant settings will affect the results. If you want to confirm whether your method will work, the fastest way is Open the Assist dialog box in the upper right corner of HA and type directly (no need to speak) to try a sentence, see if it reacts.
  • If the built-in sentence pattern does not satisfy what you want to say, the fallback option is custom sentences, corresponding to the way you are used to speaking todo.add_item. Please see the chapter on voice assistant for how to set it up.
Tip: Speech recognition can mis-transcribe item names in any language. Avoid safety- or access-critical automation conditions based on an exact voice-created item name; use list state or explicit confirmation where appropriate.

Common problems

  1. Google authorization expires every 7 days and keeps asking me to log in again

    The OAuth consent screen is probably still in Testing, where the documentation warns that tokens expire every 7 days. If appropriate for your Google project and account type, select Publish app, then authorize Home Assistant again.

  2. Google authorization fails immediately, jumping "redirect_uri_mismatch" or similar error

    This means that the redirect URL you registered with Google is different from the one actually sent by HA. Fill in the Google credential settings according to the redirect URL specified in Home Assistant documentation verbatim. Letter case, and whether there is a slash at the end, all count. Also check if you have installed the Google Calendar API enable—Many people create credentials but forget to enable the API.

  3. The event time differs by several hours (time zone misalignment)

    Check three places in order:
    (1) Home Assistant time zone—Under Settings → System → Home information, confirm that Region uses your time zone. The zh-TW source uses Asia/Taipei; choose the value for your location. If the field is unavailable, check whether configuration.yaml defines it, as explained in Chapter 2.
    (2) The time zone of the source calendar—Google Calendar itself has a calendar time zone setting. If it is another time zone, the entire set of events will be offset.
    (3) All-day event—An all-day event has all_day set to true, and start contains only a date. Check all_day before applying time-based comparisons.

  4. Calendar automation did not trigger when it should have

    First think, "How long ago did I create this event?" Home Assistant document states Calendar is only read every 15 minutes. It will be triggered after 5 minutes as soon as it is built. It is normal to be too late. The second common reason is offset Wrong writing - there must be a negative sign in advance,"-00:30:00" It's half an hour in advance."00:30:00" It's delayed by half an hour. Third, go Settings → Automations & Scenes & Scenes Click on the automation, three dots in the upper right corner → Traces, to see if it has been triggered and at which step it is stuck.

  5. A phone-created to-do item has not appeared in Home Assistant

    Local To-do does not synchronize with an external service; its items exist only in Home Assistant. Cloud sources update on polling intervals: Google Tasks polls every 30 minutes, and CalDAV also polls periodically. Wait for the documented interval, then reload the integration and if it still does not appear, open Settings → Devices & Services, find the integration, and select Reload from its three-dot menu.

  6. todo.update_item Says the item cannot be found

    Three directions: (1) name exactly the same, one more blank space, and different full-width and half-width forms are considered different; (2) There are two items with the same name in the list, and HA doesn’t know which one to change, so use uid—Use first todo.get_items Take out the UID and fill in the UID item Field; (3) You typed incorrectly entity_id, changed to another list.

  7. Adding an item reports an invalid due-date parameter

    The most common is due_date and due_datetime Wrote at the same time, you can only choose one of the two. The second is that the list you are using does not support due dates or descriptions at all - not every integration supports all fields, for example Google Tasks only supports dates but not time. Remove that parameter and try again to see if this is the reason.

  8. After deleting the integration, the to-do list panel keeps reporting errors.

    Cards on the dashboard also point to entities that no longer exist. Go to edit mode and delete the orphan card. Before deleting an integration, think about whether there are any cards or automations using it. This habit can save a lot of trouble.

FAQ

Where is the Local To-do information stored? Will the backup be taken away?
It is stored in Home Assistant's own settings directory, not in the cloud. So As long as you make a complete backup, the list data will be backed up as well., the items are still there after restoration. The backup method is Chapter 9. Please note: because it only exists in HA, If HA is down, you won’t be able to see the list., so it is recommended that really important things (such as payment deadlines) be also recorded on your phone, or switch to a solution that will be synchronized to the cloud.
Do I need to open a Google Cloud project to use Calendar? Is there an easier way?
use Google Calendar If so, yes, Home Assistant documentation clearly states that you have to create a Google Cloud project yourself, enable the Google Calendar API, and generate OAuth credentials. But if you just want the ability to “trigger automation on calendar events”, No need to touch Google at all—Just use Local Calendar. It can be installed in two minutes. The functions are exactly the same. All the automation examples in this chapter can be run. The only difference is that you can't see the calendar on your phone. If you want to see it on your phone but don't want to touch Google Cloud, the third option is CalDAV (such as the self-installed Nextcloud or Synology Calendar). The setting is relatively simple, just fill in the URL and account password.
Why can I see events on my calendar card, but the automation is not triggered?
You can see it on the card, it only represents HA Readable That event does not mean that the trigger will trigger. Can the whole family share the same list? Can it be modified on each phone?
Yes. If both Shopping list and Local to-do are installed, will there be a fight?
No, they are two independent integrations, each producing its own entity, and the data is completely separate. You will see two lists at the same time in the to-do list panel in the sidebar. I want to use the title of the calendar event for judgment. For example, it will be triggered only if the title contains "Take out the trash". How to do this?
The calendar trigger itself does not have the option of "trigger only when the title matches". It triggers when any event in the entire calendar starts. The approach is Let the trigger fire, filter in conditions:Add a template condition {{ 'Take out the trash' in trigger.calendar_event.summary }}, those who do not meet the conditions will be blocked at that level. However, the more recommended approach is to Group events for different purposes into different calendars, automation will be much simpler, and there is no need to write templates. If you want to use a template, remember to go to Settings → Tools → Template Test Run first.
