Chapter 16

To-do lists and calendars

Move recurring household reminders out of your head and into Home Assistant. Build shared to-do lists and calendars, then use their items and events to send notifications and trigger actions.

Why should you learn this?

The current situation in your family is probably like this: Mom puts sticky notes on the refrigerator door, you jot things down in the memo on your phone, and Dad stuffs the bill on the shoe cabinet. Three places, three pieces of information, all forgotten in the end.

Home Assistant has two built-in tools to cut through this mess:

  • To-do list—A bunch of "to-do-but-not-yet-to-do" things that can be checked and due dates can be set. A shopping list is one of them.
  • Calendar—An event with a clear time, what time does the garbage truck come, what time does the meeting start, and payment is due next Wednesday.

The biggest advantage of moving them into HA is not “visible”; They can be used as raw materials for automation. If you write "Take out the trash 19:30" on your calendar, HA can turn on the porch light at 19:10 and push the message to your phone; if someone adds something to the to-do list, HA can notify the whole family. This is something paper sticky notes can never do.

Concept: This chapter is Chapter 7 (Notice) and Chapter 8 (First Automation) extension. Chapter 8 teaches you the three-stage formula of "trigger → condition → action". This chapter just changes the new trigger source (calendar event, to-do item change) and new action (todo domain). The mentality of the three-stage form remains completely unchanged. If you haven’t read it, I suggest you go back and read it first.

After reading this chapter, you will have: a shopping list shared by the whole family, a local calendar, at least three automations that "automate the calendar when the time is up", and a dashboard page where you can see what you want to do today.

To-do list vs calendar: when to use which one

Many people confuse the two at first and put "take out the trash" on their to-do list, only to find that it won't remind them on their own. The judgment method is very simple: Is there a "what time" for this matter?

questionto-do list (todo)calendar
core information"Items" one by one, with or without ticksEach "event" has a start and end time
time"Due date" can be set, but there is no concept of precise timeTime is the protagonist, accurate to the minute
entity stateNumber: Number of items not yet completedon(currently in an event) or off
typical contentBuy soy sauce, change filters, pay water billsTrash removal 19:30, meeting 14:00–15:00, housework rotation
How to trigger automationWhen items are added/completed/removedWhen the event starts or ends (can be earlier)
Tip: The two are most capable when used together. The calendar is responsible for "when to remind", and the to-do list is responsible for "the things that have not been completed are piled here." The air conditioning filter situation later in this chapter is set up like this: Calendar time is up → automatically add a to-do item to the list.

There is another term that needs to be explained clearly first: Domain. HA divides entities into light, switch, sensor These areas, the areas of the backlog are called todo, the calendar field is called calendar. So you will see later todo.shopping_list, calendar.trash_day This entity ID. The field map is in Chapter 12.

Warning: Entity IDs for all examples below (like todo.family_chores) are examples. For lists you create yourself, the entity ID will be automatically generated based on the name you type. An ID generated from a non-Latin name may look very different. Before using an example, go to Settings → Tools → States (this area was called "Developer Tools" before 2026.8, in the sidebar) Copy the real ID. The rules for naming and entity_id are Chapter 4.

Hands-on 1: Create your first local to-do list

The integration we are going to use is called Local To-do (local to-do list). "Local" means that the data is completely stored in your own HA. It does not go to any cloud. It can be used even when the network is disconnected. It will also follow Chapter 9 it is included in Home Assistant backups.

  1. Open integration page

    Click on the left sidebar Settings → Devices & Services, confirm the one at the top "Integration" Tab.

  2. New integration

    lower right corner "+ New integration" Press the button, type "Local" or "To Do" in the search box, and select Local to-do (Local to-do list). This integration was added in Home Assistant 2023.11. If the version is too old, it will not be found.

  3. Just fill in one field: list name

    This integrated setting screen is very clean. I only ask you one thing -What should I call this list?. You can do "housework" or "shopping". Click send and the list will be generated.

  4. Make as many servings as you want

    Local To-do only builds one list at a time. If you want three copies of "housework", "shopping" and "parents' instructions", repeat steps 2-3 three times. Each copy will become an independent todo. entity.

  5. Go to the sidebar to find the "To-Do List" panel

    After it is built, there will be a to-do list exclusive panel. Click in and you can directly type in new items, check the box to complete, and set the due date. This panel is built into HA, so you don’t need to make your own dashboard.

  6. Confirm entity ID

    Go to Settings → Tools → States, enter in the filter box todo., you will see the list you just created. The number in the status bar is the number of items in this list that have not yet been completed. Copy the entity ID, which will be used later in automation.

Concept: Each item in the list can bring up to four types of information: Name (required), due date, Description (Additional explanation longer than the name), Status (Unfinished/Completed). Not every integration supports all four, Local To-do support is considered complete.

Action quick check for todo domain

Let’s talk about a very important wording update first: HA used to be called “Service”, and in YAML it was written service:, Now it is always called "Action" and written in YAML action:. you see on the internet service: todo.add_item Teaching, that is the old way of writing.

actionwhat to doMain parameters
todo.add_itemAdd a new itemitem(required),due_date, due_datetime, description
todo.update_itemChange an item: change name, check box, change due dateitem(required, name or UID),rename, status, due_date, due_datetime, description
todo.remove_itemDelete an entire itemitem
todo.get_itemsRead out the contents of the list for subsequent stepsstatus, match response_variable
todo.remove_completed_itemsClear all completed items at onceJust specify the list, no other parameters

Add a new item

action: todo.add_item
target:
  entity_id: todo.family_chores
data:
  item: Replace the living-room AC filter
  due_date: "2026-09-01"
  description: Remove it, rinse it with water, let it air-dry for a day, and reinstall it.
Warning:due_date(Only date, e.g. 2026-09-01) and due_datetime(Date plus time, such as 2026-09-01 23:00:00) You can only choose one of the two, not both at the same time., writing two will directly report an error. In addition, the due date and description fields are not supported by every list. Only supported lists can be used.

Tick the item (mark complete)

action: todo.update_item
target:
  entity_id: todo.family_chores
data:
  item: Replace the living-room AC filter
  status: completed

status Eat only two values:needs_action(not done yet) and completed(done). If you want to "regret" what you have done and change it back to unfinished, just status Change to needs_action.

Warning:item is used Name Go find it. If there are two items in your list called "buy milk" that are exactly the same, HA doesn't know which one you want to change. At this time, you need to switch to the item UID (A long string of garbled unique numbers), UID can be used as follows todo.get_items retrieve it.

Read list contents

This action is different from others; it will Return data, so it must match response_variable Store the result in a variable:

action: todo.get_items
target:
  entity_id: todo.family_chores
data:
  status: needs_action
response_variable: my_items

status If not written, the default is needs_action; If you want to catch them all at once, write a list [needs_action, completed]. The returned data looks like this:

todo.family_chores:
  items:
    - summary: Replace the living-room AC filter
      uid: "01244b28-e604-11ee-a0a4-e45f0197c057"
      status: needs_action
      due: "2026-09-01"
      description: Remove and rinse it with water
    - summary: Pay the building management fee
      uid: "ae993df4-e604-11ee-a0a4-e45f0197c057"
      status: needs_action

Note the field names for each item:summary(not item), uid, status, and there are two optional due(due date) and description.

Warning: Look at the second item above -For items without due date and description, those two fields are completely missing, instead of leaving a blank value there.. This is the easiest place to explode when writing templates: you think every item has due You can get it, but as a result, there is no such field for a certain item, and the entire template fails. Therefore, the following example of the payment day must be used in the first pass. selectattr('due', 'defined') Select items that do not have this field.

Triggered by changes in the to-do list

Help with the newer HA version todo Three exclusive triggers have been added, which can be found when selecting triggers in the automation editor:

triggerWhen does it trigger?What to use it for?
todo.item_addedNew item added to listWhen someone adds something to the shopping list, notify the whole family
todo.item_completedItem is tickedThe child checked "Take out the trash", notify parents
todo.item_removedItem was deletedUsed for auditing to see who deleted something

The YAML writing method is different from the general trigger. It uses target: rather than writing directly entity_id:: 

alias: Notify when an item is added to the shopping list
triggers:
  - trigger: todo.item_added
    target:
      entity_id: todo.shopping_list
actions:
  - action: notify.mobile_app_my_phone
    data:
      title: Shopping list updated
      message: Someone added an item. Remember to check the list before you go out.

The information that can be obtained when triggered is list of entity_id and the affected item ID (item_ids). If you want to know what name was added, you usually have to call it again in the action. todo.get_items Go check it out.

Warning: These three triggers are relatively new features. If you can't find them in your automation editor, it means your HA version is not available yet. Please upgrade first. If you don't want to upgrade, the next best thing is to use "State" trigger to monitor that todo. The numerical change of the entity - since the list status is the number of unfinished items, adding an item to the number is +1.
Tip: If you are not sure whether you have this version, the fastest way to verify is: add an automation → add a trigger → type "to-do" or "to-do" in the search box. If there is, it will pop out; if there is not, there is no. This is faster than checking the version number.

Hands-on 2: Create a local calendar

Next, change the calendar. Like Local To-do, there is an official one that runs completely on the local side. Local Calendar, is an integration added to Home Assistant 2022.12. The data is stored in your own HA settings directory and does not require any account or any cloud.

  1. New integration

    Settings → Devices & Services → + New integration, search Local calendar (local calendar).

  2. Pick a calendar name

    Follow the instructions on the screen to fill in the calendar name. Suggestions Separately built according to purpose, don’t stuff them all into one: build one each for “Trash Taking Out”, “Housework Rotation”, “Payment” and “Furniture Maintenance”. The reason is in the next step.

  3. Why build it separately: Because the trigger is tied to the "entire calendar"

    Calendar triggering cannot say "trigger only if the title contains a certain word" - it is this calendar any Triggers as soon as the event begins. So divide different uses into different calendars, and automation will be clean. (If you really want to distinguish within the same calendar, just add conditions to the automation to compare trigger.calendar_event.summary.)

  4. Go to the "Calendar" panel in the sidebar and add events

    After it is built, there will be a sidebar on the left calendar panel. Click on a certain day to add new events. You can set all-day events, set start and end times, or set Repeat (weekly, monthly, etc.). If something like taking out the trash is fixed on a weekly basis, set it up as a recurring event, and set it up once for a whole year.

  5. Confirm entity ID and status

    Settings → Tools → States, filter calendar.. There are only two states of calendar entities:on It means that an event is currently in progress.off means that no event is in progress.

Concept: Do not use "Calendar entity is not on” is used as a reminder because it can only express one event at a time and cannot be advanced in advance. If you want to be reminded, use the next section. calendar trigger, that only has the offset (how far in advance) that can be set.

Calendar events can also be automatically generated by yourself, which is very useful in the situation of "just jotting down the calendar after booking a restaurant":

action: calendar.create_event
target:
  entity_id: calendar.family
data:
  summary: Family dinner
  start_date_time: "2026-09-20 18:00:00"
  end_date_time: "2026-09-20 20:00:00"
  location: Grandma’s house

summary(Title) is the only required field. There are three ways to specify time, Choose one from three:

Writing methodWhere to useExample
start_date_time + end_date_timeevent with definite moment"2026-09-20 18:00:00"
start_date + end_dateall day event"2026-09-20"

Connect Google Calendar and CalDAV

The disadvantage of the local calendar is obvious: it cannot be seen on the phone. If your whole family is already using Google Calendar, it will be much more convenient to connect it to HA - add a new "Take out the Trash" space on the mobile Google Calendar, and HA will have it there.

Google Calendar

Honestly, this is the chapter The most troublesome step, and the trouble is not on HA's side, but on Google's side. HA official documentation clearly state: You must open a item in Google Cloud, enable the Google Calendar API, generate a set of OAuth client credentials (Client ID and Client Secret), and then paste this set of credentials back to HA. There is no shortcut, HA does not provide public credentials.

Danger: Client ID and Client Secret are the keys to your Google item. Absolutely not Post to forums, Discord, YouTube comments, or any screenshot. Once it is posted, go back to the Google Cloud Console immediately to delete the set of credentials and rebuild it.
Note: This is the most common pitfall. When setting up the "OAuth consent screen" in Google Cloud, if the publishing status is stuck at Testing, Home Assistant documentation clearly warns: Your OAuth token expires every 7 days, HA will disconnect once a week and ask you to reauthorize. The solution is to click on the consent screen Publish app, change the status.

After connecting, every calendar under "My Calendar" in your Google account will become a calendar. entity. It also provides an exclusive action google.create_event Used to add new events.

Tip: Because the “setting tax” paid by Google is not low, my suggestion is: First use Local Calendar to run through the entire chapter, write the automation well, make sure you can really use this set of things, and then go back and spend the 20 minutes searching Google. If the integration method is changed, the automation configuration does not need to be changed at all, because both sides are calendar. entity.

CalDAV (Nextcloud, iCloud, Synology…)

If you're using Nextcloud, Baikal, ownCloud, Synology Calendar or Apple iCloud, go CalDAV This standard agreement. Home Assistant document states that as long as the server complies with RFC 4791, it can basically be connected.

Setting methodhow to doCan I get a to-do list?
Interface settings (recommended)Settings → Devices & Services → New integration → CalDAVYes, todo entities will be generated
Manually write YAMLEdit configuration.yamlNo, Home Assistant documentation clearly states that YAML does not support to-do lists.

The main fields are url(your calendar’s full URL),username, password, in addition calendars / custom_calendars You can pick only specific calendars, and verify_ssl(Default true, only the self-hosted server with a self-signed certificate needs to be shut down). There is another days(Default 1) decided to arrest the incident a few days later, it's only in custom_calendars Only useful at the bottom, many people write in the outer layer and wonder why it doesn't work.

Warning: If you want to connect to iCloud, official documentation suggests Use an app-specific password, do not give your Apple account master password to the HA. This is a security issue, and it’s also the reason why many people can’t connect to iCloud – the master password paired with two-step verification will be blocked in the first place.

Google Tasks (to-do list, not calendar)

By the way, Google’s to-do list also has an official integration called Google Tasks (Added in Home Assistant 2023.11), will turn your Google to-do list into todo. entity. There are two limitations to be aware of first:

  • Only expiration "date" is supported, expiration "time" is not supported—This is a limitation of the Google Tasks API itself, not a problem with HA.
  • It is polling, and the update cycle for official documentation is every 30 minutes.. If you add an item to Google Tasks on your phone, HA will not see it immediately and will have to wait for the next crawl.
Tip: This 30 minute delay Only the direction "Google → HA". Home Assistant documentation clearly states that changes you make in HA will be immediately reflected in Google Tasks. Therefore, "use automation to add things to the list, and then view them on the phone" is immediate, while conversely "adding things to the phone and waiting for HA to trigger the automation" has to wait. Keep this in mind when writing automation, and you can avoid many pitfalls.

The setting method is the same as that of Google Calendar. You need to create your own Google Cloud certificate, but you need to enable the Google Tasks API.

Trigger automation with calendar events

This is the most valuable section of the entire chapter. The complete writing method of calendar trigger is just these lines:

triggers:
  - trigger: calendar
    entity_id: calendar.trash_day
    event: start
    offset: "-00:20:00"
fieldmeaning
entity_idWhich calendar should I follow?
eventstart(event starts) or end(event ends)
offsetTime offset. The format is "hour:minute:second". A negative sign in front means advance, without the negative sign means delay. The one above -00:20:00 That's "20 minutes before the event starts"
NOTE: Be sure to know the limitations. Home Assistant document is very clear: The calendar is read every 15 minutes. This means two things: (1) You have just added an event on your phone that will start in 5 minutes, and the trigger may not have time to trigger; (2) Don't set the offset to -00:02:00 This kind of value that is too personal is difficult to grasp in practice. more than 10 minutes Relatively safe. To use it as an accurate alarm clock, please use "Time" to trigger it.

The content of the event can be used directly

After triggering, the data of that grid event will be placed in trigger.calendar_event Below, you can write the notification message directly:

variablescontent

Tip: If you are not sure what words are written in the template, don't guess in the automation. go Settings → Tools → Templates Paste that page for a test run, and the results will be displayed immediately. This trick applies to the entire HA and can save you half of your debugging time.

Six practical situations you can copy right away

Each of the following paragraphs can be pasted directly into the YAML mode of the automation editor (three dots in the upper right corner → Edit YAML). Remember to replace the entity ID with your own.

1. Trash day reminder

First, create a calendar called "Taking out the Trash" in Local Calendar, and set the garbage truck time as a weekly recurring event.

alias: Garbage collection is approaching
triggers:
  - trigger: calendar
    entity_id: calendar.trash_day
    event: start
    offset: "-00:20:00"
actions:
  - action: notify.mobile_app_my_phone
    data:
      title: Garbage collection in 20 minutes
      message: "{{ trigger.calendar_event.summary }} | Do you have the bag?"
  - action: light.turn_on
    target:
      entity_id: light.entrance
    data:
      brightness_pct: 80
mode: single

Turning on the porch light is more useful than pushing the button - the push will be ignored, but if you walk over and see the light on, you will remember it.

2. Payment date: reminder as soon as the due date arrives

In this situation, use a to-do list instead of a calendar, because paying bills is somefeature that "will always exist before it is finished." The method is to scan the list at eight o'clock every morning to see if there is anything due today:

alias: Items due today
triggers:
  - trigger: time
    at: "08:00:00"
actions:
  - action: todo.get_items
    target:
      entity_id: todo.family_chores
    data:
      status: needs_action
    response_variable: result
  - variables:
      today: "{{ now().date() | string }}"
      due_today: >-
        {{ result['todo.family_chores']['items']
           | selectattr('due', 'defined')
           | rejectattr('due', 'none')
           | selectattr('due', 'search', today)
           | map(attribute='summary') | list }}
  - if:
      - condition: template
        value_template: "{{ due_today | count > 0 }}"
    then:
      - action: notify.mobile_app_my_phone
        data:
          title: {{ due_today | count }} items are due today
          message: "{{ due_today | join(', ') }}"
mode: single

The three lines of filtering in the middle are the key to the entire paragraph. Each line has one task:selectattr('due', 'defined') First, connect " due Select items that do not exist in this field.rejectattr('due', 'none') Then select the fields that have fields but empty values, and finally selectattr('due', 'search', today) Only the due date string containing today's date is left. Without the first two levels, as long as an item in the list does not have an due date, the entire automation will report a template error.

Warning: Lists from different sources,due The value returned may be pure text (2026-09-01), it may also be in the form of time, and the filtering writing method will be affected. First go to Settings → Tools → Templates and paste this paragraph for a test run to see if the printed name is the one you want, then paste it into the automation, don’t enable it in production.

3. Air conditioning filter replacement: Calendar creates to-do list

The classic "calendar + to-do" combo. The calendar is responsible for recording time periods. Once the time is up, a to-do item will be automatically added to the list. You can do it whenever you are free and tick it when you are done:

alias: Create to-do items from the maintenance calendar
triggers:
  - trigger: calendar
    entity_id: calendar.maintenance
    event: start
actions:
  - action: todo.add_item
    target:
      entity_id: todo.family_chores
    data:
      item: "{{ trigger.calendar_event.summary }}"
      due_date: "{{ trigger.calendar_event.start[:10] }}"
      description: "{{ trigger.calendar_event.description }}"
mode: queued
max: 10

Set up several full-day events in the "Maintenance" calendar that repeat every three months: "Clean the living room air conditioning filter," "Replace the water purifier filter element," and "Clean the washing machine." Set it up once and it will automatically appear on your to-do list every quarter.

Tip:mode: queued add max: 10 This is to cope with the situation where "several maintenance events start at the same time on the same day". Use default single, the second event will be discarded directly. A complete description of execution modes is in Chapter 10.

In the "Housework Rotation" calendar, write the event title directly as "It's Xiao Ming's turn to wash the dishes this week", and then:

alias: Household chore rotation reminder
triggers:

      title: Chore rotation

mode: queued
max: 10

notify.family_all It is a method of packaging the whole family’s phones into a notification group. The setting method is Chapter 7.

5. Office conference room: one-panel event tube lights and air conditioning

The most practical one for small offices. Connect the conference room reservation calendar to HA (Google Calendar or CalDAV will work), turn on the lights and air conditioner ten minutes before the meeting, and turn them off when the meeting ends:

alias: Control a meeting room from its bookings
triggers:
  - trigger: calendar
    id: meeting_start
    entity_id: calendar.meeting_room
    event: start
    offset: "-00:10:00"
  - trigger: calendar
    id: meeting_end
    entity_id: calendar.meeting_room
    event: end
actions:
  - choose:
      - conditions:
          - condition: trigger
            id: meeting_start
        sequence:
          - action: light.turn_on
            target:
              entity_id: light.meeting_room
          - action: climate.turn_on
            target:
              entity_id: climate.meeting_room
      - conditions:
          - condition: trigger
            id: meeting_end
        sequence:
          - action: light.turn_off
            target:
              entity_id: light.meeting_room
          - action: climate.turn_off
            target:
              entity_id: climate.meeting_room
mode: queued
max: 10

Here is a good practice: An automated id Distinguish multiple triggers before using choose Bifurcation, which is easier to maintain than splitting it into two separate parts. If you don’t want to eat the air conditioner climate.turn_on, use climate.set_hvac_mode, look at the control methods of each domain Chapter 12.

Linking notifications with voice assistants

Notifications: Make reminders really visible

The last mile in all of the above scenes is notifications, and the complete setup of notifications (Companion App installation,notify.mobile_app_* How to check the entity name and notify the group) in Chapter 7, not repeated here. Just three tips that work particularly well with to-do/calendar:

  • Put the event title directly into the message—Use {{ trigger.calendar_event.summary }}, one automation can serve all events on the calendar, without writing one for each event.
  • Add conditions to avoid making noise in the middle of the night—In conditions: Add a time condition, or add a "someone is at home" condition. Receiving "The garbage truck is coming" when you're out all day just makes you want to turn off the notification.
  • Notifications are not just for phones—In a conference room situation, flashing the light twice or making a voice announcement is much more effective than pushing the announcement.

Voice: add shopping list by shouting

Voice assistants are a natural companion for this chapter—it’s much faster to shout than to pull out your phone when your hands are greasy and the refrigerator door is open. The key points of this part:

  • Home Assistant documentation for Shopping list integration clearly mentions You can add things using voice commands, an example sentence is "Add eggs to my shopping list" in English.
  • Sentence support varies by language. Home Assistant does not support every sentence pattern in every language. Your version and your voice assistant settings will affect the results. If you want to confirm whether your method will work, the fastest way is Open the Assist dialog box in the upper right corner of HA and type directly (no need to speak) to try a sentence, see if it reacts.
  • If the built-in sentence pattern does not satisfy what you want to say, the fallback option is custom sentences, corresponding to the way you are used to speaking todo.add_item. Please see the chapter on voice assistant for how to set it up.
Tip: There are often typos in the Chinese characters recognized by voice recognition. It is normal for "Soy Sauce" to be changed to " Jiang You". So shopping list automation Don't To make a judgment by comparing the item names, just think of the name as a "string of words that people can see", and leave the judgment to the quantity or status.

Common problems

  1. Google authorization expires every 7 days and keeps asking me to log in again

    This is almost 100% the OAuth consent screen stops at Testing. Official documentation clearly warns that credentials expire every 7 days in this state. Return to the OAuth consent screen of the Google Cloud Console, click Publish app Change the publishing status and go back to HA to authorize again. After changing it, it won't fall off again.

  2. Google authorization fails immediately, jumping "redirect_uri_mismatch" or similar error

    This means that the redirect URL you registered with Google is different from the one actually sent by HA. Fill in the Google credential settings according to the redirect URL specified in Home Assistant documentation verbatim. Letter case, and whether there is a slash at the end, all count. Also check if you have installed the Google Calendar API enable—Many people create credentials but forget to enable the API.

  3. The event time differs by several hours (time zone misalignment)

    This is the second most common pitfall, and there are three places Everything may go wrong, so please sort them one by one:
    (1) HA's own time zone—Go Settings → System → Home Information, check whether the time zone in the “Region” area matches your location. The zh-TW source example is Asia/Taipei. If the field is gray and cannot be changed, it means that it is written in configuration.yaml Here, we need to remove that line first. This is Chapter 2 Spoken.
    (2) The time zone of the source calendar—Google Calendar itself has a calendar time zone setting. If it is another time zone, the entire set of events will be offset.
    (3) all day event—There is no time in the whole day event.all_day will be true,start Only date. It would be weird to compare it with time, you have to judge first all_day Then decide how to deal with it.

  4. Calendar automation did not trigger when it should have

    First think, "How long ago did I create this event?" Home Assistant document states Calendar is only read every 15 minutes. It will be triggered after 5 minutes as soon as it is built. It is normal to be too late. The second common reason is offset Wrong writing - there must be a negative sign in advance,"-00:30:00" It's half an hour in advance."00:30:00" It's delayed by half an hour. Third, go Settings → Automations & Scenes & Scenes Click on the automation, three dots in the upper right corner → Traces, to see if it has been triggered and at which step it is stuck.

  5. The to-do list is not synchronized, and the things added on the phone cannot be seen by HA.

    First figure out which one you are using: Local To-do has no synchronization issues, because it only exists in HA, and there is no other place to synchronize with it. There will be a synchronization gap from the cloud source - Home Assistant Google Tasks document says Poll every 30 minutes,CalDAV is also crawled regularly. Therefore, "HA is added to the phone but not seen" is usually not broken, but it is not the next crawl time yet. If you wait too long and still nothing, go Settings → Devices & Services Find the integration, three points → Reload, forcing it to catch it once.

  6. todo.update_item Says the item cannot be found

    Three directions: (1) name exactly the same, one more blank space, and different full-width and half-width forms are considered different; (2) There are two items with the same name in the list, and HA doesn’t know which one to change, so use uid—Use first todo.get_items Take out the UID and fill in the UID item Field; (3) You typed incorrectly entity_id, changed to another list.

  7. When I add an item, I get an error saying that there is something wrong with the parameters of the due date.

    The most common is due_date and due_datetime Wrote at the same time, you can only choose one of the two. The second is that the list you are using does not support due dates or descriptions at all - not every integration supports all fields, for example Google Tasks only supports dates but not time. Remove that parameter and try again to see if this is the reason.

  8. After deleting the integration, the to-do list panel keeps reporting errors.

    Cards on the dashboard also point to entities that no longer exist. Go to edit mode and delete the orphan card. Before deleting an integration, think about whether there are any cards or automations using it. This habit can save a lot of trouble.

FAQ

Where is the Local To-do information stored? Will the backup be taken away?
It is stored in Home Assistant's own settings directory, not in the cloud. So As long as you make a complete backup, the list data will be backed up as well., the items are still there after restoration. The backup method is Chapter 9. Please note: because it only exists in HA, If HA is down, you won’t be able to see the list., so it is recommended that really important things (such as payment deadlines) be also recorded on your phone, or switch to a solution that will be synchronized to the cloud.
Do I need to open a Google Cloud project to use Calendar? Is there an easier way?
use Google Calendar If so, yes, Home Assistant documentation clearly states that you have to create a Google Cloud project yourself, enable the Google Calendar API, and generate OAuth credentials. But if you just want the ability to “trigger automation on calendar events”, No need to touch Google at all—Just use Local Calendar. It can be installed in two minutes. The functions are exactly the same. All the automation examples in this chapter can be run. The only difference is that you can't see the calendar on your phone. If you want to see it on your phone but don't want to touch Google Cloud, the third option is CalDAV (such as the self-installed Nextcloud or Synology Calendar). The setting is relatively simple, just fill in the URL and account password.
Why can I see events on my calendar card, but the automation is not triggered?
You can see it on the card, it only represents HA Readable That event does not mean that the trigger will trigger. The three most common reasons: (1) The event was just built, and Calendar is only read every 15 minutes, that trigger was too late; (2) offset Forgot to write the negative sign, it becomes the event start after is triggered; (3) What you see on the card is another calendar Events - Cards can display several calendars at the same time, but the trigger is only tied to one. put entity_id Check it out. If you really can’t sort it out, just automate it. Traces Look at the record.
todo.get_items What to do with the value returned? I can't understand that response_variable.
Most of the actions are "asking HA to do something", and they are gone after they are done;todo.get_items The special thing is that it will Return data, and the returned data needs a name to be referenced in subsequent steps. This name is response_variable. you write response_variable: result, can be used later result['todo.your_list']['items'] Get the item array. Every item must have summary(name),uid, status Three fields, two more due(due date) and description(description) It is optional. If it is not set, the entire field will not appear.—This is the most popular part of handwriting templates for newbies, remember to use it first selectattr('due', 'defined') Block one layer. Strongly recommended first Settings → Tools → Actions Run that page alone todo.get_items, read the return results clearly, and then write the template.
Can you do the effect of "annoying me once a day if you haven't finished it yet"?
Yes, and you don’t have to write anything complicated. The method is the automation of "Payment Day" in this chapter - run it once a day at a fixed time todo.get_items, only catch needs_action For items with status, notifications will be sent when something is available. Because it scans every day, as long as you don't check it, you will receive it every day. If you don’t want to be annoyed for too long, you can add the judgment “only within three days before the due date” to the conditions, or use Appendix B Helper (such as a toggle switch) to make a "pause reminder" switch.
Can the whole family share the same list? Can it be modified on each phone?
Yes. HA’s to-do list is Shared throughout the system Yes, it is not tied to the user account - as long as you have an HA account and can log in, you will see the same list, and any changes will be synchronized to everyone's screen in real time. So if your family members want their own accounts, please see Chapter 5. If you want "parents can change it, but children can only read it", the more practical approach is not to rely on permissions, but Make two dashboard tabs: To-do card settings on the child’s tab hide_create: true, there will be no new input box. This isn't a true permission lock, but it's good enough for home situations.
If both Shopping list and Local to-do are installed, will there be a fight?
No, they are two independent integrations, each producing its own entity, and the data is completely separate. You will see two lists at the same time in the to-do list panel in the sidebar. The only thing to note is Don't mess with entity IDs, before writing automation, go to Settings → Tools to confirm which copy you are referring to. In addition,shopping_list.* That set of actions is only valid for shopping lists, not for lists created by Local to-do;todo.* That set is common to both sides - so it can be used todo.* Just use it.
I want to use the title of the calendar event for judgment. For example, it will be triggered only if the title contains "Take out the trash". How to do this?
The calendar trigger itself does not have the option of "trigger only when the title matches". It triggers when any event in the entire calendar starts. The approach is Let the trigger fire, filter in conditions:Add a template condition {{ 'Take out the trash' in trigger.calendar_event.summary }}, those who do not meet the conditions will be blocked at that level. However, the more recommended approach is to Group events for different purposes into different calendars, automation will be much simpler, and there is no need to write templates. If you want to use a template, remember to go to Settings → Tools → Template Test Run first.
