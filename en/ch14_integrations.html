Chapter 14

Integrations

Integrations connect Home Assistant to weather, media, calendars, phone location, messaging, and physical devices. Learn the complete setup flow, then diagnose and recover an integration when it fails.

Why this matters

The previous chapters organized what was already in Home Assistant: areas, names, dashboards, automations, and scripts. Integrations bring external devices and services into that system.

An integration is Home Assistant’s connection to a device or service. A sunset automation needs sun data; arrival music needs location and media entities; a washing-cycle alert needs a notification channel.

By the end of this chapter you will have these abilities:

  • Understand the integration → device → entity relationship and the impact of removing an integration.
  • Complete setup flows that request credentials, an API key, or a QR code.
  • Understand why OAuth authorization often gets stuck in "the URL does not match" and how to solve it
  • Determine whether an integration is cloud-dependent or local, and what happens during an outage.
  • Download diagnostics, reauthenticate, reload, and, only when necessary, remove a failing integration.
Concept: This chapter precedes the device management covered in Chapter 11. Here you connect an integration; there you configure the resulting devices and entities.

Integration, device, entity: three-layer relationship and Config Flow

The relationship in one sentence

An integration communicates with a device family or service. A configured entry may create devices, and each device may expose multiple entities that dashboards and automations can use.

Hierarchy what is Living room example what can you do with it
Integration Module to communicate with a certain brand/cloud service "Google Cast" integration Add, reload, remove, download diagnostics
Config entry One saved configuration or account; an integration can have multiple entries "Living Room Chromecast" Rename, reset, deactivate, delete
Device a physical or logical machine That Chromecast on the living room TV Assign area, check firmware, change name (Chapter 11)
Entity The smallest unit that can be read or controlled media_player.living_room_tv Put it on the dashboard and write it into the automation (Chapter 12)
Warning: Not every integration creates a device. An information-only integration such as Workday may create a binary_sensor and a calendar entity without any device. Find these under Entities, not Devices.

What is Config Flow? Why don’t you have to change YAML?

Older integrations often required manual edits to configuration.yaml. Most now use a config flow: the integration defines the questions, Home Assistant presents the form, and the completed configuration is saved as a config entry.

Config Flow has several triggering methods. Once you understand it, you will know why the screen will pop up on its own:

Process type when does it happen what will you see
User flow User Click "Add Integration" yourself Search brand → fill in form
Discovery Home Assistant detects a device through mDNS, SSDP, DHCP, or Bluetooth A Discovered card appears; select Add
Reauth The password has been changed, the token has expired, and the other party’s API will kick you out. The integration card turns red and the "Reverify" button appears.
Reconfigure Change an IP address, account, or other supported settings without removing the entry Reconfigure in the three-dot menu
Options process Options After installing it, I want to fine-tune it (update frequency, which items to focus on) Integrate "Settings/Options" on the card
Tip: Prefer reauthentication to removal. Reauthentication updates credentials while preserving entity IDs, areas, and automations. Removing and re-adding an entry can change IDs and break references.

What does that label on the integration file mean?

When you go to Home Assistant integration page, you will see the Quality Scale label. It is not fun to score, it directly affects whether you will step into a trap:

label plain-language meaning
Bronze copper Passing line: Able to use UI settings, have basic documents
Silver silver Relatively stable: error handling is complete, and there are living maintainers
Gold gold Very complete: automatic exploration, firmware updates, and detailed documentation
Platinum Technically the most beautiful: completely asynchronous, optimized performance
Legacy Old stuff, usually can only be set using YAML, and no one maintains it anymore
Custom It is done by the community and has not been reviewed by Home Assistant, so you bear the risk at your own risk (HACS is included in this category)

Hands-on: Completely run the new integration

Use a weather integration for practice because it requires no account or API key. The same config-flow pattern applies to many integrations.

  1. Make sure your location is set first

    A weather integration uses Home Assistant’s home coordinates. Open Settings → System → Home information If the latitude and longitude still contain defaults, the forecast may be for the wrong location. Older versions called this page General; current versions use Home information. The coordinates were configured in Chapter 2 ; complete that step first if needed.

  2. Open integration page

    left column Settings → Devices & services. There are several tabs at the top of this page: Integrations, Devices, Entities, and Helpers. The default setting is "Integration".

  3. Check the Discovered section

    A Discovered card means Home Assistant found a device on your network. Select Add and follow the shorter setup flow before searching manually.

  4. Click "Add Integration" in the lower right corner

    picture lower right corner There is an "Add integration" button. Pressing it will bring up a search box.

  5. Search brand name

    input Open-Meteo(or Met.no). The search is to compare brand names. If you cannot find Chinese, you will always find English. Click on the list when it appears.

  6. Complete the form

    Open-Meteo does not require any API key. Home Assistant documentation clearly states that "no account or API key is required". Select the Zone to use as the forecast location, such as Home. Zones were configured in Chapter 5 .

  7. Assign the area and press Done

    In the last step, HA will ask you which area you want to classify it into. Weather does not have a physical location and can be left blank; if it is a physical device, selecting the right area here can save the effort of manual classification later. press Finish.

  8. Review the created entities

    There will be words like "1 entity" written on the integration card, which you can see by clicking on it. Open-Meteo generates one for each Zone weather Entity, name follows Zone. Drop this entity to the dashboard (Chapter 6), you have a weather card.

Note: This English edition generalizes the zh-TW edition’s Taiwan-specific example. Check the services, regulations, frequencies, prices, and availability in your region. Most integrations can be added repeatedly. Want to see the weather in two different cities at the same time? Just look for "Add entry" on the same integration card and run the process again. There is no need to install a second integration.

OAuth integrations and redirect URLs

Services such as Spotify and Google Calendar use OAuth authorization. Home Assistant sends you to the provider’s sign-in page; after approval, the provider returns an authorization code to Home Assistant.

The provider must know where to return the browser after authorization, so you register a Redirect URI. Private URLs such as http://192.168.1.50:8123 (or http://192.168.1.50 on the referenced newer installation) may not satisfy provider redirect-URI policies.

HA solution: My Home Assistant

Home Assistant made a relay station my.home-assistant.io. Official OAuth integration instructions commonly provide this redirect URL for the provider’s developer console:

https://my.home-assistant.io/redirect/oauth

Spotify’s documentation says to copy this URL exactly and not modify it. Google Calendar uses the same authorized redirect URL.

Your Home Assistant URL remains in your browser’s local storage. My Home Assistant redirects that browser to your instance. Home Assistant documentation clearly states that your instance URL "will never be passed to any external service, not even the My Home Assistant service itself."

If you turn off My Home Assistant

Then use your own URL plus a fixed path:

<your HA URL>/auth/external/callback

At this time, "your HA URL" must be in a form that the other vendor is willing to accept (usually the domain name of HTTPS), which is why OAuth integration often forces you to settle the remote connection first. Remote access methods (Nabu Casa cloud, self-installed reverse proxy, DDNS) are Appendix A If you have something to sort out, go and finish it first and then come back.

The step to apply for Client ID/Secret yourself

Some services do not allow HA to build a universal key, and you must go to the developer console to open an app yourself. The ones you are currently determined to apply for include:

  • Spotify: Go to the Spotify Developer Dashboard to create an App, check Web API, and get the Client ID and Client Secret. Home Assistant document states that "Starting from February 2026, a Premium account is required to enter the developer console to create an app."
  • Google Calendar: Create a project in Google Cloud Console, enable the Google Calendar API, set up the OAuth consent screen, and create a "web application" type client.

The obtained ID and key will be required to be posted when running Config Flow. If you want to replace or delete it later, the path is Settings → Devices & Services, upper right corner Three-dot menu → Application credentials.

Danger: Treat a Client Secret as a credential. Never include it in a forum post, chat, log, or screenshot. Backups also contain credentials; protect them as described in Chapter 9.

Weather: Met.no, Open-Meteo, and national weather services

Weather entities can support useful automations: close a window when rain is forecast, cool a room before the temperature exceeds 30 degrees, or remind someone to take sun protection when the UV index is high.

Integration API key? Configuration Best fit
Met.no (Norwegian Meteorological Institute) No Name, latitude, longitude, and elevation A straightforward default that creates standard Home Assistant weather entities
Open-Meteo No Select a zone Forecasts tied to Home Assistant zones, such as a workplace
Your national weather service Depends on the provider Follow the provider's API documentation Official terminology or more detailed data for your region

Two details about Met.no

  • The integration includes an "Elevation" field. The official documentation notes that elevation affects forecast temperature, especially in mountainous areas. Enter your actual elevation when you know it; for low-lying locations, a value from 0 to 50 is generally sufficient.
  • You cannot configure the update interval. The Home Assistant documentation specifies an update every 55 to 65 minutes, randomized to spread API load. Do not expect updates as frequently as those from an indoor temperature sensor.

Using a national weather service

Availability varies by country. Check the official Home Assistant integrations first. If your national provider is not listed, use one of these approaches:

  1. Check access requirements

    Consult your-national-weather-service.example for registration, API credentials, data licensing, and regional availability. Do not assume that access is free or available in every country.

  2. Route A: use a maintained community integration

    Search HACS for an integration for your provider. Community integrations are not maintained or reviewed by the Home Assistant project, so check recent releases, open issues, and compatibility with your Home Assistant version before installing one.

  3. Route B: use a RESTful sensor

    If the provider offers a REST API, Home Assistant's RESTful integration can retrieve its JSON response and expose selected fields as sensors. This requires more configuration, but avoids depending on a provider-specific custom integration.

Note: The zh-TW edition uses Taiwan's Central Weather Administration as its worked example. This international edition uses a provider-neutral pattern. Use Met.no or Open-Meteo for a standard weather entity, and add a national source only when you need data that the general provider does not offer.

Music & Media: Spotify, Apple TV, Chromecast

All three create media_player entities controlled through the actions described in Chapter 12. Their connection methods differ.

Integration Connection method Created entities Main limitation
Spotify Cloud OAuth media_player If you want Premium, you need to apply for Client ID/Secret yourself.
Apple TV Local network + PIN pairing media_player, remote, binary_sensor If AirPlay access permissions are set too strictly, pairing will fail.
Google Cast Local network with mDNS discovery media_player Can’t find it across network segments

Spotify

The documentation requires a Premium account. Setup creates a media_player entity for playback control; use Source to choose an available playback device.

Warning: The Spotify integration is not an audio output. It controls Spotify playback on a phone, Chromecast, or Spotify Connect device. Select an available playback target before expecting sound.

Apple TV

During setup, HA will ask you to read the PIN code on the TV screen and enter it back to HA to complete pairing. After installation, you will get three types of entities:media_player(See what is playing now and control playback),remote(Simulating remote control buttons), and one that tracks keyboard focus binary_sensor—The latter is very useful. It can automatically call up the phone keyboard when the Apple TV pops up the input box.

The official documentation lists these limitations:

  • Some features, such as quick action menus, require tvOS 14.0 or above.
  • Can the button be used? It’s up to each app to decide, not a question of integration. If the pause button of a certain app does not respond, it means that the app does not implement it.
  • The volume control is only reliable when connected to HomePod; using HDMI CEC it can only fine-tune it up and down, while using infrared it cannot be remotely controlled at all.
  • There is no way to detect the power status without interaction. Home Assistant FAQ directly answers "no".
  • remote The physical switch is Only change the power status recorded here by HA, not actually waking up or turning off the machine. So don't use it as a reliable basis for "whether the TV is on or not."

Google Cast (Chromecast, Google Nest speaker)

Normally it appears under Discovered a few minutes after booting. If you cannot find it, please check the network conditions listed in Home Assistant documentation one by one:

  • mDNS must be passed: Automatic discovery depends on it; the integration documentation lists it as required.
  • Need the same network segment: mDNS packets will not cross subnets. HA is in VLAN 10 and Chromecast is in VLAN 20 but cannot be found.
  • Docker needs to use host network mode: If you use Container to install HA, Home Assistant documentation states that it must run in host network mode.
  • Chromecast has a quirk: it doesn’t use the DNS sent by your router, Home Assistant documentation states that it goes directly to Google’s public DNS (8.8.8.8 / 8.8.4.4). Therefore, Chromecast cannot find the intranet domain name you set on the router. The actual impact is: the media URLs to be posted (such as videos and camera footage on your NAS) must use Direct IP, or a public URL that can be found outside, otherwise the TV will just spin in circles.

It really can't be discovered. You can fill in "Known hosts" in the integration settings. Home Assistant description is a comma-separated list of host names or IPs. You can bypass mDNS exploration by typing in directly.

Tip: Google Cast provides the action cast.show_lovelace_view, which can cast a Home Assistant dashboard view to a compatible display. Use it only where the display and household workflow make that useful.

Location tracking: determine presence

Location enables presence-based automations such as turning off selected devices when everyone leaves or turning on an entry light on arrival. Location sources create device_tracker entities, which work with Person and Zone entities from Chapter 5.

Plan Accuracy/immediacy Power consumption Suggestions
Companion App (official mobile app) Geofence-based, generally the most responsive option Adjustable Recommended starting point
iCloud Polling, there will be a delay Low (will automatically adjust the frequency) My family refuses to install the app but I use it when I have an iPhone
Google Maps location sharing polling low Officially labeled as Legacy, don’t use it if you can.

Companion App (recommended)

Install Home Assistant App on your phone and log in. It will create an app for the first time you start it. device_tracker.<your_device_name> Entity, whose attributes include GPS coordinates, battery level, accuracy, altitude, and speed.

Report timing (according to official documentation): Entering or leaving the Zone you defined in HA, when the App is started, when the background is captured, when notifications are received, and "major location changes" on iOS. iOS will automatically establish geofences for all set Zones upon startup; Android requires you to turn on Zone tracking in the App settings.

Warning: On iOS, disabling location permission can stop all Companion App sensors, including battery and step-count updates. Android behavior varies by sensor. If multiple mobile entities become unavailable, check operating-system permissions first.

See Chapter 7 for Companion App notifications and sensor details.

iCloud

During setup, do not use your primary Apple Account password. Generate an app-specific password for Home Assistant. In addition, the device must be registered with the "Find My" service to be captured.

It generates device_tracker and battery sensor for each iCloud device, and provides several actions: display messages, activate lost mode, play sounds, and request location updates. Its polling interval is dynamic and will be adjusted according to which zone it is installed in, how far away from home it is, and how much power it has, so as to avoid draining the phone's battery.

Google Maps location sharing

Home Assistant labels this integration Legacy. It is community maintained and is unlikely to gain new features. Prefer the Companion App where possible.

And it’s not easy to set up at all. You’ll probably give up after reading these points:

  • Cannot be set using UI, can only be written by hand configuration.yaml of device_tracker Sections – This is exactly what the Legacy tag is.
  • Need two Google accounts: Account A is responsible for sharing the location, and account B is responsible for reading. You cannot share it to yourself.
  • To manually dig out Google Maps cookies from your browser, save it as a specified file name and put it into the HA configuration folder. When the cookie expires, it will be dug again.

Conclusion: Don’t use it if you can. Only consider it when your family refuses to install any apps and they don’t use iPhone, and definitely don’t use it as the only basis for judging “no one is home, start security” - there is a delay in polling, and you may still be in the living room when it says you are not at home.

Calendars and notifications

Google Calendar

After setup, every calendar under "My calendars" becomes a calendar entity. For example, a calendar named "Personal" becomes calendar.personal. The integration also provides the google.create_event action, allowing an automation to create an event.

A calendar entity can trigger an automation when an event starts, ends, or a specified number of minutes before it starts. For example, an event for tomorrow's trash collection can trigger a phone reminder at 9:00 p.m. the previous evening.

Setup requires a Google Cloud project, the Google Calendar API, an OAuth consent screen, and a web-application client. Set the authorized redirect URL to https://my.home-assistant.io/redirect/oauth. The initial setup takes about 15 minutes; follow the current Home Assistant documentation step by step.

CalDAV (Nextcloud, iCloud, and Synology)

If you prefer not to configure Google Cloud, CalDAV can be set up entirely in the UI: Settings → Devices & Services → Add integration, search for CalDAV, and enter the server URL, such as https://caldav.icloud.com/, and your credentials.

The Home Assistant documentation lists Baikal, iCloud Calendar, Nextcloud, ownCloud, and Synology Calendar as tested servers. Other RFC 4791-compliant servers may also work. For iCloud, create an app-specific password; do not give Home Assistant your Apple ID password.

Note: The CalDAV YAML configuration does not support to-do lists. Use the UI setup flow if you need CalDAV to-do entities.

Telegram or Slack: protect credentials before you start

Danger: Treat every bot token and webhook URL as a password. Never paste one into a forum, issue, chat, or screenshot. If a credential is exposed, revoke it at the provider immediately and create a replacement. Avoid examples that expose a real token. Store credentials outside configuration.yaml.

For Telegram, create a bot with BotFather, obtain the chat ID, and configure the official Telegram bot integration. For Slack, create an incoming webhook or app according to Slack's current documentation. In either case, store the credential in secrets.yaml rather than in the main configuration.

Once the provider is configured, call notify.send_message. In the action editor, set action to the notification action, use target with entity_id, and replace notify.family and message with values from your installation.

actions:
  - action: notify.send_message
    target:
      entity_id: notify.family
    data:
      message: "{{ msg }}"

For example, an automation can send this message when a washing cycle finishes:

actions:
  - action: notify.send_message
    target:
      entity_id: notify.family
    data:
      message: "The washing cycle has finished. Remember to hang the laundry."
Warning: Provider limits, pricing, and feature availability can change. Check the provider's current documentation before using a third-party channel for frequent or critical notifications. Do not treat a consumer messaging service as a guaranteed alert channel.

The simplest option: Companion App notifications

If the recipients use the Home Assistant Companion App, its push notification support is usually the shortest path: no separate messaging account, bot, or webhook is required.

telegram_bot.send_message can send photos, videos, files, polls, and stickers, and can edit or delete previously sent messages. When multiple chat IDs are allowed, use the generated notify entities with notify.send_message. Verify the exact entity IDs and supported actions in your installation.

For household alerts, start with Companion App notifications from Chapter 7, then add Telegram or Slack only when it solves a specific delivery requirement.

Choose between cloud and local integrations

Make this choice before buying a device. The same type of light can behave very differently through a local protocol and a vendor cloud.

Compare items Local integration (Zigbee, Matter, ESPHome, District Network IP) Cloud API integration (original App account)
When disconnected Business as usual. As long as your router is still alive All become unavailable, and the entire automated group shuts down.
Vendor closes the service or API not affected Integrate direct death, devices becomes decoration
Response time Usually low latency on a healthy local network Depends on internet path, provider infrastructure, and API load
Data path Control traffic remains on the local network Selected device and account data is processed by the provider
rate limit almost none have. If you poll too frequently, your IP will be locked or temporarily blocked.
Set difficulty You may need to buy a USB coordinator and flash the firmware Usually just fill in the account password, it’s the easiest
functional completeness Occasionally missing some advanced features Usually as complete as the original app
Concept: The pragmatic principle is—"If it responds immediately when you press it, or if it hurts to turn it off, always go local." Lighting, door locks, alarms, electric curtains, etc., all purchased locally. Information such as weather, calendar, music streaming, and electricity bill data that are already in the cloud can be integrated through the cloud without any problem, because they have no data to give you when the Internet is disconnected.
Warning: Some integrations control locally but require a cloud-issued token for initial setup or reauthentication. They may respond quickly yet fail to initialize after an outage. Check the integration’s documented IoT class, such as Local push or Local polling, and read its authentication requirements.

Integration maintenance: diagnose, reauthenticate, reload, or remove

Credentials expire, provider APIs change, and devices become unavailable. Use these recovery steps from least to most disruptive.

  1. 1. Reload

    On the integration card, select Three-dot menu → Reload. This restarts only that integration without restarting Home Assistant. Try it first for a temporary device, network, or provider error.

  2. 2. Reauthenticate

    If the card reports that reauthentication is required, the credential or token is no longer valid. Select the prompt and authorize again. Your entity_id, region, and automation are all retained, this is the biggest difference between it and "delete and add".

  3. 3. Download diagnostics

    The path is Settings → Devices & Services → Click on that integration → Three-dot menu in the upper right corner → Download diagnostics. A JSON file will be downloaded, which contains the current status, settings (sensitive data will be officially masked), and captured raw data. When you go to GitHub to open an issue or go to the forum to ask for help, attaching this file will have a much higher chance of getting a reply. Not every integration has this option, it will only appear if it is supported.

    The matching ones are in the same menu. Enable debug logging: Open it → Reproduce the problem → Come back and close it, HA will automatically download the log file for you.

  4. 4. Remove only as a last resort

    Last resort. Three-dot menu → Delete. When deleted, all devices and entities under this integration will disappear together., all automation, scripts, and dashboard cards that reference them all become red text errors.

Danger: Before removing an integration, export or record all referenced entity IDs as described in Chapter 4. Re-adding can create IDs ending in _2, breaking automations, scripts, and dashboard cards. Make a backup first as described in Chapter 9.
Tip: What needs to be reloaded is what is written in YAML (such as the paragraph above rest_command), instead of integrating UI, then go to Settings → Tools → YAML tab to press reload. This block was called "Developer tools" before version 2026.8, and that was the name in the old teaching.

HACS custom integration: easy to use, but you have to know what you’re doing

Home Assistant supports many official integrations, but some devices require HACS (Home Assistant Community Store)—It is not an official store; it downloads community integrations and manages their updates from GitHub. Installation and basic operation of HACS Appendix A There is a complete version, but here I only cover the parts related to "integration".

The installation method depends on your HA installation method

your installation method HACS Official Documentation Practice
Home Assistant OS / Supervised put https://github.com/hacs/addons Add as repository and then Settings → Apps Install and start HACS
Container (Docker) Enter the container and execute wget -O - https://get.hacs.xyz | bash -
Core Switch to the HA user identity and execute the same line of commands

After downloading Restart HA, then go back to Settings → Devices & Services → New Integration, search for HACS and set it up. The process will require a GitHub account Do device authorization. Home Assistant FAQ of HACS explained the reason: it always uses the GitHub API to check whether there are new versions of each item, and GitHub has Not logged in The number of requests is only 60 times per hour, which is not enough; after logging in, the quota is much higher. The scepter it obtained does not require any special permissions and can only read information that is already public.

Tip: HA officially renamed "Add-ons" to "Apps" in version 2026.2, and the sidebar and settings page were changed accordingly. If the tutorial you see on the Internet still says "Supervisor → Add-on Store", that is the old version, and the things are still the same. See detailed differences Appendix A.
Warning: Home Assistant HACS documentation makes it very clear: If you don’t know which installation method you have, it is not recommended to install HACS. Because not only will it not move if you install it the wrong way, it may also mess up your environment. If you're not sure, check it out first Appendix A.

Four risks of custom integration (really understand before installing)

  • No review: Code review is required before official integration is put on the shelves, but HACS does not. It runs with the same permissions as your HA, and in theory you can do whatever you want.
  • Will slow down the upgrade: HA is updated once a month, and the internal API is frequently changed. If the maintainers can't keep up, the integration will explode after you upgrade it. In severe cases, the entire HA will not be able to get up.
  • Maintainers will disappear: The item has not been touched for two years and no one has responded to the issue. This is normal. Before installing, check when was the "last commit" on GitHub and whether the issue was handled by anyone.
  • Not within the backup compatibility range: When restoring a backup to a new version of HA, custom integration is the most trouble-prone area.
Danger: HACS can add a "custom repository", which is equivalent to installing the program code directly from any GitHub website into your home server. Only add items that you can understand, or that are used by many people in the community and have been maintained for a long time. Copying a GitHub URL from a stranger's private message or an unknown blog and pasting it up is the same thing as opening a backdoor to your own home.

Three-minute inspection before installation

  1. Look at the number of stars and the last updated date

    With a few hundred stars and commits in the last three months, it's usually pretty safe. More than a dozen stars, not moved for three years, think carefully.

  2. Look at the issue area

    Search for the version number of the most recent major HA update (e.g. 2026.8) to see if anyone reports the problem and whether the maintainer responds.

  3. Back up first and then install

    Make a complete backup before installation. When it breaks, it can be restored in ten minutes, otherwise it might take all night to repair it.

What should I do if I buy the devices but can’t find the integration?

If a device works in its vendor app but its brand does not appear under Add integration, check these items in order.

  1. First make sure you are searching for "brand" and not "model"

    Search uses brand and integration names, not every product model. For example, a Xiaomi sensor may use Xiaomi Miio; If you buy a certain brand of WiFi socket, the integrated name may be the name of the foundry platform behind it (such as Tuya). Search the official Home Assistant integration list by brand, faster than guessing in the search box.

  2. Look for a protocol logo on the packaging

    Check for Matter, Thread, Zigbee, Z-Wave, or Works with Home Assistant. A standards-based device may require a protocol integration, such as Matter or Zigbee Home Automation, rather than a brand integration.

  3. Make sure you have the corresponding transceiver

    Zigbee and Z-Wave devices cannot connect to WiFi by themselves, and the host must plug in a USB coordinator to receive it. Without that stick, it won't appear no matter how you set it. Thread requires a Thread border router.

  4. Try to automatically discover whether it is blocked by the network

    Wi-Fi devices are commonly discovered through mDNS/SSDP/DHCP. Check: Are the device and HA on the same network segment? Do you have "AP Isolation/Guest Network" enabled on your home WiFi? Does the router block multicast? Does Docker version of HA use host network mode? Any one of these settings can block discovery.

  5. Check Home Assistant integration list to see if it exists.

    See the consolidated list of official documentation directly. If it cannot be found, it means that the core is not available. Stop looking for it in the UI. By the way, pay attention to whether there is any "removed" message—When the original API and dependent packages are not maintained, Home Assistant will remove the integration in the revision notes (for example, Permobil and Volvo On Call were removed in 2026.8). The teaching you are looking at was probably written when it was still around.

  6. Go to HACS to find the community version

    The core doesn’t have it, but the community often does. Search the brand name in HACS. Once you find it, follow the three-minute inspection in the previous section and then install it.

  7. Last resort: go through the universal pipeline

    If the device has an open HTTP API, you can use RESTful sensors or rest_command Connect it yourself; if it can send MQTT, set up MQTT to connect. These two paths are equivalent to integrating themselves, which is troublesome but almost omnipotent.

  8. Know when the device is incompatible

    If a device is cloud-only, has no supported API, and has no maintained community integration, it may not be compatible. Return it within the seller’s policy rather than exposing credentials or installing unknown code. Before future purchases, search the exact model with “Home Assistant.”

Tip: The safest opinion before buying: It’s on the packaging Matter The logo is given priority because Matter is a universal standard across brands. HA can integrate it with Matter without having to wait for any engineer to write the exclusive integration for that brand.

Common problems

  1. After OAuth authorization is completed, the webpage stops at a white screen or "unable to connect"

    Check two items. First, register https://my.home-assistant.io/redirect/oauth exactly as documented; even a trailing slash can cause a mismatch. Second, the browser completing authorization must be able to reach your Home Assistant URL. If the instance is local-only, complete authorization from a browser on the same trusted local network.

  2. The integration card turns red and says that it needs to be re-verified.

    The token has expired or you changed the password for that service. Just click on re-verify, don’t delete and add again. If re-authentication fails repeatedly, go to the "Linked Applications" page of the other party's account to see if the HA authorization has been revoked. If so, you will need to re-authorize it again.

  3. The device is clearly online, but the entities are all "unavailable"

    Press reload first. If that doesn't work, download the diagnostic file and see what it reports. Common reasons for cloud integration are Being speed-limited by the other party’s API—You may have installed two integrations at the same time to open the same account, or poll to set too many passwords. Turn off the duplicate one first.

  4. Nothing appears under Discovered

    Repeat step 4 in the previous section: Check the network one by one: the same network segment, turn off AP isolation, multicast is not blocked, Docker uses the host network. These four items are the four pillars of automatic exploration. If one is missing, all will be silent.

  5. After deleting the integration and re-adding it, all the automation was broken.

    Because entity_id has changed, there are usually more new ones. _2. Go to the entity list and change the name back to the original one (make sure the original one no longer exists), or go back to Chapter 4 Use batch rename. This is why Don’t delete it if you can re-verify it..

  6. After upgrading HA, an integration disappears

    There are two possibilities: the core integration has been officially removed (see the revision instructions for that version), or the custom integration cannot keep up with the new version. The former needs to find an alternative, while the latter needs to go to GitHub to see if there is a new version; in case of emergency, restore to the backup before the upgrade and wait for the maintainer to fix it before upgrading.

FAQ

Can an integration be installed multiple times? For example, two Spotify accounts
Yes. Each setting under the integration is an independent config entry and does not interfere with each other. Just look for "Add entry" on the integration card and run the process again. The same goes for weather integration, which can be placed in three locations: home, work, and hometown at the same time.
What is the difference between "reload" and "restart HA"?
Reloading is only for that one integration, everything else runs as usual, usually in a few seconds, and your home automation is not interrupted. Restarting means turning off the entire HA and then on again, and re-integrating everything together. Nothing will be available for a minute or two. The order is always to reload first, then restart if that doesn't work. In addition, if you want to reload the settings written in YAML, go to Settings → Tools → YAML(This area was called "Developer Tools" before 2026.8).
Which notification method should I use for an international deployment?
Companion App notifications are the simplest option for Home Assistant users. Use Telegram or Slack when the household already relies on one of those services. The calendar and notifications section shows the provider-neutral pattern: call notify.send_message with your actual notify.family entity. See Chapter 7 for Companion App setup.
Will downloading the diagnostic file leak my password?
Home Assistant diagnostics are designed to redact sensitive fields, but implementation quality varies by integration. Before publishing a JSON file, inspect it for token, password, secret, email addresses, precise coordinates, and other personal data.
I don’t have a fixed IP or domain. Is the OAuth integration hopeless?
Not necessarily. Most go my.home-assistant.io The integration of your own browser Bring the authorization result back to HA. Your HA URL is stored locally in the browser and will not be sent to any service. So as long as you are on the same network as HA and use a browser to complete the entire authorization process, the intranet address usually works. Only when it really fails will you need to deal with the external URL. See how you do it. Appendix A The remote connection section.
Will Home Assistant help me with the integration of HACS installation?
No. Things on HACS belong to Home Assistant classification Custom, there is no official review or support. If something goes wrong, you can only go to the GitHub of that item to open an issue. So before installing, be sure to check the last update date and whether anyone is replying in the issue area. In addition, when reporting problems with the HA body, Home Assistant will usually ask you to stop all custom integrations and then try again.
Chromecast can be seen on the phone, but HA cannot be found
First confirm HA and Chromecast in the same network segment—mDNS packets will not cross subnets. If you can see it on your phone, it only means that your phone is in the same network segment as it. Then confirm whether the Docker version uses the host network mode. If everything is correct and you still can't find it, you can fill in "Known Hosts" in the Google Cast integration settings and enter the IP directly to bypass automatic discovery. Remember to fix that IP on the router first, otherwise DHCP will have to be reset when changing IP.
Which weather integration should I use?
For basic temperature, humidity, and precipitation forecasts, start with Met.no or Open-Meteo; neither requires an API key. If you need official local terminology or finer regional data, check your-national-weather-service.example for an API or a maintained integration. Do not make a critical automation depend only on an unreviewed community integration; keep a standard integration as the primary source.
