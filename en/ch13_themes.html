Chapter 13

Theme and appearance personalization

The same set of Home Assistant can look like the situation room of a space capsule or the blank paper in a stationery store. This chapter teaches you how to clean the dark/light colors, install a community theme, write your own theme YAML, change colors in a single page, and solve the problem of unclear visibility of Chinese fonts and dark mode. After reading this, you will have an interface that "belongs to you" instead of someone else's default interface.

Why should you learn this?

In the previous 12 chapters, you have completed the functions: the device has a name, the area has a floor, the dashboard has pagination, and the automation will run by itself. But the moment I turned on the phone, what I saw was the same picture that looked like that from the beginning.

This matter is more important than you think. If the interface is ugly, you won’t want to turn it on; if you don’t want to turn it on, you will go back and use the physical switch, and then the entire system will gradually become "it was just pretending to be fun". On the contrary, as long as the color matches the lighting in your home, the wallpaper on your phone, or your eyes when you wake up in the middle of the night, you will keep using it.

This chapter will deal with three very specific types of pain:

  • Dazzling at night: Swiping the phone with a white background interface in the middle of the night is like a flash bomb. What you want is for the system to automatically switch to darker colors.
  • The family has different tastes: You like neon on a black background, but my mother thinks she can’t see the words. The good news is that themes can be "one for each user."
  • Looks like a half-finished product: The default blue color + the browser tab says "Home Assistant". When placed on the wall, the tablet looks like an engineer's test machine.
Concept:This chapter only touches on "appearance", not function. Even if the theme is completely broken, your automation, installation, and backup will not be affected. The worst thing is that the screen will return to the default appearance. So feel free to give it a try.

The HACS part will be used. If you haven’t installed it yet, go back first.Appendix APack up the HACS and come back. The dashboard itself is edited inChapter 6I’ve talked about it before, so I won’t repeat it here.

What exactly is a theme?

Many people think that the theme is "a skin", and if they change it, the entire interface will be redrawn. no. Home Assistant themes are actually justA stack of color settings, officially called CSS variables.

Imagine there is a row of labels on your wall:

  • Write "Main Color = Sky Blue" on one page
  • One says "Card background color = white"
  • Write "Main text = dark gray" on one page

Each component on the interface does not decide the color by itself, but looks at the label paper. So as long as you erase and rewrite the words on the label, the buttons, cards, and sidebars of the entire site will change together. This is why a theme file with dozens of lines can change the appearance of the entire system.

Because of this mechanism, the theme has its ceiling:

Warning:The theme can only be changed "where there are tags". How to arrange the layout, how wide the cards are, whether the rounded corners should be rounder, some can be changed and some cannot. If you want to change to areas that are not officially open, you have to use tools such as card-mod, which will be discussed later. That means writing CSS directly.

In addition, we must first distinguish three things that are often confused:

nounWhat does it care about?Where to set up
ThemeColor, section spacing, and rounded cornersPersonal information page selection; theme files are placed in the settings folder
Dark/light mode ModeTwo light and dark versions of the same themeProfile page, optional automatic follow system
Dashboard layoutWhat cards are there and how to arrange themDashboard edit mode (Chapter 6)

Changing the theme will not change your cards, and changing the cards will not change the theme. The two things are separate.

The theme setting is where you live (the location has been changed recently, note)

This is the easiest section to miss, because Home Assistant has been undercut in version 2026.2.

Current location: Profile page.Click on the sidebarYour own name at the bottom, the profile page is divided into two pages: "General" and "Security". The topic selector is inAverageIn the "User preferences" section of the page, the official description is "What does Home Assistant look like?"

The official revision description of 2026.2 is very straightforward: "The theme has been moved! You can now find and switch your favorite appearance directly in your user profile, so that you can apply the same theme on any device you log in to."

Warning:The second half of this sentence is an important behavioral change.The theme now follows the "account" instead of "this browser".In the past, you could use dark colors for tablets in the living room and light colors for computers; after the revision, the same account will be the same on all devices. There has been a debate about this in the community, and the current official answer is that they do not plan to change it back. The topic section of the profile page usually has two levels of choices:

    There will be at least "Default" in the drop-down menu, plus any social themes you install later. The newly installed system will only have the default one, which is normal.

  2. Choose light and dark mode

Unless otherwise specified, it will follow the dark mode of your phone or computer—when the phone turns dark, Home Assistant will follow suit. If you want to fix it into one type, specify it yourself. If you want to save trouble, leave it alone.

    The name and location of this option are different on different versions (some versions are "Auto", others are a set of light/dark buttons),Based on what you see on the screen, just accept the behavior of "following the system".

Home Assistant itself only gives you a set of "Default" themes when shipped from the factory, which comes with two modes: light and dark. The 2026.2 version has completely redrawn this set of default themes. The official statement is "We abandoned the old blue top bar and replaced it with a clean style consistent with the settings page." So if you upgrade from a very old version and you feel that the entire system suddenly becomes outdated, it is not broken.

If you want more choices, there are three ways:

When choosing a community theme, useChapter 11Choose the same set of criteria for integration: first look at the last updated date. Do it yourself: Install the first community theme from scratch

The entire process has five steps. Steps 2 and 3 are most likely to be missed by novices. If they are missed, the classic hurdle of "HACS says it is installed, but nothing appears on the profile page" will appear.

  1. Download topics in HACS

    Open HACS, use the search box to find the topic name you want, go in and click download. The official HACS document states very clearly: “Any theme downloaded through HACS will be stored under your Home Assistant settings folder. themes/ in the folder. "That's what most people say /config/themes/.

    The classification name of HACS is "Theme". If your HACS does not see the topic classification, it is usually because the topic function has not been enabled in the system. It will appear after completing the next step.

  2. Add three lines to configuration.yaml

    Use an add-on such as "File editor" or "Studio Code Server" to open the settings folder configuration.yaml, add to the outermost layer:

    frontend:
  themes: !include_dir_merge_named themes

    These three lines mean "put themes/ All files in the folder are combined into a topic list."!include_dir_merge_named It's Home Assistant's own syntax, not ordinary YAML, just copy it. The official frontend document also demonstrates how to write a custom folder name, for example !include_dir_merge_named my_themes, but it can be used permanently with HACS themes The most trouble-free.

    if your configuration.yaml There is already frontend: This is enough,Don't add a second one, directly put themes: That line goes under it. YAML does not allow two identical keys to appear in the same layer.

  3. Check whether the settings are written correctly

    ArriveSettings → Tools → YAML, first press the button to check settings. Official documentation says this tab "provides buttons to trigger profile checks and reload settings." If there is red text, just change it according to the message. Usually it is either the indentation is wrong or there is an extra colon.

    Danger:If you directly restart the configuration file if there is a syntax error, Home Assistant will not start, and you will see a blank page or be unable to connect.Be sure to check before restarting, this is the only step that can save you. If it really hangs after restarting, just do the sameChapter 9Restore backup.

  4. Reload theme

    Added for the first time frontend: When this happens, please restart Home Assistant completely. If you just change the theme content or install a new theme later, you don’t need to restart - toSettings → Tools → Actions, execute frontend.reload_themes This action. It does not have any parameters, just one line in YAML mode:

    action: frontend.reload_themes

    The official description of it is to "reload the theme settings from your configuration.yaml" and does not require a restart. Another reminder from the file: If the theme you are currently using no longer exists after reloading, the system will return to the standard theme. Only administrators can perform this action.

    Settings → Tools → YAML This paging itself can also reload settings. The official statement is: "Quick reload will reload all settings, while YAML paging allows you to reload only one setting at a time." If your version happens to have a theme in that list, pressing it is the same thing as performing the above action; if not, just use actions, don't worry.

  5. Return to profile page to apply

    Click your name at the bottom of the sidebar, find the theme selector in the general tab, and scroll down to see the newly installed theme. Once selected, the screen should change color immediately—no need to refresh or log in again.

    If it does not change immediately, do a forced rearrangement first (Ctrl + Shift + R), browser cache is the most common culprit.

Tip:Make a backup before installing. The theme is unlikely to break the system, but configuration.yaml Changes are possible, and backups take three minutes.

Write your own topic: YAML structure and variable quick check

Once you understand other people's theme files, you can fine-tune it or write one from scratch. The minimum example given by the official frontend document looks like this:

frontend:
  themes:
    happy:
      primary-color: pink
      accent-color: orange
    sad:
      primary-color: steelblue
      accent-color: darkred

If you use the previous !include_dir_merge_named themes Writing method, that’s it /config/themes/ Open a new file below, for example my_home.yaml, in the fileDon'tWrite again frontend: and themes:, starting directly from the topic name:

my_home:
  primary-color: "#2f8f6b"
  accent-color: "#e0a458"
  primary-text-color: "#1c1c1c"
  card-background-color: "#ffffff"
  primary-background-color: "#f4f2ed"

The color can be written in English (pink), 16 carry ("#2f8f6b") or rgb(47,143,107). use # Remember to add quotes at the beginning, otherwise YAML will treat it as a comment, which is the number one mistake of newbies.

Dark and light modes

A truly useful theme will offer both modes. The official way of writing is to add one modes: Block:

day_and_night:
  primary-color: coral
  modes:
    light:
      secondary-text-color: olive
    dark:
      secondary-text-color: slategray

The application order is officially explained in detail, and it’s worth remembering because it explains “why it didn’t work if I changed it”:

  1. Lay out the default theme first

    The system first takes into account all the variables of the default theme. Therefore, variables you have not written will not become transparent or black, but will retain the default value.

  2. Then cover the settings regardless of mode.

    That is to say, it is written in modes: Those variables outside, at the top level. In the above example primary-color: coral It will take effect regardless of light or dark.

  3. Finally, cover the settings specific to this mode.

    written in modes: light: or modes: dark: The one at the bottom has the highest priority. The same variable is written both at the top level and in the model, win in the model.

The document describes two additional behaviors: the old format (which has no modes: (single theme) will automatically use the default light theme as the base; if a themeonlydefined dark, then this mode will be automatically adopted.

Make different page lengths different and automatically change themes

Single View specified theme

This is how to do the "coexisting situation room and blank space" mentioned earlier. Each view on the dashboard can specify its own theme. The setting variable listed in the official View document reads "theme: string (optional), apply the theme to this view and the cards in it."

The method is very simple: enter the dashboard editing mode, click the pencil icon of the page you want to change, find the theme field in the settings, and select one. If you want to write YAML directly, the official example is:

- title: Home
  theme: happy

Put it into a real situation: leave the main dashboard for the whole family, with simple white space; open another "System" tab, designate it as a dark high-density theme, and specifically put CPU, network, battery, Zigbee signal, things that only you can see. The two do not interfere with each other.

Concept:The theme specified by View only affects the content area of that page. The part of the sidebar that is shared by the entire site will still follow the theme you selected on the profile page. So don't expect the entire window to change when you split the page.

Use automation to replace the site-wide default theme

The system-level default themes can be changed with actions. The purpose of the official document is to "set default light and dark themes for everyone, such as using a lighter one during the day and automatically changing to a darker one at night." action call frontend.set_theme, the official example is:

action: frontend.set_theme
data:
  name: "HA Light"
  name_dark: "HA Dark"

Official definitions of the two parameters:name It is the theme to be used in light mode, fill in "default" Represents a return to the standard theme;name_dark Is the theme to be used in dark mode? Fill in the "none" Represents removal of overrides. At least one of the two must be filled in. The settings will be saved and will persist after reboot, and only administrators can execute them.

pick upChapter 8The three-part formula I have learned, changing the subject at sunset is like this:

alias: sunset changed to dark theme
triggers:
  - trigger: sun
    event: sunset
actions:
  - action: frontend.set_theme
    data:
      name: "my_home_dark"
Warning:The official document states clearly that "the themes selected by individual users will override this system setting." So after you select a theme on your profile page, this automatedyourselfIt doesn't feel like it, and it will only affect those users who haven't touched the settings. If you want to change yourself, just select the theme of the profile page back to "Default" and let it take over the system settings.
Tip:In fact, most people don't need this automation at all. If you select "Auto" as the mode on your profile page, it will switch to dark mode according to the system of your phone/computer, and your phone will switch automatically according to sunrise and sunset. Use the built-in ones first, and then write automation if they are not enough.

card-mod: places where the theme cannot be changed

The theme can only be changed to "where the official label has been left." When what you want to do is "enlarge the title text of this specific card", "rotate the icon of this button 45 degrees", "turn the entire card red when the temperature exceeds 28 degrees", that is beyond the scope of the theme, so you need to use card-mod.

card-mod is a front-end custom component on HACS. Its function is to "insert CSS styles into any dashboard card". It is still under maintenance, and the author has put a version comparison table on the project page—Installing the wrong version is the most common reason for "Following the instructions but nothing happens", check your HA version first:

Your version of Home AssistantThe card-mod version to install

HACS will install the latest version by default, so if your HA has not kept up with the latest version, remember to manually select the version in the HACS download window, do not click directly.

The usage is to add a paragraph at the bottom of the YAML set by the card card_mod:: 

type: entity
entity: sensor.living_room_temperature
card_mod:
  style: |
    ha-card {
      color: red;
    }

ha-card It is the outermost element of the card, and the curly brackets are standard CSS. To use the theme's colors instead of hard-coding them, reference variables:

card_mod:
  style: |
    ha-card {
      border: 1px solid var(--primary-color);
      border-radius: 18px;
    }

Warning:Card-mod operates by "poking into the internal structure of official components", which means that once the Home Assistant front-end is revised, your card-mod style may become invalid or misaligned. This is not a bug, it is an inherent risk of this approach.It is recommended to treat card-mod as a dessert rather than a staple food: Never use card-mod if it can be solved with themes, so that there are fewer things to fix when upgrading.

Practical issues in Chinese fonts and typesetting

Home Assistant does not have built-in Chinese fonts. It directly calls the browser to use the system fonts. So the same screen will look different on different devices:

  • iPhone / iPad / Mac: Usually Ping Fang, the Chinese display looks the best and almost no need to adjust.
  • Android: Siyuan Blackbody series is also good.
  • Windows: Often falls into the Microsoft True Black font, the font weight is too thin, and it will appear blurry on a dark background.
  • cheap chinese brand tablet: The easiest thing to happen is that the whole set may only have simplified fonts, and the traditional characters will have missing characters or become boxes.

Three very practical countermeasures:

  1. Don’t make the name too long

    Chinese characters are much wider than English characters. "The standing lamp behind the sofa in the living room" will definitely be cut off into "Behind the sofa in the living room..." on the mobile phone card. Four to six words are the safest.Chapter 4The naming principle here will be directly reflected on the screen.

  2. Font weight is more important than font size

    Dark background + thin text = blurry. If your theme is dark, making the text color lighter will be much more effective than changing the font type, because changing the font type requires a third-party module, and changing the color only changes a variable.

  3. Test the flat panel on the wall first

    Don't think it's over once you finish adjusting it on your computer. Go to the tablet and look at it from your usual distance. The characters are too small and the buttons are too small. You can only find out if you stand on site.

Warning:There is a method of "using theme variables to change fonts" on the Internet. Whether it can take effect depends on whether your version also supports the corresponding font variables, and the font file itself must exist on that device.Changing font type is much less reliable than changing color, it is recommended to spend effort on color and font size, which is much more cost-effective.

Dark Mode Contrast and Accessibility

The most common failure of dark themes is not that they don’t look good, butCan't see. And people who do it can often see it - because you are in a bright room, using a high-end screen, and your eyes are still young. Your grandma can't be seen in the living room.

A few rules to follow directly:

ruleshow to dowhy
The comparison in this article is at least 4.5:1Search "contrast checker" on the Internet and paste the foreground color and background color into it for testing.This is the accessibility standard WCAG’s threshold for general text, below which many people will have difficulty reading.
Be careful with pure black bottoms#000000 Match #ffffff The contrast is too hard and there will be an afterimage after watching it for a long time; use instead #121212 Match #e8e8e8It is true that OLED saves power, but eye comfort will be reduced
Don’t rely solely on color to convey status"On/Off" should not only change color, but also have icons or text differences.The proportion of men with color vision difficulties is quite high. There will probably be one or two in a class, and red and green may look the same to them.
Don’t make secondary text too graysecondary-text-color It is the variable that is most often adjusted out of sight.It manages timestamps, units, and status descriptions, all of which are useful information.
Don’t use accent colors as contentNeon green and fluorescent green can be used as button borders, but it will be painful to use as a whole paragraph of text.High-color fine text will appear color fringing on small screens

In addition, I would like to remind you of two physical environmental factors that cannot be adjusted on the front of the screen:

  • Mobile phones on balconies and entrances: Under the bright sun, light themes are actually easier to read than dark themes. If you often use it outdoors, don't lock the mode in dark colors. It would be smarter to leave it to "Auto".
  • Get up in the middle of the night: What you want at this time is not just dark color, but "low brightness". The dark mode and automatic brightness of the mobile phone system have already taken care of most of the problem, as long as the theme does not use large areas of white cards.
Tip:After adjusting the theme, find a family member who has not participated, give him your phone directly, and say, "Help me turn off the lights in the living room." Where he hesitates or can't find it, that's where you need to change. This is more accurate than any checklist.

Common stuck levels

  1. HACS says it is installed, but it is not available in the drop-down menu on the profile page.

    90% yes configuration.yaml Not added frontend: themes: !include_dir_merge_named themes, or added but not restarted yet. Added for the first time frontend: The block must be completely restarted before it can be used only frontend.reload_themes.

    The remaining 10% is because the folder name does not match: you write themes, but HACS exists elsewhere, or the folder you created manually has one more layer. Go to the settings folder to confirm themes/ There really is something underneath .yaml file.

  2. Profile check sprays YAML errors

    Check these four things in order of appearance: whether Tab is used for indentation (YAML only eats white space), whether there is a space after the colon,# Are there quotation marks for the color at the beginning? Are there two by accident? frontend:. The fourth one is the most insidious because the error message often refers to another line number.

  3. There is no response after selecting a theme, or the entire screen turns black.

    Force a refresh first (Ctrl + Shift + R) and try the incognito window again. If all else fails, switch the theme back to "default" to confirm that the system itself is fine - if it works fine after switching back to default, it means that the theme file is incompatible with your version.

    In addition, the front end occasionally reports that the theme application fails, which is usually fixed in subsequent minor versions.If it happened after upgrading, first read the update notes and known issues for your version, and don't rush to rewrite the theme file.

  4. I changed the variables, but somewhere in the picture remains the same

    Three possibilities: that component does not use the variable you changed at all (use the browser inspection tool to click on it to see which one it actually uses); your variable is written in modes: The top level is overwritten by a value with the same name in the pattern; that variable has been renamed or removed in the new version. The official variable list itself is marked under construction, so incompleteness is the norm.

  5. The mobile phone is dark and the computer is light. I want the two to be different.

    After 2026.2, the theme will be tied to the account and will be consistent with all devices in the account. The official has no plans to change it back to being able to separate devices. The only way is to create a separate user login for that device. It's a hassle, but that's it for now.

  6. I wrote frontend.set_theme automation, but I can’t see the effect.

    Because the theme selected by the user on the profile page has priority over the system default. Select the profile page theme back to "Default" before automation will affect you.

  7. Card-mod ran away after style upgrade

    First make sure that the card-mod version matches your HA version (there is a comparison table on the author's project page), and update it in HACS if necessary. If the version is correct but the style is still misaligned, it means that the internal structure of the official component has changed, and you can only readjust the selector. This is the fixed cost of using card-mod.

  8. Can't find "Developer Tools"

    In 2026.2, it was moved from the sidebar to under settings, and in 2026.8, the name was simplified to "Tools". The current position isSettings → Tools, YAML, status, action, template and other paginations are still in it, and there are many functions.

FAQ

Will changing the theme affect my automation or devices?
No. The theme is just a bunch of color settings and has nothing to do with automation, scripts, or entity states. The worst case scenario is that the picture becomes ugly or some parts are unclear. Switch the theme back to "Default" and it will be restored immediately. The only risky part is editing configuration.yaml A typo caused the restart to fail, so check the settings before starting.
Do I have to use HACS to change topics?
No need. You can not install HACS at all and create one yourself under the settings folder. themes/ Folder, throw a copy of what you wrote .yaml Go in and stay the same configuration.yaml add frontend: themes: !include_dir_merge_named themes. HACS just helps you save the trouble of "finding a theme, downloading it, and then updating it". It is not a necessary condition.
Can each person in the family have a different theme?
Yes, and this is now the default behavior. The theme is selected on the personal profile page, one for each account, and does not interfere with each other. The premise is that everyone really has their own account - if the whole family shares a login, of course there will only be one. How to open an accountChapter 5. Be aware of the reverse limitation: the same account on different devicesCan'tSet up different themes. After 2026.2, the theme will be tied to the account instead of the browser.
How does the "auto" mode determine whether to darken?
It depends on your operating system settings, that is, the dark mode switch on your phone or computer - and your phone is usually set to switch itself to sunrise and sunset. So you don't have to do anything and it will darken in the evening. If you want it to cut according to Home Assistant's own sunset time instead of according to the phone, then you need to write frontend.set_theme of automation.
Can I change the name and icon of "Home Assistant" to those of my home?
The official does not provide this setting, all methods are third-party, and there is a risk of upgrade failure. The lowest risk approach is to change the name yourself when the phone is "added to the home screen", which will completely disable Home Assistant. If you want to change the browser pagination icon, you can check out Browser Mod, which is still under maintenance. The favicon custom component used by many people in the past has been stopped for maintenance. The author himself wrote on the project page that please use the Browser Mod instead and do not install that one again.
What is the difference between theme and card-mod? Which one should I learn?
Let’s learn the topic first, and that’s enough for most people. The theme is an officially supported mechanism, and the changed color is shared by the entire site. It will almost not break after upgrading. card-mod directly inserts CSS into a single card, which can do things that themes cannot (for example, only this card should be different and change color according to the value), but it relies on poking into the internal operation of official components. Once the front end is revised, the entire section may become invalid. It is recommended not to use card-mod if it can be solved with themes.
I changed the theme file, do I have to restart Home Assistant?
first time in configuration.yaml New frontend: A restart is required when performing a block. After that, just change the theme content or install a new theme, and then go toSettings → Tools → Actionsexecute frontend.reload_themes That’s it, the official said it doesn’t need to be restarted. Pay attention to one detail: if the theme you are using no longer exists after reloading, the system will automatically return to the standard theme, which will not be broken but the screen will change.
Some parts of the interface are still in English. Did I set it wrong?
Usually not. The translation of Home Assistant is done by community volunteers on Lokalise, and the latest progress is packaged every time it is released. It is common for translations to not catch up when a new feature is first launched, and it will probably be completed after one or two versions. First, make sure that the language of the profile page is indeed Traditional Chinese; if it is selected correctly and there is English, it means you haven’t reached that paragraph yet, just wait, or you can participate in the translation yourself.
