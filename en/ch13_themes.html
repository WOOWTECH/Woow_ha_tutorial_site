Chapter 13

Themes and appearance

Home Assistant can look like a control room or a clean, quiet dashboard. Configure light and dark modes, install a community theme, customize theme YAML and individual views, and keep text readable on every display.

Why this matters

After the first 12 chapters, your devices are named, areas are assigned to floors, dashboards have views, and automations run on their own. The interface, however, may still look unchanged from the initial installation.

Appearance affects usability. An interface that is comfortable in your lighting, readable on your devices, and suitable at night is easier for everyone to keep using.

This chapter addresses three specific problems:

  • Glare at night: A bright white interface is uncomfortable in a dark room. Use automatic dark mode.
  • Different user needs: One person may prefer a dark, high-contrast display while another needs larger, lighter text. Each user can select a theme.
  • An unfinished wall display: Default styling may not suit a permanently mounted tablet or shared workspace.
Concept: Themes change appearance, not automation logic, devices, or backups. A broken theme may make the interface unreadable, but switching back to Default restores the standard appearance.

Community-theme steps require HACS; install it as described in Appendix A. See Chapter 6 for dashboard editing.

What exactly is a theme?

A Home Assistant theme does not redraw the interface. It supplies a set of visual values, primarily through CSS variables.

Imagine there is a row of labels on your wall:

  • Write "Main Color = Sky Blue" on one page
  • One says "Card background color = white"
  • Write "Main text = dark gray" on one page

Each component on the interface does not decide the color by itself, but looks at the label paper. So as long as you erase and rewrite the words on the label, the buttons, cards, and sidebars of the entire site will change together. This is why a theme file with dozens of lines can change the appearance of the entire system.

Because of this mechanism, the theme has its ceiling:

Warning: A theme can change only the variables exposed by the frontend. It cannot control every layout, card width, or corner. Tools such as card-mod can reach further by injecting CSS, but carry additional maintenance risk.

In addition, we must first distinguish three things that are often confused:

Term What it controls Where to configure it
Theme Color, section spacing, and rounded corners Personal information page selection; theme files are placed in the settings folder
Light/dark mode Light and dark variants of one theme Profile; can follow the operating system automatically
Dashboard layout What cards are there and how to arrange them Dashboard edit mode (Chapter 6)

Changing the theme will not change your cards, and changing the cards will not change the theme. The two things are separate.

Where to find theme settings

Home Assistant 2026.2 changed the location and behavior of this setting.

Current location: Profile. Select your name at the bottom of the sidebar. Under General → User preferences, find the theme selector described as “What does Home Assistant look like?”

The Home Assistant 2026.2 release notes state: "The theme has been moved! You can now find and switch your favorite appearance directly in your user profile, so that you can apply the same theme on any device you log in to."

Warning: The theme now follows the account, not the browser. The same account uses the same selected theme on every device. If a dedicated wall display needs a different theme, create a separate user for it as described in Chapter 5.

The theme section of Profile usually has two choices:

  1. Choose a theme

    There will be at least "Default" in the drop-down menu, plus any community themes you install later. The newly installed system will only have the default one, which is normal.

  2. Choose light and dark mode

    If the same theme provides both light and dark modes, you can choose between light or dark. Unless otherwise specified, it will follow the dark mode of your phone or computer—when the phone turns dark, Home Assistant will follow suit. If you want to fix it into one type, specify it yourself. If you want to save trouble, leave it alone.

    The name and location of this option are different on different versions (some versions are "Auto", others are a set of light/dark buttons), Based on what you see on the screen, just accept the behavior of "following the system".

By the way, the same revision also moved the "Developer Tools" from the sidebar. Settings Underneath, The release notes state that the tools moved into Settings. In 2026.8, the name was further simplified from "Developer tools" to "Tools". So the path discussed later in this chapter will be written as Settings → Tools; In an older version, use Developer tools in the sidebar; its contents are the same.

Tip: If you can't find "Tools", it's fastest to use the keyboard to quickly search. press Ctrl + K (Mac is Cmd + K) call a quick search and find what you want directly.

Choose a monitoring or control-oriented style

Choose a design goal before installing themes. Most shared dashboards favor either dense monitoring or simple controls.

Compare items Route A: Technological Situation Room Route B: Simple and blank
background color Near black or dark blue-grey, OLED screens can use pure black to save power Off-white, light gray, close to the color of paper
main color High chroma: turquoise, electric blue, orange Low chroma: wood color, gray blue, dark green
card It has obvious borders, small rounded corners, and dividers, like a dashboard. No borders, large rounded corners, and partitions by white space
information density High. A page filled with numbers, charts, and status lights low. Only put a few buttons on one page that you will really press today.
Where to place it? Tablet on the wall of the study room, computer second screen, computer room Entrance, living room coffee table, phones for family members
The biggest pit Pure black background + dark gray text = invisible; neon text is hard on the eyes on a small screen The contrast is too low, and the light gray text on the white background completely disappears under the bright sun on the balcony.

A useful rule is: monitoring screens can be information-dense; control screens should be simple. A personal energy view may contain many charts, while a shared entry tablet should present a few large, clear controls.

The good news is that these two routes can coexist - the section "Single Page Change Theme" below is for this purpose.

Built-in themes vs. HACS community themes

Home Assistant includes the Default theme with light and dark modes. Version 2026.2 redesigned it, replacing the old blue top bar with styling aligned with Settings. A visual change after upgrading is therefore expected.

If you want more choices, there are three ways:

practice Do you want to touch YAML? Advantages Disadvantages Suitable for whom
Only use built-in default themes Not at all It will never break, nothing will happen if you upgrade it There is only one look People who just want to get the system running
Install a community theme with HACS Yes, three configuration lines Many ready-made color schemes and managed updates The maintainer may stop, or frontend changes may break parts of it Users who want more styles without designing one
Write your own theme YAML Yes, all written by hand Follow your wishes 100%, don’t rely on others You have to check the variable names yourself and maintain them yourself. People who already have clear color ideas
Concept: A HACS theme is not executable integration code. HACS downloads a YAML theme file into the configuration folder. An already downloaded file remains available if HACS is temporarily unavailable, though the theme can still become incompatible with frontend changes.

When choosing a community theme, use Chapter 11 Choose the same set of criteria for integration: first look at the last updated date. A theme that has not been touched in two years is probably still using variable names that have been removed long ago, and half of the places that are installed will not take effect.

Do it yourself: Install the first community theme from scratch

The process has five steps. Do not skip steps 2 and 3; otherwise HACS may report success while the theme remains absent from Profile.

  1. Download a theme in HACS

    Open HACS, use the search box to find the theme you want, go in and click download. Home Assistant HACS document states very clearly: “Any theme downloaded through HACS will be stored under your Home Assistant settings folder. themes/ in the folder. "That's what most people say /config/themes/.

    The classification name of HACS is "Theme". If your HACS does not show the Theme category, it is usually because themes have not been enabled in the system. It will appear after completing the next step.

  2. Add three lines to configuration.yaml

    Use an add-on such as "File editor" or "Studio Code Server" to open the settings folder configuration.yaml, add to the outermost layer:

    frontend:
  themes: !include_dir_merge_named themes

    These lines merge files from themes/ into the theme mapping. !include_dir_merge_named is a Home Assistant YAML extension. The frontend documentation also allows another directory, such as !include_dir_merge_named my_themes, but HACS uses themes.

    If configuration.yaml already contains frontend:, do not add another one. Add themes: under the existing key. YAML does not allow two identical keys to appear in the same layer.

  3. Check whether the settings are written correctly

    Go to Settings → Tools → YAML, select Check configuration. Correct every reported error before proceeding; indentation and extra colons are common causes.

    Danger: A YAML syntax error can prevent Home Assistant from starting. Run the configuration check before restarting. If startup fails, correct the file through available host access or restore a known-good backup as described in Chapter 9.

  4. Reload theme

    After adding frontend: for the first time, restart Home Assistant. For later theme changes or installations, a restart is unnecessary. Open Settings → Tools → Actions, execute frontend.reload_themes This action. It does not have any parameters, just one line in YAML mode:

    action: frontend.reload_themes

    This action reloads theme settings from configuration.yaml without restarting. If the selected theme no longer exists after reloading, Home Assistant returns to the standard theme. Only Administrators can run the action.

    Settings → Tools → YAML can also reload configuration. Quick reload reloads all supported configuration, while this tab may offer individual reload controls. If Themes is unavailable, run the action above.

  5. Return to profile page to apply

    Click your name at the bottom of the sidebar, find the theme selector in the general tab, and scroll down to see the newly installed theme. Once selected, the screen should change color immediately—no need to refresh or log in again.

    If it does not change immediately, do a forced rearrangement first (Ctrl + Shift + R), browser cache is the most common culprit.

Tip: Make a backup before installing. The theme is unlikely to break the system, but configuration.yaml Changes are possible, and backups take three minutes.

Write a theme: YAML structure and variables

Once you understand other people's theme files, you can fine-tune it or write one from scratch. The minimum example given by Home Assistant frontend document looks like this:

frontend:
  themes:
    happy:
      primary-color: pink
      accent-color: orange
    sad:
      primary-color: steelblue
      accent-color: darkred

If you use the previous !include_dir_merge_named themes Writing method, that’s it /config/themes/ Open a new file below, for example my_home.yaml, in the file Don't Write again frontend: and themes:, starting directly with the theme name:

my_home:
  primary-color: "#2f8f6b"
  accent-color: "#e0a458"
  primary-text-color: "#1c1c1c"
  card-background-color: "#ffffff"
  primary-background-color: "#f4f2ed"

Colors can use a named value such as pink, hexadecimal such as "#2f8f6b", or rgb(47,143,107). Quote values that begin with #; otherwise YAML treats the remainder as a comment.

Dark and light modes

A truly useful theme will offer both modes. Home Assistant way of writing is to add one modes: Block:

day_and_night:
  primary-color: coral
  modes:
    light:
      secondary-text-color: olive
    dark:
      secondary-text-color: slategray

The application order is officially explained in detail, and it’s worth remembering because it explains “why it didn’t work if I changed it”:

  1. Lay out the default theme first

    The system first takes into account all the variables of the default theme. Therefore, variables you have not written will not become transparent or black, but will retain the default value.

  2. Then cover the settings regardless of mode.

    That is to say, it is written in modes: Those variables outside, at the top level. In the above example primary-color: coral It will take effect regardless of light or dark.

  3. Finally, cover the settings specific to this mode.

    Values under modes: light: or modes: dark: have the highest priority. If a variable appears at both the top level and under a mode, the mode-specific value wins.

The document describes two additional behaviors: the old format (which has no modes: (single theme) will automatically use the default light theme as the base; if a theme only defined dark, then this mode will be automatically adopted.

"What color is the light on?" is more complicated than you think

The color of the diagram is the one that most people get stuck on, because it is not a variable that has the final say. Home Assistant frontend document states that the system will search in the following order: The more names you write, the more priority you find. Use the first one you find and ignore the following ones.:

Priority variable writing In plain language
1 (highest priority) state-{domain}-{device_class}-{state}-color The most detailed specification of "when the curtain type cover is open"
2 state-{domain}-{state}-color "When the lights are on"state-light-on-color
3 state-{domain}-active-color "As long as the light is moving"state-light-active-color
4 (used only last) state-active-color / state-inactive-color Common presets for all entities

To use warm orange for active lights and blue for active climate entities, set state-light-active-color and state-climate-active-color. To change the fallback for every active entity, set state-active-color.

Warning: There are a lot of old teachings on the Internet that will ask you to write state-icon-active-color Let’s change the color of the “on light”. This variable is no longer used as of Home Assistant 2022.12, Home Assistant developer blog directly compares it with paper-item-icon-active-color Put them on the "no longer used" list. If the color of the icon does not respond to the theme you copied, first check whether it has been hit by this shot, and change it to the writing method on the 3rd and 4th levels in the above table.
Warning: Home Assistant variable list is placed on the wiki of the frontend item, and the title itself is "WIP (Under Construction)", which means that it is not guaranteed to be complete or real-time. There are actually more variables available than on the list, and occasionally variables are renamed or disappear after revisions. If there is no response after writing it, it is probably because this variable is no longer available in your version, and it is not because you wrote it wrong. Please refer to the actual effect on your own version. It is easier to change one variable at a time.
Tip: If you don’t know which variables a certain component uses, use the browser’s inspection tool (right-click on the screen → Inspect) to click on that component, and the CSS variables applied to it will be listed on the right. This is the most accurate way to look up variable names and is ten times faster than looking through lists on the Internet.

Apply themes to views and system defaults

Single View specified theme

This is how to do the "coexisting situation room and blank space" mentioned earlier. Each view on the dashboard can specify its own theme. The setting variable listed in Home Assistant View document reads "theme: string (optional), apply the theme to this view and the cards in it."

The method is very simple: enter the dashboard editing mode, click the pencil icon of the page you want to change, find the theme field in the settings, and select one. If you want to write YAML directly, Home Assistant example is:

- title: Home
  theme: happy

Put it into a real situation: leave the main dashboard for the whole family, with simple white space; open another "System" tab, designate it as a dark high-density theme, and specifically put CPU, network, battery, Zigbee signal, things that only you can see. The two do not interfere with each other.

Concept: The theme specified by View only affects the content area of that page. The part of the sidebar that is shared by the entire site will still follow the theme you selected on the profile page. So don't expect the entire window to change when you split the page.

Use automation to replace the site-wide default theme

The system-level default themes can be changed with actions. The purpose of Home Assistant documentation is to "set default light and dark themes for everyone, such as using a lighter one during the day and automatically changing to a darker one at night." action call frontend.set_theme, Home Assistant example is:

action: frontend.set_theme
data:
  name: "HA Light"
  name_dark: "HA Dark"

Official definitions of the two parameters:name It is the theme to be used in light mode, fill in "default" Represents a return to the standard theme;name_dark Is the theme to be used in dark mode? Fill in the "none" Represents removal of overrides. At least one of the two must be filled in. The settings will be saved and will persist after reboot, and only administrators can execute them.

pick up Chapter 8 The three-part formula I have learned, changing the subject at sunset is like this:

alias: Switch to dark theme at sunset
triggers:
  - trigger: sun
    event: sunset
actions:
  - action: frontend.set_theme
    data:
      name: "my_home_dark"
Warning: A theme selected by an individual user overrides the system default. To let frontend.set_theme affect your account, set the profile theme back to Default.
Tip: In fact, most people don't need this automation at all. If you select "Auto" as the mode on your profile page, it will switch to dark mode according to the system of your phone/computer, and your phone will switch automatically according to sunrise and sunset. Use the built-in ones first, and then write automation if they are not enough.

card-mod: styling beyond themes

The theme can only be changed to "where Home Assistant label has been left." When what you want to do is "enlarge the title text of this specific card", "rotate the icon of this button 45 degrees", "turn the entire card red when the temperature exceeds 28 degrees", that is beyond the scope of the theme, so you need to use card-mod.

card-mod is a front-end custom component on HACS. Its function is to "insert CSS styles into any dashboard card". It is still under maintenance, and the author has put a version comparison table on the item page—Installing the wrong version is the most common reason for "Following the instructions but nothing happens", check your HA version first:

Your version of Home Assistant The card-mod version to install
2026.2.0 or above 4.2.0 (currently the latest)
2025.11.0 and above 4.1.0
2025.1.0 or above 3.4.4
2023.10.0 and above 3.2.3

HACS will install the latest version by default, so if your HA has not kept up with the latest version, remember to manually select the version in the HACS download window, do not click directly.

The usage is to add a paragraph at the bottom of the YAML set by the card card_mod:: 

type: entity
entity: sensor.living_room_temperature
card_mod:
  style: |
    ha-card {
      color: red;
    }

ha-card It is the outermost element of the card, and the curly brackets are standard CSS. To use the theme's colors instead of hard-coding them, reference variables:

card_mod:
  style: |
    ha-card {
      border: 1px solid var(--primary-color);
      border-radius: 18px;
    }
demand Should I use themes or card-mod?
Change colors across the site Theme
Change all cards to rounded corners together Theme (ha-card-border-radius)
Only this card is different card-mod
Changes color according to sensor value card-mod (to write a template)
Hide a line of text on the card card-mod
Warning: card-mod depends on internal frontend structure. A Home Assistant update can invalidate selectors or misalign a card. Use standard theme variables whenever possible to reduce upgrade maintenance.

Font and layout considerations

Home Assistant uses the browser’s available system fonts rather than bundling every writing system. The same dashboard can therefore look different across platforms:

  • iPhone / iPad / Mac: The system font generally provides broad language coverage and needs little adjustment.
  • Android: The system’s default sans-serif font generally provides broad language coverage.
  • Windows: Font rendering and weight vary by Windows version; test thin text on dark backgrounds.
  • Low-cost tablets: Limited font packages may omit glyphs for some languages, causing missing characters or boxes.

Three very practical countermeasures:

  1. Don’t make the name too long

    Text width varies by language and script. Long entity names can be truncated on phone cards, so use concise display names. Chapter 4 The naming principle here will be directly reflected on the screen.

  2. Font weight is more important than font size

    Dark background + thin text = blurry. If your theme is dark, making the text color lighter will be much more effective than changing the font type, because changing the font type requires a third-party module, and changing the color only changes a variable.

  3. Test the flat panel on the wall first

    Don't think it's over once you finish adjusting it on your computer. Go to the tablet and look at it from your usual distance. The characters are too small and the buttons are too small. You can only find out if you stand on site.

Warning: There is a method of "using theme variables to change fonts" on the Internet. Whether it can take effect depends on whether your version also supports the corresponding font variables, and the font file itself must exist on that device. Changing font type is much less reliable than changing color, it is recommended to spend effort on color and font size, which is much more cost-effective.

Dark-mode contrast and accessibility

The most serious dark-theme failure is not appearance but readability. Test with different displays, room lighting, viewing distances, and users rather than relying on the designer’s screen.

A few rules to follow directly:

rules how to do why
The comparison in this article is at least 4.5:1 Search "contrast checker" on the Internet and paste the foreground color and background color into it for testing. This is the accessibility standard WCAG’s threshold for general text, below which many people will have difficulty reading.
Be careful with pure black bottoms #000000 Match #ffffff The contrast is too hard and there will be an afterimage after watching it for a long time; use instead #121212 Match #e8e8e8 It is true that OLED saves power, but eye comfort will be reduced
Don’t rely solely on color to convey status "On/Off" should not only change color, but also have icons or text differences. The proportion of men with color vision difficulties is quite high. There will probably be one or two in a class, and red and green may look the same to them.
Don’t make secondary text too gray secondary-text-color It is the variable that is most often adjusted out of sight. It manages timestamps, units, and status descriptions, all of which are useful information.
Don’t use accent colors as content Neon green and fluorescent green can be used as button borders, but it will be painful to use as a whole paragraph of text. High-color fine text will appear color fringing on small screens

In addition, I would like to remind you of two physical environmental factors that cannot be adjusted on the front of the screen:

  • Phones on balconies and entrances: Under the bright sun, light themes are actually easier to read than dark themes. If you often use it outdoors, don't lock the mode in dark colors. It would be smarter to leave it to "Auto".
  • Get up in the middle of the night: What you want at this time is not just dark color, but "low brightness". The dark mode and automatic brightness of the phone system have already taken care of most of the problem, as long as the theme does not use large areas of white cards.
Tip: Give the interface to someone who did not design it and ask them to perform a common task. Any hesitation reveals where labels, contrast, or layout need improvement.

Common problems

  1. HACS says it is installed, but it is not available in the drop-down menu on the profile page.

    90% yes configuration.yaml Not added frontend: themes: !include_dir_merge_named themes, or added but not restarted yet. Added for the first time frontend: The block must be completely restarted before it can be used only frontend.reload_themes.

    Another possible cause is a directory mismatch. Confirm that the configured themes path matches the themes/ directory at the HACS location and directly contains at least one .yaml file.

  2. The configuration check reports a YAML error

    Check four items: indentation uses spaces rather than Tab; a space follows each mapping colon; colors beginning with # are quoted; and only one frontend: key exists at that level. A duplicate key can produce an error reported on another line.

  3. There is no response after selecting a theme, or the entire screen turns black.

    Force a refresh first (Ctrl + Shift + R) and try the incognito window again. If all else fails, switch the theme back to "default" to confirm that the system itself is fine - if it works fine after switching back to default, it means that the theme file is incompatible with your version.

    In addition, the front end occasionally reports that the theme application fails, which is usually fixed in subsequent minor versions. If it happened after upgrading, first read the update notes and known issues for your version, and don't rush to rewrite the theme file.

  4. I changed the variables, but somewhere in the display remains the same

    Three possibilities: that component does not use the variable you changed at all (use the browser inspection tool to click on it to see which one it actually uses); your variable is written in modes: The top level is overwritten by a value with the same name in the pattern; that variable has been renamed or removed in the new version. Home Assistant variable list itself is marked under construction, so incompleteness is the norm.

  5. The phone is dark and the computer is light. I want the two to be different.

    After 2026.2, the theme will be tied to the account and will be consistent with all devices in the account. The Home Assistant project has no plans to change it back to being able to separate devices. The only way is to create a separate user login for that device. It's a hassle, but that's it for now.

  6. I wrote frontend.set_theme automation, but I can’t see the effect.

    Because the theme selected by the user on the profile page has priority over the system default. Select the profile page theme back to "Default" before automation will affect you.

  7. card-mod styles broke after an upgrade

    First make sure that the card-mod version matches your HA version (there is a comparison table on the author's item page), and update it in HACS if necessary. If the version is correct but the style is still misaligned, it means that the internal structure of Home Assistant component has changed, and you can only readjust the selector. This is the fixed cost of using card-mod.

  8. Can't find "Developer Tools"

    In 2026.2, it was moved from the sidebar to under settings, and in 2026.8, the name was simplified to "Tools". The current position is Settings → Tools, YAML, States, Actions, Templates and other tabs are still in it, and there are many functions.

FAQ

Will changing the theme affect my automation or devices?
No. The theme is just multiple color settings and has nothing to do with automation, scripts, or entity states. The worst case scenario is that the display becomes ugly or some parts are unclear. Switch the theme back to "Default" and it will be restored immediately. The only risky part is editing configuration.yaml A typo caused the restart to fail, so check the settings before starting.
Do I have to use HACS to change themes?
No. You can create a theme without installing HACS. themes/ directory, place your .yaml file there, and configuration.yaml add frontend: themes: !include_dir_merge_named themes. HACS simplifies discovery, download, and updates; it is optional.
Can each person in the family have a different theme?
Yes, and this is now the default behavior. The theme is selected on the personal profile page, one for each account, and does not interfere with each other. The premise is that everyone really has their own account - if the whole family shares a login, of course there will only be one. How to open an account Chapter 5. Be aware of the reverse limitation: the same account on different devices Can't Set up different themes. After 2026.2, the theme will be tied to the account instead of the browser.
How does the "auto" mode determine whether to darken?
It depends on your operating system settings, that is, the dark mode switch on your phone or computer - and your phone is usually set to switch itself to sunrise and sunset. So you don't have to do anything and it will darken in the evening. If you want it to cut according to Home Assistant's own sunset time instead of according to the phone, then you need to write frontend.set_theme of automation.
Can I change the name and icon of "Home Assistant" to those of my home?
Home Assistant does not provide this setting. Third-party methods can fail after upgrades. The lowest-risk option is to edit the shortcut name when adding Home Assistant to your phone’s home screen; this does not modify Home Assistant. Browser Mod can change some browser-level behavior. The older favicon custom component is no longer maintained and directs users to Browser Mod.
What is the difference between theme and card-mod? Which one should I learn?
Start with themes; they cover most needs. The theme is an officially supported mechanism, and the changed color is shared by the entire site. It uses a supported mechanism and is less likely to break after a frontend update. card-mod directly inserts CSS into a single card, which can target individual cards in ways themes cannot (for example, only this card should be different and change color according to the value), but it relies on poking into the internal operation of official components. Once the front end is revised, the entire section may become invalid. Prefer themes when they can meet the requirement.
I changed the theme file, do I have to restart Home Assistant?
first time in configuration.yaml New frontend: A restart is required when performing a block. After that, just change the theme content or install a new theme, and then go to Settings → Tools → Actions execute frontend.reload_themes That’s it, Home Assistant said it doesn’t need to be restarted. Pay attention to one detail: if the theme you are using no longer exists after reloading, the system will automatically return to the standard theme, which will not be broken but the screen will change.
Some parts of the interface are still in English. Did I set it wrong?
Usually not. The translation of Home Assistant is done by community volunteers on Lokalise, and the latest progress is packaged every time it is released. It is common for translations to not catch up when a new feature is first launched, and it will probably be completed after one or two versions. First, make sure that the language of the profile page is indeed Traditional Chinese; if it is selected correctly and there is English, it means you haven’t reached that paragraph yet, just wait, or you can participate in the translation yourself.
