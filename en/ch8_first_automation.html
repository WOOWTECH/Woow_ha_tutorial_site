Chapter 8

First automation

The previous 7 chapters have set up the home structure, naming, dashboard, and notifications. This chapter takes you through writing your First automation to make HA really move.

Why should you learn this?

Automation is the core of HA, and it is also the biggest difference between it and ordinary smart socket apps.

If you only think of HA as "a webpage that can turn lights on and off remotely", then it is actually no more useful than Xiaomi/Google Home. What really makes HA worth installing is that it can:

  • According totime(sunset, seven o'clock every morning) do things.
  • According tosensor(Someone comes in, the temperature is too high, the electricity bill exceeds a certain value) Do something.
  • According tomultiple conditions(Someone is at home + dark + mid-week) Decide whether to do it or not.

Without writing about automation, HA is just a relatively expensive remote control. Starting from this chapter, we let it become the automatic housekeeper of the home.

Three-stage concept: trigger / condition / action

Every automation of HA is composed of three blocks. Remember these three words, and you will not get lost when you look at any examples in the future:

  • Trigger: When to "start checking" this automation. For example: at sunset, a switch is pressed, the temperature exceeds 28 degrees.
  • Condition: After triggering, whether to actually execute it. For example: turn on the lights only when "someone is at home", and sound the alarm only when "it is not a holiday". The condition isfilter.
  • Action: What to actually do. For example: turn on the lights, send tweets, play music, close the curtains.
Mental method:The trigger is "when to ask", the condition is "do you want to do it", and the action is "what to do". If these three sections are clearly broken down, any complex automation can be spelled out.

Pitfalls of device_id and entity_id

This is the number one pitfall recognized by the HA community, and it is also the reason why many people's automation "breaks after a while."

When building automation in the UI, HA defaults to usingdeviceAs a trigger object, for example, "the device of the living room lamp is turned on." It seems intuitive, but writing automation like this is tied toThat physical piece of hardwareThe identification code (device_id) on the. Once you replace the light, re-pair Zigbee, or the integration is removed and re-added, the device_id changes and the entire automation is broken, and there is no error message, it justQuietly and still.

This teaching rule:All automated triggers and actions will be changed to entity_id(e.g. light.livingroom_ceiling) without device_id. The UI will show the "Entity" option instead of the "Device" option.

entity_id islogical name, the string you named yourself in Chapter 4. If the device is changed or the integration is reinstalled, as long as you change the new device to the same entity_id, all automation will be automatically connected without any changes.

This is whyChapter 4 Naming and LabelingSo important - a good entity_id is the foundation of maintainable automation.

DIY: Turn on the living room lights when the sun sets

We use the most classic "turn on the lights at sunset" to implement it. Goal: 30 minutes after the sun goes down, turn on the main light in the living room and send a push notification on your mobile phone.

The name has been changed:Starting from HA 2024.8, "Service" will be officially renamed "Action", and "Call service" on the UI will become "Perform action". Starting from 2024.10, the outermost three keys of automation YAML will also be changed to plural numbers:trigger: → triggers:, condition: → conditions:, action: → actions:; in action service: Change to action:, service_data: Change to data:. The old writing method has not been officially abolished and is still used, so don’t be nervous when you see old examples on the Internet. Always use the new name in the following steps. The old name in brackets is the word you will see on the old version of the screen.

  1. Build new automation

    Go to "Settings → Automation & Scenes → Create Automation" and select "Start from Blank". Give it a name that is easy to understand, such as "Sunset·Living room main light on".

  2. Set trigger: Sun

    Click "New Trigger" and select "Sun". Select "sunset" for the event and fill in the offset +00:30:00, representing 30 minutes after sunset.

  3. (Optional) Add condition: only execute when someone is home

    Click "Add Condition", select "Status", and select the entity zone.home(or the home area you set in Chapter 3), the status is "Greater than 0". This way no electricity is wasted when no one is home.

  4. Set action: turn on the light

    Click "Add Action", select "Perform action (the old version is called "Call service")", and select light.turn_on.Important: Please switch the target column to "Entity" instead of "Device", choose light.livingroom_ceiling(or your living room main light entity_id). Brightness can be set to 60%.

  5. Add a push notification action

    Then click "Add Action" and select notify.mobile_app_xxx(set in Chapter 7notification action), fill in the message "The lights in the living room have been turned on with the sunset."

  6. Save and test

    "Save" in the lower right corner. After confirming the name, go back to the automation list and you can see the one you just created. Click the "Execute" button next to it to manually trigger it once. The confirmation light will turn on and the phone will receive a notification.

Verify:Set the time on your phone to 30 minutes just after sunset and the lights should come on. Or go to "Settings → Automation → The one you just created → Execute" to trigger it manually. If the mobile phone receives the push message "The living room lights have been turned on with sunset", it means that the entire path (trigger → condition → action → notification) has been passed.

Execution mode: single/restart/queued/parallel

What should we do when the automation is triggered again while it is "still running"? This is what the execution model determines. Go to the bottom of the automation editing page to see the "Mode" settings.

mode behavior Applicable situations
single(Default) Ignore new triggers while still running last time "Just run it" automations like turning on the lights at sunset and making daily backups
restart When a new trigger is received, it will interrupt the previous one and run from the beginning. Motion sensor turns on lights + turns off after 5 minutes (restarts every time someone moves)
queued New triggers are queued and executed sequentially after the previous runs are completed. Ringing the doorbell requires a "ding-dong" sound that cannot be repeated, or there are a large number of events in a short period of time
parallel Run multiple copies at the same time Rarely used, only select if you clearly want multiple copies in parallel.

If you're not sure, stay single, which is the safest default.

Blueprint: Import automation written by others with one click

Blueprint is HA’s official “automated template” mechanism. The author has written the logic and left the adjustable parts as form fields. You only need to fill in a few drop-down menus and there will be an available automation.

Common uses:

  • Zigbee button binding (IKEA, Aqara, Hue remote control)
  • Motion sensor turns on lights + turns off lights after timeout
  • Washer/Dryer Completion Notifications
  • Low battery reminder

Import process:

  1. Arrive HA Blueprint Exchange Forum Or find the blueprint you want on GitHub and copy its URL.
  2. In HA "Settings → Automation and Scenarios → Blueprints → Import Blueprint", paste the URL.
  3. Go back to "Automation", click "Create Automation with Blueprint", select the one you just imported, and fill in the device/entity parameters.
Suggestions:First become familiar with handwriting automation once (that is, the example in this chapter), and then start using Blueprints. In this way, if there is a problem with the blueprint, you will know how to look at it and how to correct it.

Common stuck levels

Question 1: The automation is not running and there is no error message.

Go to the automation list and click on it. There is a "Trace" button in the upper right corner. The complete process of the last 5 triggers will be displayed here: which trigger is activated, whether the condition is passed or not, and which step the action reaches. Looking at the trace is the first step in troubleshooting, which is more direct than looking at the log.

Problem 2: The trigger occurs, but the condition blocks it.

Trace will be marked with color: if the condition box turns gray/white, it means it failed, and moving the mouse up will display the actual value of the current entity. Common reasons:zone.home judged to be 0(Everyone is not at home), the time conditions and time zone are not aligned.

Issue 3: Entity name is misspelled/renamed.

If you change the entity_id, the old automation will not automatically follow the change and will run silently. After the HA 2024 version, "Unused entities" and "Prompt for update when renaming" were added, but the old automation recommended manually running a verification using "Settings → Tools → YAML → Check Settings" (Settings → Tools → YAML; the old version of this page was called "Developer Tools", it was moved under "Settings" in 2026.2, and simplified to "Tools" in 2026.8).

FAQ

Can I call another automation within an automation?
Yes, but it is more recommended to use "Script". A script is a reusable sequence of actions that can be called by multiple automations or manually triggered by placing a button on the dashboard. Settings → Automation & Scenarios → Script Creation.
Is it better to write automation in UI or YAML?
Novices must use the UI, with friendly error messages and Trace debugging. YAML is suitable for advanced users who are already familiar with it, want to do version control, or want to copy to multiple HAs. The bottom layer of the automation built by the UI is actually YAML, which can be exported at any time.
Why is my sunset trigger time so different from the actual sky color?
The sunset time of HA is calculated based on the "latitude and longitude" set in Chapter 2. If the longitude and latitude are not set, the default value (probably Germany) will be used, and the time will be skewed. Go to "Settings → System → Home information (called "General" in the old version)" to confirm.
Is there a way to temporarily deactivate an automation (for example while traveling abroad)?
There is a switch on the right side of the automation list that can be turned off directly. Or use "input_boolean" to create a "vacation mode" switch, reference it in the condition, and you can switch it on the dashboard with one click.
