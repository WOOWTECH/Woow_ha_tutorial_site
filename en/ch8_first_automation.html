Chapter 8

Your first automation

The previous chapters established your home structure, names, dashboard, and notifications. Now build an automation that makes Home Assistant act on its own.

Why automate?

Automation is where Home Assistant goes beyond an ordinary smart-device app.

If you use Home Assistant only as a remote control, you miss its main advantage. It can act:

  • At a time, such as sunset or 7:00 every morning.
  • When a sensor changes, such as motion being detected or temperature rising above a threshold.
  • Only when multiple conditions match, such as someone being home after dark on a weekday.

Without automations, Home Assistant is just another remote control. This chapter makes it respond to your home on its own.

Three-part model: trigger, condition, action

Every Home Assistant automation uses three building blocks:

  • Trigger: What starts the automation, such as sunset, a button press, or temperature exceeding 28 degrees.
  • Condition: A filter checked after the trigger, such as whether someone is home or today is a workday.
  • Action: What Home Assistant does, such as turning on a light, sending a notification, playing music, or closing a cover.
Remember: A trigger asks “when?”, a condition asks “should it run?”, and an action answers “what should happen?” Breaking a complex idea into these parts makes it easier to build and debug.

The device_id trap and entity_id

A device-based automation can stop working after hardware is replaced or paired again.

A device trigger may look intuitive, but it ties the automation to one physical device through its device ID. Replacing a light, pairing it again, or removing and re-adding an integration can create a new device ID. The automation may then fail without an obvious warning.

Rule for this guide: Prefer entity_id references, such as light.livingroom_ceiling, when the same behavior is available. In the UI, choose an entity trigger or target instead of a device option.

An entity ID is a logical name that you control. If hardware changes, assigning the replacement the same entity ID can keep entity-based automations working.

This is why Chapter 4: Naming and labels matters: clear, stable entity IDs are the foundation of maintainable automations.

Further reading: HA community discussion: Why avoid device_id.

DIY: Turn on the living room lights when the sun sets

Goal: 30 minutes after sunset, turn on the main living-room light and send a push notification.

Current terminology: Home Assistant now calls a service call an action, and the UI uses “Perform action.” Current automation YAML uses the plural top-level keystrigger: → triggers:, condition: → conditions:, action: → actions: . Within an action, use service: instead of action:, service_data: instead of data:. Older examples may use the legacy keys. This guide follows the current terminology and syntax.

  1. Build new automation

    Go to "Settings → Automations & scenes → Create Automation" and select "Start from Blank". Give it a name that is easy to understand, such as "Sunset·Living room main light on".

  2. Set trigger: Sun

    Click "New Trigger" and select "Sun". Select "sunset" for the event and fill in the offset +00:30:00, representing 30 minutes after sunset.

  3. (Optional) Add condition: only execute when someone is home

    Select Add condition → Numeric state, then choose zone.homeand set Above to 0. The actions then run only when at least one tracked person is home.

  4. Set action: turn on the light

    Click "Add Action", select "Perform action (the old version is called "Call service")", and select light.turn_on. Important: Please switch the target column to "Entity" instead of "Device", choose light.livingroom_ceiling(or your living room main light entity_id). Brightness can be set to 60%.

  5. Add a push notification action

    Then click "Add Action" and select notify.mobile_app_xxx(set in Chapter 7 notification action), fill in the message "The lights in the living room have been turned on with the sunset."

  6. Save and test

    Select Save, confirm the name, then open the automation and run its actions manually. The light should turn on and the phone should receive a notification.

Verify: Do not change your phone clock. Open the automation under Settings → Automations & scenes and run its actions for an immediate test. To test the full path, temporarily choose a safe trigger that will occur soon, then restore the sunset trigger.

Execution mode: single/restart/queued/parallel

What should we do when the automation is triggered again while it is "still running"? This is what the execution model determines. Go to the bottom of the automation editing page to see the "Mode" settings.

mode behavior Applicable situations
single (Default) Ignore new triggers while still running last time One-shot tasks such as sunset lighting or a daily backup
restart When a new trigger is received, it will interrupt the previous one and run from the beginning. Motion sensor turns on lights + turns off after 5 minutes (restarts every time someone moves)
queued New triggers are queued and executed sequentially after the previous runs are completed. Ringing the doorbell requires a "ding-dong" sound that cannot be repeated, or there are a large number of events in a short period of time
parallel Run multiple copies at the same time Rarely used, only select if you clearly want multiple copies in parallel.

If you're not sure, stay single, which is the safest default.

Blueprint: Import automation written by others with one click

A Blueprint is a reusable automation template. Its author supplies the logic and exposes adjustable inputs as form fields.

Common uses:

  • Zigbee button connection (IKEA, Aqara, Hue remote control)
  • Motion sensor turns on lights + turns off lights after timeout
  • Washer/Dryer Completion Notifications
  • Low battery reminder

Import process:

  1. Arrive HA Blueprint Exchange Forum Or find the blueprint you want on GitHub and copy its URL.
  2. In HA "Settings → Automations & scenes → Blueprints → Import Blueprint", paste the URL.
  3. Return to Automations, create one from the imported Blueprint, and complete its device or entity inputs.
Suggestions: Build the example in this chapter before relying on Blueprints. Understanding the editor helps you diagnose a Blueprint-based automation later.

Common problems

Question 1: The automation is not running and there is no error message.

Open the automation and inspect Traces. A trace shows which trigger fired, whether each condition passed, and how far the actions ran. Check it before searching the system log.

Problem 2: The trigger occurs, but the condition blocks it.

Trace will be marked with color: if the condition box turns gray/white, it means it failed, and moving the mouse up will display the actual value of the current entity. Common reasons:zone.home judged to be 0(Everyone is not at home), the time conditions and time zone are not aligned.

Issue 3: Entity name is misspelled/renamed.

A stale entity reference can make an action fail. Check each referenced entity in the editor, inspect the trace, and use Settings → Tools → YAML → Check configuration before restarting after YAML changes.

FAQ

Can I call another automation within an automation?
Yes, but it is more recommended to use "Script". A script is a reusable sequence of actions that can be called by multiple automations or manually triggered by placing a button on the dashboard. Settings → Automations & scenes → Script Creation.
Is it better to write automation in UI or YAML?
Novices must use the UI, with friendly error messages and Trace debugging. YAML is suitable for advanced users who are already familiar with it, want to do version control, or want to copy to multiple HAs. The bottom layer of the automation built by the UI is actually YAML, which can be exported at any time.
Why is my sunset trigger time so different from the actual sky color?
The sunset time of HA is calculated based on the "latitude and longitude" set in Chapter 2. If the longitude and latitude are not set, the default value (probably Germany) will be used, and the time will be skewed. Go to "Settings → System → Home information (called "General" in the old version)" to confirm.
Is there a way to temporarily deactivate an automation (for example while traveling abroad)?
Turn off the automation from its list row. For reusable control, create an input_boolean vacation-mode helper and check it in the conditions.
