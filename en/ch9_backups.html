Chapter 9

Backups

A failed storage device, problematic update, accidental deletion, or broken integration can undo hours of work. Configure automatic backups in three minutes so you can experiment with confidence.

Why backups matter

Keeping no backup is a costly beginner mistake. A failed storage device, unsuccessful update, or accidentally removed Zigbee integration can otherwise force you to rebuild hours of work.

The recovery plan is simple: restore a recent, tested backup.

These practical guides also identify missing backups as a common mistake:

  • How-To Geek: Mistakes to avoid when setting up HA
  • Everything Smart Home: Common mistakes made by HA newbies

Complete Chapter 2: System settings first. A baseline backup is more useful when the time zone, units, and location are already correct.

Backup contents

Name changed: Starting from version 2026.2, HA has officially renamed "Add-on" to "Apps", and the installation entrance has also changed from the old version of "Settings → Add-ons" to "Settings → Apps". The Add-on you see in the old version is the same thing as the new version of Apps, and will use the new name after this chapter. The backup page itself has not been moved, the old and new versions are both in "Settings → System → Backups".

A full backup of HA is a .tar The compressed file has two main parts after expansion:

  • Home Assistant core settings
    • .storage/: All UI building stuff (automation, scripts, dashboards, users, integrated login tokens).
    • configuration.yaml and related YAML files.
    • Floor, area, label, entity naming.
    • Lovelace dashboard configuration.
  • Apps (called add-ons in older versions) data
    • Pairing list for Zigbee2MQTT.
    • Node-RED’s process.
    • Mosquitto broker settings.
Does not include: media library (media/, such as camera recordings, TTS voice files) defaults are excluded because they are usually large. Historical data (Recorder DB) default Will backup, but can be unchecked during creation to shrink the file.

Create your first backup manually

  1. Open backup page

    Go to "Settings → System → Backups". The list will be empty the first time you enter.

  2. Click "Create backup"

    Select the backup type: "Full backup" (includes all content, recommended for the first time) or "Customized backup" (check which ones you want).

  3. Naming and Encryption

    Use a date and purpose for the backup name, for example 2026-08-01-baseline. It is strongly recommended to check "Encryption" and set a password, because an encrypted backup cannot be restored without it. Keep the recovery material in a password manager.

  4. After creation, download to computer

    Wait for the backup to finish, open it in the list, and select Download. This creates an Off-site backup—if the host storage fails, a backup stored only on that host is lost too.

Verify: After the backup is completed, there will be one more entry in the "Settings → System → Backups" list, with the timestamp being now. Click to download to your computer once as an off-machine backup.

Enable automatic backup schedule

HA OS 2024.10 and later has a complete automatic backup scheduling function built-in, and there is no need to install additional automatic backup apps.

Go to "Settings → System → Backups → Automatic backup (upper right corner)" and you can set:

  • Frequency: Daily, weekly, monthly, and execution time (3-5am recommended).
  • Retention: Keep enough recent copies for recovery without allowing the destination to fill.
  • backup location: Can upload to multiple locations at the same time:
    • Home Assistant Cloud (Nabu Casa)—Available to eligible subscribers as a managed off-site destination.
    • Google Drive—Connected through official integration.
    • Samba / NFS Netfang—Save to your home NAS.
    • Nextcloud App—Self-installed in the cloud.
  • Encryption: Always turn on and set the same password.
Recommended combination: Back up to NAS every morning + weekly backup to Google Drive. The former saves daily misoperation, and the latter saves the entire host from damage.

Two scenes for restoring backups

Scenario 1: Selective restore of an item on the same HA

An automation was accidentally deleted, or an integration was broken. Go to "Settings → System → Backups → Select a backup → Restore", you can check Only restore this part (For example, only restore the Zigbee2MQTT configuration and leave the others unchanged). This is the most common firefighting scenario.

Scenario 2: Restoring from backup on fresh installation

Replace the SD card with a new one, get a new host, or the original system is too damaged to start. After refreshing and installing HA OS, when you go to the first page of "Start Settings", there will be an option to "Restore from backup". upload .tar file (or connect to Google Drive), enter the encryption password, and wait 5 to 15 minutes to completely return to the previous state.

Reminder: After restoration, Chapter 5 The set user password may become invalid (depending on the HA version). Please prepare the administrator's password or SSH to reset it. When logging into the restored system for the first time, it is recommended that each family member test login first.

Backup locations (important)

A local backup remains on the Home Assistant host under /backup . That location is on the same storage device as Home Assistant.

Fatal misunderstanding: Only backup to local machine /backup, which means there is no backup. Once the SD card is damaged or the hard drive is disconnected, the backup is gone along with the main unit.

Keep at least one additional copy, preferably using two of these options:

  • Cloud: Nabu Casa or Google Drive integration, set to upload automatically.
  • NAS: Store copies on Synology, QNAP, TrueNAS, or another configured Samba/NFS destination.
  • Offline hard drive: Periodically download a backup to removable storage, then disconnect it.

3-2-1 backup Rules: 3 backups, 2 media, 1 offsite. When used in HA, it is "local + NAS + cloud".

Troubleshooting

Problem 1: The backup file is too large.

Check the database size in system information. Reduce Recorder retention withrecorder.purge_keep_daysor exclude noisy entities only after reviewing the effect on History. Also review large selected folders and apps.

Issue 2: Some integrated passwords/tokens become invalid after restoration.

Most integrated tokens exist .storage/ usually restore with the backup. A cloud provider may still require reauthorization because a token expired or a security check detected a new host. Reauthenticate through the integration flow.

Problem 3: The SD card is damaged and cannot be read, and the backup and restore path is broken.

This is why you need to have off-site backups. If there is no last available backup, you can only rebuild from scratch. This is why it is strongly recommended to use SSD + USB adapter Replacing the SD card to run HA OS has much worse usability.

FAQ

What should I do if I forget my backup password?
An encrypted backup cannot be restored without its recovery material. Store that information in a password manager instead of relying on memory.
Can I restore a backup from an old HA version to a new version?
Restoring onto the same or a newer compatible Home Assistant version is the normal direction because migrations can run forward. Do not assume that a backup from a newer version can be restored onto an older release.
Will the backup take up a lot of space?
Size depends on database history, apps, and selected folders; it can range from megabytes to many gigabytes. Measure your own backups and set retention so the destination cannot fill unexpectedly.
Will HA stop while the backup is running?
Home Assistant normally continues running, but backup creation can increase CPU and storage activity. Schedule it during a quiet period and investigate if time-sensitive automations become unreliable.
