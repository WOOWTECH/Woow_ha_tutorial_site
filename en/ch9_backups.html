Chapter 9

Backups

A failed storage device, problematic update, accidental deletion, or broken integration can undo hours of work. Configure automatic backups in three minutes so you can experiment with confidence.

Why should you learn this?

"No device copy" is recognized by the HA community The first blood and tears lesson for newbies. Almost every week, people on Reddit's r/homeassistant post crying complaints: the SD card is broken, can't get up after updating, accidentally deletes the Zigbee integration results and the entire Zigbee network needs to be re-paired.

All these pains can be solved in one sentence: As long as you have the backup from the previous day, just restore it.

Several must-read community articles list "not backing up" as the number one novice mistake:

  • How-To Geek: Mistakes to avoid when setting up HA
  • Everything Smart Home: Common mistakes made by HA newbies

It is recommended to read it first System Settings for Chapter 2—It will be cleaner to make sure the basic settings are correct before backing up, and it will be less likely to bring back multiple strange old values when restoring.

What does a backup contain?

Name changed: Starting from version 2026.2, HA has officially renamed "Add-on" to "Apps", and the installation entrance has also changed from the old version of "Settings → Add-ons" to "Settings → Applications". The Add-on you see in the old version is the same thing as the new version of Apps, and will use the new name after this chapter. The backup page itself has not been moved, the old and new versions are both in "Settings → System → backup".

A full backup of HA is a .tar The compressed file has two main parts after expansion:

  • Home Assistant core settings
    • .storage/: All UI building stuff (automation, scripts, dashboards, users, integrated login tokens).
    • configuration.yaml and related YAML files.
    • Floor, area, label, entity naming.
    • Lovelace dashboard configuration.
  • Applications (Apps, called add-ons in the old version) data
    • Pairing list for Zigbee2MQTT.
    • Node-RED’s process.
    • Mosquitto broker settings.
Does not include: media library (media/, such as camera recordings, TTS voice files) defaults are excluded because they are usually large. Historical data (Recorder DB) default Will backup, but can be unchecked during creation to shrink the file.

Create your first backup manually

  1. Open backup page

    Go to "Settings → System → backup". The list will be empty the first time you enter.

  2. Click "Create backup"

    Select the backup type: "Full backup" (includes all content, recommended for the first time) or "Customized backup" (check which ones you want).

  3. Naming and Encryption

    It is recommended to use "date + purpose" as the backup name, for example 2026-08-01-baseline. It is strongly recommended to check "Encryption" and set a password, because the backup contains all your integrated login tokens. Please remember the password in the password manager (1Password/Bitwarden). If you forget it, you cannot restore it.

  4. After creation, download to computer

    backup usually takes 30 seconds to 3 minutes to complete. There will be one more item in the list, click on it and click "Download" to pull it to your computer. This step is Off-site backup—If the HA host is completely broken, the backup in the hard disk will also be lost. The off-machine copy is life-saving.

Verify: After the backup is completed, there will be one more entry in the "Settings → System → backup" list, with the timestamp being now. Click to download to your computer once as an off-machine backup.

Enable automatic backup schedule

HA OS 2024.10 and later has a complete automatic backup scheduling function built-in, and there is no need to install additional automatic backup apps.

Go to "Settings → System → backup → Automatic backup (upper right corner)" and you can set:

  • Frequency: Daily, weekly, monthly, and execution time (3-5am recommended).
  • Keep copies: For example, "Keep the latest 7 daily backups + 4 weekly backups", and the excess will be automatically deleted.
  • backup location: Can upload to multiple locations at the same time:
    • Home Assistant Cloud (Nabu Casa)—The simplest, just check it directly after subscribing.
    • Google Drive—Connected through official integration.
    • Samba / NFS Netfang—Save to your home NAS.
    • Nextcloud App—Self-installed in the cloud.
  • Encryption: Always turn on and set the same password.
Recommended combination: Back up to NAS every morning + weekly backup to Google Drive. The former saves daily misoperation, and the latter saves the entire host from damage.

Two scenes for restoring backups

Scenario 1: Selective restore of an item on the same HA

An automation was accidentally deleted, or an integration was broken. Go to "Settings → System → backup → Select a backup → Restore", you can check Only restore this part (For example, only restore the Zigbee2MQTT configuration and leave the others unchanged). This is the most common firefighting scenario.

Scenario 2: Restoring from backup on fresh installation

Replace the SD card with a new one, get a new host, or the original system is too damaged to start. After refreshing and installing HA OS, when you go to the first page of "Start Settings", there will be an option to "Restore from backup". upload .tar file (or connect to Google Drive), enter the encryption password, and wait 5 to 15 minutes to completely return to the previous state.

Reminder: After restoration, Chapter 5 The set user password may become invalid (depending on the HA version). Please prepare the administrator's password or SSH to reset it. When logging into the restored system for the first time, it is recommended that each family member test login first.

Where to store backups (important)

HA OS stores backups on the host by default. /backup Directory. This directory is the same as your HA ontology On the same SD card/same hard drive.

Fatal misunderstanding: Only backup to local machine /backup, which means there is no backup. Once the SD card is damaged or the hard drive is disconnected, the backup is gone along with the main unit.

Correct approach (choose at least one, it is recommended to do both):

  • Cloud: Nabu Casa or Google Drive integration, set to upload automatically.
  • NAS/wangfang: If you have Synology / QNAP / TrueNAS at home, write to it through Samba backup App or native integration.
  • Offline hard drive: Manually download to the flash drive once a month and keep it.

3-2-1 backup Rules: 3 backups, 2 media, 1 offsite. When used in HA, it is "local + NAS + cloud".

Troubleshooting

Problem 1: The backup file is too large.

Check "Settings → Tools → Statistics" (the old version was called "Developer Tools", it is an item in the sidebar) to see how big the Recorder database is. Retention days can be shortened (recorder.purge_keep_days, preset for 10 days) or exclude high-frequency sensors (such as power meter, CPU temperature). Confirm that the media library has not been checked in.

Issue 2: Some integrated passwords/tokens become invalid after restoration.

Most integrated tokens exist .storage/ will be restored together. However, cloud services (Google, Alexa, Nest) often require re-authorization because the token has a validity period or is tied to an IP. This is expected behavior, just connect it again.

Problem 3: The SD card is damaged and cannot be read, and the backup and restore path is broken.

This is why you need to have off-site backups. If there is no last available backup, you can only rebuild from scratch. This is why it is strongly recommended to use SSD + USB adapter Replacing the SD card to run HA OS has much worse usability.

FAQ

What should I do if I forget my backup password?
There is no way to restore it, this is a necessity of encryption. Passwords must be stored in a password manager (1Password / Bitwarden) rather than "I should remember".
Can I restore a backup from an old HA version to a new version?
Yes, restoring up is Home Assistantly supported path, and HA will automatically run the necessary database migration. The other way around (restore the new version backup to the old version HA) will not work, it will break.
Will the backup take up a lot of space?
Typical home use (10~50 devices) is approximately 100 MB ~ 500 MB. If you have a camera or a lot of historical data, you may want to go to GB. The setting "Keep the last 7 copies" is usually limited to 5 GB.
Will HA stop while the backup is running?
No, backups are done in the background and automation and notifications work normally. However, the CPU/IO is busy at the moment of backup, and operations with high immediacy such as Zigbee may be delayed by 1 to 2 seconds.
