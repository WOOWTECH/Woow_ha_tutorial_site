Chapter 11

Device settings

A Home Assistant device page is the record for one piece of hardware. Learn to read each section, rename devices and entities, disable unneeded entities, update firmware, download diagnostics, and remove a device cleanly.

Device page anatomy

Open Settings → Devices & services → Devices, then select a device.

A typical device page contains six kinds of information:

  1. Device information: Name, manufacturer, model, firmware version, integration, and assigned area. Additional commands are in the three-dot menu.
  2. Controls: Interactive controls appear for entities such as switches and lights.
  3. Entities: Every endpoint exposed by the device. A Zigbee switch might provide switch.* for control, sensor.*_battery for battery level, and update.*_firmware for firmware.
  4. Automations/Scenes/Scripts: Related items show where the device is used. Review this list before renaming or removing hardware.
  5. Related information: Links may open the Logbook and History views.
  6. Diagnostics: Download diagnostic data, usually JSON, for an integration maintainer or support request. Review it before sharing.
Remember: A device represents physical hardware; an entity is one readable or controllable endpoint. A socket may expose one switch, while an environmental monitor may expose temperature, humidity, CO₂, battery, and firmware entities.

Rename devices and entities

  1. Device rename

    Device page → Pencil icon in the upper right corner → Change "Name". Effect: The default display-name prefix for its entities may update unless you overrode an entity name.

    Things that won't change: The entity ID (entity_id) will not be changed automatically and needs to be changed separately on the entity page. This is intentional on HA: if automation is hard-coded light.old_name, you can change the device display-name without breaking the automation. If you want to change the entity_id together, you have to do it manually.

  2. Entity rename (display-name & entity_id)

    Open an entity from the device page, then select its settings icon. Edit the display name and entity ID separately. When Home Assistant offers to update references in dashboards, automations, and scripts, Be sure to tickand then test the affected items.

  3. Choose a recognizable icon

    On the entity settings page, enter mdi:xxx, for example mdi:lightbulb-outline, mdi:ceiling-light, mdi:desk-lamp. Browse the icon library at pictogrammers.com/library/mdi/.

Entities

A device may expose many entities. Use these rules to keep the registry manageable:

  • Useful → Give it a clear name, assign an area, and add relevant labels.
  • Useful but infrequently viewed, such as battery level → Keep it enabled and consider a “Battery” label for monitoring.
  • Not useful, such as an unwanted diagnostic entity → Hide or disable it after understanding the difference below.

There are two operation paths:

  1. Device page: Review every entity belonging to one device.
  2. Settings → Devices & services → Entities: Filter the complete entity registry by domain, integration, label, or status.

Disable vs. hide vs. delete

Do not treat these as synonyms: Hiding changes presentation, disabling stops an entity, and deleting removes a registry entry when the integration permits it. Start with the least destructive option.
Operation Effect Historical preservation? How to restore
Hide Hidden The entity is still running and data is still being collected, but the UI is not displayed by default and the card cannot be selected. Reserve Turn off "Hide" on the entity page
Disabled The entity no longer updates, no longer collects data, and becomes unavailable The history is retained and will not be added after deactivation. Turn off "Disabled" on the entity page, and it will usually come back only after reloading the integration.
Delete Delete Clear entities and all references Reserved (but no source) Usually you need to remove the device integration and re-pair it

When to use which one?

  • "I won't use this entity, but I might want to see it someday" → hide
  • "This entity disturbs my log/occupies resources" → deactivate , for example: Z-Wave has multiple unused diagnostic entities)
  • "I dismantled this device and will never use it again." → First "Delete device" on the device page, or go to the integration page to remove the entire device. Simply "deleting the entity" will usually not succeed if the device still exists (it will be rebuilt).

Firmware update (Update entity)

In recent years, new integrations will make "firmware updates" into one update.* Entities, displayed on the device page like other entities.

  1. Check to see if any updates are available

    Check the Updates card or Settings → System → Updates. A supported device also shows its update.*entity on the device page.

  2. Back up before updating (Chapter 9)

    Especially Zigbee / Z-Wave firmware update failure will brick the device. A 3-minute backup costs far less than re-pairing an entire device.

  3. Click "Install"

    Battery-operated devices (door contacts, motion sensors) often take a few clicks to receive a message because they sleep most of the time. Some integrations will be queued for the next time it wakes up.

  4. Verify after update

    Go back to the device page and see if the "Firmware version" jumps. The common reasons why the status has not changed are: the update has not been pushed in the queue, or the update failed (see the log).

Zigbee firmware update (OTA): ZHA turns off OTA by default and needs to be turned on in the integration settings; Zigbee2MQTT supports most brands by default. in process Do not cut off power or turn off HA, usually takes 10-30 minutes.

Diagnosis & Repairs

Version differences: The fixed location of the Repairs is now Settings → System → Repairs, a digital badge will be used next to "Settings" in the sidebar to remind you how many items you still have to deal with. In addition, starting from 2026.2, "Add-on" will be officially renamed as "Apps", and the store path will become Settings → Apps; Where Add-on is written on the old version of the screen, application is written in the new version.

There are two tools for HA when the device is weird:

1. Download Diagnostics

Device page → "⋮" in the upper right corner → "Download Diagnostics" will download a JSON file containing all status, attributes, and integrated raw data of the device (sensitive information has been masked). It is helpful to attach it to GitHub issues or when asking for help in the community.

2. Repairs (repair suggestions)

The path is Settings → System → Repairs; Home Assistant raises repair issues for conditions such as deprecated configuration or an integration that needs attention. Open an issue, read its explanation, and follow the guided repair.

Read before Ignore: Repairs has an "ignore" button, but many issues really need to be addressed. After ignoring it, the badge disappears but the problem remains. Ignore it unless you are sure the issue does not affect you.

Reset & remove device

Reconfigure

If the integration supports it, use Reconfigure to update an IP address, key, or token without removing the config entry. Zigbee re-interview controls depend on the integration; follow its documented device-management flow.

Remove a single device

Device page → "⋮" → "Delete". The result depends on the integration: a Zigbee integration may remove the node from its network, while a cloud integration may discover it again on the next sync.

No "Delete" option? The integration may not support removing individual devices. Open Settings → Devices & services → Integrations and reconfigure or remove the relevant config entry only after reviewing everything it provides.

Remove entire integration

Under Settings → Devices & services → Integrations, open the config entry menu and select Delete. Review every device and entity it provides, then create a backup before confirming.

FAQ

A device is unavailable. How do I tell whether it is disconnected or broken?
Check the Logbook for its last successful update. A sudden change to unavailable often points to power, battery, network, or signal trouble. Review integration-specific signal data and logs before concluding that the hardware failed.
Can an entity use a different area from its device?
Yes. An entity can override the device’s area. For example, one channel of a multi-channel controller may serve another room. Use overrides sparingly because they make the physical device harder to understand.
After deleting the device, will the history records still be found?
Yes, the Recorder database still retains the original data, but it cannot be seen in the UI (because the corresponding entity no longer exists). If you want to be really clean, you have to go into the database and delete it (most people don’t have to do this), or wait. purge_keep_days Automatically clear when due (default 10 days).
What should I do when two integrations discover the same device?
Compare capabilities, then keep one integration path if duplicate control conflicts. Remove the unwanted config entry under Settings → Devices & services → Integrations. Prefer an official integration unless a custom integration provides a requirement you have evaluated.
Can the device page URL be shared directly?
Yes, the URL structure is /config/devices/device/deviceID. Recipients must sign in and have permission to view the device; the URL itself grants no access.
