Chapter 11

Device details

The "Device Page" is the file card for each piece of physical hardware within HA. This chapter breaks down each block of it, teaches you how to rename it, deactivate unnecessary entities, update the firmware, view diagnostics, and cleanly remove it.

Device page anatomy

Path:Settings → Devices & Services → Devices(Tab) → Click on any device card to enter the device details page.

A typical device page is divided into 6 sections:

  1. Device information: Name, manufacturer, model, firmware version, which integration is used, and which region it belongs to. There is a "⋮" menu in the upper right corner.
  2. control: If there is an actively controlled device (switch, light), there will be a big button.
  3. Entities: All entities spawned by this device. A Zigbee switch may have both switch.*(control),sensor.*_battery(power),update.*_firmware(Firmware) Three entities.
  4. Automation/Scenarios/Scripts: this devicewhere is it used. If you want to change automation, it’s faster to jump here. It’s also a checklist of “what will be the impact of deleting this unit?”
  5. Related: There are often links to "View Record" and "View History" at the bottom.
  6. Diagnosis / Download diagnostic data: The original information shown to the integration author when a problem occurs, usually JSON.
Mental method:"Device" is the physical hardware; "entity" is each readable/controllable endpoint exposed by this hardware. A socket may have only 1 entity (switch); an environmental monitor may have 5 (temperature, humidity, CO₂, power, firmware).

Rename devices and entities

  1. Device rename

    Device page → Pencil icon in the upper right corner → Change "Name".influence: All entities under this devicedisplay nameThe prefix will be automatically changed (if it has not been overwritten individually).

    Things that won't change: The entity ID (entity_id) will not be changed automatically and needs to be changed separately on the entity page. This is intentional on HA: if automation is hard-coded light.old_name, you can change the device display name without breaking the automation. If you want to change the entity_id together, you have to do it manually.

  2. Entity rename (display name & entity_id)

    Device page → click on an entity → gear icon. You can change the "Name" (for display) and "Entity ID" (identification code referenced by the program) respectively. When changing entity_id, HA will ask if you want to help you change the references in all dashboards/automation/scripts — Be sure to tick, otherwise it creates a broken reference.

  3. Change the icon (to prevent the whole family from looking the same)

    Physical gear page → "Icon" column → fill in mdi:xxx(Example mdi:lightbulb-outline, mdi:ceiling-light, mdi:desk-lamp). Illustration library:pictogrammers.com/library/mdi/.

Entities

A device usually has many entities, especially environmental sensors and Zigbee all-in-one switches. Organizing principles:

  • available → Name it clearly, specify the area, and add labels.
  • Visible but not commonly used(Example: battery level) → Just leave it alone, or add a label "battery" for centralized monitoring.
  • Totally useless(Example: Some integrations will produce a bunch of unused diagnostic entities) → Disable or hide (see next section).

There are two operation paths:

  1. Enter from device page: See the entity of a single device, suitable for organizing the entire device.
  2. Settings → Devices & Services → Entities(Tab): A summary list of all entities in the entire site, which can be filtered by domain, tag, and status; suitable for large-scale sorting.

Deactivate vs Hide vs Delete - three different buttons

These three are often confused: Newbies often want to "delete", but in 90% of cases it should be "hide" or "disable". Sometimes you have to reset the integration to get it back if you delete it by mistake.
Operation Effect Historical preservation? How to restore
Hide Hidden The entity is still running and data is still being collected, but the UI is not displayed by default and the card cannot be selected. Reserve Turn off "Hide" on the entity page
Disabled The entity no longer updates, no longer collects data, and becomes unavailable The history is retained and will not be added after deactivation. Turn off "Disabled" on the entity page, and it will usually come back only after reloading the integration.
Delete Delete Clear entities and all references Reserved (but no source) Usually you need to remove the device integration and re-pair it

When to use which one?

  • "I won't use this entity, but I might want to see it someday" → hide
  • "This entity disturbs my log/occupies resources" → deactivate(Example: Z-Wave has a bunch of unused diagnostic entities)
  • "I dismantled this device and will never use it again." → First "Delete device" on the device page, or go to the integration page to remove the entire device. Simply "deleting the entity" will usually not succeed if the device still exists (it will be rebuilt).

Firmware update (Update entity)

In recent years, new integrations will make "firmware updates" into one update.* Entities, displayed on the device page like other entities.

  1. Check to see if any updates are available

    The "Updates" card of the overview will be displayed together. Or go to "Settings → System → Updates" to see them all. Updates for a single device are at the bottom of the device page update.* entity.

  2. Back up before updating (Chapter 9)

    Especially Zigbee / Z-Wave firmware update failure will brick the device. A 3-minute backup costs far less than re-pairing an entire device.

  3. Click "Install"

    Battery-operated devices (door contacts, motion sensors) often take a few clicks to receive a message because they sleep most of the time. Some integrations will be queued for the next time it wakes up.

  4. Verify after update

    Go back to the device page and see if the "Firmware version" jumps. The common reasons why the status has not changed are: the update has not been pushed in the queue, or the update failed (see the log).

Zigbee firmware update (OTA): ZHA turns off OTA by default and needs to be turned on in the integration settings; Zigbee2MQTT supports most brands by default. in processDo not cut off power or turn off HA, usually takes 10-30 minutes.

Diagnosis & Repairs

Version differences:The fixed location of the Repair Center (Repairs) is nowSettings → System → Repairs, a digital badge will be used next to "Settings" in the sidebar to remind you how many items you still have to deal with. In addition, starting from 2026.2, "Add-on" will be officially renamed as "Apps", and the store path will becomeSettings → Applications; Where Add-on is written on the old version of the screen, application is written in the new version.

There are two tools for HA when the device is weird:

1. Download Diagnostics

Device page → "⋮" in the upper right corner → "Download Diagnostics" will download a JSON file containing all status, attributes, and integrated raw data of the device (sensitive information has been masked). It is helpful to attach it to GitHub issues or when asking for help in the community.

2. Repairs (repair suggestions)

The path isSettings → System → Repairs; There will also be a badge with pending results next to "Settings" in the sidebar. This is a problem that is proactively detected by HA (integration stopped working, application out of date, duplicate entities, database too large, etc.). There is a "Fix Now" button for each issue you click on, which can usually be solved with one click.

Read before Ignore: Repairs has an "ignore" button, but many issues really need to be addressed. After ignoring it, the badge disappears but the problem remains. Ignore it unless you are sure the issue does not affect you.

Reset & remove device

Reconfigure

If integrated support is available, go to "⋮" → "Reset" on the device page to change the connection method (change IP, change key, change API token) without deleting and re-adding. ZHA/Zigbee2MQTT devices can also be "re-identified" (interviewed) from here and repair the remaining damaged entities.

Remove a single device

Device page → "⋮" → "Delete". This only deletes the record in HA; if it is Zigbee, it will notify the coordinator to kick it off the network; if it is cloud integration (Xiaomi, Tuya), it may be pulled back the next time the account is synchronized.

No "Delete" option?This means that this integration does not support deleting devices individually (for example, HomeKit Bridge can be used as a whole package). In this case, you need to go to "Settings → Devices and Services → Integration" to remove the entire integration or change the settings.

Remove entire integration

Settings → Devices and Services → Find the integration → Three dots → "Delete". It will warn "All devices and entities integrated with this will be deleted." Back up first!

FAQ

The device is always displayed when offline unavailable, how to distinguish whether it is disconnected or really broken?
look Logbook(Log) - When this device was last online. If it was still moving yesterday, start this morning unavailable, it's mostly a WiFi or Zigbee signal problem; if it hasn't been used for several days, the battery or hardware may be bad. Z-Wave/Zigbee Signal Strength (LQI) can also be viewed on the device page.
Can the entity of a device be "belonged" to different regions?
Yes, entities can overwrite areas of a device. For example: The light strip device belongs to the "living room", but one section of the lamp entity wants to belong to the "entry". Just change the "Region" on the entity page. Disadvantages: This device becomes more difficult to manage as a whole.
After deleting the device, will the history records still be found?
Yes, the Recorder database still retains the original data, but it cannot be seen in the UI (because the corresponding entity no longer exists). If you want to be really clean, you have to go into the database and delete it (most people don’t have to do this), or wait. purge_keep_days Automatically clear when due (default 10 days).
A device seems to be recognized by two integrations at the same time (for example: Xiaomi official + HACS version), what should I do?
Two sets of entities will be generated with conflicting behaviors. Select one to keep and the other to "Settings → Devices and Services → Integration" to remove them all. In practice: the official brand integration is stable but has few functions; the HACS community version has many functions but frequent updates. It’s up to you to weigh the balance. Don’t keep both.
Can the device page URL be shared directly?
Yes, the URL structure is /config/devices/device/deviceID. Just paste the URL when sharing it with your family, and you will jump to the same page after logging in.
