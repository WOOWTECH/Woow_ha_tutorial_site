43 Home Assistant prompts for AI

Connect Home Assistant to Claude, ChatGPT, or Gemini through an HA MCP server such as ha-mcp-woow. These 43 English prompts cover eight practical categories; copy one, then replace example areas and entity IDs with those in your home.

What this library is for

Home Assistant provides a REST API, a WebSocket API, and an official REST API reference. With ha-mcp-woow or the official MCP Server integration, an LLM agent can use the tools you authorize to:

  • Control devices: Call actions such as light.turn_on, climate.set_temperature, and cover.open_cover.
  • Query data: Read entity states, attributes, and available history to answer questions such as “What is the living-room temperature?”
  • Edit configuration: Create or change automations, scripts, scenes, and dashboards when the connected tools support those operations.
  • Manage the system: Work with add-ons, HACS packages, integrations, backups, and upgrades when explicitly authorized.

Each entry is a natural-language prompt for an AI agent. Unlike a short voice command, it can describe several actions, require a preview, and ask the agent to report what it did.

Get started

  1. Connect Home Assistant to an MCP server

    Option 1: Connect a compatible client through the official MCP Server integration (HA 2025.7+). Option 2: Use ha-mcp-woow, a WoowTech version with additional configuration, HACS, backup, log, and trace tools. See Chapter 19 and Chapter 20.

  2. Expose entities to the LLM

    Open Settings → Voice assistants → Expose, then select only the areas and entities the AI needs. Start safely: expose low-risk entities such as lights and sensors first. Verify the agent’s behavior before considering locks, alarms, or other security-sensitive controls.

  3. Copy a prompt for your task

    Replace example names such as “living room” and “main bedroom,” along with values such as “26 degrees,” with the areas, devices, and settings in your home. Then paste the prompt into Claude, ChatGPT, or Gemini.

  4. Require a preview before important changes

    For prompts that change configuration, retain instructions such as “summarize the change and wait for my confirmation before applying it.” Review before approval to protect your existing setup.

Tip: If you only need short voice commands, use an Assist conversation agent instead. Many prompts in this library are too long or complex for a voice exchange.

Lights and scenes

These common requests use actions such as light.turn_on, light.turn_off, scene.turn_on, and light.toggle.

Turn on every living-room light at 60% brightness and set the color temperature to a warm white at 3000 K. Respond in English.

Uses light.turn_on with brightness_pct and kelvin. The agent should skip color-temperature settings for unsupported lights.

List every light that is currently on and identify the area containing each one. Respond in English.

Queries states in the light domain and matches them against the area_registry.

Turn on the “Movie mode” scene: switch off the main living-room light, dim the accent light to red, and turn on the TV backlight. If the scene does not exist, first help me create a dynamic scene with scene.create. Respond in English.

Create a sunrise effect for the main bedroom light: over 20 minutes, raise brightness gradually from 5% to 100% and color temperature from 2200 K to 5000 K. Use script transitions rather than multiple turn_on actions. Respond in English.

Use light.turn_on with transition, or call an existing script.wake_up.

Turn off every light in the home except night-lights whose entity IDs begin with light.nightlight_. Respond in English.

Create a welcome effect for the entryway lights: cycle from purple to blue to white three times, then finish at normal white. Use only RGB-capable lights and skip color-temperature-only lights. Respond in English.

Climate and air conditioning

These requests use actions such as climate.set_temperature, climate.set_hvac_mode, and climate.set_fan_mode. Some also compare sensor.*_temperature entities with weather.* data.

Report the current temperature and humidity in every area. If an area is cooler indoors than outside, turn off its air conditioner and tell me what you changed. Respond in English.

Compares entity states with weather.* data, then calls climate.turn_off only when the stated condition is true.

Prepare to put every air conditioner into sleep mode: 25 degrees with low fan speed in the main bedroom, and 26 degrees with automatic fan speed elsewhere. List the entities you intend to change and wait for my confirmation before acting. Respond in English.

If weather.forecast_home reports rain and indoor humidity exceeds 70%, turn on all dehumidifiers and set their target to 55%. Check humidity again after 30 minutes and notify me if it has not fallen. Respond in English.

Using the current forecast and tomorrow’s 08:00 temperature forecast, recommend either “sleep at 26 degrees” or “energy-saving mode” for the main-bedroom air conditioner tonight. Explain which is likely to be more comfortable and wait for my approval before changing anything. Respond in English.

List hvac_mode, target_temperature, and current_temperature for every climate entity in a table. Flag any entity whose target and current temperatures differ by more than 3 degrees. Respond in English.

Energy monitoring and analysis

These requests combine history or recorder data with sensor.*_energy entities. Large data sets may require a model with sufficient context and analysis capability.

Use ha_get_history to retrieve the past 7 days for every sensor.*_energy entity. Calculate energy use for today and yesterday and the 7-day daily average. Rank the five highest-consuming devices and identify what each sensor probably measures. Respond in English.

Analyze the living-room air conditioner’s energy-use curve over the past 30 days and correlate it with outdoor temperature. Compare energy use at setpoints of 25 and 26 degrees, then recommend savings based on this household’s usage periods. Respond in English.

Report the current instantaneous total power from sensor.total_power. If it remains above 5000 W for 3 minutes, pause deferrable high-power devices such as the dehumidifier, dishwasher, and dryer for 30 minutes to avoid exceeding the contracted power limit. Respond in English.

Using my utility’s time-of-use tariff, identify the devices that consumed the most energy during peak hours (Monday–Friday, 16:00–22:00) over the past week. Estimate one month of savings if those loads moved to off-peak hours. Respond in English.

Create this week’s energy report: compare total use with last week, show changes among the five highest-consuming devices, report average indoor temperature, and include solar generation when sensor.solar_* entities exist. Send it to my phone with notify.mobile_app_*. Respond in English.

Notifications

Use notify.mobile_app_myphone to send a test notification titled “HA notification test” with the current timestamp as its message. Also list any other mobile_app notification actions available. Respond in English.

Create an automation for when washing machine switch.washer changes from on to off and remains inactive for more than 3 minutes. Send an actionable notification with “Collected” and “Delay 30 minutes” buttons, and create handlers for both button actions. Summarize the automation and wait for my confirmation before enabling it. Respond in English.

Put every device below 20% battery into one notification, including its area, entity name, and current battery level. Filter with label.battery when available; otherwise find entities named *_battery. Respond in English.

When any binary_sensor.*_leak sensor triggers, immediately send a highest-priority notification naming the sensor and the water-valve entity ID for its area, then call switch.turn_off for that valve. Respond in English.

At 22:00 tonight, check every door and window sensor. If any opening is not closed, notify my phone with its location and how long it has been open. Send nothing if everything is closed. Respond in English.

Write or modify automations and scripts

These requests use ha_config_set_automation, ha_config_set_script, and ha_config_set_scene. Review the proposed configuration before allowing the agent to apply it.

Help me write an arrival automation. When any household member’s phone device_tracker changes from not_home to home, turn on light.entrance, set the air conditioner to 26 degrees, and play my favorite playlist. Show me a YAML summary and wait for confirmation before enabling it. Respond in English.

Important: Tell the agent to use entity_id rather than hard-coding device_id. See Chapter 8.

Modify the “Good night” automation so that, when calendar.family contains an event before 08:00 the next morning, the morning scene starts 30 minutes earlier. Read the existing automation YAML first, explain the proposed change, and wait for approval. Respond in English.

Split the “Living-room AC automatic control” automation into two automations: turn on above 28 degrees and turn off below 25 degrees. Use mode: restart to prevent competing actions. Respond in English.

Write script.movie_night to turn off the main lights, set the living-room accent light to red at 30% brightness, turn on the TV, and select Netflix. Then add a dashboard button that runs the script. Respond in English.

List my current automations and flag three risky patterns: device_id references, wait_for_trigger without a timeout, and time-only triggers with no conditions. Explain each finding and recommend a change. Respond in English.

Import this blueprint: https://community.home-assistant.io/t/motion-activated-light/262970. Create an automation instance using binary_sensor.master_motion and light.master_bedroom. Respond in English.

Query sensors and devices

These requests use tools such as ha_get_state, ha_get_history, ha_search, ha_get_device, and ha_list_floors_areas.

List every floor and area in the home and the devices assigned to each area. Use a table and identify any entities that have not been assigned to an area. Respond in English.

Report current living-room temperature, humidity, CO2, and PM2.5 and compare them with outdoor conditions. If CO2 exceeds 1000 ppm, recommend either starting the ventilation system or opening windows. Respond in English.

Use ha_get_history to retrieve every state change for binary_sensor.front_door over the past 24 hours. Report how many times it opened, the average open duration, and the longest open duration, then identify any anomaly. Respond in English.

Find every entity that has not reported a state for 7 days, which may indicate a depleted battery or disconnected sensor, and list the results. Respond in English.

Rename the living-room sensor from sensor.living_temp to sensor.living_room_temperature. First list every automation, script, scene, and dashboard that references it. Wait for my confirmation, then update all references together. Respond in English.

Use the references returned by ha_get_entity before renaming the entity.

List every entity with device_class: motion and identify those that have not triggered during the past 24 hours; they may be faulty or poorly positioned. Respond in English.

Everyday voice and chat requests

These short, conversational prompts work well for both voice and chat, including the Assist setup described in Chapter 19.

Turn on the living-room lights. Respond in English.

I am leaving. Turn off all lights, lock the door, and put the air conditioner into away mode. Respond in English.

Set the air conditioner to 26 degrees with sleep fan mode. Respond in English.

Troubleshooting and maintenance

These requests use ha_get_logs, ha_get_automation_traces, ha_get_system_health, and ha_manage_backup to investigate Home Assistant problems.

The “Turn on the lights at sunset” automation did not trigger as expected today. Use ha_get_automation_traces to retrieve its five most recent traces and identify the cause. If a fix is available, summarize it and wait for my confirmation before applying it. Respond in English.

Use ha_get_logs to retrieve entries at log_level=ERROR or higher from the past 24 hours. Group them by integration and entity, identify the groups with the most errors, and recommend the three highest-priority fixes. Respond in English.

Run ha_get_system_health once and check Recorder, Supervisor, and networking for unhealthy states. If you find a problem, follow the repair steps in the official Home Assistant documentation. Respond in English.

List automatic backups from the past 7 days. Confirm that one ran each day and that every file is > 100MB, because a much smaller file may be incomplete. If the newest backup is more than 24 hours old, run a full backup first and then report the result. Respond in English.

Use ha_report_issue to report the current open issues from Repairs. List each issue by severity and explain which can be deferred and which require action. Respond in English.

Five ways to write better agent prompts

An AI agent needs more explicit instructions than a person. Use these patterns to reduce ambiguity and protect existing configuration:

Say thisNot thisWhy
Use entity_id: “Turn on light.living,” or use the clear friendly name “Turn on the main living-room light.” “Turn on that light.” The agent needs a specific entity_id or an unambiguous name.
Name the action for a complex request: “Use climate.set_temperature to set the target to 26 degrees.” “Set it to 26.” An explicit action and target reduce the chance that the agent will choose the wrong tool. Simple requests can remain conversational.
Read before writing: “Read the existing automation YAML, then explain how you propose to change it.” “Change my automation.” The agent must understand the current configuration before editing it.
Preview before applying: “Show me a YAML summary and wait for my confirmation before enabling it.” “Add an automation.” A confirmation step helps prevent unintended configuration changes.
Use entity_id rather than device_id: “Trigger on binary_sensor.front_door.” Use a device_id UUID. An entity ID is easier to inspect and maintain. See Chapter 8.
Warning: Connecting Home Assistant to an LLM may allow the agent to change configuration and control entities. Expose only low-risk entities, such as lights and sensors, while you validate the setup. Do not expose locks, alarms, or main power controls without a deliberate security review. Require a preview and confirmation for prompts that change configuration.

FAQ

How do an MCP server, the REST API, and Assist differ?
Assist processes conversational intents and is best suited to concise requests. The REST API lets software read states and call actions over HTTP. An MCP server presents authorized tools to an LLM agent, which can discover and combine them for a task. Many prompts in this library are designed for API or MCP tools and are more complex than a typical Assist request.
Should I use ha-mcp-woow or the official MCP Server integration?
The official integration (HA 2025.7+) supports Home Assistant control through exposed entities. ha-mcp-woow adds WoowTech tools for configuration editing, HACS management, backups, logs, and traces. Prompts that mention ha_config_set_*, ha_get_automation_traces, or ha_manage_backup require those additional tools. Choose ha-mcp-woow or the official integration according to the documented capabilities and permissions your task requires.
Why does the AI call the wrong action or use the wrong entity_id?
Three common causes are: (1) the entity is not exposed under Settings → Voice assistants → Expose; (2) its name is ambiguous—sensor.abc123 is harder to identify than sensor.living_temperature; or (3) too much context prevents the agent from seeing the relevant entity. Start with clear names (Chapter 4), expose only what is needed, and state the intended entity ID in the prompt.
How many tokens will these prompts use?
Usage depends on the model, provider, tool output, and task. A simple control request generally uses less context than a 7-day log analysis or a large automation refactor. Limit tool output and expose only relevant entities. Check your provider’s current pricing before choosing a model.
Can I trigger a prompt automatically?
Yes. You can package a workflow as a skill (see the Skill Handbook) or use a Home Assistant script with action: conversation.process. An automation can also ask an LLM to analyze an event such as a leak or low battery. Restrict its permissions and do not let an unattended agent perform irreversible or safety-critical actions.
Can household members use these prompts?
Yes. Share the downloaded HTML file, then have each person replace the examples with your actual area and entity names. The everyday requests are a simple place to start. Make sure each account and agent has only the permissions it needs.
