Chapter 20

Add-ons and Docker architecture

An add-on installed from the store is a Docker container managed by Supervisor. Learn the concepts behind images, volumes, and ports; install useful add-ons; configure off-device backups; and troubleshoot from logs.

Why add-on architecture matters

In Appendix A you learned where to find and install add-ons. This chapter explains their architecture so you can diagnose failures.

What's the difference? Here are a few situations that actually happen:

  • You installed Home Assistant on your laptop, but you cannot find the Add-on store in the menu on the left - it is not that you are at fault, it is Wrong installation method.
  • You installed Zigbee2MQTT, but it does not start, and the page only says "stopped". You don't know where to look to see what it's complaining about.
  • If you install Node-RED and another web tool at the same time, the second one will fail - both are trying to use the same port.
  • You reinstalled the entire machine, only to find that the backups were all stored only on the failed machine.

All four situations depend on the same concepts: an add-on is a container with an image, persistent data, network ports, and logs. After this chapter, you will know where to begin when one fails.

Warning: Starting from Home Assistant version 2026.2, Home Assistant name of “Add-on (add-on)” is “Apps ", the menu also changes from "Settings → Add-ons" to " Settings → Apps”. Technically, it hasn't changed at all, it's just a name that's easier to understand. The two words in this chapter will be used interchangeably, referring to the same thing; whichever one appears on your screen will be based on your version.

Installation types and add-on availability

This is the biggest pitfall for beginners: Not every Home Assistant has an Add-on store. Whether or not there is a store is determined the moment you decide how to install it, and you cannot open it later by setting it.

Installation methodPlain-English explanationIs there an add-on store?One-click updateCurrent support status
Home Assistant OS (HAOS) The entire machine only runs Home Assistant, and the operating system is officially made. Home Assistant Green, Yellow, and Raspberry Pi burning official image files are all considered this. Yes Yes Recommended and fully supported
Home Assistant Container On your own Linux/NAS/Synology, use Docker to run a Home Assistant container. No No (you need to pull the new image file and rebuild the container yourself) Official support
Home Assistant Supervised Supervisor installed manually on Debian to create an environment similar to HAOS. Yes Yes Unsupported, officially stopped supporting since 2025.12
Home Assistant Core Home Assistant Core running directly in a Python environment. No No Unsupported, officially stopped supporting since 2025.12
Warning: Home Assistant announced in May 2025 that the two installation methods Core and Supervised will be eliminated, and support will be officially ended in version 2025.12. Also eliminated are 32-bit architectures such as i386, armhf, and armv7. The old machine technically still runs and can be updated, but there is no official support if something goes wrong. Currently, only HAOS and Container are officially supported.

So the conclusion is simple:

  • You want Add-on Store → use HAOS. Green, Yellow, or Raspberry Pi can burn Home Assistant image file, or install HAOS on an empty mini host.
  • You use Container (e.g. Docker on Synology NAS) → There is no store, and there never will be. If you need things like MQTT broker and Node-RED, you can open a separate Docker container to run it. The function is the same, you just have to do it yourself.
Concept: Official documentation clearly states that part of the integration of Thread and Z-Wave is supported by Add-on, so Container installation No out-of-the-box support. If you plan to play Zigbee/Z-Wave/Thread, but do not want to bother, choosing HAOS directly will save you half the trouble.

An add-on is a Docker container managed by Supervisor

Home Assistant developer documentation explains that an add-on is distributed as a container image through a registry, such as GitHub Container Registry or Docker Hub.

In other words, when you press "Install" in the store, what happens is:

  1. Supervisor downloads the image

    Supervisor reads the add-on configuration to find the image URL, version, and CPU architecture, such as arm64 or amd64. This is often the longest step and may fail if the network connection is interrupted.

  2. Supervisor opens a container using that image file

    By the way, according to the settings of the Add-on, decide which ports to open, which folders to attach to it, and whether to give it a USB device.

  3. Supervisor helps you connects the configuration interface to Home Assistant

    That's why you will see the Add-on's "Settings" tab and "Log Files" tab in the Home Assistant page, without having to type the Docker command yourself.

  4. Supervisor monitors it

    It is responsible for starting, stopping, updating, watchdog (Watchdog) restart, and automatic startup at boot. These are the switches you see on the add-on page.

So Supervisor is the "manager". The Home Assistant itself is a container, and each add-on is also a container. The Supervisor stands beside it and manages their lifecycle. This also explains why Container installations don't have stores - it does not include Supervisor, only Home Assistant is running in its own container.

Concept: Add-on and "Integration" are two completely different things. This is the most common confusion among beginners. This is also the reason why Home Assistant name is changed to Apps. Integration is to "connect" external devices and services into Home Assistant (e.g. Xiaomi, Google, Weather); Add-on/App is an independent program that runs "next to" Home Assistant. (such as an MQTT server). Some things require both sides: Zigbee2MQTT is an Add-on, and Mosquitto is also an Add-on, but in order for Home Assistant to see the light bulb, you have to install MQTT Integrate.

Docker in plain English: a restaurant kitchen

Docker terminology becomes easier when you compare it with a restaurant kitchen. Each technical component has a distinct role.

Docker termRestaurant metaphorWhat it means for Home Assistant
Image
Image		 A read-only recipe and ingredient kit. Every kitchen using the same version starts with the same contents. The application package downloaded from a registry. The same Mosquitto image version contains the same files on every compatible host.
Container
Container		 A meal prepared from that recipe. You can discard it and prepare another from the unchanged recipe. A running App instance. Restarting or recreating it starts another instance from the image.
Data volume
Volume		 A separate pantry. Replacing a meal does not discard what is stored in the pantry. Persistent settings and data, such as the database and Zigbee pairing records. Recreating a container does not remove a correctly mounted volume.
Port
Port		 A numbered pickup window. Two services cannot operate the same host window at the same time. Home Assistant normally uses 8123, Mosquitto uses 1883, and Node-RED has its own port. A conflicting port prevents the second service from starting.
Restart policy
Restart policy		 A rule that tells the kitchen when to reopen after it stops. The "Start on boot" and "Watchdog" switches on an App page serve a similar purpose. A Container installation uses --restart=unless-stopped, which restarts the container unless you deliberately stopped it.

For a Container installation, the Docker Compose example in the Home Assistant documentation combines these terms as follows:

services:
  homeassistant:
    container_name: homeassistant
    image: "ghcr.io/home-assistant/home-assistant:stable"
    volumes:
      - /PATH_TO_YOUR_CONFIG:/config
      - /etc/localtime:/etc/localtime:ro
      - /run/dbus:/run/dbus:ro
    restart: unless-stopped
    privileged: true
    network_mode: host
    environment:
      TZ: Etc/UTC

Compare it:image selects the container image. volumes maps a folder on your computer (left) to a path inside the container (right). restart defines the restart policy. TZ sets the time zone, which should match Chapter 2. network_mode: host gives the container direct access to the host network, so port 8123 is exposed directly on that machine.

Note: The zh-TW edition uses a local boxed-meal metaphor; this edition uses a general restaurant metaphor. HAOS users do not enter these commands because Supervisor manages the containers. The example is included so you can recognize the terms when troubleshooting.

Hands-on: install an add-on and review its controls

We'll use the File editor as an exercise because it's lightweight and low risk, and easy to use later.

  1. Open the store

    lower-left corner Settings → find Apps (called before 2026.2 Add-ons). After entering, select Install app Click the button and you will see a whole row of things that can be loaded. The button on the old version said "ADD-ON STORE".

  2. Find "File editor" and install it

    It's in the Official section. Click in and select Installation, and then wait. The first installation requires downloading the image file. It is normal for the Raspberry Pi to take three to five minutes. If the screen does not move, it does not mean that it has crashed.

  3. Don't start it in a hurry, take a look at the four switches

    After installation, several switches will appear: Start at boot (The machine will run automatically after restarting), Watchdog (It will automatically pull it up when it stops), Automatic updates (Update as soon as there is a new version), Show in sidebar (Shortcuts appear directly in the menu on the left). File editor suggestion: enable the first three, and also enable the fourth.

  4. Click "Start"

    The status will change from "Stopped" to "Running". If it changes to "Stopped" and then jumps back, it means it failed to start - then go directly to the next section to see the log.

  5. Open it from the sidebar

    There should be an additional "File editor" on the left menu. Click in and you will see /config Folder - that is the "persistent volume" mentioned in the previous section, your configuration.yaml Just inside.

  6. Test a reversible edit

    This is only a write-access test, not a configuration change. Edit one word, save the file, and restore the original text. You now know that the editor can save changes when you need it later.

Danger: File editor can modify files in ways that prevent Home Assistant from starting. Before editing configuration.yaml, make sure the backup process from Chapter 9 works. A configuration mistake is recoverable only when you have a usable backup.

Troubleshooting by looking at log files: three keywords are enough

The log (Log) can look dense, but you don't need to understand it all. Use three things you have to do:

  1. Start at the bottom

    Logs run chronologically from top to bottom, so the newest entries are at the bottom. The final five to ten lines often explain a startup failure. Begin there before reading earlier startup messages.

  2. Find error markers

    Look for ERROR, FATAL, Traceback, Permission denied, Address already in use, and No such file or directory. Inspect the surrounding lines when one appears. You can usually review WARNING entries after resolving errors.

  3. Search for the exact message

    Search for the exact message together with the add-on name, such as “zigbee2mqtt Address already in use.” Do not paraphrase the error; an exact search is more likely to find a relevant solution.

  4. Capture a clean startup

    Stop the Add-on, refresh the log page, click Start, and stare at it. What you see in this way is a "clean start", which is much faster than digging through thousands of lines of old messages.

Use this quick reference for common messages:

Log messagePlain-English meaningHow to fix it
Address already in useSomeone is already using this portGo to the "Network" tab and change the port
Permission deniedIt does not have permission to touch a file or deviceMost likely the USB device path is set incorrectly, or the folder filled in in the settings does not exist.
Connection refusedThe object it wants to connect to doesn't have the door open.Another Add-on it depends on (commonly MQTT) is not started
No such file or directoryThe file/device you specified cannot be foundCheck whether there are any typos in the path entered in the settings.
No space left on deviceStorage is fullLook at the last item of "Common Obstacles" in this chapter
Concept: The log of the Add-on and the log of the Home Assistant Core are separate. The add-on is in the "Log" tab of its own page; the Home Assistant's is in the "Logs" tab of its own page; Settings → System → Logs. If you look in the wrong place, you won't see anything.

Adding a third-party repository: What to do if it is not available in the store

Use dozens of official store presets. For example, Node-RED, Studio Code Server, Zigbee2MQTT, etc., you must first add their "Repository" before the store will have a whole row of new things.

  1. Copy repository URL

    Two commonly used ones: community Add-on collection is https://github.com/hassio-addons/repository, Zigbee2MQTT official is https://github.com/zigbee2mqtt/hassio-zigbee2mqtt.

  2. Enter the Add-on store

    Settings → Apps, then select Install app Go into the store.

  3. Open "Repositories" in the three-dot menu in the upper-right corner

    Home Assistant documentation makes it clear: on the store page The three-dot menu in the upper-right corner choose Repositories. The old version may show "repository" in Chinese, which is the same thing.

  4. Paste the URL, click Add, and then refresh

    After adding stores, there will be several more areas. If you can't find something new, press Ctrl + F5 Force a refresh. If the reorganization still doesn't show up, go to Settings → System → Logs, switch to the upper-right corner of Supervisor, the URL will be written there, is it a typo?

Danger: Adding a repository means "I trust this author and am willing to let his program run in my home." An add-on is a container with considerable permissions, and things of unknown origin can look into your configuration files. Only add repositories that you can find, are used by many people, and have been updated recently. The ones listed above are all large-scale projects recognized by the community.
Concept: The repository (used for Add-on) and HACS (used for custom integration and dashboard cards) are two different things, so don't confuse them. Appendix A There is a contrast between the two.

Automatically upload backups to the cloud: Let backups leave this machine

How to create a backup, how to set up the schedule, how many copies to keep, why not just save the local machine, Chapter 9 I’ve already talked about it, so the details are not repeated here.

This section only makes up for one feature that was not covered in detail in Chapter 9 and is just relevant to this chapter: Sending backups to the cloud is now completely built-in and does not require any Add-ons. In the past, this was the domain of third-party Add-ons. Now, the "Location" on the backup page can check several places at the same time, and each backup will be automatically sent to each place. Here’s where the differences vary from destination to destination — especially the restrictions that bite:

Configure a remote backup destination in three steps:

  1. Configure the destination

    With a Nabu Casa subscription you do not have to do anything, it is already there. If not, go to Settings → Devices & services → Add integration, install Google Drive or OneDrive, follow the screen to authorize the account. To use a home NAS, take another route: Settings → System → Storage Add a network storage and mark it for backup.

  2. Enable the destination for backups

    Settings → System → Backups, in the "Locations" of the automatic backup settings, open the destination you just connected. Schedule and retain copies of photos Chapter 9 Just set it up. local machine /backup Remember to keep it too: When restoring, the local machine is much faster. The remote copy is available if the entire host fails.

  3. Run and verify a manual backup

    Do not skip verification. An unverified backup is not a reliable backup. Open Google Drive or OneDrive and confirm that the file exists. If a Home Assistant Cloud upload exceeds the 5GB limit, return to backup settings and exclude the media folder, which is often the largest part.

Tip: There is also an "Automatically back up before updating" option in the backup settings, which is highly recommended. It just sets a default value, and you can still change it temporarily every time before you really want to update it. This is the quickest way back after an update fails, and the chance of an add-on update failing is higher than you think.
Warning: Many old tutorials on the Internet will ask you to install the third-party Add-on "Home Assistant Google Drive backup". It was an artifact before built-in cloud backup came out, but now it is great for beginners Built-in Google Drive integration is a better place to start:Officially maintained, no need to run an extra container. Third-party Add-ons still have their advantages (such as day/week/month/year generation retention policies), but if you just want "the backup doesn't die on the local machine", the built-in one is enough. In the same way, the need to dump backups to Samba network disks can now be achieved using the built-in "Network Storage" without having to install Samba backup.
Danger: backups are encrypted, Be sure to have the encryption key when restoring. The first time you set up automatic backup, the screen will ask you to download a copy. backup emergency kit—That's a file that contains your encryption key. Save it now outside of Home Assistant (Password manager, cloud drive, printing it out and putting it in a folder will all work). Home Assistant documentation is very clear: without the key, there is no way to restore the encrypted backup. Lost the key = the backup in the cloud is just unusable encrypted data that cannot be opened. I want to take it again later and go back to Settings → System → Backups The backup settings page can re-download the current set of keys.

Resource use on lower-end hardware

Each add-on is a running program that consumes CPU, memory, and storage. A Raspberry Pi 4 with 2GB of memory or an older mini PC can slow down when several add-ons run: pages respond slowly, automations are delayed, and updates may fail. Home Assistant does not publish fixed resource requirements for every add-on. The table below is a relative guide, not a measured capacity claim.

Add-on typeResource useAdvice on low-end hardware
File editor, Samba, Terminal & SSHVery low, barely noticeableSuitable
Mosquitto brokerlowUsually suitable
Zigbee2MQTTModerate; runs continuouslySuitable, but avoid combining it with several resource-intensive add-ons.
Node-REDMedium to high, memory usage is relatively heavyConsider using memory below 2GB. For simple automation, just use the built-in one
Studio Code ServerHigh, especially obvious when the page is openUse File editor instead on low-end machines
Database (MariaDB), Grafana, InfluxDB and the likeVery high, and can perform frequent storage writesRaspberry Pi + SD card is not recommended. SD cards being overwritten is a real thing.
Speech related (Whisper, Piper, etc.)Very high, especially CPUIt requires relatively capable hardware, and the Raspberry Pi will be too slow to use.

A few practical principles:

  • Remove what you don't need, don't just disable it. Disabled Add-ons still take up storage drive space.
  • Only install new items one at a time. After installing it, observe for a day or two before installing the next one. Only when something goes wrong will you know who caused it.
  • Please use SSD or USB to boot the Raspberry Pi, do not use SD card. The easiest reason why the SD card is damaged is that it is written too many times, and the add-on for the database class is specifically designed to do this.
  • First see if the built-in function can solve the problem. Many people install Node-RED just to do a "turn on the lights at sunset", which can be done with three lines of built-in automation (see Chapter 8).
Tip: If you want to know how crowded it is now, go to Settings → System → Storage Look at the storage drive; if you want to see system information such as version and installation method, go to Settings → System → Repairs The three-dot menu in the upper-right corner System information.If you find that the storage drive is used more than 80%, it is time to clean things up.

Troubleshooting

  1. Add-on store not found

    First confirm which installation method you have: Settings → System → Repairs, click on the upper-right corner Three-dot menu → System information (System information), it will say whether your computer is an OS or a Container. If it's a Container or Core, that's that installation type has no add-on store, you cannot find it no matter how you look for it. The only solution is to reinstall using HAOS (remember to back up first and then restore from the backup). If you are HAOS and can't find a specific Add-on, such as Terminal & SSH, it's probably Advanced mode is not enabled —Click your name in the lower-left corner to enter the profile page and turn on "Advanced Mode".

  2. Add-on cannot be installed, stuck during installation or fails directly.

    90% yes Failed to download image file. Check in order: (1) The network is unavailable. Can Home Assistant access the internet? (2) Is there still space on the storage drive? See Settings → System → Storage; (3) Is there a corresponding version for your CPU architecture? The unpopular Add-on often only provides amd64, which cannot be installed on the Raspberry Pi. In this case, it will say that the image file cannot be found. Try again first. If you fail the first time, sometimes you just get half disconnected.

  3. Port conflict: The second Add-on cannot be started.

    A log will appear Address already in use or port is already allocated. Go to that Add-on Network tab, change the right cell to a number that no one uses (for example, the original 1880 is changed to 1881), save and restart. After the change is completed, you will also need to change its website address to the new number. If you don't need to connect it from the outside at all, just go directly to the right Leave blank, the conflict disappears instantly.

  4. Will not start after updating

    Start with the final lines of the log. An add-on may state that its configuration format changed and identify the option you must update. If the required change is unclear, the fastest recovery is to restore the pre-update backup from Chapter 9. This is why you should enable backup before updating. Also check Settings → System → Repairs, where major changes may create a repair notice.

  5. Not enough disk space

    Symptoms are various strange failures, and the log contains No space left on device. Cleanup sequence: (1) Delete old backups, which are usually the largest; (2) Remove (not deactivate) unused Add-ons; (3) Check media and share Are there any accumulated video files in the folder? (4) If the database is too large, adjust the Recorder retention days. If it is still full after completing the first three items, it is time to consider changing to a larger storage device.

  6. Add-on keeps restarting

    The status jumps between "Running" and "Stopped", usually Watchdog Repeatedly pulling up a program that was already broken. first Turn off the watchdog, let it stop quietly in the failed state, so that you can see the complete error message. Open it again after repairing it.

  7. Zigbee2MQTT cannot find the USB adapter

    The log commonly shows No such file or directory. Go to Settings → System → Hardware, then select Three-dot menu → All Hardware. Find the connected adapter and copy its path into the Zigbee2MQTT settings. Do not copy a path from an online tutorial; every host is different. Prefer the stable long path beginning with /dev/serial/by-id/ instead of a short path such as /dev/ttyUSB0. A short path can change after devices are reconnected or the host restarts, while the by-id path identifies the adapter itself.

FAQ

Is Add-on now called Add-on or App?
Starting from version 2026.2, Home Assistant name will be Apps, the menu also changes to "Settings → Apps". The underlying technology (Docker container, Supervisor) has not changed, it is just a name change to prevent beginners from confusing it with "Integration". Most of the online tutorials still write Add-on. Treat the two words as the same thing. If your version is older than 2026.2, Add-ons will continue to appear on the screen.
I run Docker on Synology NAS to run Home Assistant. Can I find a way to install the Add-on store?
No, you shouldn’t try. The add-on store requires the Supervisor, but the Container installation does not have it. In the past, there was a method called Supervised that could be forced out, but Home Assistant Support has been discontinued in version 2025.12. The correct approach is: you need Mosquitto and Node-RED, just put them on your NAS Open another Docker container Come and run, the functions are exactly the same, you just need to write the compose file yourself and update it yourself. If you really want the comfort of one-click, just open a VM or find a small host to install HAOS.
Will updating the Add-on lose my settings?
Normally not. Settings and data are stored in a volume, while an update replaces the image. The two are separate. but update It is possible to change the format of the setting, causing the old settings to no longer be valid and the startup to fail. So the rules are: Important add-ons Do not turn on automatic updates, confirm that the backup has been run before updating, and take a look at the log after updating. Lightweight and harmless ones (File editor, Samba) have no problem turning on automatic updates.
The backup has been uploaded to Google Drive. Do I still want to keep the local copy?
Yes. The copies serve different purposes: a local copy provides a fast recovery from a configuration mistake, while a remote copy remains available if the host fails. Select multiple backup locations rather than choosing only one. Set an appropriate retention policy so local backups do not fill the storage drive.
Does Zigbee2MQTT have to install Mosquitto first? Can I just install Zigbee2MQTT?
The job of Zigbee2MQTT is to "translate Zigbee signals into MQTT messages". It requires an MQTT server to receive these messages, so there must be a broker. The first step in Home Assistant installation instructions is to ask you to install Mosquitto first. The order is: Mosquitto → Create a user for MQTT → Set up MQTT integration → Add Zigbee2MQTT repository → Install Zigbee2MQTT → Fill in the broker address and password. If you skip the steps, the Zigbee2MQTT log will be full of Connection refused.
If the port in the "Network" tab is left blank, will it cause the Add-on to become unusable?
No. A blank field means that the port is not published on the host. The add-on still runs, and Home Assistant can connect to it internally. For example, if only Home Assistant and other add-ons use Mosquitto, leaving the field blank is safer because other local-network devices cannot reach that port. Publish a port only when another computer or program must connect directly.
Should I install File editor or Studio Code Server?
Both edit configuration files in a browser. File editor is an official, lightweight option for occasional small changes and runs well on a Raspberry Pi. Studio Code Server provides a fuller VS Code environment with entity-name completion and live YAML checks, but uses more resources and loads more slowly. Start with File editor; consider Studio Code Server when you edit longer YAML frequently. Keep File editor on lower-end hardware.
