Chapter 20

Add-on and Docker architecture

The Add-on you click "Install" in the store is actually a Docker container. This chapter explains the terms Supervisor, image file, data volume, and port in a convenient way, walks you through installing several necessary Add-ons, sets up backups to automatically upload to the cloud, and learns to look at the log files to troubleshoot on your own.

Why do we need to understand the layer underneath Add-on?

you are hereAppendix AAlready know where the Add-on store is and how to install it. That one is about "knowing how to use it", and this chapter is about "knowing why it breaks".

What's the difference? Here are a few situations that actually happen:

  • You installed Home Assistant on your laptop, but you can’t find the Add-on store in the menu on the left - it’s not that you’re handicapped, it’sWrong installation method.
  • You installed Zigbee2MQTT, but it never starts, and the page only says "stopped". You don't know where to look to see what it's complaining about.
  • If you install Node-RED and another web tool at the same time, the second one will not work - both are trying to grab the same house number.
  • You reinstalled the entire machine, only to find that the backups were all stored in the dead machine.

The solutions to these four things are all hidden in the same layer of knowledge: Add-on is a container, and the container has an image file, a data volume, a connection port, and a record file. After reading this chapter, if you encounter any of the above situations, you will know where to click as the first step.

Warning:Starting from Home Assistant version 2026.2, the official name of “Add-on (add-on)” is “Apps", the menu also changes from "Settings → Add-ons" to "Settings → Apps”. Technically, it hasn't changed at all, it's just a name that's easier to understand. The two words in this chapter will be used interchangeably, referring to the same thing; whichever one appears on your screen will be based on your version.

Four installation methods, and their relationship with "whether there is an Add-on store"

This is the biggest pitfall for newbies:Not every Home Assistant has an Add-on store.Whether or not there is a store is determined the moment you decide how to install it, and you cannot open it later by setting it.

Home Assistant Container On your own Linux/NAS/Synology, use Docker to run a Home Assistant container. No No (you need to pull the new image file and rebuild the container yourself) Official support
Home Assistant Supervised I manually installed Supervisor on my Debian to create an environment close to HAOS. Yes Yes Obsolete, officially stopped supporting since 2025.12

Also eliminated are 32-bit architectures such as i386, armhf, and armv7. The old machine technically still runs and can be updated, but there is no official support if something goes wrong.Currently, only HAOS and Container are officially supported.

The essence of Add-on: a Docker container managed by Supervisor

The official development document is very straightforward:The bottom layer of Apps (also known as Add-on) is the container image file published to the container registry., sources such as GitHub Container Registry or Docker Hub.

In other words, when you press "Install" in the store, what happens is:

  1. Supervisor goes to the Internet to grab the image file

    It looks at the Add-on configuration file and knows which URL to go to, which version to grab, and which one corresponds to your CPU architecture (arm64 or amd64). This step takes the most time and is also the most likely to fail due to network failure.

  2. Supervisor opens a container using that image file

    By the way, according to the settings of the Add-on, decide which ports to open, which folders to attach to it, and whether to give it a USB device.

  3. Supervisor helps you connect the setting interface to Home Assistant

    That's why you will see the Add-on's "Settings" tab and "Log Files" tab in the Home Assistant web page, without having to type the Docker command yourself.

  4. Supervisor keeps watching it

    It is responsible for starting, stopping, updating, watchdog (Watchdog) restart, and automatic startup at boot. These are the switches you see on the Add-on page.

So Supervisor is the "housekeeper". The Home Assistant itself is a container, and each Add-on is also a container. The Supervisor stands beside it and manages everyone's life and death. This also explains why Container installations don't have stores - it has no steward at all, only Home Assistant is running in its own container.

Concept:Add-on and "Integration" are two completely different things. This is the most common confusion among novices. This is also the reason why the official name is changed to Apps.Integration is to "connect" external devices and services into Home Assistant(e.g. Xiaomi, Google, Weather);Add-on/App is an independent program that runs "next to" Home Assistant.(such as an MQTT server). Some things require both sides: Zigbee2MQTT is an Add-on, and Mosquitto is also an Add-on, but in order for Home Assistant to see the light bulb, you have to install MQTT Integrate.

The term Docker sounds hard, but in fact each one corresponds to daily life. We think of it like a chain bento shop.

    container_name: homeassistant
    image: "ghcr.io/home-assistant/home-assistant:stable"

Note: This English edition generalizes the zh-TW edition’s Taiwan-specific example. Check the services, regulations, frequencies, prices, and availability in your region. HAOS users do not need to enter the above commands at all, Supervisor does it for you. I put this paragraph so that you can "understand" it and won't be scared when you look up information on the Internet in the future.

Hands-on: Install an Add-on and understand each switch

We'll use the File editor as an exercise because it's light, harmless, and easy to use later.

  1. open store

    lower left cornerSettings → find Apps(called before 2026.2 Add-ons). After entering, pressInstall appClick the button and you will see a whole row of things that can be loaded. The button on the old version said "ADD-ON STORE".

  2. Find "File editor" and install it

    It's in the Official section. Click in and pressInstallation, and then wait. The first installation requires downloading the image file. It is normal for the Raspberry Pi to take three to five minutes. If the screen does not move, it does not mean that it has crashed.

  3. Don't start it in a hurry, take a look at the four switches

    After installation, several switches will appear:Start at boot(The machine will run automatically after restarting),watchdog watchdog(It will automatically pull it up when it hangs up),Automatic updates(Update as soon as there is a new version),Show in sidebar(Shortcuts appear directly in the menu on the left). File editor suggestion: enable the first three, and also enable the fourth.

  4. Click "Start"

    The status will change from "Stopped" to "Executing". If it changes to "Stopped" and then jumps back, it means it failed to start - then jump directly to the next section to see the log file.

  5. Open it from the sidebar

    There should be an additional "File editor" on the left menu. Click in and you will see /config Folder - that is the "fresher box" mentioned in the previous section, your configuration.yaml Just inside.

  6. Try changing one word and then change it back

    It's not asking you to change the settings, it's asking you to confirm "I can really write". After changing the archive, change it back to the original. Once you've done this step, you won't be afraid when you really need to edit a profile in the future.

Danger:The file editor can directly change files that will prevent Home Assistant from opening. move configuration.yaml Before, make sure youChapter 9The backup taught is running. It’s not scary if it’s changed, but it’s scary if it can’t be restored.

Troubleshooting by looking at log files: three keywords are enough

The log file (Log) looks like gibberish, but you don't need to understand it all. There are only three things you have to do:

  1. Looking up from the bottom

    The log files are arranged by time from top to bottom.The latest is at the bottom. The reason why it hangs is usually in the last five to ten lines. The hundreds of lines of boot messages above can be ignored.

  2. Find these words

    ERROR, FATAL, Traceback, Permission denied, Address already in use, No such file or directory. See one of them, and that line before and after is the answer.WARNING It can usually be ignored at first.

  3. Search for that line of original text

    Search together with the Add-on name, such as "zigbee2mqtt Address already in use".Don't describe it in your own words, directly copy that line of English, and the chance of finding the answer is ten times higher.

  4. I still have no clue so I’ll watch it again.

    Stop the Add-on, refresh the log file page, click Start, and stare at it. What you see in this way is a "clean start", which is much faster than digging through thousands of lines of old messages.

Compare the Chinese meanings of common messages:

log messagevernacular translationhow to fix
Address already in useSomeone is already using this number windowGo to the "Network" tab and change the port
Permission deniedIt does not have permission to touch a file or deviceMost likely the USB device path is set incorrectly, or the folder filled in in the settings does not exist.
Connection refusedThe object it wants to connect to doesn't have the door open.Another Add-on it depends on (commonly MQTT) is not started
No such file or directoryThe file/device you specified cannot be foundCheck whether there are any typos in the path entered in the settings.
No space left on devicehard drive fullLook at the last item of "Common Obstacles" in this chapter
Concept:The log file of the Add-on and the log file of the Home Assistant body areseparate. The Add-on is in the "Log" tab of its own page; the Home Assistant's is in the "Logs" tab of its own page;Settings → System → Log files. If you look in the wrong place, you won't see anything.

Resource usage: How to choose low-end hardware

Each Add-on is a real running program that consumes CPU, memory, and hard disk. The 2GB version of the Raspberry Pi 4, or an older mini console, will start to freeze as soon as it is installed - web pages will slow down, automation will be delayed, and updates will fail. The official has not announced how many resources each Add-on consumes. The table below is a relative grading, not an actual measured number. It is used for prioritization.

Add-on typeresource consumptionAdvice on low-end hardware
File editor, Samba, Terminal & SSHVery low, barely noticeableFeel free to install
Mosquitto brokerlowDon’t worry, it saves money
Zigbee2MQTT, will continue to runIt’s worth installing, but don’t squeeze it with a bunch of heavy things.
Node-REDMedium to high, memory usage is relatively heavyConsider using memory below 2GB. For simple automation, just use the built-in one
Studio Code ServerHigh, especially obvious when the web page is openUse File editor instead on low-end machines
Database (MariaDB), Grafana, InfluxDB and the likeVery high, and can write hard disks like crazyRaspberry Pi + SD card is not recommended. SD cards being overwritten is a real thing.
Speech related (Whisper, Piper, etc.)Very high, especially CPUIt requires relatively capable hardware, and the Raspberry Pi will be too slow to use.

A few practical principles:

  • Remove what you don't need, don't just disable it.Disabled Add-ons still take up hard drive space.
  • Only install new items one at a time.After pretending, observe for a day or two before pretending to be the next one. Only when something goes wrong will you know who caused it.
  • Please use SSD or USB to boot the Raspberry Pi, do not use SD card.The easiest reason why the SD card is damaged is that it is written too many times, and the Add-on of the database class is specifically designed to do this.
  • Let’s first see if the built-in function can solve the problem.Many people install Node-RED just to do a "turn on the lights at sunset", which can be done with three lines of built-in automation (seeChapter 8).
Tip:If you want to know how crowded it is now, goSettings → System → StorageLook at the hard disk; if you want to see system information such as version and installation method, go toSettings → System → RepairThe three-dot menu in the upper right cornerSystem information.If you find that the hard drive is used more than 80%, it’s time to clean things up.

Common stuck levels

  1. Add-on store not found

    First confirm which installation method you have:Settings → System → Repairs, click on the upper right cornerThree-dot menu → System information (System information), it will say whether your computer is an OS or a Container. If it's a Container or Core, that'sThere are no shops in the structure, you can’t find it no matter how you look for it. The only solution is to reinstall using HAOS (remember to back up first and then restore from the backup). If you are HAOS and can't find a specific Add-on, such as Terminal & SSH, it's probablyAdvanced mode is not enabled —Click your name in the lower left corner to enter the profile page and turn on "Advanced Mode".

  2. Add-on cannot be installed, stuck during installation or fails directly.

    90% yesFailed to download image file. Check in order: (1) The network is unavailable. Can Home Assistant access the external network? (2) Is there still space on the hard drive? SeeSettings → System → Storage; (3) Is there a corresponding version for your CPU architecture? The unpopular Add-on often only provides amd64, which cannot be installed on the Raspberry Pi. In this case, it will directly say that the image file cannot be found. Try again first. If you fail the first time, sometimes you just get half disconnected.

  3. Port conflict: The second Add-on cannot be started.

    A log file will appear Address already in use or port is already allocated. Go to that Add-onInternetPaging, change the right cell to a number that no one uses (for example, the original 1880 is changed to 1881), save and restart. After the change is completed, you will also need to change its website address to the new number. If you don't need to connect it from the outside at all, just go directly to the rightLeave blank, the conflict disappears instantly.

  4. Can’t get up after updating

    Let’s first look at the last few lines of the log file. The author often directly writes “The setting format of this version has been changed. Please change the so-and-so option to so-and-so.” If you don’t understand, the fastest way isRestore from pre-update backup(Chapter 9) - This is why the "backup before updating" switch needs to be turned on. Go elsewhereSettings → System → RepairsSee, major changes often leave a note card there.

  5. Not enough disk space

    Symptoms are various strange failures, and the log file contains No space left on device. Cleanup sequence: (1) Delete old backups, which are usually the fattest; (2) Remove (not deactivate) unused Add-ons; (3) Check media and share Are there any accumulated video files in the folder? (4) If the database is too large, adjust the Recorder retention days. If it’s still full after completing the first three items, it’s time to consider changing to a larger storage device.

  6. Add-on keeps restarting

    The status jumps between "Executing" and "Stopped", usuallyWatchdogRepeatedly pulling up a program that was already broken. firstTurn off the watchdog, let it stop quietly in the failed state, so that you can see the complete error message. Open it again after repairing it.

  7. Zigbee2MQTT cannot find USB stick

    Log files are usually No such file or directory. goSettings → System → Hardware, click on the upper right cornerThree-dot menu → All Hardware, the currently connected devices and their paths will be listed. Find the path of the stick and copy it back to the Zigbee2MQTT settings.Don’t copy the path of online teaching, each machine is different. In addition, official recommendationspriority /dev/serial/by-id/ The long path at the beginning, do not use /dev/ttyUSB0 This short - the short path will change with the plug-in sequence and reboot, the long path is tied to the device itself and will not escape no matter which hole it is plugged into.

FAQ

Is Add-on now called Add-on or App?
Starting from version 2026.2, the official name will be Apps, the menu also changes to "Settings → Apps". The underlying technology (Docker container, Supervisor) has not changed a word, it is just a name change to prevent novices from confusing it with "Integration". Most of the teachings on the Internet still write Add-on. Just think of the two words as the same thing. If your version is older than 2026.2, Add-ons will continue to appear on the screen.
I use Docker on Synology NAS to run Home Assistant. Can I find a way to install the Add-on store?
No, you shouldn’t try. The Add-on store requires the Supervisor, but the Container installation does not have it. In the past, there was a method called Supervised that could be forced out, but the officialSupport has been discontinued in version 2025.12. The correct approach is: you need Mosquitto and Node-RED, just put them on your NASOpen another Docker containerCome and run, the functions are exactly the same, you just need to write the compose file yourself and update it yourself. If you really want the comfort of one-click, just open a VM or find a small host to install HAOS.
Will updating the Add-on lose my settings?
Normally not. The settings and data are stored in the "Volume", and what is updated is the "image file". The two are separate - just like changing the cooking bag will not touch your crisper. but updateIt is possible to change the format of the setting, causing the old settings to no longer be valid and the startup to fail. So the rules are:Important Add-on Do not turn on automatic updates, confirm that the backup has been run before updating, and take a look at the log file after updating. Lightweight and harmless ones (File editor, Samba) have no problem turning on automatic updates.
The backup has been uploaded to Google Drive. Do I still want to keep the local copy?
Want. The uses of the two copies are different:The copy of this machine is for "my handicap changed the settings", restore quickly;The cloud portion is for "the whole machine dies". You can check multiple backup locations at the same time, and send backup to multiple locations at one time. There is no need to choose one or the other. What really should be noted isKeep copiesIt must be set properly, otherwise the local hard drive will be filled sooner or later.
Does Zigbee2MQTT have to install Mosquitto first? Can I just install Zigbee2MQTT?
The job of Zigbee2MQTT is to "translate Zigbee signals into MQTT messages". It requires an MQTT server to receive these messages, so there must be a broker. The first step in the official installation instructions is to ask you to install Mosquitto first. The order is:Mosquitto → Create a user for MQTT → Set up MQTT integration → Add Zigbee2MQTT repository → Install Zigbee2MQTT → Fill in the broker address and password. If you skip the steps, the Zigbee2MQTT record file will be full of Connection refused.
If the port in the "Network" tab is left blank, will it cause the Add-on to become unusable?
No. Leaving it blank means "Don't open this external window on my machine." Add-on itself will still run, and Home Assistant can still connect to it internally. Taking Mosquitto as an example, if only Home Assistant and a few Add-ons will use it, leaving it blank willsafer —Other devices on the home network cannot touch it. You only need to fill in the number when you need to connect directly from another computer or other program. This is the simplest and most effective information security habit.
Should I install File editor or Studio Code Server?
Both of them change the configuration file in the browser.File editor It's official, light, and fast. It's enough to occasionally change a few lines, and the Raspberry Pi can also run it.Studio Code Server It is a complete VS Code for the community. It will automatically fill in entity names and catch YAML syntax errors in real time. It is much less efficient when writing a large number of settings, at the cost of significantly heavier resources and slower loading. Recommendation: Beginners install File editor first, and then switch to Studio Code Server when you find yourself opening it several times a day and starting to write longer YAML. For low-end hardware, don’t consider the latter.
