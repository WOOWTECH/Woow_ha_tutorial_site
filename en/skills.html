Install a skill to teach your AI agent about Home Assistant

A skill is an operating manual for an AI agent: a folder containing SKILL.md and optional references. This handbook surveys 10 Home Assistant-related skills and 6 catalogs, then covers installation, compatibility, authoring, and safety.

Survey baseline: The collection size, number of stars and maintenance status of this volume are: 2026-08-20 GitHub public snapshot, will change over time; it is recommended to click on the original repo to confirm again before installation.

What is Skill and why should it be installed?

Think of AI agents such as Claude/Codex/Gemini/OpenClaw/Hermes as very smart interns: any home system can talk, but it will definitely not be able to understand "your HA's entity naming, area planning, existing blueprint, and Zigbee topology." Skill is Handover file thrown to AI—Write "What scenario should you encounter HA, what steps should you follow?" in Markdown, and put it in the skill folder. When the AI encounters it, it will translate it and follow it.

  • Pretending to be written by someone else: HA management, ESPHome firmware, Dashboard design, Blueprint import, custom integration development - the community has already written a lot.
  • Then write your own: Unique processes at home (washing machine reminders, weekly energy reports) can also be packaged as skills. See this handbooklet for how to write them. SKILL.md Specifications One section.

Skill follows Assist voice assistant, Integration, Blueprint is something completely different - it is added to Which side of the AI agent do you use?, not on the HA side. HA You may not move a line.

How to install (3-minute version)

SKILL.md This specification is sponsored by Anthropic (anthropics/skills), has been adopted by mainstream agent harnesses such as Claude Code, Codex, Gemini CLI, Cursor, OpenCode, OpenClaw, and Hermes. The installation method varies slightly depending on the harness. The common steps are:

  1. Open the Skills/Plugins panel of your agent harness

    Claude Code: Settings → Skills; OpenClaw / Hermes: Skills panel; Codex:~/.codex/skills/ Directory.

  2. Paste the package spec and press Install

    Each harness supports slightly different writing methods, the most common ones are:

    # GitHub repository (most common)
git:github.com/komal-SkyNET/claude-skill-homeassistant

# Pin a version (tag or commit; recommended in production)
git:github.com/anthropics/skills@v1.0.0

# npm package
npm:@scope/some-skill

# Local path (your own skill or a subdirectory cloned from a monorepo)
~/skills/my-ha-skill

  3. Reload session verification

    After installation, open a new session (skill is loaded at the beginning of the session) and ask it: "What skills are currently loaded?" Make sure it is in the list.

  4. Read first, then use: Ask AI what this skill will do

    Don’t rush to let it run after installing it. First ask the AI to read the summary of SKILL.md to you - this is also safety rules The first article.

Tip: Monorepo (e.g. anthropics/skills, tonylofgren/aurora-smart-home) is included in the entire package, and most harnesses recursively scan all SKILL.md. When you only want one of them, clone it and use the local path to point to that subfolder - currently git spec does not have a standard "only install subdirectory" syntax.

Compatibility information

The SKILL.md specification has been adopted by mainstream agent harnesses such as Claude Code, Codex, Gemini CLI, Cursor, OpenCode, OpenClaw, and Hermes; pure Markdown skills can run almost everywhere. There are only three situations that will "degenerate":

  • Rely on Claude Code exclusive mechanism (hooks, plugin commands, subagent dispatch) - skill This article is still readable, but the automatic triggering behavior may be incomplete.
  • Rely on specific MCP/SaaS account—For example, HA-related skills are mostly assumed to be equipped properly. ha-mcp-woow Or official MCP Server integration; if not connected, it is useless.
  • scripts/ Requires a runtime that is not available in the container—If you run the agent in the HA add-on container, the Python package and Node version must match. Pure Markdown skill has the best compatibility.
Concept: The first criterion for choosing a skill is not the number of stars, but "do you have the environment it assumes?" Especially important for HA related skills - most assume you already have HA + MCP + corresponding integration.

Safety rules

Warning: The essence of Skill is "instructions fed to the agent". Install third-party skill=Let a strange text instruct your AI to move your HA.
  • Read first and install later: Open SKILL.md and read it before installation, or ask AI to read it to you first: "Read the content of SKILL.md of this skill first, tell me what it will do, and whether there is any risk of touching my HA config. I agree to install it again."
  • If you know how to move HA config, make a complete backup first.: like claude-skill-homeassistant, aurora-smart-home This type will directly change automation/dashboard/configuration.yaml. First press Settings → backups to perform manual backup—If you mess up, you can still recover.
  • First test the HA instance verification: If the HA at home is already very complex, it is strongly recommended to open another clean HA container as a test machine, and then put it into Home Assistant machine after verifying the skill action.
  • Formal environment nail version: use @tag or @commit Pin it to avoid upstream changes and you won’t feel the need to upgrade.
  • Entities exposed to AI should be selected: Settings → Voice Assistants → Expose Check only the necessary areas/entities. Don't give it to door locks, alarms, and power switches that "cannot be restored".
  • Number of stars = popularity, not = safety: Popular collections also depend on what permissions they have and what they do - especially if there are scripts/ skill.

SKILL.md Quick Specs

The minimum skeleton of a skill (for detailed specifications, see anthropics/skills): 

washer-notify/
├── SKILL.md          ← The only required file
└── references/       ← Optional supporting files (read by the AI only when needed)
    └── ha-service-map.md

# SKILL.md content
---
name: washer-notify
description: |
  Use this skill when the user asks whether the washing machine has finished,
  whether it is time to collect the laundry, or requests an automated laundry
  reminder. Read sensor.washer_power through the HA API to determine whether
  the machine is running, idle, or finished.
license: MIT
compatibility:
  agents: [claude-code, opencode, openclaw, hermes]
  mcp: [ha-mcp-woow, home-assistant/mcp-server]
allowed-tools: [ha_get_state, ha_get_history, notify_send]
---

# Laundry reminder skill

When the user mentions the washing machine, first read the past 15 minutes of
history for sensor.washer_power. If power falls from >100W to <5W and remains
there for at least 3 minutes, reply that the cycle is complete. If the machine
is still running, estimate the time remaining from an average 45-minute cycle.

If the user requests an automatic reminder, use ha_config_set_automation to create one:
trigger: sensor.washer_power < 5W for 3 minutes
action: notify.mobile_app_myphone
Show the user a YAML summary and obtain approval before applying it.
fieldRequiredDescription
nameYesLowercase numbers and hyphens, 1–64 characters.
descriptionYesWhat to do + when to use. The AI relies on this line to decide whether to load—Write in what the user would say.
licenseNoI suggest you write it and let others know if it can be changed.
compatibilityNoMark supported agents/MCPs, which is useful when sharing across harnesses.
allowed-toolsNoLimit which tools the skill can call, which is a line of security.

Convention: Keep SKILL.md simple and put attachments references/, scripts/, assets/, AI reads only when needed to avoid overloading the context. HA related skills are recommended in references/ Put a "service comparison table" and check it before the AI calls.

FAQ

Installed but no response at all?
Open a new session first (skill is loaded when the session starts). Then ask the AI "What skills are currently loaded?" to confirm that they are in the list; if they are in the list but are not triggered, it is probably description Didn’t cover what you said – just name it: “Use claude-skill-homeassistant Help me do this".
What is the difference between Skill and HA’s Blueprint, Integration, and Assist?
The location is different: Skill is added to the end of the AI agent you use (Claude Code/OpenClaw/...), and HA does not move a line. Blueprint/Integration/Assist are all added on the HA side. Skill teaches "AI how to deal with HA", and Blueprint teaches "how HA handles events on its own" - the two do not conflict and can be overlapped.
What happens if you install too many Skills?
The name and description of each skill will occupy the context of the system prompt. Installing dozens of packages will distract the AI and become expensive. Principle: Keep the commonly used ones (3-5 related to HA + official document set), and remove the ones you don’t use after the trial.
Can I install only one of the monorepo? For example, only esphome in aurora-smart-home?
git spec currently has no standard subdirectory syntax. Practical approach: Clone to the local machine and put the desired subfolder (including SKILL.md) into the skills directory of the harness (Claude Code is ~/.claude/skills/), or install using a local path.
Will skill damage my HA? How to save?
Yes, especially if ha_config_set_* Permission skill. So the 2nd safety rule says "make a full backup first" - if you mess up, go back to Settings → backups → Restore. If there is no backup or Home Assistant machine has been modified, see configuration.yaml git/snapshot version; HA Green/Yellow factory WoowTech models have daily automatic snapshots.
How to write a HA skill yourself?
Fastest: install skill-creator (anthropics/skills (within), call it "Help me write the "Family Weekly Report Production Process" as a skill." You can modify it as you describe it, and the prototype will be ready in 10 minutes. Or depend on SKILL.md Specifications The types in the section start by themselves.
