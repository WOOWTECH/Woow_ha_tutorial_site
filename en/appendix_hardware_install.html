Appendix C

Before installation: hardware and HAOS

The main guide assumes that Home Assistant is already running. If it is not, start here: choose a host and storage, flash Home Assistant OS, boot it, and create the first account. Then continue with Chapter 1.

Why do you need your own host?

Before following the rest of the guide, you need to answer a practical question: Where will Home Assistant run?

Home Assistant is not a mobile app, nor is it a website account. it is a set that runs on On a computer at your home The software is open 24 hours a day, connected to your home router, and talks to your home lights and sensors. All the data stays at your home, which is why many people choose it, but the price is: you have to have that "computer" first.

The host can be a Raspberry Pi, official Home Assistant hardware, a used mini PC, or a virtual machine on a home NAS. This appendix compares those options and walks through installation.

Concept: This host is usually called "Host" or "Instance" in the Home Assistant world. It is the brain of your home automation. If the power is cut off, the whole system will shut down - so be sure to read the following paragraphs on power adapter and backup.

After reading this article you will have the ability to:

  • Understand the differences between the four installation methods and know which one you should choose (spoiler: choose HAOS).
  • Depending on the size of your home and budget, choose a host you will not regret.
  • Image the system image file into the SD card or SSD yourself, plug it in and boot it up.
  • Complete the first-time setup (Onboarding), create an owner account, and set the home location.
  • Diagnose common failures: the host is not discoverable, the system will not boot, or it restarts unexpectedly.

Four installation methods: HAOS is the default for beginners

Online tutorials refer to four installation types. The practical recommendation is simple: for a first installation, choose Home Assistant Operating System (HAOS).

Home Assistant document itself currently only recommends two types: HAOS and Container. Core and Supervised will be officially announced to be deprecated (Deprecate) in May 2025. Home Assistant announcement timetable is from the 2025.6 version to the Version 2025.12 officially ends support, and the 32-bit i386/armhf/armv7 architecture was also axed. Home Assistant relocation advice is: Those who originally used Core should move to Container, and those who originally used Supervised should move to HAOS.

How to choose hardware: compare five routes

Base Home Assistant workloads are lighter than optional processing tasks. The source describes a typical installation with 30–50 devices as comfortable on a quad-core ARM system with 4GB of memory, but this is not a capacity guarantee. Optional workloads drive hardware requirements, especially camera recording and image recognition, local voice processing, and a growing history database. Plan for the features you expect to add later, not only today’s device count.

So if you see a second-hand Yellow on an auction website, you need to know its positioning: it uses Raspberry Pi Compute Module 4, has an M.2 M-Key slot to plug in an NVMe SSD (supported by 2230/2242/2260/2280), and has a built-in Silicon Labs MGM210P wireless module that also supports Zigbee 3.0, OpenThread and Matter. It replaces the discontinued ZBT-1, formerly SkyConnect, and includes a 1.5-meter USB cable for placement away from interference. It cannot run Zigbee and Thread at the same time; choose one protocol per adapter. Home Assistant documentation recommends separate adapters rather than long-term multiprotocol use.

Storage media: SD cards are the most common cause of death

This section is the most valuable part of the entire article. The most common "breakdown" of the Home Assistant host is not that the motherboard is burned, but that the SD card is damaged.

Why does the SD card fail?

The flash memory in the SD card has a limited number of times that each block can be written to. Most people use SD cards to take photos, and they can write hundreds of photos a day, and it will be fine even if it lasts five years. But Home Assistant is different:

  • The database receives frequent writes. Every change in the sensor value and every time the light is turned on and off will be written into the database by the recorder. If you have a temperature and humidity sensor at home, this is happening every minute.
  • The system log is updated continuously. Integration errors, device offline reconnection, all will be recorded.
  • It runs continuously. Multiply the amount you write in a day by 365.

The result is that many people have been using it for half a year to a year, and one morning they find that the dashboard cannot be called, the host does not respond, and restarting cannot save it - the SD card has entered a read-only state or is directly damaged. Even more annoying is that it is often Slowly getting bad: First, the dashboard becomes stuck, automation occasionally fails to trigger, and updates fail halfway. You will first suspect that it is a software problem, and then you will find out that it is stuck after going around a lot.

Danger: A damaged SD card usually means No warning, irreversible of. Your only insurance is a backup, and the backup can't just stay on the same card. Chapter 9 When talking about automatic backup and off-site storage, please set it up within the first week after installing the machine. Do not delay.

How to measure capacity? For the system itself and the database of an average family, 32GB can actually hold up, but as soon as you start leaving backups, installing a few apps, or saving some camera clips, it will soon become crowded. If you configure it yourself, you can go directly to 128GB or above. The price difference is not big and it saves you the trouble of moving in the future.

It is already installed on the SD card, is there any way to save it?

Yes. HAOS has a built-in "Move data disk" function that can move data to another connected storage device. After that, the system will boot from the original media as usual, but data reading and writing will go to the new storage drive. The path is in Settings > System > Storage, look for "Move data disk" inside.

Warning: Before moving data disk Be sure to make a full backup first and download it to your own computer. This is an operation that moves to the underlying storage, and the cost of making a mistake is to start over.

Do it yourself: Image in HAOS, plug it in and turn it on

The following takes the most common Raspberry Pi as an example. The Home Assistant documentation recommends is Raspberry Pi Imager (from raspberrypi.com/software Download), because it will download the correct image without having to find the file yourself. If you want to download the image file manually, the Home Assistant UI also accepts it. balenaEtcher Come and image.

  1. Install the imaging tool on another computer

    Arrive raspberrypi.com/software Download Raspberry Pi Imager and install it. This step needs to be done on your regular computer, not on the Pi - which is still empty.

  2. Connect the SD card or SSD to the computer

    Plug it in with a storage reader. The system may pop up a window such as "Do you want to format?" Press Cancel, the imaging tool will handle the formatting by itself.

  3. Select operating system in Imager

    Open Raspberry Pi Imager, click the operating system button, and enter in sequence Other specific-purpose OS > Home automation > Home Assistant. There will be a list of versions corresponding to different models. Choose the one that matches the machine you have (for Raspberry Pi 4, choose RPi 4 version, for Raspberry Pi 5, choose RPi 5 version). If you choose the wrong model, you can image it successfully but you will not be able to turn it on., this is the most common pitfall for beginners.

  4. Select the device to write to and then write

    Select your SD card or SSD and make sure the capacity numbers match (do not select your mobile storage drive). Press "Next" and then "Write" to start imaging. This step will Erase entire device, the imaging process takes several minutes. When finished, click "Finish" to exit the device safely.

  5. Reinstall the host, plug in the network cable, and plug in the power

    Put the burned media back into the host, Plug in the network cable first Plug it in again. Home Assistant installation process requires that there be an internet connection when booting for the first time, because the system downloads the latest components at this time. There is no need to connect the screen and keyboard at this time - if you do, multiple text will run on the screen, that's normal, don't pay attention to it.

  6. Wait a moment and then connect using your browser

    On a computer or phone connected to the same network, open homeassistant.local in a browser. Official documentation says a Pi 4 or Pi 5 will typically appear within a minute. If it does not respond, try homeassistant.local:8123; if that also fails, use the host’s IP address with :8123. A “Preparing Home Assistant” page means that the latest version is downloading. Home Assistant documentation does not promise a duration and says preparation may take some time depending on hardware and network speed. An SD card can make this stage slower. Do not disconnect power while it is running.

Concept: from 2026.8 Starting from version 1, newly installed HAOS defaults to a general URL without a port number (that is, a direct homeassistant.local That is fine, no need to add :8123). Existing installations remain intact and are not affected. So you see some writing in different tutorials :8123 Some are not written, and both may be correct. The URL on your own screen shall prevail..

If you have a mini computer or an old laptop (x86-64)

The process is different, the focus is on BIOS. Home Assistant document requires that the machine must be 64-bit capable and usable UEFI Power on. Enter BIOS (usually press F2, Del, F1 or F10, each manufacturer is different), set the boot mode to UEFI, Turn off Secure Boot, archive and leave.

The image file is haos_generic-x86-64-Version.img.xz. Home Assistant recommended method is to boot into Ubuntu with a flash drive, and then use Ubuntu's built-in "Disk" tool to restore the image to the target storage drive; another method is to use balenaEtcher on your own computer to image to the target media, and then install the media back into the machine. After installation, the same steps are to plug in the network cable, turn on the computer, and connect homeassistant.local.

If you want to install on a virtual machine or NAS

Official disk image formats corresponding to various platforms are provided:.vdi (VirtualBox), .qcow2 (KVM/Proxmox), .ova(VMware ESXi/vSphere), the documentation also covers Unraid. Home Assistant minimum configuration of virtual machine resources is 2GB memory, 2 vCPUs, if it is not enough, add more.

Warning: Home Assistant documentation of Synology and QNAP follow the Docker route, which is what is shown in the previous table. Container installation, Not HAOS, so an entire functionality of Apps will be lost. If you want to get a complete experience on the NAS, the best way is to "open a VM and run HAOS in the NAS hypervisor" instead of directly installing a Docker container. These two things are often conflated.

Onboarding for the first time: Creating your owner account

After "Preparing Home Assistant" finishes running, the screen will change to the welcome page. This section is officially called Onboarding. Just click on it in the browser. No need to type any instructions at all.

  1. Select "Build My Smart Home" or restore the backup

    Brand new candidates create new ones (Home Assistant copy is Create my smart home). If you are changing machines and have a backup file of the old machine, this is the entry point for restoration - this is why Chapter 9 Worth watching early.

  2. Fill in your name, username, and password

    Home Assistant documentation states that the account created during initial setup is the Owner. The Owner is always an Administrator and can manage the entire system, including creating users. The username must use lowercase letters and cannot contain spaces.

    Please set your password carefully, and Remember—This machine will know when your home is empty, and Home Assistant documentation clearly states: If the owner forgets his password, he has to go through the "I'm locked out" rescue procedure and put the system back into a re-onboarding state., it is not as simple as clicking “Forgot Password” and sending you a letter. Details of users and permissions are in Chapter 5.

  3. Set home location

    Mark the location to your home on the map. This step isn't just fun - Home Assistant documentation says it will set it up for you at once Time zones, unit systems and currencies, and establish a "home" zone with a preset radius of 100 meters, and then rely on it to determine automation such as "turn on the lights when someone comes home." Choose the IANA time zone for your location. After these settings, Chapter 2 It can all be changed.

  4. Decide whether to send analysis data

    This page asks you if you want to share anonymous usage statistics. Home Assistant documentation is written very honestly: Default is off, but they encourage you to turn it on, as these numbers will influence the development team's decision on which devices to prioritize support. Whether to send it or not will not affect the function, it is up to you.

  5. Press "Done" and see what it finds

    Pressing Finish will take you to the dashboard. Home Assistant will automatically scan the devices that are visible on your home network and pop up multiple "XXX found, do you want to set it up?" Do not rush to click them all now., let the host run stably for a day first.

Tip: The default homepage after 2026.2 is called Home Dashboard, there is a "For You" section that lists the newly discovered devices for you to quickly join, and there is also a "Devices" section that collects devices that have not been assigned to rooms. If the screen you see in other tutorials looks different, it may be the old version of "Overview (legacy)". How to change the dashboard to what you want, see Chapter 6.
Concept:After completing this step, you will officially be connected to the main guide of this site. Next, please go directly to Chapter 1: Login to HA, where you will be familiar with the interface, install the mobile app, and then build it all the way to automation. Network: use a wired connection for installation

You cannot say this a hundred times too many times: For your Home Assistant host, please use a wired network.

It is not that Wi-Fi cannot work, but it will make you waste a lot of time in the wrong place. Imagine this scenario: You set up an automation to "automatically turn on the lights in the living room at 7:30 pm". As a result, it will sometimes be tens of seconds late, and sometimes it will not move at all. You go through the automation settings, devices, and logs, and everything is normal - in fact, the host's Wi-Fi dropped for a few seconds at that time. This kind of problem It doesn't look like a network problem at all, so it is particularly difficult to check.

Compare itemsWiredWi-Fi
Can it be used during installation?OKNo, Home Assistant installation process requires connecting the network cable first
StabilityAlmost never breaksWill be affected by microwave oven, neighbor AP, distance
Symptoms of disconnectionIt's obvious, you can tell at a glanceIntermittent, random, extremely difficult to check
Interference to 2.4GHz devicesNoThe host's own Wi-Fi will compete with Zigbee for the 2.4GHz frequency band

Pay attention to the last column. Zigbee and Thread both run at 2.4GHz, and so does your home Wi-Fi. If the host itself uses 2.4GHz Wi-Fi, and a Zigbee radio stick is plugged in next to it, the two will interfere with each other, and your sensors will start to "occasionally lose connection." This is why many people suggest extending the Zigbee stick a little further with a USB extension cable - it's not superstitious, it really works.

Warning: After the installation is complete, Please go to your router and fix the IP address of the host. (DHCP Reserve/Static Lease, each router has a different name). Otherwise, one day the router will be restarted and the host will change its IP, and all your bookmarks saved as IP, monitor connections, and mobile app settings will have to be redone. Take five minutes to do this and save yourself a whole night in the future.

The network settings and host name of the host can be found in Settings > System > Network See and adjust. By the way,homeassistant.local This way of writing relies on mDNS (Multicast DNS), and some routers or company networks will block it - if you really can't connect, just use IP, the function is exactly the same.

Power adapter, cooling, UPS: three boring things that will save your life

Power adapter: Do not just use a phone charger

This is the classic disaster for Raspberry Pi users. Symptoms are: The host will randomly reboot when you don't touch it at all., or it becomes unstable after connecting the USB storage drive. You may think that the system is broken, the SD card is broken, or the memory is not enough, but it is actually a lack of power.

ModelOfficial power adapter specificationsWhat happens if there is insufficient power adapter?
Raspberry Pi 5Official 27W USB-C PD power adapter, 5.1V / 5AFrequency reduction, USB device power adapter limited, random reboots
Raspberry Pi 4Official USB-C power adapter, 5.1V/3A (15W)A lightning symbol appears on the screen and it restarts randomly.
Home Assistant Green12V power adapter included in the boxJust use the one attached, don't replace it yourself.
mini computerOriginal transformerSame as above

Special attention should be paid to the Pi 5: it requires a 5A USB-C PD power adapter, which is not a specification given by ordinary phone chargers. If you pick up a charger that "looks like USB-C and has enough wattage", you may still not be able to feed it, and the symptoms will be very subtle. It is really recommended to buy the original power adapter directly. This is the least worth saving in the entire system.

Danger: The greatest risk from an undersized power adapter is not the restart itself: if the system loses power during a database write, the database may be damaged. Repeated interruptions increase the risk of corruption and lost history.

Heat dissipation: will not image, but will slow down

An overheating ARM processor protects itself by reducing its clock speed. The dashboard may become unresponsive and updates may slow down. A Raspberry Pi 4 or 5 can become hot in a sealed plastic case, so use a ventilated case with a heat sink or fan. Home Assistant Green uses a passive aluminum heat sink and does not require a fan.

Placement also affects cooling. Do not bury the host behind a television, stack it on other warm equipment, or cover it with cables. Choose a ventilated, accessible location.

UPS: Insurance in case of power outage

Grid and construction-related outages can happen in any region. Your host is hard powered off while writing, which is the risk of database damage mentioned earlier. A cheap uninterruptible power adapter system (UPS) is enough if it can last for more than ten minutes - the point is not to let it continue to run, but to give it a chance Shut down properly, or survive the brief interruption of a few seconds.

Tip: If the budget does not allow buying a UPS, the next best thing to do is: Set up automatic backup and have backups automatically uploaded to a location other than the host. Hardware will eventually break, and backup is your real insurance. Chapter 9 The whole chapter is about this.

The first three things to do after installation

Now that the system is running, don't rush to buy multiple light bulbs. Follow this order and you'll be less miserable later on.

  1. Go to the router and fix the IP

    The DHCP reservation mentioned in the previous network section. This is the only thing to do outside of Home Assistant, so do it first.

  2. Set up automatic backup and let it leave this machine

    If the backup only exists on the host's own storage device, the backup will be buried with it when the card fails, which means there is no backup. Chapter 9 It will take you to set up automatic backup and send it to a place other than the host.

  3. Check for updates and make a habit of backing up before updating

    Home Assistant Core is released approximately once a month (the version number looks like 2026.8, which is the "August 2026 version"), the operating system HAOS is a completely independent version number, with a much smaller number (the examples used in Home Assistant documentation and the latest releases at the time of writing are 18.2). Do not be surprised to see “Core 2026.8” and “Operating System 18.2” appear at the same time. They are two different things. Updates are well worth following, but Always back up before updating.

  4. Then go to Chapter 1

    The hardware part ends here. The next journey starts from Chapter 1 Get started: Get to know the interface, install the mobile app, set the time zone and region, naming rules, all the way to your Your first automation.

Concept: You may see the "Advanced Mode" switch in old tutorials and be asked to turn it on to see certain functions. This switch has been removed in 2026.6, the functions that were originally hidden are now visible by default. In addition, in 2026.8, "Developer Tools" will be renamed directly to "Tools" because Home Assistant believes that it is a place that everyone can use. When you see a tutorial with a mismatched name, first think about whether it is a version difference.

Troubleshooting

  1. When the browser calls homeassistant.local, there is no response at all.

    This is almost always an mDNS problem, not a host failure. Try in order: (1) Change to type homeassistant.local:8123—Machines installed before 2026.8 need to have communication ports. (2) Go to the router's management page and look for the "Connected Devices" list, and look for one with a name like homeassistant Yes, copy its IP and type it again http://thatIP:8123. (3) Make sure your phone or computer is connected to the host same network segment—The guest network (Guest Wi-Fi) or 2.4G/5G separate SSIDs of many routers will be isolated from each other. At this time, no matter how hard you try, you cannot connect. (4) Company or school networks often block mDNS, so just use IP.

  2. The imaging was successful, but there was no movement at all after plugging it in.

    Confirm first Imaging the wrong model No - a Raspberry Pi 4 image put into a Pi 5, or vice versa, will silently boot, which is why it's #1. The second reason is that the imaging tool fails to write (especially when using a cheap storage reader), so image the card again. Third, connect an HDMI screen to see if there is any picture: if there is no signal at all, it is usually a problem with the media being turned on. If text is running but stops, it is another problem. For x86 machines, you need to go back and check whether the BIOS is set to UEFI and whether Secure Boot is turned off.

  3. After startup, it is stuck in "Preparing Home Assistant" for a long time.

    This page is normal, it is downloading the latest version. Home Assistant documentation does not specify how long this step will take, only saying that "it may take some time"; Allow sufficient time for the download to complete., using an SD card is even slower. Never unplug the power adapter at this time. But if it continues to transfer for more than an hour, check whether the Ethernet cable is actually connected, whether the router has given it an IP, and whether the internet is normal - this step must be connected to the Internet.

  4. The host will reboot itself and no pattern can be found

    The first suspect is power adapter, not software. Especially if the Raspberry Pi 5 does not use the original 27W/5A power adapter, or the Pi 4 uses a phone charger, or you plug in a storage drive that does not have an independent power adapter on the USB port. Replace the original power adapter and try it for a week. The second suspect is overheating, touch the case to see if it is hot, and add a heat sink or fan. The third thing is that the storage media starts to break.

  5. After using it for several months, the dashboard has become very stuck and updates often fail.

    This is a classic sign that the SD card is starting to go bad. Make a full backup now and download it to your own computer, and then prepare to switch to SSD. available Settings > System > Storage "Move data disk" in "Move data disk" to move the data to SSD, or directly take the backup and reinstall it on the new media and then restore it. Don't put it off with a lucky mentality, otherwise you won't be able to save it.

  6. After installing it, I found that I couldn’t find the “add-ons”.

    Because it changed its name. After 2026.2 it will be called Apps, the path is Settings > Apps. Also note: Container installation really does not have this panel, Home Assistant documentation says in black and white “Container installation cannot use Apps”, it is not that you cannot find it. Among the installation methods that are still available and supported, only HAOS has Apps (the old Supervised also has it, but it will cease support in 2025.12, so do not install it just for this).

FAQ

Can I try it out with an old laptop or the Raspberry Pi at home first, and then switch to a better machine?
It's absolutely possible, and it's highly recommended. Home Assistant's backup mechanism makes "changing machines" relatively easy: Make a complete backup on the old machine and download it. After installing HAOS on the new machine, select "Restore backup" instead of "Create New" in the first step of Onboarding, and all your settings, automation, and devices will be back. This is why Chapter 9 It's worth reading it before you accumulate too much.
What’s the difference between Home Assistant Green and owning a Raspberry Pi?
The trade-off is time versus hardware cost. Green is official hardware with a power adapter, Ethernet cable, 32GB eMMC storage, and passive cooling. It avoids image-selection and power-sizing mistakes. A Raspberry Pi is flexible, widely available, and can be upgraded to an SSD, but you must select and assemble the parts. Choose Green for a ready-to-use appliance; choose a Pi when you already own one or prefer a DIY setup. Both run the same HAOS software.
I want to buy Home Assistant Yellow because it has Zigbee built in, is that okay?
Not recommended. Home Assistant page has clearly marked Yellow no longer produced, just continue to provide software updates and recommend new buyers to buy Green instead. The built-in radio is really convenient, but you can buy a Green (or any host) and plug it in Connect ZBT-2 This type of USB wireless stick achieves the same effect, and if the stick is broken, it can be replaced separately, and it can also be moved farther away to avoid interference (the ZBT-2 box comes with a 1.5-meter USB cable, which is originally meant for you to use at a distance). It is not worth it to buy a second-hand product for a discontinued product.
I already have a NAS. Wouldn’t it be the cheapest to install it directly on the NAS?
It depends on how you install it. Home Assistant documentation of Synology and QNAP take the Docker route, which is Container Installation will eliminate the entire Apps ecosystem, and Home Assistant documentation states that integrations such as Thread and Z-Wave, which are supported by Apps, do not have ready support on Container. For a complete experience, you need to open a VM in the NAS virtual machine management program to run HAOS (officially provided .qcow2, .vdi, .ova and other formats, the minimum configuration recommended is 2GB memory and 2 vCPUs). Also be mentally prepared: When the NAS is restarted or updated, your home automation will shut down entirely., and NAS is often updated more frequently than you think. USB wireless sticks often have problems when trying to penetrate virtual machines.
Home Assistant said that 32GB SD card is OK, so I can just use 32GB, right?
32GB is written in official documentation Minimum requirements, not a recommended value. The system itself and the database of an average family can support 32GB, but as soon as you start to keep a few backups, install a few apps, or save some camera clips, it will start to squeeze. What's more important is the issue of media type: SD cards have a short lifespan when they are written non-stop 24 hours a day. This is what really needs to be solved. If you can buy an SSD, buy an SSD with a capacity of 128GB or more., the price difference is not big and it saves the effort of moving in the future. If you really need to use an SD card, it is recommended to select Home Assistant installation file. A2 marked card.
Online instructions include homeassistant.local:8123, but my host connects without the port number. Is that wrong?
No. Starting with 2026.8, a new HAOS installation defaults to a URL without an explicit port number. Existing installations remain unchanged and may still use :8123. Both forms can therefore be correct; the difference is when the system was installed. When an older tutorial differs, use the address shown in your browser.
I saw someone saying Supervised installation is more flexible, should I go that route?
Don't. Official announcement of deprecation in May 2025 Core with Supervised There are two installation methods (32-bit architectures such as i386, armhf, and armv7 have been cut at the same time), and the schedule will start from 2025.6. Version 2025.12 officially ends support, then Home Assistant will no longer build distributions for these methods, and will not accept problem reports. Home Assistant relocation advice is: Supervised should use HAOS (either physical machine or virtual machine), and Core should use Container. Most of the "Supervised Tutorials" you see now were written before that time.
Will there be any privacy issues when sending the "shared analysis data" when setting it up for the first time?
Home Assistant documentation make it very clear: this Default is off, it is entirely up to you to decide whether to turn it on or not, and it does not affect any functions. What is sent out is anonymous statistical data, which Home Assistant uses to determine which devices and integrations should be prioritized for support. If you want to support the item, open it. If you don't mind, keep it closed. Either way is fine. This option can also be changed later in the system settings, so it is not a one-time decision.
Can the "owner" account be changed or open more accounts later?
Home Assistant documentation explains these things: The owner (Owner) is Created on first startup That account, Always an administrator at the same time, has the highest authority, and The owner account cannot be deleted (You also cannot delete the account you are logged in to). As for "whether the owner's identity can be transferred to others" and "whether there can be a second owner", Home Assistant documentation does not clearly explain it, and there is no ready-made switch on the interface, so in practice, Treat the first account as permanent To deal with this: remember the account number and set the password carefully. If the owner really forgets his password, Home Assistant rescue procedure is to return the system to a state where it can be onboarded again, which is costly. You can of course add other users to the system later (including administrator rights). Users, permissions, and relationships with "Person", Chapter 5 Very complete.
