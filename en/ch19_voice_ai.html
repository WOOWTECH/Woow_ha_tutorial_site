Chapter 19

Voice assistants and LLM integration

Move from tapping a phone to speaking naturally. Configure Home Assistant Assist, speech-to-text and synthesis, entity exposure, voice hardware, and optional LLM conversation agents that can control your home.

Why this matters

You already built a dashboard in Chapter 6 and wrote an automation in Chapter 8. Neither helps when you carry a pot into the kitchen or cannot reach your phone from bed. In those moments, voice control is more practical than a dashboard.

Home Assistant’s built-in voice assistant is called Assist. Its basic features are included with Home Assistant. Unlike Google Assistant or Alexa, you can decide whether each processing stage runs locally or in the cloud.

After this chapter, you can:

  • Explain how Assist differs from a large language model (LLM).
  • Choose which entities voice assistants can control and which must remain private.
  • Build an Assist pipeline and choose local or cloud processing for each of its four stages.
  • Configure an OpenAI, Google, or Anthropic model as a conversation agent and allow it to control selected devices.
  • Know the role of Model Context Protocol (MCP) in Home Assistant.
  • Evaluate cost, latency, and privacy trade-offs.
Concept: This chapter depends on your earlier setup. Assign devices to areas as described in Chapter 3, and give them clear names as described in Chapter 4. Unclear names make voice commands unreliable.

Assist: three terms to understand

Many people are confused by three words at the beginning. Let us cut it clean first.

TermPlain-English explanationWhere you see it
AssistHome Assistant’s name for its full set of voice features, including typed and spoken conversations.The conversation icon in the upper-right corner and the three-dot menu of the mobile app
Conversation agentThe component that interprets your request. Use the built-in agent or replace it with an LLM-based agent.Settings → Voice assistants → an assistant’s settings
Voice pipeline (Assist pipeline)The complete processing chain: wake word → Speech-to-text → conversation agent → text-to-speech.Each "Assistant" in Settings → Voice assistant is a pipeline

Most importantly, The conversation agent built into Home Assistant is not AI, it is a sentence comparer. It compares what you say with a large number of pre-written sentence templates, and triggers the corresponding intent when it finds a match, such as "turn on the lights in the living room". HassTurnOn.

This creates two clear trade-offs:

  • Advantages: Extremely fast, completely local, zero cost, no hallucinated responses. You tell it to turn off the lights and it turns off the lights.
  • Disadvantages: A request that does not match a supported pattern may fail. For example, it may not understand “Could you make the living room darker?” It is also not designed for open-ended chat.

The built-in agent has become more flexible. Version 2025.9 added a “fuzzy matcher,” which can recognize an intent despite extra words or different phrasing. Home Assistant documentation notes that this feature was implemented in English first, with other languages to follow. For other languages, clear names and aliases remain especially important.

Tip: Make common commands work with the built-in agent before adding an LLM. The built-in agent provides a fast, local, predictable baseline; add an LLM only for requests that need more flexible language.

If you want to play it for a while without setting anything up: After logging in to Home Assistant, click the conversation icon (a speech bubble) in the upper-right corner and type "turn on the living room light" or speak a sentence in the language you set. This is the smallest usable form of Assist.

A voice pipeline has four independently configurable stages

Think of a voice assistant as a factory conveyor belt. You speak a request; the pipeline produces an action and a reply. There are four stations in the middle, and each station can independently choose whether to use local or cloud.

Concept: Mix local and cloud stages to suit your hardware, language, privacy needs, and preferred voices. For example, use an on-device wake word, cloud speech-to-text, the built-in local conversation agent, and cloud text-to-speech. The pipeline does not have to be entirely local or entirely cloud-based.

If you only type and do not speak (for example, typing and asking Assist in a mobile app), stations 1, 2, and 4 will not start at all, and only the conversation agent will run. So "I want to chat via ChatGPT" and "I want to shout into the speaker" are two very different things.

Local processing options

  • Whisper: General-purpose speech-to-text with broad language support, including Chinese. The Home Assistant add-on defaults to auto; it selects tiny-int8 on ARM hardware such as a Raspberry Pi and base-int8 elsewhere. Larger models such as small and medium can improve recognition but require more CPU resources.
  • Speech-to-Phrase: Fast speech-to-text for a limited set of phrases relevant to your Home Assistant configuration. It works on modest hardware but does not support unrestricted speech. Chinese is not in the language list described by the source, so use another engine when you need Chinese recognition.
  • Piper: text-to-speech, local reading, fast speed and low resource requirements.
  • openWakeWord: Wake word detection, running on the Home Assistant host. Home Assistant documentation is that a Raspberry Pi 4 can handle approximately 5 voice satellites (satellites) streaming audio at the same time. If there are more, the detection must be moved to another machine.
Warning: Do not leave Whisper’s language settings in auto. Home Assistant documentation clearly states that automatic language detection will make every request much slower. Simply specify the language your home speaks.

These four are official Add-ons. After installation, use Wyoming This protocol is discovered by Home Assistant. How to use the Add-on store is already in Appendix A covers this, so the details are not repeated here.

Entity exposure: decide what Assist can access

This is the most important setting in the entire chapter and the one that most people miss. Home Assistant does not hand over all of your entities to the voice assistant. You must explicitly "Expose" them for the voice assistant to see them. This is intentionally safe by design.

  1. Open the exposure settings

    sidebar Settings → Voice assistants, then switch to Expose Tab.

  2. Review current exposure

    The list lists the entities that have been exposed, and the assistants to which it was exposed. The assistant here is not only Assist, if you have connected Google Assistant or Alexa, they will also appear on the same table.

  3. Expose only required entities

    Select Expose entities to add several entities at once. Select an individual entity to choose which assistants can access it.

  4. Add useful aliases

    Select an entity to add an alias. If the entity is named “living room main light” but your household calls it “main lamp,” add that phrase as an alias. You can also open the entity dialog, select the gear, and open Voice assistants.

  5. Remove sensitive controls

    Keep door locks, alarm systems, water heaters, and any device that creates heat or presents a safety risk off the exposure list unless you have assessed the risk carefully.

Danger: Exposing a door lock (lock) or alarm system (alarm_control_panel) may allow someone within microphone range to operate it. Keep these entities private unless you fully understand and accept the risk.

What happens if you expose too much?

Home Assistant best practices are very straightforward: Expose only the minimum necessary entities. There are two reasons, and both of them hurt:

When using the built-in conversation agentWhen using LLM as a conversation agent
More names and aliases take longer to match, and similar names increase ambiguity. A request for the “room light” might select an air purifier’s indicator light.Every exposed entity adds context and token cost to the model request. A longer list also increases the chance of selecting the wrong device. The Ollama documentation recommends testing local models with fewer than 25 exposed entities.

Aliases for areas and floors

Entity exposure works with areas and floors. For “turn off all the lights in the living room” to work, those lights must belong to the living room area. You can also add aliases to areas and floors: go to Settings → Areas, labels & zones, select the pencil on an area card, then Add alias. For a floor, use its three-dot menu → Edit floor → Add alias.

Tip: Home Assistant recommended naming format is "Area + Description + Device Type", such as "Living Room Table Lamp". If there is only one light in that room, just call it "living room light". like Tuya Light Controller 0E54B1 Light 1 With this kind of original name, the voice assistant will definitely not be able to call you. Please rename it. Chapter 4 Change name.

Hands-on: build a local voice pipeline

Build an assistant that can speak to the phone. The following uses "local Whisper + local Piper + built-in proxy" as an example. This is the cheapest and most private way to start.

  1. Install the Speech-to-Text Add-on

    Go to Settings → Add-ons → add-on store, find Whisper, start after installation. Before starting, go to its Settings tab and put language Change it to the language you want to use, leave it blank auto.

  2. Install the Text-to-Speech Add-on

    Found in the same store Piper, start after installation.

  3. Accept Wyoming's automated exploration

    Return to Settings → Devices & services. The two Add-ons just started will be Wyoming Protocol Integrate automatic discovery, click once each Add to finish. If it does not pop up automatically, you can manually Add integration → Search Wyoming Protocol.

  4. Create assistant

    Go to Settings → Voice assistants, select Add assistant. Choose a name you can understand (for example, "Home Local Version") and choose a language.

  5. Configure the pipeline stages

    In the same screen: conversation agent choose Home Assistant; Speech-to-text Select the Whisper you just added and select the language; text-to-speech Select Piper and choose a voice variant. If you do not have a physical voice device yet in the wake word column, you can leave it alone for now.

  6. Expose entities

    Switch to the Expose tab and add only the lights, outlets, and fans that you want to control. Voice commands cannot operate entities that are not exposed.

  7. Test from your phone

    Open the Companion App (Chapter 7 The installed one), three-dot menu in the upper-right corner → Assist. Test by typing first. After you can type and turn off the light, press the microphone to test.

  8. Set as default assistant

    After every stage works, Return to Settings → Voice assistants, set this assistant as the default. All Assist entrances will follow it.

Warning: if Settings → Voice assistants You can't see the Assist block at all. Home Assistant solution is in configuration.yaml Add a line assist_pipeline: Reboot again. General use default_config: The installation will not encounter this problem.

Connect an LLM as the conversation agent

The built-in agent only recognizes sentence patterns. When you want a vague way of saying "It's a bit cold today, help me deal with it", or you want it to respond with personality, you should change the conversation agent to LLM.

Setup

  1. Add integration

    Settings → Devices and Services → Add integration, search for the one you want (OpenAI, Google Generative AI, Anthropic, Ollama), fill in the API key or local URL according to the screen.

  2. Create a new assistant

    Go to Settings → Voice assistants → Add assistant. Enter a name, then select the LLM integration under Conversation agent.

  3. Define its response style

    Go into the gear next to the agent name and there will be a prompt template field. You can write "You are a butler who speaks very briefly and answers no more than two sentences", or you can write "You are Super Mario and your speech must be funny." This column supports Home Assistant's template syntax, so real-time information can be inserted.

  4. Enable control permissions

    Find it in the same settings screen Control Home Assistant (Control Home Assistant). This must be turned on, otherwise it will only chat with you and not turn off the light. See the next section for details.

  5. Test by typing first

    Select Start conversation from the agent menu and test with typed requests first. Add speech-to-text and text-to-speech only after the conversation agent works, so you can isolate any later audio failure.

Warning: Speech-to-text and text-to-speech are configured independently of the conversation agent. Selecting an LLM conversation agent does not configure audio input or output; choose an engine for each of those stages separately.

Allow an LLM to control exposed entities

An LLM may reply that it turned off a light even though the light remains on. That usually means one of the following three requirements is not met.

First: enable Home Assistant control

The OpenAI, Google Generative AI, and Anthropic integrations include a Control Home Assistant option. Enable it to give the model the Assist API as a tool. When it is disabled, the model is only a chatbot.

If the version is older, the same position may not be a switch, but a drop-down menu with the options saying "No control" and "Assist" - select Assist It means turning on the control, which means the same thing.

Second: expose the entity

This is the most common cause. The integration documentation states that a model can query or control only exposed entities. Enabling control without exposing any entities gives the model no available controls. Complete the earlier entity-exposure steps.

Third: verify that the model supports tool use

If you are using Ollama to run local small models, Home Assistant documentation is very honest: small models are more error-prone than large models, and After turning on the control function, small models may not be able to maintain dialogue stably.. Home Assistant even suggested a workaround: configure two Ollama settings, one with no control and dedicated to chatting, and the other with control and dedicated operation of the device.

Concept: "Control Home Assistant" and "Exposed entity" are two independent gates that must be opened at the same time. This double-checking is intentional: You don't want a cloud-based model to turn on all your appliances on a whim one day.

A combination that saves money and is safe: Prioritize local processing

There is one in the assistant's three-dot menu Prefer handling commands locally switch. After opening it, Home Assistant will first let the built-in sentence pattern comparer try it. If the comparison is found, it will be executed directly. If the comparison fails, it will be thrown to LLM.

This trick solves three problems at the same time:

  • Fast: A simple command like "turn on the living room lights" is sent locally with almost zero delay.
  • Lower cost: 80% of the daily commands do not call the API at all and do not burn tokens.
  • reliable: Turning off the lights is left to a comparator that does not think too much, which is more reliable than leaving it to a model.
Tip: This switch should be on in almost all cases. Unless you just want LLM to completely take over all semantic understanding (for example, you are working in a multilingual family, or your speech rarely conforms to the built-in sentence patterns).

Expose scripts as controlled capabilities

Scripts created in Chapter 10 can also be exposed to voice assistants. Wrap a sequence of complex actions in a clearly named script, expose that script, and let the model call it as one controlled capability. This is more reliable than asking the model to assemble a long action sequence.

Model Context Protocol (MCP): server and client roles

MCP is a set of open protocols that allow large language models to communicate with external tools. Home Assistant officially described it in the blog as "a very thin layer that allows LLM to connect to anything." Official hardware: Voice Preview Edition

If you are too lazy to bother, this is the easiest one. Inside is ESP32-S3 (16MB flash, 8MB PSRAM) plus XMOS XU316 audio chip, which is responsible for echo cancellation, noise reduction and automatic gain - in plain language, "the TV can still hear you when it is playing sound." It has a dual microphone array and a built-in speaker with a 3.5mm output hole. The body has a physical mute switch, volume knob, LED light ring, and a Grove expansion port for connecting sensors. Dimensions: 84×84×21mm, 96 grams. It does not require Home Assistant Cloud to work, can be run fully locally, but Home Assistant reminder is that a complete full local experience requires a relatively capable host (approximately Intel N100 level starting).

Tip: Starting with version 2025.10, each Assist voice satellite can be configured Up to two sets of wake words, corresponding to two different pipelines. This is super easy to use: for example, "Okay Nabu" uses a local quick light-off pipeline, and "Hey Jarvis" uses LLM's cloud pipeline. One machine has two personalities. Whichever name it says, it will take whichever path it takes. Multilingual families can also use one wake word per language.

By the way: Voice satellites can actively talk to you

Voice devices do not just passively wait for you to shout.assist_satellite This domain (Domain) provides three actions that can be written into automation:

actions:
  - action: assist_satellite.announce
    target:
      entity_id: assist_satellite.living_room
    data:
      message: The washing machine is ready

The other actions are assist_satellite.start_conversation (start a conversation) and assist_satellite.ask_question (ask a question and capture the answer). For example, after a door opens, an entryway satellite can ask whether to turn on the living-room lights and act on the reply.

It is easy to step into a pit when writing this kind of automation: When it is talking to people, you ask it to broadcast again, the two paragraphs will overshadow each other. Starting from 2026.2, there is an additional set of conditions specifically for voice satellites in the automation conditions (Condition), which can determine whether the device is now Idle, listening, processing, or answering. Before broadcasting, add a condition of "Broadcast only when idle", so that the family members will not be interrupted in the middle of speaking.

Tip: Starting from 2025.10, there is also a very considerate behavior: when the command you give is executed in the area where the satellite is located (for example, you say "turn on the lights" to the speaker in the living room), it will use One short beep Instead of saying the entire sentence "I have turned on the living room light for you". Those two seconds saved make a huge difference in physical sensation.

Control token costs

Cloud LLM is billed based on usage, and each company's unit price is constantly changing. We do not list hard numbers here (it will expire soon after writing them down, so go to each company's official website to see the latest prices). But there are a few principles that will keep your bills skyrocketing:

  • Each sentence will send you a list of exposed entities. The cost difference between exposing 200 entities and 20 entities is an order of magnitude.
  • Prompt template is too long Also paying every time. Just write three or five sentences about personality settings, don't write a novel.
  • "Prioritize local processing of instructions" is turned on, the API will not be called at all when turning off and on the lights in daily life. This is the most effective money-saving switch.
  • First Set usage limit Then paste the API key. The backends of the three suppliers can be set up.
Danger: The API key is equal to your credit card. Do not post the key in forums, screenshots, GitHub, or messages asking for help with setting up. If the key is accidentally leaked, go to the supplier's backend immediately to cancel and reissue it. Don't take any chances.
Concept: Latency is a critical usability factor. If it takes more than three seconds from the time you finish shouting until the light comes on, your family will no longer use it, and your work has been in vain. If you can only optimize one thing, optimize the speed of "your five most common commands", it doesn't matter if the others are slower.

Troubleshooting

  1. Can't call any device, it says "Sorry, I don't know about that"

    First confirm that the entity is exposed under Settings → Voice assistants → Expose. Next, compare the spoken name with the entity name and aliases; add the phrase your household actually uses. Finally, verify the entity’s area assignment as described in Chapter 3.

  2. You do not know which section the problem lies in

    Use official debugging tools. Settings → Voice assistants → Click your assistant → Open the Debug dialog box, select the execution you just performed from the drop-down menu, and you can see how long each paragraph took and what text was recognized. In the icon in the upper-right corner of the debugging screen, you can also select Run text pipeline, just type one sentence and run the entire pipeline.

  3. You only want to know whether the sentence has been parsed, not actually executed.

    Use Assist’s sentence pattern testing tool: Settings → Tools → Assist Tab. It will tell you which intent the sentence was parsed into and which entities were locked, but Doesn't really move. After changing the name and adding an alias, it is the fastest to use it for acceptance.

    If you can't find "Tools", check your version: 2026.2 ago This set of tools is called "Developer tools" and is hung at the bottom of the sidebar; it will be moved into Settings At the bottom of the page, it's called "Tools". The fastest way to move on the computer is to press Ctrl + K (Mac is Cmd + K) Open quick search and type "tools" or "developer" directly.

  4. It responds but produces no sound

    Check first Settings → system → Internet Is the "Local Network Home Assistant URL" in "Local Network Home Assistant URL" correct? The audio file that is read aloud depends on this URL for the device to capture. If the URL is wrong, there will be pictures but no sound. YAML is useless if you write it purely by hand default_config:, also confirm media_source: There are plus.

  5. Assist recognizes an entity only when I use its full formal name

    Add an alias under Settings → Voice assistants → Expose → select the entity. An entity can have multiple aliases, so add the everyday terms used by different household members or languages.

  6. False trigger: Call A but drive to B

    This is the complication of too much disclosure + too much similarity in names. The order of processing is: first cut off the entities that do not need to be exposed, and then rename the remaining ones that are easy to confuse into the "region + description" format. Official best practices also remind that the domain of the entity (Domain) and the device class (Device class) must be set correctly - you cannot ask Assist to "open" a valve classified as a switch.

  7. Local Whisper is so slow that I want to cry

    Three directions: turn language from auto Change to a fixed language (officially, auto will be slower) a lot); adjust the model downward (tiny-int8, base-int8 This int8 compressed version); or convert Speech-to-text into Home Assistant Cloud, leaving the local machine to the conversation agent. Whisper's beam_size The default is 0, which means that it automatically uses 1 on ARM machines and 5 on other machines - the larger the number, the more accurate it is but the slower it is.

  8. There is often no response to the wake-up word, or I wake up by myself in the middle of the night

    First confirm whether your wake word is running on the device (microWakeWord) or on the host (openWakeWord). When running on the host, Home Assistant mentioned that a Raspberry Pi 4 can support approximately 5 satellite streams at the same time, and it will start to freeze if it exceeds that. The problem on the device side is probably the microphone gain or noise reduction settings. Use ESPHome to adjust the settings of that device.

  9. LLM says it does but it does not

    Classic scene of model hallucination. Checking order: Integration settings Control Home Assistant Is it turned on → Is the entity public → Is the model too small (local small models may not even be able to hold conversations after the control is turned on). The improvement method is to turn on "Priority to process instructions locally" so that instructions with high certainty do not go through the model at all.

  10. Web pages with embedded sidebars are blank

    The other website uses a security header to prohibit iframe embedding. This is decided by them and you cannot change it. Change a website, or use the "open in new tab" method instead. Also check whether HTTPS/HTTP are mixed.

FAQ

Do I have to pay for Home Assistant Cloud to use voice?
No. Assist itself is completely built-in for free, and the local Whisper, Piper, and openWakeWord are also free official Add-ons. What you buy by subscribing to Cloud is "you don't have to have a capable host yourself" and "Chinese speech-to-text and reading quality". If your Home Assistant runs on a Raspberry Pi and you want to use Chinese, subscribing is usually more cost-effective than upgrading the hardware; if you have an idle small host, going full local is completely feasible.
What is the difference between built-in Assist and ChatGPT? Do I have to take LLM?
Built-in Assist matches supported sentence patterns. It is fast, free, local, and predictable, but it is not designed for open-ended conversation. An LLM understands more flexible phrasing and supports ongoing conversations, but adds latency, usage cost, and the possibility of hallucination. A practical setup is to use both: select the LLM as the conversation agent and enable Prefer handling commands locally. Simple commands stay local, while unmatched requests go to the LLM.
If I paste the API key into Home Assistant, will my family’s data be used to train the model?
It depends on which provider you use and how the provider's API terms are written. Home Assistant cannot control this matter, and each provider's policies will also change. Please go directly to the provider's data usage policy. What you can control is How much to give away: Expose only the necessary entities and the model will only see those. Do not disclose door locks, cameras, or anything with a sense of personal status. If you don't accept data leaving home at all, the answer is to run local models with Ollama, or simply use the built-in proxy.
Can I ask the voice assistant to unlock the door or release security?
Technically possible (put lock or alarm_control_panel It is OK if the entity is exposed), but it is strongly not recommended. There is no way to reliably tell who is speaking with voice, and you may be heard standing outside the door and shouting into the window. If you really want to do it, at least use a script to wrap it up, add additional conditions (for example, a certain phone must be at home, within a certain time range), and know clearly what risks you are taking. Chapter 10 Scripted writing.
You cannot speak Chinese accurately, what’s the order of optimization?
Follow this order: 1. Make sure the speech-to-text engine language setting is Chinese and not auto. 2. Change the name of the device to a colloquial language that is easy to pronounce ("living room lamp" is a hundred times better than "living room ceiling lamp set 1"), and add a lot of aliases. Three. If the local Whisper cannot hear accurately with a small model, adjust the model upward or use Home Assistant Cloud's speech-to-text instead (zh-TW is in its list). Four. If that still does not work, replace the conversation agent with an LLM and let the model tolerate the identified typos. By the way, the local Speech-to-Phrase currently does not have Chinese in the language list, so there is no need to try this method.
Assist doesn't understand a specific teaching method of mine, can I teach it myself?
Yes, and there are two ways. If you do not want to touch YAML, go this way: Go to Settings → Automation and scenes → Build automation, select from the drop-down menu of Trigger Sentence, fill in the sentence you want to say, and pick up what you want to do on the action side. This is equivalent to using automation to teach it a new line, just click the whole process. If you want to write a configuration file, go this way: in configuration.yaml To extend an existing intent:
conversation:
  intents:
    HassTurnOn:
      - "activate [the] {name}"
A more complete approach is to open it in the settings folder config/custom_sentences/<language_code>/ Table of contents (English is config/custom_sentences/en/) into a YAML file, you can define your own intentions, lists, value ranges, and even change it back to your sentences (put one in the same directory responses.yaml). It is safest to restart Home Assistant after making changes.
Can one speaker serve me who speaks Chinese and my family who speak English at the same time?
Yes. Starting with version 2025.10, every Assist voice satellite supports up to two wake words, each assigned to a separate pipeline. Assign “Okay Nabu” to one language and “Hey Jarvis” to another. The same mechanism can separate a fast local pipeline from a cloud LLM pipeline; the wake word determines which one runs.
Should MCP be touched?
If you just want to use your voice to turn off the lights at home, No need to touch at all, the previous content is enough. MCP is best suited to two types of people: those who want to directly operate their homes in external apps such as Claude and ChatGPT (integrated with Model Context Protocol Server, the endpoint is /api/mcp), or want to add additional tools to the conversation agent at home such as memory and network search (integrated using the Model Context Protocol client, added in version 2025.2, currently only supports Tools). Both involve handing over control and minimizing the list of "exposed entities" before setting them up.
I put the external AI website into the sidebar, but the result is blank. Am I setting it wrong?
Usually not. Many websites will use the browser's security mechanism to explicitly prohibit themselves from being embedded in other people's web pages. This is the other party's decision and you cannot bypass it. Also make sure the protocols are consistent: if Home Assistant uses HTTPS, the embedded URL must also be HTTPS. By the way, as a reminder, in the old teaching panel_iframe: YAML settings have been replaced by the "Web" dashboard (will be automatically migrated when upgrading), please use now Settings → Dashboard → Add new dashboard → page.
Can I "ask AI to do things for me" in automation?
Yes, and there are two ways. The first one is conversation.process Action, throw a piece of text to the designated dialogue agent for processing, which is equivalent to talking to Assist in a programmatic way. The second article is AI Task (Building block integration added in version 2025.7), provided ai_task.generate_data follow ai_task.generate_image Two actions, specifically used to generate text, structured data or images in automation, such as "take a look at the camera screen and count the number of cars in the lane". This is much cleaner than putting together multiple templates yourself.
