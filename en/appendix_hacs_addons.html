Appendix A

Ecosystem: HACS, add-ons, and remote access

Understand the three main extension paths around Home Assistant: official add-ons, community content from HACS, and secure remote access. Choose only what solves a real need.

Official App store

Note on name change: Starting from version 2026.2, Home Assistant name of "Add-on" has been officially changed to "Apps", the store is called "App store", and the menu path has also changed from "Settings → Add-ons" to "Settings → Applications". Nothing has changed at all, just the name has been changed. If you still have a version before 2026.2 and see "Add-on / Add-on / Add-on Store", it refers to the application discussed in this section.

Applications (Apps, called add-ons in the old version) run on HA OS standalone container program, can be thought of as a small server that the HA host helps you open. Only HA OS and HA Supervised have app stores, HA Container / HA Core no.

Path: "Settings → Apps → Install app" (Settings → Apps → Install app).

When the app will be used:

  • To run local services such as Zigbee2MQTT / ESPHome.
  • SSH into the host to debug.
  • Use Node-RED, a visual process tool.

Some of the most commonly installed official applications:

  • File editor—Change YAML files directly in the browser, suitable for light editing.
  • Studio Code Server—The complete VS Code web version, the first choice for writing large amounts of YAML or templates.
  • Samba share—Put HA’s /config KaiChengWangFang allows you to operate using your computer's file manager.
  • Terminal & SSH—SSH into HA OS for advanced troubleshooting.
  • Node-RED—Drag-and-drop visual automation tool, complex processes are easier to maintain than UI.
  • ESPHome—Burning ESP32 / ESP8266 firmware, a must for DIY sensors.
  • Zigbee2MQTT—Supports more Zigbee devices than ZHA, and the community updates quickly.
  • Mosquitto broker—MQTT message broker, the communication underlying layer of Z2M/many DIY devices.
Recommended practices: Make sure you have clear needs before installing. Every time you install an application, there is one more service that needs to be maintained, updated, and takes up resources.

HACS (Home Assistant Community Store)

HACS is Community maintenance third-party package store, which is the same as Home Assistant App store (App store) two different things:

  • Official App Store: It deals with "independent container programs running on HA OS" and is officially reviewed.
  • HACS: It is in charge of "things that are plugged into the HA ontology" - custom integrations, custom dashboard cards (Lovelace cards), themes, python_script, and AppDaemon applications. There is no official review, and the author is responsible for the quality.

When should I install HACS? When you find that "my device is not included in Home Assistant integration" or "the built-in cards are not pretty/capable enough", 80% of the time HACS has a solution. There is no need to rush before installing. First confirm that there is no official support before considering.

Key points of the installation process (see official documentation for details):

  1. Installing HACS itself requires SSH/Studio Code Server to enter HA and execute an installation script (recent versions also support one-click processing using the application "HACS Bootstrap").
  2. Then add a new integration "HACS" to HA, which will display a set of GitHub device codes and URLs; open the URL in a browser, log in to GitHub, and paste the device code for authorization (no need to manually generate a personal access token).
  3. After completion, there will be a HACS icon on the left menu, which is the community package market.

Official installation files: https://hacs.xyz. The steps will change with the version, please refer to Home Assistant version.

Directions for installing common kits:

  • Customize dashboard cards: mushroom-cards(Modern simplicity),button-card(Customized to the extreme),mini-graph-card(beautiful historical curve),swipe-card(Swipe left and right on your phone).
  • community integration: Xiaomi/Aqara localized, Tuya localized (avoiding the international version of the cloud), SwitchBot API, your utility bill and national weather service forecast.
  • Topic: Google Home, Graphite, Noctis and other community themes.
Reminder: The HACS suite is No review For third-party code, select authors with a large number of stars and recent updates (within 3 months). Do not install a large number of them at once, as they may all break when updating HA.

Four remote connections

It is enough to use the local network IP to connect to HA at home, but once you go out and want to watch the camera remotely, turn off the lights, and receive notifications, you need an external network connection. There are four mainstream options:

Plan cost security difficulty suitable for
Nabu Casa USD $6.5/month high very low Most people. By the way, support HA official
DuckDNS + Let's Encrypt free Medium (Exposed public network) in It needs to be free + have a public IP + be willing to set up a router
Tailscale / ZeroTier Free (individual) highest low Technical gamer, concerned about privacy, no need to share with non-family members
Cloudflare Tunnel free Middle to high in It can be externally connected without public network IP (telecom CGNAT)

1. Nabu Casa (Home Assistant Cloud)—Official paid cloud. The most worry-free thing is to just pay the money and install the integration. Comes with additional Google Assistant/Alexa linkage and Cloud TTS (cloud speech synthesis). The first choice if you don’t want to bother, and the only one that can Sponsor HA development by the way plan.

2. DuckDNS + Let's Encrypt—Use free dynamic DNS service to connect the floating IP at home to a URL (such as myhome.duckdns.org), then use Let's Encrypt to get a free SSL certificate. Need to do port forward on the router. The disadvantage is that it exposes HA to the public network, which is the solution with the largest attack surface.

3. Tailscale / ZeroTier—This is the approach of "VPN to your home". Install the Tailscale App on your phone and the HA at home. The two form a private local network. You can use the local network IP to connect to the HA when you go out, just like at home. safest Because it is not exposed to the public network at all. Disadvantages: Family members also need to install the app, and it cannot be shared with outsiders (it cannot be passed to plumbers like a URL).

4. Cloudflare Tunnel—Cloudflare helps you establish an encrypted tunnel between HA and its CDN. You don’t need to have a public IP or open a router port. Cloudflare will provide a URL for you to connect. It is suitable for environments where the home is a telecom operator CGNAT (no public network IP), and you can also use Cloudflare's WAF protection.

Security warning

Absolutely not Directly forward HA's 8123 port to the public network without applying HTTPS credentials. HA does not have two-step verification enabled by default, nor does it have an IP whitelist. Crawlers on the Internet scan port 8123 every day, and as long as it is exposed, it will be attacked. If you really want to go the DDNS route, Must (1) Hang Nginx reverse proxy in front to process HTTPS, (2) Enable HA's two-step authentication (MFA), (3) Use strong passwords, (4) If possible, add Cloudflare / fail2ban to prevent brute force cracking.

If you don't know what the above are, please use Nabu Casa or Tailscale directly instead of opening the port yourself. This is not the money you can save by tinkering with technology, but the risk of exposing your entire smart home + camera + door lock permissions to the Internet.

FAQ

Will the HACS stuff slow down Home Assistant?

Yes, but it depends on which one you install - there are two completely different types of things in HACS:

TypeWhere to runinfluence
Custom integration (custom integration)The backend of the HA host is integrated with the built-in to grab the same CPU and memoryThe startup is slow, poorly written ones will block the entire startup process, and some will frequently hit external APIs.
Customized cards/themes (Lovelace card, theme)Your browser or mobile appAlmost no impact on the host, just downloading a few more files when the dashboard is first loaded

So "installing 20 beautiful cards" is usually fine, but "installing 8 custom integrations, each of which is polling the cloud" will be fine. HACS itself will regularly check GitHub for updates, but that is a small amount of traffic in the background.

If you suspect who is stalling for time, the cleanest way to judge is Open in safe mode (See the next question for how to do it): Safe mode does not load custom integrations, custom cards, and custom themes at all. If it runs like new in safe mode, the answer is obvious.

hint: Before installing, ask "Is the built-in one really not good?" Many people pack multiple cards, and in the end only two or three are commonly used, and the rest become mines during updates.
After updating Home Assistant, something installed in the HACS is broken/cannot be turned on. What should I do?

This is the only way to play HACS, don’t be nervous, follow this order:

  1. Use safe mode to rescue HA

    Settings → System → "Restart Home Assistant" in the upper right corner → select "Restart in Safe Mode". This will load the HA core, but not any custom integrations, custom cards, or custom themes, so you can at least get into the interface.

  2. Look at the records to find the murderer

    Settings → System → Records. Broken custom integrations often leave a whole section of errors, with the first line saying which custom_components Something happened.

  3. Go to the GitHub of that package to see the Issues

    HA has a new version every month. On the day of the major revision, someone must have opened an issue in the author's repo. Usually, just wait for the author to send an updated version, and press update in HACS to solve the problem.

  4. If you can't wait, remove it first.

    Remove the package from HACS, reboot the system to allow HA to return to normal, and then install it back again. It’s better to have one less function than to not be able to use the entire machine.

  5. If you really can’t save it, restore the backup.

    return to Chapter 9 backup and restore process, return to the version before the update. This is why you must have a backup before upgrading.

Make it a habit: Before updating HA, first read the Breaking changes section of Home Assistant release announcement, and then confirm whether the custom integration you have has been updated recently. The package that the author has not touched for half a year will sooner or later be killed in a major revision.
For the same function, when should we look for applications (formerly known as add-ons) and when should we look for HACS?

Use "Does this thing need to run a separate program" to classify:

what you wantWhere to find
An independent server program: MQTT broker, Zigbee2MQTT, ESPHome, Node-RED, database, SSHApplications (formerly known as Add-on)
Let HA recognize a device or service that is not officially supportedCustom integration for HACS
The dashboard should look better, have more special cards, and change the themeHACS Cards/Topics

Zigbee2MQTT is the most confusing example because it Will be encountered on both sides: The program itself is an application (or a container you run yourself). The device appears in HA through the automatic discovery of MQTT integration, and its beautiful network map card is something on HACS. Three things, three places, not the same.

I installed it with Docker (HA Container) and there is no app store (formerly known as the add-on store). Am I unable to play these games?

No, you just have to take one more step. Let’s break it down into two things:

  • HACS still works. HACS supports three installation methods: OS/Supervised, Container, and Core. Container and Core use the same official download script: enter the terminal of the container (or host) and execute it wget -O - https://get.hacs.xyz | bash -, restart HA, go to the integration page to join HACS, and go through GitHub authorization to complete. OS/Supervised is installed directly by adding the HACS app repository. The steps will be adjusted according to the version to hacs.xyz The description shall prevail.
  • The functions of the application must be opened in its own container. To put it bluntly, the application is a Docker container managed by Supervisor for you. Zigbee2MQTT, ESPHome, Mosquitto, and Node-RED all have their own official Docker images. You can docker compose Just write one more paragraph and it will have the same function. The difference is Updates, backups, and interface settings are all yours to take care of., will not appear in the HA interface, nor will it be included in the HA backup package.
Think clearly first: If you find yourself constantly completing these manual steps, HA OS may be more suitable for you. On the other hand, if there are other services running on this machine and you are familiar with Docker, then the flexibility of Container is worth it. This is a trade-off, and there is no standard answer.
Which of the four types of remote connections is the safest?

As far as safety is concerned, the ranking is as follows:

  1. Tailscale / ZeroTier - the most secure

    Because of your HA Never appeared on the public internet. There is no URL to scan, no port to type, and the attacker cannot even find the target. The price is that everyone who wants to use it must install the app and be authorized by you.

  2. Nabu Casa – safe and worry-free

    Home Assistant cloud helps you handle credentials and connection channels, and there is no need to open a port on the router. All you have to worry about is your HA account password.

  3. Cloudflare Tunnel - Above average, but it depends on how you set it up

    It’s good that you don’t need to open a port, but by default the URL is Anyone can even get it Yes, except they will stop at the HA login page. To get to the "Secure" level, you need to use identity verification like Cloudflare Access to get in front of it.

  4. DuckDNS + port forward - the most dangerous

    Hang the HA directly on the public network. The security warning earlier in this article talks about this approach.

No matter which one you choose, Two-step verification (MFA) must be turned on—The setting method is in Chapter 5. This is the only feature that must be done no matter which plan is used.

Nabu Casa costs $6.50 a month. Is it worth booking?

First look at what you are paying for. The current official pricing is $6.5 per month, $65 per year (Eurozone is €7.50 per month, €75 per year), and you can Free trial for one month Decide again. Content includes:

  • Secure remote connection without touching the router.
  • Google Assistant and Amazon Alexa are connected - it is really troublesome to apply for a developer account and set up OAuth to connect these two.
  • Cloud-based speech synthesis (TTS) and speech recognition (STT) for Assist voice assistant.
  • When the camera WebRTC connection cannot be directly connected to the relay (TURN) server, there will be errors when people look at the camera outside.
  • Your money goes directly to the development of Home Assistant. This item has no ads and doesn't sell your data. It just depends on this.

It is recommended to judge like this:

your situationSuggestions
I just want remote connection, I don’t have a voice assistant at home, and I don’t mind if everyone installs the app.Tailscale is free and that’s enough
Want to connect to Google/Alexa, or someone at home doesn’t want to install VPN AppNabu Casa, the time saved far exceeds the money
Often looking at the camera at home outsideNabu Casa, the relay server is difficult to fix on your own
You just want to learn these Internet technologiesFight it yourself, but be sure to follow the security warning section
Honestly: If you even want to Google what "port forward" is, then what you pay for is not the function, but the insurance that "your home camera will not be exposed to the Internet due to incorrect settings." Use the free trial for a month first, and the answer will appear by itself.
Cloudflare Tunnel is free, can I use it to watch my home cameras from outside?

Technically possible, but this is the easiest way to step on the line. Cloudflare's CDN terms have always had restrictions on "transmitting videos and large files that are not hosted on Cloudflare's own services through it" - later revisions to the terms clearly stated that video content must be placed on Cloudflare's own services (Stream, Images, R2) to be unrestricted. Your camera's live stream obviously doesn't fall into this category.

It probably won't matter if you click on it occasionally to take a look, but if you hang four cameras on the dashboard and stream all day long, you are testing people's patience with long-term heavy traffic. It is not unfair to have your account restricted or closed.

If you want to watch the camera smoothly outside, a more appropriate choice is:

  • Nabu Casa - Camera remote streaming is one of its functions, and TURN relay helps.
  • Tailscale/ZeroTier - It is equivalent to watching on your own private network. There are no third-party terms and conditions, but the display quality will be affected by the phone network speed when the route is far away.

Cloudflare Tunnel is more suitable for positioning: the home is a telecommunications company and CGNAT cannot get the public network IP. The main requirement is to turn on and off the lights remotely and check the status, rather than serving as the image channel of the monitor.
