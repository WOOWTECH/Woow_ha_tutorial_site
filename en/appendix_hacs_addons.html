Appendix A

Ecosystem: HACS, add-ons, and remote access

Understand the three main extension paths around Home Assistant: official add-ons, community content from HACS, and secure remote access. Choose only what solves a real need.

Official add-on store

Version note: Starting with Home Assistant 2026.2, the UI calls add-ons "Apps," the store is the "App store," and the path is Settings → Apps. Older versions use "Add-ons" and "Add-on store" for the same feature.

Add-ons are stand-alone containerized services managed alongside Home Assistant. The App store is available on Home Assistant OS and the former Supervised installation type; it is not available in Home Assistant Container or Core.

Path: Settings → Apps → Install app.

Use an add-on when you need to:

  • To run local services such as Zigbee2MQTT / ESPHome.
  • SSH into the host to debug.
  • Run Node-RED for visual automation flows.

Some of the most commonly installed official add-ons:

  • File editor—Edit YAML files in the browser; suitable for small changes.
  • Studio Code Server—A browser-based VS Code environment; better suited to extensive YAML or template work.
  • Samba share—Exposes HA’s /config folder so you can manage it from your computer’s file manager.
  • Terminal & SSH—SSH into HA OS for advanced troubleshooting.
  • Node-RED—A drag-and-drop automation tool that can make complex flows easier to inspect.
  • ESPHome—Build and flash firmware for ESP32 or ESP8266 devices.
  • Zigbee2MQTT—Supports more Zigbee devices than ZHA, and the community updates quickly.
  • Mosquitto broker—An MQTT broker used by Zigbee2MQTT and many DIY devices.
Tip: Make sure you have clear needs before installing. Every time you install an application, there is one more service that needs to be maintained, updated, and takes up resources.

HACS (Home Assistant Community Store)

HACS is a community-maintained store for third-party packages. It is different from the Home Assistant App store:

  • Official App store: Installs independent containerized services on HAOS and distributes packages reviewed through the official project.
  • HACS: Installs custom integrations, dashboard cards, themes, python_script packages, and AppDaemon apps. These community packages do not receive official Home Assistant review; assess each project before installation.

When should you install HACS? Consider it when Home Assistant has no official integration for a device or when a built-in dashboard card cannot meet a requirement. Check official support first, then evaluate the maintenance and security implications of a community package.

Key points of the installation process (see official documentation for details):

  1. Installing HACS itself requires SSH/Studio Code Server to enter HA and execute an installation script (recent versions also support one-click processing using the add-on "HACS Bootstrap").
  2. Then add a Add integration "HACS" to HA, which will display a set of GitHub device codes and URLs; open the URL in a browser, log in to GitHub, and paste the device code for authorization (no need to manually generate a personal access token).
  3. After completion, there will be a HACS icon on the left menu, which is the community package store.

Official HACS installation instructions: https://hacs.xyz. Follow the instructions for your Home Assistant installation type and version.

Common package categories:

  • Custom dashboard cards: mushroom-cards(Modern, compact design),button-card(Extensive customization),mini-graph-card(Compact history graphs),swipe-card(Swipe left and right on your phone).
  • Community integrations: Device and service integrations that are not available through Home Assistant’s official integration catalog. Availability varies by vendor and region.
  • Themes: Google Home, Graphite, Noctis and other community themes.
Warning: HACS packages contain third-party code that Home Assistant does not review., select authors with a large number of stars and recent updates (within 3 months). Do not install a large number of them at once, as they may all break when updating HA.

Four remote-access options

It is enough to use the local network IP to connect to HA at home, but once you go out and want to watch the camera remotely, turn off the lights, and receive notifications, you need an internet connection. There are four mainstream options:

Plan Cost Security Difficulty Best for
Nabu Casa USD $6.5/month high very low Most people. Most households; subscription supports Home Assistant development
DuckDNS + Let's Encrypt free Medium (Exposed public internet) in It needs to be free + have a public IP + be willing to set up a router
Tailscale / ZeroTier Free (individual) highest low Technically confident users who value privacy and do not need public sharing
Cloudflare Tunnel free Middle to high in Works without public internet IP (telecom CGNAT)

1. Nabu Casa (Home Assistant Cloud)—The official paid service. Enable remote access without changing router settings. The subscription also includes Google Assistant/Alexa integration and cloud text-to-speech (TTS), and its revenue supports Home Assistant development.

2. DuckDNS + Let's Encrypt—Use free dynamic DNS service to connect the floating IP at home to a URL (such as myhome.duckdns.org), then use Let's Encrypt to get a free SSL certificate. Need to do port forward on the router. The disadvantage is that it exposes HA to the public internet, which is the solution with the largest attack surface.

3. Tailscale / ZeroTier—A VPN connects your phone to the home network. Install the VPN client on your phone and Home Assistant host, then use a private address while away. This creates very little public exposure, but every authorized user needs the client and access cannot be shared as a simple public URL.

4. Cloudflare Tunnel—Cloudflare establishes an encrypted tunnel between Home Assistant and its network. You do not need a public IP address or an inbound router port. This option works behind carrier-grade NAT (CGNAT), and you can apply Cloudflare access controls in front of Home Assistant.

Security warning

Danger: Never forward HA's 8123 port to the public internet without applying HTTPS credentials. Do not rely on default settings alone to protect an internet-facing Home Assistant instance. Crawlers on the Internet scan port 8123 every day, and as long as it is exposed, it will be attacked. If you use DDNS, you must (1) place an NGINX reverse proxy in front to provide HTTPS, (2) enable Home Assistant multi-factor authentication (MFA), (3) use strong passwords, and (4) consider an additional control such as Cloudflare or fail2ban to reduce brute-force attempts.

If you don't know what the above are, please use Nabu Casa or Tailscale directly instead of opening the port yourself. An incorrect configuration can expose sensitive smart-home data and controls to the internet.

FAQ

Will HACS packages slow down Home Assistant?

Yes, but it depends on which one you install - there are two completely different types of things in HACS:

TypeWhere it runsInfluence
Custom integration (custom integration)Home Assistant Core, sharing the host’s CPU and memoryThe startup is slow, poorly written ones will block the entire startup process, and some will frequently hit external APIs.
Customized cards/themes (Lovelace card, theme)Your browser or mobile appAlmost no impact on the host, just downloading a few more files when the dashboard is first loaded

So "installing 20 beautiful cards" is usually fine, but "installing 8 custom integrations, each of which is polling the cloud" can consume significant resources. HACS itself will regularly check GitHub for updates, but that is a small amount of traffic in the background.

If you suspect who is causing the slowdown, the cleanest way to judge is Open in safe mode (See the next question for how to do it): Safe mode does not load custom integrations, custom cards, and custom themes at all. If it performs normally in safe mode, the answer is obvious.

Tip: Before installing, ask "Is the built-in one really not good?" Many people pack multiple cards, and in the end only two or three are commonly used, and the rest become update risks during updates.
After updating Home Assistant, something installed in the HACS is broken/cannot be turned on. What should I do?

Compatibility failures are an accepted risk of HACS, do not be nervous, follow this order:

  1. Use safe mode to rescue HA

    Settings → System → "Restart Home Assistant" in the upper-right corner → select "Restart in Safe Mode". This will load the HA core, but not any custom integrations, custom cards, or custom themes, so you can at least get into the interface.

  2. Inspect the logs to identify the cause

    Open Settings → System → Logs. A failed custom integration often leaves a group of errors whose first lines identify the affected custom_components package.

  3. Go to the GitHub of that package to see the Issues

    HA has a new version every month. On the day of the major revision, other users may already have opened an issue in the author's repo. Usually, just wait for the author to send an updated version, and press update in HACS to solve the problem.

  4. If you can't wait, remove it first.

    Remove the package from HACS, reboot the system to allow HA to return to normal, and then install it back again. It is better to have one less function than to not be able to use the entire machine.

  5. If you really cannot save it, restore the backup.

    return to Chapter 9 backup and restore process, return to the version before the update. This is why you must have a backup before upgrading.

Make it a habit: Before updating HA, first read the Breaking changes section of Home Assistant release announcement, and then confirm whether the custom integration you have has been updated recently. The package that the author has not touched for half a year will sooner or later break after a major release.
For the same function, when should I run add-ons and when should you look for HACS?

Use "Does this thing need to run a separate program" to classify:

What you wantWhere to find
An independent server program: MQTT broker, Zigbee2MQTT, ESPHome, Node-RED, database, SSHAdd-ons
Let HA recognize a device or service that is not officially supportedCustom integration for HACS
The dashboard should look better, have more special cards, and change the themeHACS Cards/Topics

Zigbee2MQTT is the most confusing example because it Will be encountered on both sides: The program itself is an application (or a container you run yourself). The device appears in HA through the automatic discovery of MQTT integration, and its beautiful network map card is something on HACS. Three things, three places, not the same.

I run it with Docker (HA Container) and there is no app store (formerly known as the add-on store). Am I unable to use these tools?

No, you just have to manage the containers yourself. Let us break it down into two things:

  • HACS still works. HACS supports three installation methods: OS/Supervised, Container, and Core. Container and Core use the same official download script: enter the terminal of the container (or host) and execute it wget -O - https://get.hacs.xyz | bash -, restart HA, go to the integration page to join HACS, and go through GitHub authorization to complete. OS/Supervised is installed directly by adding the HACS app repository. The steps will be adjusted according to the version to hacs.xyz The description shall prevail.
  • The functions of the application must be opened in its own container. To put it bluntly, the application is a Docker container managed by Supervisor for you. Zigbee2MQTT, ESPHome, Mosquitto, and Node-RED all have their own official Docker images. You can docker compose Just write one more paragraph and it will have the same function. The difference is Updates, backups, and interface settings are your responsibility., will not appear in the HA interface, nor will it be included in the HA backup package.
Think clearly first: If you find yourself constantly completing these manual steps, HA OS may be better suited to you. On the other hand, if there are other services running on this machine and you are familiar with Docker, then the flexibility of Container is worth it. This is a trade-off, and there is no standard answer.
Which of the four types of remote connections is the safest?

As far as safety is concerned, the ranking is as follows:

  1. Tailscale / ZeroTier - lowest public exposure

    Because of your HA Never appeared on the public internet. There is no URL to scan, no port to type, and the attacker cannot even find the target. The price is that everyone who wants to use it must install the app and be authorized by you.

  2. Nabu Casa – low-maintenance

    Home Assistant cloud helps you handle credentials and connection channels, and there is no need to open a port on the router. All you have to worry about is your HA account password.

  3. Cloudflare Tunnel - Low public exposure, but it depends on how you set it up

    It is good that you do not need to open a port, but by default the URL is reachable by anyone who has it Yes, except they will stop at the HA login page. To get to the "Secure" level, you need to use identity verification like Cloudflare Access to get in front of it.

  4. DuckDNS + port forward - the most dangerous

    Exposes Home Assistant directly on the public internet. The security warning earlier in this article talks about this approach.

No matter which one you choose, Two-step verification (MFA) must be turned on—The setting method is in Chapter 5. This is the only feature that must be done no matter which plan is used.

Nabu Casa costs $6.50 a month. Is it worth subscribing?

First look at what you are paying for. The current official pricing is $6.5 per month, $65 per year (Eurozone is €7.50 per month, €75 per year), and you can Free trial for one month Decide again. Content includes:

  • Secure remote connection without touching the router.
  • Google Assistant and Amazon Alexa are connected - it is really troublesome to apply for a developer account and set up OAuth to connect these two.
  • Cloud-based text-to-speech (TTS) and speech-to-text (STT) for Assist voice assistant.
  • When the camera WebRTC connection cannot be directly connected to the relay (TURN) server, there will be errors when people look at the camera outside.
  • Subscription revenue supports Home Assistant development.

It is recommended to judge like this:

Your situationSuggestions
You only want remote connection, I do not have a voice assistant at home, and I do not mind if everyone installs the app.Tailscale is free and that is enough
You want Google/Alexa integration, or someone at home does not want to install VPN AppNabu Casa, the time saved far exceeds the money
Often looking at the camera at home outsideNabu Casa, the relay server is difficult to fix on your own
You just want to learn these Internet technologiesBuild it yourself, but follow the security warnings above
Tip: If port forwarding and reverse proxies are unfamiliar, a managed option reduces the risk of exposing Home Assistant through a configuration error. Use the available trial, then evaluate whether the service meets your needs.
Cloudflare Tunnel is free, can I run it to watch my home cameras from outside?

Technically possible, but this is the easiest way to violate service terms. Cloudflare's CDN terms have always had restrictions on "transmitting videos and large files that are not hosted on Cloudflare's own services through it" - later revisions to the terms clearly stated that video content must be placed on Cloudflare's own services (Stream, Images, R2) to be unrestricted. Your camera's live stream obviously doesn't fall into this category.

It probably won't matter if you click on it occasionally to take a look, but if you hang four cameras on the dashboard and stream all day long, you are risking enforcement of the service terms with long-term heavy traffic. Your account could be restricted or closed.

If you want to watch the camera smoothly outside, a more appropriate choice is:

  • Nabu Casa - Camera remote streaming is one of its functions, and TURN relay helps.
  • Tailscale/ZeroTier - It is equivalent to watching on your own private network. There are no third-party terms and conditions, but the display quality will be affected by the phone network speed when the route is far away.

Cloudflare Tunnel is better suited to a connection behind CGNAT whose main requirement is remote control and status checks, rather than continuous camera streaming.
