Chapter 21

Networking and remote access

Make Home Assistant reliable on your local network before exposing it remotely. Configure a stable address, compare four secure remote-access paths, and apply the security rules that must not be skipped.

Why is remote connection the easiest thing to do wrong?

Appendix A Having compared the four remote routes side by side, that article is “Which one to choose?” This chapter is "After making a choice, how to actually do it and what will happen if you do it wrong."

Let me first explain what is special about this level: if you did something wrong in the first twenty chapters, the worst thing is that the lights will not turn on, the automation will not run, and you will feel sad behind closed doors. What went wrong in this chapter is that the door to your home is open for the whole world to see on the Internet.

What’s inside Home Assistant? Is there anyone in each room of your house, door and window switches, camera images, electronic locks, what time do you go out and what time do you come home. If these things are obtained by others, it is no different than the keys being copied. So the order of this chapter is deliberate: First stabilize the local network, and then talk about external affairs. Many people skip the first step and think directly about "how to connect from the outside." As a result, even the home is in trouble.

After reading this chapter you will have these abilities:

  • Pin the IP of the Home Assistant host on the router so it never runs away
  • Understand homeassistant.local Why sometimes it works and sometimes it doesn't, and you know what to do when it doesn't work.
  • Choose one of the four external routes and follow the steps to complete it
  • Do you know why you can’t log in if you don’t set the two lines after the reverse proxy?
  • know what things never do, including the "Open 8123 port forward" tutorial that you will definitely see on the Internet.
Warning: Home Assistant 2026.8 version changes network-related settings Move the entire UI into , originally written in configuration.yaml of http: The block has entered the elimination period. This chapter will focus on the new UI location and the old YAML writing method as a supplement. If your version is older than 2026.8, the screen you see will be different. This is noted in each paragraph below.

Basics of local network: IP, DHCP, and why they must be fixed

It’s fastest to think of it in terms of “building door number”.

Your router is the building administrator. For every device connected to your home's Wi-Fi or network cable—your phone, your laptop, your TV, your Home Assistant console—the administrator will issue it a house number that looks like 192.168.1.37. This is the house number IP Address.

There is a name for issuing house numbers. DHCP. It's automatic, you don't have to do anything, just plug it in and it goes. Convenient, but has a fatal feature: House numbers are for renting, not buying.

The lease will expire. Your Home Assistant console is today 192.168.1.37, restart after a power trip, the administrator may send it 192.168.1.52, while .37 You were given a new sweeping robot.

What will be damaged if the house number is lost?

Internal URL set by the mobile appI can't connect at home, but when I go out, I can use the cloud normally. It's super counter-intuitive.

So the rules are simple: The IP of the Home Assistant host must be fixed. This is not an advanced technique, this is step zero that must be done.

Learn MAC address easily

To make a reservation on the router, you must first let the router recognize "which one is Home Assistant." The way to recognize it is MAC Address —A set of numbers that are engraved into each network card at the factory. They look like DC:A6:32:1B:4E:F0.

The house number will change, but the MAC will not. So the reservation rule on the router actually says: "Whenever the guy who sees this MAC string comes and asks for the house number, give it to him. 192.168.1.37.”

Do it yourself: Pin the host IP and confirm the network page

  1. Find out the host’s IP and MAC in Home Assistant

    go Settings → System → Network. This page will list your host's network interface (wired, wireless) and the IP address it currently has. Copy the IP.

    The MAC address may not be displayed on this page. The best place to look is in the router's list of connected devices. —Open the router management page and look for the name containing homeassistant, or the one whose IP is the same as the one you just copied down, the MAC will be listed next to it. This also has another advantage: if you want to make a reservation later, you have to do it on the router, and you are already there.

  2. Log in to the router management page

    The router's management URL is usually 192.168.1.1 or 192.168.0.1, is also often printed on a sticker under the machine. The password is also on the sticker - if you have never changed the default password, Change it now, which is the foundation for all subsequent security measures.

  3. Find the DHCP reserved settings page

    Every router has a different name, and this is the trickiest step. Common names include: DHCP reserved address, DHCP Reservation, Address Reservation, Static DHCP, Static Lease, fixed allocation. The location is usually under "Local Area Network/LAN" or "Advanced Settings → DHCP Server".

    If you can't find it, use your router model to search for "Model + DHCP Reserved". This feature is available even on the cheapest home computers, but it’s just hidden deep inside.

  4. Add a new reservation

    Fill in the MAC address copied in step 1 and specify the IP you want to give. It is recommended to choose a number that is easy to remember and difficult to bump into, for example 192.168.1.10. Write "Home Assistant" in the remarks column, and you will thank you now three months later.

    Archive. Some routers need to be restarted to take effect.

  5. Let the host get the number again

    After the reservation is set, the host will not be changed immediately until the old lease expires. The fastest way is to restart the Home Assistant host (Settings → System Power menu in the upper right corner → Restart system), or unplug the network cable.

  6. Acceptance

    After reopening, return to Settings → System → Network, confirm that the IP displayed is the one you specified. Then use the new IP to open the webpage, and you can log in normally and it will be successful. Bookmark this URL instead of your original one.

  7. Fill in the internal URL

    Also in Settings → System → Network This page has two spaces: "Internal URL" and "External URL". Fill in the internal URL with the one you just pinned, for example http://192.168.1.10:8123.

    These two grids Just fill in the connection port and don’t add the path later.. fill in http://192.168.1.10:8123/lovelace This way of writing will cause the subsequent link generation function to receive a strange URL, which is a common cause of trouble.

Concept: Why are these two boxes important? Because Home Assistant uses these two boxes when it generates notification links, pushes camera images to the phone, or tells the app "where you should go." If you fill it in incorrectly, the symptoms will be very strange: all the functions are there, but you can’t access the notification when you click on it.

What is homeassistant.local and the number 8123?

The magic behind .local URLs is called mDNS

When you first installed Home Assistant, the tutorial asked you to homeassistant.local:8123, and then it works. This thing is actually a bit magical - you don't have a DNS server at home, who tells you where this string of characters on your computer is going?

The answer is mDNS (Multicast DNS, multicast DNS). In plain English, the way it works is shouting in the classroom:

  1. Your computer broadcasts to the entire local network

    "Is there anyone called HomeAssistant?" This sentence is sent out in a multicast manner, and every machine in the same network segment can hear it.

  2. Home Assistant host raises hand

    "I am, I'm at 192.168.1.10."

  3. Write it down on your computer and connect directly.

    The whole process does not require any server, it all relies on shouting. The Apple side calls this Bonjour, and the Linux implementation is called Avahi, which is actually the same thing.

Why it often fails

Because "shouting" can be blocked in many ways:

Failure reasonHow to judgeSolution

The device's Wi-Fi has "Client Isolation" turned onThe phone can connect to the external network, but cannot connect to any machine at home.Turn off the router’s AP Isolation / Client Isolation

Warning: The most important sentence— homeassistant.local It will never work on the external network. It is not your public URL and cannot be used to set up port forward. I saw someone asking "I can't connect to homeassistant.local when I call it outside." The answer is this.

The number 8123, changes after 2026.8

If the IP is a house number, The port is the extension number behind the house number.. The same machine can run many services at the same time, and the extension number is used to distinguish who is who. The number that Home Assistant historically uses is 8123, so the URL must be written as http://192.168.1.10:8123.

But this matter has changed in version 2026.8, and the changes are worth knowing:

your situationDefault portHow long is the URL?

The system that was running before 2026.8 was upgraded.maintain 8123http://homeassistant.local:8123

Home Assistant statement on the revision is very clear: Nothing will change on systems that are already running and you don’t need to do anything. This only affects fresh installations of Home Assistant OS. In other words, most teachings on the Internet :8123 It's probably right for you.

Why change? because 80 It is the default number of the web page, and the browser will automatically fill it in, so the URL can be shortened - purely to reduce the threshold for novices.

Tip: After 2026.8 you can Settings → System → Network Change the connection port. Home Assistant has put a very considerate insurance policy here: After making the changes, the system will wait for you to confirm "Is it still connected?" If you don't confirm within five minutes, it will treat it as something wrong and automatically put back the old settings and restart. So even if you change for the worse, you won't lock yourself out.

Choose in thirty seconds

  • Don’t want to bother, want to use Alexa or Google Voice, and want to support official development → Nabu Casa. This is also the option that Home Assistant documentation itself labels as "the simplest and safest for most people."

Route 1: Home Assistant Cloud (Nabu Casa)

This is an official subscription service operated by itself. The subscription fee goes directly back to support the development of items such as Home Assistant, ESPHome, and Z-Wave JS. Therefore, it is at the same time “the easiest solution” and “the most direct way to sponsor”.

What it provides

Your host actively establishes a connection with Nabu Casa's server, and all subsequent requests from the outside come in through this existing connection. There is no need to make any holes in your router —This is why it is not afraid of CGNAT or your IP changing every day.

Implementation steps

  1. Find cloud settings

    go Settings → System → Network, under "Home Assistant URL" Internet In that column, turn on "Use Home Assistant Cloud". Another entrance is Settings → Home Assistant Cloud, both sides can go to the same place, whichever is on your screen.

  2. Register or log in to an account

    Register a Nabu Casa account using email. This is different from the account you use to log into Home Assistant., don’t get confused. When registering, you can choose "Start a one-month free trial" without paying upfront.

  3. Turn on the remote connection switch

    After logging in, turn on the remote control switch. The system will allocate a fixed set of URLs to you. The format is a long string of codes plus .ui.nabu.casa, for example https://abcd1234-ef56-7890-abcd-ef1234567890.ui.nabu.casa.

    It's ugly, but it's HTTPS, it's unique, and it won't change.

  4. Save the URL into the mobile app

    Open the Companion App (Chapter 7 The one that is installed), go to the App settings and fill this URL into the "External URL". The internal URL maintains your IP on the local network. The app will decide which one to use now.

  5. Test

    Turn off your phone's Wi-Fi, use only the mobile network, and open the app. If you can get in, you will be successful.

Warning: Home Assistant document has an easy-to-follow explanation: For connections coming through Home Assistant Cloud, all IP addresses from the system’s perspective are 127.0.0.1. This means that the "IP Blocking" function to be discussed later has little ability to identify cloud connections - blocking one is equivalent to blocking all cloud users. This is why people who use Nabu Casa Rely on MFA more than IP blocking.
Tip: If you have your own domain, official support is to change the default URL to home.yourdomain.com This kind of custom URL. This function requires Home Assistant 2023.9.0 or above. The setting method is to add it in the Nabu Casa account and add a corresponding record to your DNS service provider.

Tip: The Cloudflare dashboard can add another layer of access control, requiring verification before accessing the Home Assistant login page. For people who say "I don't want my login page to be scanned by the whole world", this is the biggest plus point of this path.

Route 3: VPN (Tailscale or WireGuard)

The first two paths are to "put Home Assistant securely on the Internet." VPN is a completely different idea: Connect your phone to your home network.

The metaphor of a key is the most vivid: the first two are to install a very strict guard at the door, but the VPN has no door at all, and only the person who gets the key knows that the house exists. Because Home Assistant has never been open to the public network from beginning to end, This is the strongest security path among the four..

Tailscale: Newbies should choose this directly

Tailscale helps you automate all the hardest parts of VPN (key exchange, hole drilling, and path finding). It can even pass through CGNAT, which is important for users behind carrier-grade NAT in any region.

  1. Register for a Tailscale account

    Just log in with a Google or GitHub account, and the free quota for personal use is more than enough for family scenes.

  2. Join the community app repository

    go Settings → Apps → Install App → Three-dot menu in the upper right corner → warehouse, join https://github.com/hassio-addons/repository. This is the repository for Home Assistant Community Add-ons (now called Community Apps), which includes Tailscale and WireGuard.

  3. Install and start Tailscale

    Start after installation, and then View log file tab, there will be an authorization URL inside. Open it with a browser and add the machine to your Tailscale network.

  4. Tailscale is also installed on phones

    Install the Tailscale App from the App Store or Play Store and log in with the same account.

  5. Connect with Tailscale URL

    After connecting to the VPN, you can use Home Assistant to connect to an address on the Tailscale network. If MagicDNS is turned on, the URL will look like homeassistant.tail1234.ts.net This format (tail1234 It is assigned to you by the system).

Concept: Tailscale App has one called advertise_routes The default setting is to share your home's local network segment. The advantage of turning it on is: after connecting to the VPN, you can not only connect to Home Assistant, but also the NAS, printer, and router management pages at home, which means that the entire network line is connected to your phone. Very useful during maintenance.
Warning: If you use Tailscale's Serve or Funnel function to share externally, the traffic will pass through a layer of local proxy. Also set up a trusted proxy, and the trusted address is 127.0.0.1. If you don't set it, you will keep being asked to log in but unable to log in. Simply using VPN direct connection (without turning on Serve/Funnel) does not require this step.

Warning: The VPN path has inherent limitations— Cloud voice assistants such as Alexa and Google Assistant cannot be used. Because their servers are on the Internet, not in your VPN, they will never be able to connect to your Home Assistant.     The default certificate file name is fullchain.pem and privkey.pem, don’t change it without any special reason.

    This app takes the voucher DNS-01 Verification — In plain words, "Let's Encrypt will not connect to your home, it will check the DNS record of your domain to confirm that the domain is yours." So Just to get the credentials, you don’t need to make any holes in the router.     Do not open any one except 443. —especially 8123 Never transfer (That is equivalent to hanging the unencrypted login page directly on the Internet. See the next section for the reason).   7. Fill in the external URL and test

    Go to Settings → System → Network, fill in the external URL https://yourdomain.duckdns.org. Then turn off the phone Wi-Fi test.

So those who take this path, The section on "Information Security Hard Rules" that follows is required reading, not optional reading..

Behind the reverse proxy, you will not be able to log in if you do not set these two settings.

This section is the most frequently asked help question in the entire chapter. As long as you use Cloudflare Tunnel, NGINX, Tailscale Serve/Funnel, or any form of reverse proxy, Will encounter.

Why it breaks: Home Assistant sees the agent, not you

Under normal circumstances, when Home Assistant receives a request, it will look at "Which IP this request came from" to record the login, determine whether it is an intranet, and perform IP blocking.

But after inserting a reverse proxy in the middle, all requests will appear in the eyes of Home Assistant. They all come from the agent's machine.. You are in one city and a family member is in another, and there is a Russian scanning robot - they all look exactly the same.

The solution is that the agent will attach a note to the request saying X-Forwarded-For, it says "The real source of this request is xxx". But Home Assistant Default is not to trust this note, because anyone can forge it - if you believe it casually, an attacker can just forge a note that says "I am 127.0.0.1" and install to be this machine.

So you have to explicitly tell Home Assistant two things: (1) Please trust this note; (2) Only notes from these IPs count.

Danger: Official documentation describe the incident as " If these options are not set, requests from the reverse proxy will be blocked”, and this is a deliberate design behavior, not a bug. The description of NGINX App is more specific: "Requests received through this proxy 400 Bad Request, then you probably missed it trusted_proxies settings. "The symptoms are usually being able to open a webpage, entering the account password but not being able to enter, or simply getting a 400."

Hard rules for security: these things are non-negotiable

Home Assistant safety checklist actually only lists three core principles: "Use a strong, unique password for each account and turn on multi-factor authentication.", "Put sensitive data in secrets (remember to back up)", "Follow monthly version updates". Here are the actions you should take to put them into practice today.

Warning: There is a point in Article 2 that many people have misunderstood, and Home Assistant specifically noted: put password in secrets.yaml It will not be encrypted. That's just for "centralized management so that you can share your profile without leaking it," not a safe. Therefore, the backup files should be treated as confidential, and do not throw away the public folder of the cloud drive (see the backup processing Chapter 9).

Rule 1: Do not port forward 8123 directly to the public network

Danger: The most common tutorial on the Internet - "Add a rule to the router to transfer 8123, and you can connect from the outside" - is the only practice explicitly prohibited in this chapter. There are three reasons, each of which is fatal:
(1) The default is http:// Without encryption, your account password is The plain text of streaking, any intermediate node can be seen.
(2) Scanning robots scan 8123 all over the world all day long. You will be found within a few minutes of driving, and then there will be non-stop brute force cracking.
(3) Once Home Assistant is compromised, it means that all your door locks, cameras, and records of whether you are home or not are handed over.

If you have already opened it, Now go to the router and delete that rule., and then choose one of the first four paths to redo. This is no exaggeration, this is the most important sentence in this chapter.

Rule 2: Be sure to open an MFA

Multi-factor authentication (MFA / two-step verification) means that it’s not enough to have a password, but also to enter a six-digit number that changes every 30 seconds on your phone. If the password is leaked, the attacker still can't get in without your phone.

  1. Open the secure tab of your profile page

    Click your name in the lower left corner to enter User profile, cut to Security Tab.

  2. Enable multi-factor authentication module

    Find the area "Multi-factor authentication modules" and click Enable.

  3. Scan the QR Code using the validator app

    First install a validator app on your phone, scan the QR Code on the screen, and then fill in the six-digit number displayed by the app to confirm.

  4. Keep the backup code

    backup information given to you during the setup process Must be stored somewhere other than your phone. If your phone is dropped and there is no backup, you will be locked out of your home.

  5. Do this once for every account in the family

    It’s useless if you open it yourself. Your family member’s account password is 123456 It's the same breach. Chapter 5 There are complete instructions for multi-user management.

Tip: In addition to the authenticator app, Home Assistant also has a notification-based authentication module that will send the one-time password to the place you specify through notifications. But official documentation warn of its weaknesses: This module has no way of knowing whether the notification was successfully delivered. If you don't receive the notification, you won't be able to log in. Therefore, the main force is to use the authenticator app which is more stable.

Rule 3: Turn on IP blocking

Home Assistant has a built-in function: If the same IP fails to log in for a certain number of times, it will be blocked.. This is the most effective way to deal with brute force cracking.

Set location at Settings → System → Network, two fields:

The blocked IP will be written into a file called ip_bans.yaml file, which contains The blocked IP and the UTC time it was added to. To unblock it, just delete the corresponding lines and restart.

Warning: Two common failure scenes.
(1) When using Home Assistant Cloud, Home Assistant stated that all cloud connections appear to be 127.0.0.1, so IP blocking is basically ineffective against them, and your line of defense depends on MFA.
(2) If the reverse proxy does not set up a trusted proxy, all requests will appear to come from the proxy. Blocking one is equivalent to blocking all - you will also lock yourself out. This is back to the previous section. First, let’s trusted_proxies Let it be right.

Site level: VLAN, guest network, multi-layer NAT

What I talked about before was “one home, one router”. If you are dealing with an office, a store, or a more elegant residence, there will be three more questions.

Put IoT devices into separate network segments

The problem lies with cheap smart sockets, light bulbs, and camera bodies: their firmware quality varies, and some are never updated after using them. A compromised smart socket, if it is on the same network segment as your laptop or NAS, is a ready springboard.

The solution is VLAN (Virtual Area Network): Cut out several mutually isolated logical networks on the same set of physical wires. A common cutting method:

Network segmentWhat to putWho can be reached?
Main network segmentComputer, phone, NAS, Home Assistant hostCan connect to all network segments
IoT network segmentSockets, light bulbs, sensors, TVsYou can only connect to the external network and cannot actively connect to the main network segment.
Camera segmentIP Cam, NVRmost stringent, usually Even external networks are prohibited, only allows Home Assistant to capture the screen
Guest segmentGuest's phoneI can only access the Internet and cannot see anything in your home.
Warning: After switching to VLAN, you will almost certainly encounter Device automatic exploration all failed. Because Home Assistant relies on mDNS "shout" to find new devices, and the shout will not cross network segments by default. You need to additionally enable mDNS forwarding on the router or firewall (different brands have different names, common ones include mDNS Repeater, Avahi Reflector, Bonjour Gateway), and open the necessary one-way rules to allow Home Assistant to actively connect to the IoT network segment. Cutting VLAN without dealing with this matter is the most common reason for overturning the case.
Tip: If your router only has a "guest network" switch and does not have full VLAN functionality, it is a simplified version of two-segment isolation - throw the least trusted devices and guests into the guest network, and leave the main network segment for serious devices. It's rough, but much better than all mixed together, and it can be done this afternoon.

Multi-layer NAT: Two routers at home

A very common situation: the modem provided by the telecommunications provider is itself a router. You think it has poor Wi-Fi, so you connect it yourself. The result is a two-layer NAT, and your Home Assistant host is actually hiding behind two doors.

How to judge: Log in to your own router and look at the WAN IP. if it shows 192.168.x.x or 10.x.x.x With this kind of private address, you're under multiple layers of NAT.

SolutionpracticeEvaluation
Change the telecommunications provider's machine to bridge modeCall telecom customer service and ask them to change it, or set it yourself on the modem management page.Cleanest. From now on there is only one layer of NAT
Both floors are equipped with port forwardThe outer layer forwards it to the inner layer router, and the inner layer forwards it to the host.Active but fragile, if you reset any level, you will have to start over again.
Switch to a solution that does not require port forwardNabu Casa, Cloudflare Tunnel, TailscaleThe most trouble-free. Multi-layer NAT is no problem for them

See the third column? This is why this chapter pushes those three paths all the way - They bypass the three most annoying problems of CGNAT, multi-layer NAT, and floating IP at once.

Pre-delivery checklist

  • The host IP has been reserved on the router and recorded in the handover file
  • The router management password has been changed and is not the factory default.
  • The internal URL and external URL have been filled in and tested
  • MFA is turned on for all accounts and IP blocking is enabled
  • There is no rule on the router pointing to 8123
  • UPnP and router remote management are closed
  • The backup is scheduled and saved to a location other than the host (Chapter 9)
  • If there is a VLAN: mDNS forwarding has been configured and new device discovery has been tested
  • The expiration and renewal mechanism of the voucher has been confirmed to be automatically executed.

Common problems

  1. Certificate application failed, Let's Encrypt keeps reporting errors

    Let’s figure one thing out first: Duck DNS App uses DNS-01 verification, Let's Encrypt checks the DNS records of your domain and will not connect to your home. So "I can't get the voucher" Usually it has nothing to do with port, don’t rush to dig holes in the router.

    Check in this order. (1) Are the DNS settings correct?:Duck DNS has the domain over there really been built, has the token been posted incorrectly, and if you have connected your own domain, has the CNAME used for verification been added? (2) Is DNS effective?: It will take some time for the newly modified record to be visible to the entire network. If you press it too early, it will fail. (3) Have you accepted the terms?: In Duck DNS App accept_terms Forgot to change to true It's a UHF error. (4) Is the current flow restricted?: Let's Encrypt has an upper limit on the number of applications for the same domain within a short period of time. If you try again and again, you will be locked for a period of time - the only solution at this time is stop and wait, continuing to press will only make things worse. (5) View the App’s log files, the real reasons for the error are written there, don’t just read the red letters.

  2. You can connect at home, but you can’t connect when you go out (or vice versa)

    Almost all are problems with the internal and external network URL settings. Go to Settings → System → Network Confirm internal and external URLs Both boxes are filled in, and both are filled in correctly.. Then open the settings of the Companion App on your phone and confirm that the App also has these two URLs.

    Special reminder: these two spaces Stop filling in the connection port and do not continue to follow the path.. Fill in .../lovelace This will cause notification links and camera push notifications to lead to strange URLs, and the symptoms are all kinds of strange and difficult to associate here.

    Another situation is that "it works fine when I go out, but not when I go home." Usually the IP written in the internal URL has expired - go back to the first section of this chapter to nail the IP.

  3. The web page can be opened, but after entering the account password, it cannot be entered, or it will directly get 400

    This is a typical symptom of the reverse proxy not having a trusted proxy. Return to the section "Reverse proxy must be set up" and set Trust X-Forwarded-For open, Trusted proxies Fill in the correct address (App-based agents are 172.30.33.0/24, Tailscale Serve/Funnel is 127.0.0.1), save and restart.

    If it still doesn't work if you have set it up, check whether it is set in the old configuration.yaml But the version has been upgraded to 2026.8 - at this time, it is time to refer to the UI value and delete the YAML block. If you can’t find the settings in the UI after deleting them, forcefully refresh the browser first.

  4. DDNS is set up, but still cannot be connected to the outside - CGNAT

    First make the judgment taught in this chapter: Is the IP displayed on the WAN of the router different from the "My IP" you find online? The difference is CGNAT (Telecom operators allow hundreds of households to share an external IP).

    CGNAT bottom, DDNS and port forward are all invalid, this is not a setting problem, it is that you simply do not have an external door number of your own. There are three options: (1) Call the telecom provider and ask if you can apply for a real IP, which usually requires adding money or changing plans; (2) Go to Nabu Casa, Cloudflare Tunnel or Tailscale instead, these three are completely unaffected; (3) Give up the far end. Ninety percent of people should choose (2).

  5. homeassistant.local suddenly stops working

    Make sure you are home first. Double check that the phone is not connected to guest Wi-Fi or another network segment. If everything is correct, use IP direct connection to verify that the host is still alive - if you can use IP to get in, it means it is just an mDNS problem, not that the host is down. The long-term solution is to peg the IP and use the IP as a bookmark instead, which will be the least likely to happen.

  6. Can't connect after changing the port

    If you changed the UI after 2026.8, Don't be nervous, don't do anything —Home Assistant design is to wait for your confirmation after the change is completed. If there is no confirmation within five minutes, the old settings will be automatically put back and restarted. Make a cup of tea and wait for it to come back on its own.

    If it is an old version or the Container installation has been manually modified, you have to change it back from the host (connect the screen keyboard, or change the Docker port corresponding).

  7. Blocked by own IP block

    Typing the wrong password too many times triggered the block. The solution is to edit from the host side ip_bans.yaml, delete your own, and then restart Home Assistant. If you can't access the file, try another network (for example, turn on a mobile network hotspot on your phone), and your IP will change.

  8. New device cannot be found after switching VLAN

    Within expectations. Automatic discovery relies on multicast traffic that does not cross network segments. Go to the router or firewall to enable mDNS forwarding (mDNS Repeater / Avahi Reflector / Bonjour Gateway), and confirm that there are rules that allow Home Assistant to actively connect to the IoT network segment.

FAQ

I just want to check whether the lights at home are on outside. Do I really need to make it so complicated?
No need. Pay to subscribe to Home Assistant Cloud, turn on a switch, and it's over in five minutes, and Home Assistant documentation itself lists it as "the simplest and safest option for most people." The reason why this chapter is thick is to take care of people who do not want to pay, want to learn networking, or have special circumstances (cases, multi-layer NAT). If your time is worth more than a few hundred bucks a month, just subscribe without feeling guilty —The money was directly used back to support this open-source project.
The teachings I saw on the Internet all said that just opening the 8123 port forward would be sufficient. Why do you say no?
Because most of those teachings were very old, and the threat environment was different when they were written than it is now. Three specific reasons: no encryption (The default is http://, the account password is in clear text on the Internet), will be scanned (Scanning robots scan for 8123 all over the world all day long, and usually come to your door within a few minutes), The consequences are too serious (Home Assistant contains your door locks, cameras, and records of whether you are at home or not). All four paths described in this chapter achieve the same results and are much safer, so there is no reason to take that one.
My Home Assistant has been upgraded from 2026.8, do I need to add :8123 to the URL?
Want. Home Assistant revision description made it very clear: Nothing will change on the system you're already running, and you don't need to do anything. The new presets only affect newly installed Home Assistant OS. So your original :8123 Just keep using it. If you really want to switch to a version that doesn’t require dialing a number, you can get it after 2026.8 Settings → System → Network Change it yourself, and it will automatically recover within five minutes if it is changed. The risk is not high - but after the change, remember to update all bookmarks, app settings, and reverse proxy settings.
mine configuration.yaml There is http: Block, do you want to delete it now?
Want. from 2026.7.5 When the version starts, Home Assistant will pop up a warning saying that the HTTP YAML setting has been eliminated and the setting has been imported for you. Please import it for you. http: Block removed and noted "This will stop working in version 2027.2.0, please deal with it before upgrading". When upgrading, your original settings will be automatically imported into the UI. The correct method is: first come first Settings → System → Network Confirm that the settings are all in (trusted_proxies Pay special attention to whether they have been brought over correctly), and then take them after confirming that there is no problem configuration.yaml the whole inside http: Delete the block and restart. If you can’t find the setting on the UI after deleting it, force refresh the browser first.
Can Nabu Casa and Tailscale be opened at the same time?
Yes, and it's a very practical combination. Nabu Casa is for daily use by your family (you can use it by just posting the URL, and can also connect to voice assistants), and Tailscale is for you to maintain yourself (after connecting, you can access the entire home network, and you can open the router management page and NAS). The two do not interfere with each other. The only thing to note is that if Tailscale has Serve or Funnel enabled, remember to 127.0.0.1 Add to list of trusted agents.
Why can’t I use Alexa or Google Voice on the VPN route?
Because the logic of VPN is to "pull your device into the home network", and the servers of Alexa and Google Assistant are on the Internet, they cannot join your VPN, so they will never be able to connect to your Home Assistant. If you want a cloud voice assistant, you have to go to Nabu Casa (this connection is included in the subscription), or switch to a voice solution that runs completely locally and does not require external connections (Chapter 19).
Trusted proxies I can be lazy and fill in 0.0.0.0/0 ? Anyway, no one in my family wants to be hacked.
No, this is the most non-negotiable aspect of this chapter.0.0.0.0/0 means "I trust the source IP claimed by anyone." The attacker only needs to forge a request X-Forwarded-For header, you can install to be any IP - your IP blocking is completely invalid, your login records are all fake, and you can't even trace it afterwards. And "no one wants to hack me" is an illusion. The scanning robot doesn't pick targets, it scans the entire Internet. The correct approach is to only fill in the proxy address that you really know: fill in the App-type proxy address 172.30.33.0/24, fill in Tailscale Serve/Funnel 127.0.0.1.
I'm not sure if I'm under CGNAT, how can I confirm it in thirty seconds?
Just compare the two numbers. first one: Log in to the router and find the external IP displayed on the WAN status page. second: Search "My IP" on your phone or computer to see the IP the website tells you. Both are the same It means you have a real external IP, DDNS is the way to go. Two different There is a layer of telecom operators between the representatives, and you are under CGNAT. Also, if the router WAN IP falls on 100.64.x.x Arrive 100.127.x.x This section is reserved exclusively for CGNAT by telecom operators and can be determined directly. Please use Nabu Casa, Cloudflare Tunnel or Tailscale under CGNAT, these three will not be affected at all.
Why do I enable IP blocking, but all attack records show 127.0.0.1?
Two possibilities. The first type: You are using Home Assistant Cloud. Home Assistant documentation clearly states that “If you use Home Assistant Cloud for remote access, all cloud connections will be displayed as IP 127.0.0.1”, this is normal and means that IP blocking has no discernible effect on cloud connections - your line of defense depends on MFA. The second type: You have a reverse proxy but haven't set up a trusted proxy, so all requests appear to come from the proxy itself. In this case, you must not press block, because blocking one is equivalent to blocking all (including yourself). Go ahead and block trusted_proxies Let it be right.
After cutting VLANs to isolate IoT devices, can Home Assistant still find them?
It requires additional settings to find it. Automatic discovery relies on mDNS's "shout within the network segment" mechanism. By default, the shout will not cross VLANs, so you will find that all new devices cannot be discovered. The solution is to enable mDNS forwarding on the router or firewall (each name is different: mDNS Repeater, Avahi Reflector, Bonjour Gateway), and additionally allow the Home Assistant host One way Connect to the IoT network segment (the IoT side still cannot connect back to the main network segment). This is the most common cause of overturning at the scene. Before proceeding, make sure your network device supports these functions.
