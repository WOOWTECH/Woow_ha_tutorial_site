裝機前傳：硬體選擇與 HAOS 安裝

這本書從第 1 章開始，就假設你手上已經有一台跑著 Home Assistant 的主機。如果你根本還沒有那台機器，這篇就是你的第 0 步：挑主機、挑儲存媒體、把系統燒進去、插電開機、建立第一個帳號。走完這篇，你可以直接接到第 1 章往下讀。

為什麼需要一台自己的主機

你可能已經看過本站前面幾章，覺得「這個我想玩」，然後卡在一個很現實的問題：那個 Home Assistant 到底裝在哪裡？

Home Assistant 不是一個手機 App，也不是一個網站帳號。它是一套跑在你家裡某台電腦上的軟體，24 小時開著、接在你家的路由器上、跟你家的燈跟感測器講話。所有資料都留在你家，這正是很多人選它的原因，但代價就是：你得先有那台「電腦」。

這台電腦可以是一顆手掌大的 Raspberry Pi、一台官方賣的小盒子、一台二手迷你電腦，甚至是你家 NAS 上開的一個虛擬機。這篇會把選擇攤開來比，然後帶你把系統裝好。

觀念：這台主機在 Home Assistant 的世界裡通常被叫做「主機（Host）」或「實例（Instance）」。它就是你家自動化的大腦，斷電就整套停擺——所以後面的電源與備份段落請務必看完。

讀完這篇你會有的能力：

  • 看得懂四種安裝方式的差別，並且知道自己該選哪一種（劇透：選 HAOS）。
  • 依照你家的規模與預算，挑出一台不會後悔的主機。
  • 自己把系統映像檔燒進 SD 卡或 SSD，插電開機。
  • 完成首次設定（Onboarding），建立擁有者帳號、設定家的位置。
  • 知道哪些坑最容易踩：找不到主機、開不了機、隨機重開。

四種安裝方式：新手就選 HAOS，沒有懸念

網路上的教學會提到四個名字，很容易讓人混淆。先講結論：如果你是第一次裝，選 Home Assistant Operating System（簡稱 HAOS），不要想別的。

官方文件本身現在也只主推兩種：HAOS 與 Container。Core 與 Supervised 這兩種在 2025 年 5 月被官方宣布棄用（Deprecate），官方公告的時程是從 2025.6 版開始跳提醒、到 2025.12 版正式終止支援，同時被砍掉的還有 32 位元的 i386 / armhf / armv7 架構。官方給的搬家建議是：原本用 Core 的搬到 Container，原本用 Supervised 的搬到 HAOS。

安裝方式它是什麼能用 Apps（原「附加元件」）嗎現在的狀態適合誰
HAOS
（Home Assistant Operating System）		 一整套作業系統。整台機器從開機到 Home Assistant 全部由它包辦，你不用碰 Linux。 可以，全部功能都在 官方主推、官方推薦 所有新手，以及九成以上的人
Container 在你自己的 Linux／Docker 環境裡跑一個 Home Assistant 容器。 不行 官方仍然支援 本來就有 Docker 主機、且很清楚自己在做什麼的人
Supervised 自己管一套 Debian，再把官方的 Supervisor 裝上去。 可以，但要自己維護底層 已棄用，2025.12 起終止支援 不建議新設，官方請你搬到 HAOS
Core 直接在 Python 環境裡跑 Home Assistant 程式本體。 不行 已棄用，2025.12 起終止支援 不建議新設，官方請你搬到 Container
注意：Container 少掉的不只是「方便」。官方文件明講，像 Thread 與 Z-Wave 這類整合是靠 Apps 在背後撐著的，Container 安裝沒有現成支援。你如果打算之後玩 Zigbee／Thread／Matter 的無線裝置，這是很致命的差別。
提示：從 2026.2 版開始，官方把原本的「附加元件（Add-ons）」正式改名叫 Apps（應用程式），面板位置也從「設定 > 附加元件」變成 設定 > Apps。官方給的區分方式很好記：Apps 是跟 Home Assistant 並排跑的獨立程式，整合（Integration）是把 Home Assistant 接到你的裝置與服務。附錄 A 講的就是這一塊。

硬體怎麼挑：五條路線攤開來比

先建立一個心理座標：Home Assistant 本身不吃效能，一般家庭裝個三五十個裝置，一顆四核心的 ARM 晶片配 4GB 記憶體綽綽有餘。真正會把主機拖垮的是你之後加上去的東西——攝影機錄影與影像辨識、本地語音助理、資料庫累積的歷史紀錄。所以「現在夠用」跟「兩年後還夠用」是兩件事。

路線效能感受價位帶概念適合的規模要注意什麼
Raspberry Pi 4（至少 2GB RAM） 夠用，開機與更新偏慢 入門 幾十個裝置的一般家庭 官方明訂最低 2GB RAM；建議直上 4GB。務必配 SSD，別長期用 SD 卡
Raspberry Pi 5 明顯比 Pi 4 快，儀表板反應乾脆 入門偏中 一般到中型家庭 吃電比 Pi 4 兇，電源要求較高（見電源段落）
Home Assistant Green（官方硬體） 跟 Pi 4 同級體感，但完全免調校 中 只想開箱即用、不想折騰的人 32GB eMMC 是內建焊死的，容量之後不好擴
迷你電腦（Intel N100 這類 x86） 最快，一台可以同時跑很多東西 中到中高 大型家庭、多攝影機、想跑本地語音／AI 要自己進 BIOS 設定；體積與耗電比 Pi 大
NAS 上開虛擬機 看 NAS 本身的等級 如果 NAS 已經有就等於零成本 本來就有 NAS 且 24 小時開機的人 NAS 重開機＝家裡自動化全停；USB 無線電棒穿透虛擬機常出狀況
舊筆電 通常很夠用，甚至過剩 零（家裡本來就有） 想先試水溫、不想花錢 要能 UEFI 開機並關掉 Secure Boot；電池老化反而是風險

官方硬體現況（這一段特別容易過時）

Home Assistant Green 是目前官方主推的現售機種，規格是 Rockchip RK3566、四核心 ARM Cortex-A55 1.8GHz、4GB 記憶體、32GB eMMC 儲存，另有一個 microSD 插槽做救援用。介面上有 Gigabit 乙太網路、兩個 USB 2.0、一個給診斷用的 HDMI，鋁製散熱片被動散熱不用風扇。盒裝就附一條 Gigabit 網路線跟一顆 12V / 1A 的萬用電源（含 EU／US／UK 三種插頭轉接頭，台灣插座跟美規同型，用 US 那顆就好），插上去就能用。官方頁面標示的建議售價是 US$199 / €179，但各地經銷商實際價格差很多，請以你買的通路公告為準。

Green 有一個規格值得先知道：官方標示兩個 USB 2.0 埠合計最多供到 5V 2A。這代表你之後如果想在上面插沒有獨立供電的 USB 硬碟，要先確認它吃得動；插 Zigbee 無線電棒這種小東西則完全沒問題。

Home Assistant Yellow 已經停產了。官方頁面寫得很清楚：這個產品不再生產，但仍持續收到軟體更新，並建議新買家改買 Green。所以你如果在拍賣網站上看到二手 Yellow，要知道它是什麼定位：它用 Raspberry Pi Compute Module 4、有一個 M.2 M-Key 插槽可以插 NVMe SSD（2230／2242／2260／2280 都支援），還內建一顆 Silicon Labs MGM210P 無線模組，同時支援 Zigbee 3.0、OpenThread 與 Matter。內建無線電這點是它最大的賣點——但既然停產了，新手不要為了它去追二手。

另外還有 ODROID 系列（官方安裝文件目前涵蓋 N2、N2+、C2、C4、M1、M1S），走的是類似 Pi 的路線但用 eMMC 模組。要注意 M1 的文件明講不支援從 NVMe 開機，N2+ 與 M1S 則是把板子用 USB-OTG 線直接接到你的電腦上、讓它變成一顆「隨身碟」再燒進去，程序跟 Pi 不一樣。這條路對新手不太友善，除非你剛好手上就有。

提示：如果你打算玩 Zigbee 或 Thread／Matter 裝置，主機本身通常沒有內建這些無線電，要另外插一根 USB 無線電棒。官方目前在賣的是 Home Assistant Connect ZBT-2（Silicon Labs MG24 晶片，另外用一顆 ESP32-S3 當 USB 控制器），它取代了已停產的 ZBT-1（舊名 SkyConnect）。它是「一根天線加一個底座」的造型，盒裝就附一條 1.5 公尺的 USB 線，讓你把它擺遠一點避開干擾。要注意它不能同時跑 Zigbee 跟 Thread，你得選一邊——官方的說法是他們不認為「一根棒子跑兩種協定」適合家裡長期使用，建議一種協定配一根。這不是這篇的重點，先知道有這回事就好。

儲存媒體：SD 卡是最常見的死因

這一段是整篇最值錢的地方。Home Assistant 主機最常見的「壞掉」，不是主機板燒了，是 SD 卡寫壞了。

SD 卡為什麼會壞

SD 卡裡的快閃記憶體，每個區塊能被寫入的次數是有限的。一般人拍照用 SD 卡，一天寫幾百張照片，用五年也沒事。但 Home Assistant 不一樣：

  • 資料庫一直在寫。每一個感測器數值變動、每一次開燈關燈，都會被記錄器（Recorder）寫進資料庫。家裡有溫溼度感測器的話，這是每分鐘都在發生的事。
  • 系統日誌一直在寫。整合出錯、裝置離線重連，全部都會留下紀錄。
  • 它 24 小時不關機。一天寫的量乘以 365。

結果就是很多人用了半年到一年，某天早上發現儀表板叫不出來、主機沒回應，重開機也救不回來——SD 卡已經進入唯讀狀態或直接壞軌。更煩的是它常常是慢慢壞的：先是儀表板變卡、自動化偶爾不觸發、更新到一半失敗，你會先懷疑是軟體問題，繞一大圈才發現是卡。

危險：SD 卡壞掉通常是沒有前兆、不可還原的。你唯一的保險是備份，而且備份不能只留在同一張卡上。第 9 章講的自動備份與異地存放，請在裝好機器的第一週就設好，不要拖。

那該用什麼

儲存媒體耐用度建議容量怎麼用
microSD 卡 最差，一年內壞掉不稀奇 官方最低要求 32GB 當作「先試看看」的起步，或緊急救援用
USB 外接 SSD 好非常多 128GB 以上很夠 Pi 4／Pi 5 常見做法，成本低效果明顯
NVMe SSD 最好，速度也最快 128～256GB 迷你電腦、有 M.2 插槽的機器
eMMC（焊在板子上） 比 SD 卡好，但容量固定 Green 是 32GB 官方硬體的做法，不用你操心，但也擴不了

容量怎麼抓？系統本身加上一般家庭的資料庫，32GB 其實撐得住，但你只要開始留備份、裝幾個 Apps、或存一點攝影機片段，很快就會擠。如果是自己配，直接上 128GB 以上，價差不大而且省掉未來搬家的麻煩。

已經裝在 SD 卡上，還有救嗎？

有。HAOS 內建一個「搬移資料磁碟（Move data disk）」的功能，可以把資料搬到另一顆接上去的儲存裝置上，之後系統照常從原本的媒體開機，但資料讀寫都跑到新的硬碟去。路徑在 設定 > 系統 > 儲存空間，裡面找「Move data disk」。

注意：搬資料磁碟前一定先做一份完整備份並下載到你自己的電腦。這是一個動到底層儲存的操作，出錯的代價是整套重來。

開箱前檢查清單

在你按下購物車之前，對照一下這張表。少一樣東西，安裝就會卡在半路，然後你會在深夜跑去便利商店。

要準備的東西規格重點為什麼一定要
主機本體見上一節；至少 2GB 記憶體官方對 Raspberry Pi 明訂的最低記憶體門檻
電源供應器對應機型的原廠或同等級規格供電不足是隨機重開機的頭號原因
儲存媒體SSD 優先；SD 卡至少 32GB，最好有 A2 標示官方安裝文件建議選有 A2 標記的卡
讀卡機或 USB 轉接能接上你要燒錄的電腦燒錄一定要在另一台電腦上做
網路線一條接得到路由器或交換器官方安裝流程要求開機時有網路線與可連外的網路
燒錄用的電腦Windows／macOS／Linux 都行跑 Raspberry Pi Imager 或 balenaEtcher
外殼與散熱散熱片或小風扇見電源與散熱一節
（可選）不斷電系統 UPS能撐十幾分鐘就夠避免跳電當下正在寫入而毀掉資料
（可選）USB 無線電棒如 Connect ZBT-2之後要玩 Zigbee／Thread 才需要
提示：如果你買的是 Home Assistant Green，上面清單的前五項它盒裝就附了（主機、12V 電源含多國轉接頭、網路線），你只要有一台能上網的電腦跟一個路由器空孔就能開始。這也是為什麼它適合完全不想研究的人。

動手做：把 HAOS 燒進去、插電開機

下面以最常見的 Raspberry Pi 為例。官方推薦的工具是 Raspberry Pi Imager（從 raspberrypi.com/software 下載），因為它會直接幫你抓正確的映像檔，不用自己找檔案。如果你想手動下載映像檔，官方也接受用 balenaEtcher 來燒。

  1. 在另一台電腦上裝好燒錄工具

    到 raspberrypi.com/software 下載 Raspberry Pi Imager 並安裝。這一步要在你的日常電腦上做，不是在 Pi 上做——Pi 現在還是空的。

  2. 把 SD 卡或 SSD 接到電腦

    用讀卡機插上去。系統可能會跳出「要格式化嗎」之類的視窗，按取消，燒錄工具會自己處理格式化。

  3. 在 Imager 裡選作業系統

    打開 Raspberry Pi Imager，點選作業系統的按鈕，依序進入 Other specific-purpose OS > Home automation > Home Assistant。這裡面會列出對應不同機型的版本，選跟你手上機器相符的那一個（Raspberry Pi 4 選 RPi 4 版、Raspberry Pi 5 選 RPi 5 版）。選錯機型會燒得成功但開不了機，這是新手最常踩的坑。

  4. 選擇要寫入的裝置，然後寫入

    選好你的 SD 卡或 SSD，確認容量數字對得上（不要選到你的行動硬碟）。按「Next」再按「Write」開始燒。這一步會清空整個裝置，燒錄過程幾分鐘不等。完成後按「Finish」，安全退出裝置。

  5. 裝回主機、插網路線、插電

    把燒好的媒體裝回主機，先插網路線再插電。官方安裝流程要求首次開機時要有可以連外的網路，因為系統會在這時候把最新的元件抓下來。這時候不需要接螢幕跟鍵盤——如果你接了，畫面上會跑一堆文字，那是正常的，不用理它。

  6. 等一下下，然後用瀏覽器連進去

    在同一個網路下的電腦或手機，瀏覽器打 homeassistant.local。官方文件說 Pi 4／Pi 5 通常一分鐘內就會出現畫面。如果沒反應，先試 homeassistant.local:8123，再不行就改用 IP 位址加上 :8123。你會看到一個「Preparing Home Assistant」的頁面，那表示它正在下載最新版本。官方文件對這一步只寫「依你的硬體與網路速度，準備可能需要一段時間」，沒有給明確的分鐘數；實務上等個十幾二十分鐘很常見，用 SD 卡的話更慢，總之不要拔電。

觀念：從 2026.8 版開始，新安裝的 HAOS 預設改用不帶連接埠號的一般網址（也就是直接 homeassistant.local 就好，不用加 :8123）。既有的安裝維持原樣不受影響。所以你在不同教學裡看到有的寫 :8123 有的沒寫，兩種都可能是對的，以你自己畫面上的網址為準。

如果你裝的是迷你電腦或舊筆電（x86-64）

流程不太一樣，重點在 BIOS。官方文件的要求是：機器要能 64 位元、而且要能用 UEFI 開機。進 BIOS（開機時通常按 F2、Del、F1 或 F10，各家不同），把開機模式設成 UEFI、把 Secure Boot 關掉，存檔離開。

映像檔是 haos_generic-x86-64-版本.img.xz。官方推薦的做法是先用隨身碟開機進 Ubuntu，再用 Ubuntu 內建的「磁碟」工具把映像還原到目標硬碟；另一個做法是在你自己的電腦上用 balenaEtcher 燒到目標媒體，再把媒體裝回機器。裝好之後一樣是插網路線、開機、連 homeassistant.local。

如果你要裝在虛擬機或 NAS 上

官方有提供對應各種平台的磁碟映像格式：.vdi（VirtualBox）、.qcow2（KVM／Proxmox）、.ova（VMware ESXi／vSphere），文件也涵蓋 Unraid。虛擬機的資源官方給的最低配置是 2GB 記憶體、2 顆 vCPU，不夠再往上加。

注意：Synology 與 QNAP 的官方文件走的是 Docker 路線，也就是前面表格裡的 Container 安裝，不是 HAOS，所以會少掉 Apps 那一整塊功能。如果你想在 NAS 上得到完整體驗，要走的是「在 NAS 的虛擬機管理程式裡開一台 VM 跑 HAOS」，不是直接裝個 Docker 容器。這兩件事常常被混為一談。

首次開機的 Onboarding：建立你的擁有者帳號

「Preparing Home Assistant」跑完之後，畫面會換成歡迎頁。這一段官方叫做 Onboarding，全程在瀏覽器裡點一點就好，完全不用打任何指令。

  1. 選擇「建立我的智慧家庭」或還原備份

    全新的人選建立新的（官方文案是 Create my smart home）。如果你是換機器、手上有舊主機的備份檔，這裡就是還原的入口——這也是為什麼第 9 章值得早點看。

  2. 填名字、使用者名稱、密碼

    官方文件的說法是：Home Assistant 第一次啟動時建立的這個帳號就是擁有者（Owner），它永遠同時是管理員、權限最高，可以管系統的每一個部分，包含開新帳號。官方特別提醒：使用者名稱要全部小寫、不能有空白。

    密碼請認真設，而且記牢——這台機器之後會知道你家什麼時候沒人，而且官方文件明講：擁有者的密碼忘了，就得走「我被鎖在外面」的救援程序、把系統打回重新 onboarding 的狀態，不是點個「忘記密碼」寄信給你那麼簡單。使用者與權限的細節在第 5 章。

  3. 設定家的位置

    在地圖上把位置標到你家。這一步不只是好玩——官方文件說它會一次幫你設好時區、單位系統與貨幣，並且建立一個預設半徑 100 公尺的「家」區域（Zone），之後「有人回家就開燈」這類自動化就是靠它判斷的。台灣的話時區應該會抓成 Asia/Taipei。這幾個設定之後在第 2 章都還能改。

  4. 決定要不要送出分析資料

    這一頁問你要不要分享匿名的使用統計。官方文件寫得很老實：預設是關閉的，但他們鼓勵你打開，因為這些數字會影響開發團隊決定要優先支援哪些裝置。送不送都不影響功能，自己決定。

  5. 按「完成」，然後看看它找到了什麼

    按下 Finish 就會進到儀表板。Home Assistant 會自動掃描你家網路上已經看得到的裝置，跳出一堆「發現了 XXX，要設定嗎」。現在先不要急著全部點下去，先把主機穩定跑個一天再說。

提示：2026.2 之後的預設首頁叫做 Home Dashboard（首頁儀表板），裡面有一區「For You」會列出剛發現的裝置讓你快速加入，還有一個「Devices」區塊收集還沒被分到房間的裝置。如果你在別的教學看到的畫面長得不一樣，那可能是舊版的「Overview（legacy）」。儀表板怎麼改成你想要的樣子，看第 6 章。
觀念：這一步做完，你就正式接上本站主線了。接下來請直接跳到第 1 章：登入 HA，那邊會帶你熟悉介面、裝手機 App、然後一路蓋到自動化。這篇後面的內容是硬體層面的補充，你可以之後遇到問題再回來翻。

網路：拜託你牽一條網路線

這件事講一百次都不嫌多：你的 Home Assistant 主機，請用有線網路。

不是說 Wi-Fi 不能跑，是它會讓你在錯的地方浪費非常多時間。想像一下這個場景：你設了一條「晚上七點半客廳自動開燈」的自動化，結果它有時候會晚個幾十秒，有時候完全不動。你去翻自動化設定、翻裝置、翻日誌，什麼都正常——實際上是主機的 Wi-Fi 在那個時間點掉了幾秒。這種問題看起來完全不像網路問題，所以特別難查。

比較項目有線Wi-Fi
安裝時能不能用可以不行，官方安裝流程要求先接網路線
穩定性幾乎不會斷會受微波爐、鄰居 AP、距離影響
斷線時的症狀很明顯，一看就知道間歇性、隨機，極難查
對 2.4GHz 裝置的干擾沒有主機自己的 Wi-Fi 會跟 Zigbee 搶 2.4GHz 頻段

注意最後一列。Zigbee 跟 Thread 都跑在 2.4GHz，你家的 Wi-Fi 也是。如果主機本身用 2.4GHz Wi-Fi，又插著一根 Zigbee 無線電棒在旁邊，兩個會互相干擾，你的感測器就會開始「偶爾失聯」。這也是為什麼很多人會建議把 Zigbee 棒用一條 USB 延長線拉遠一點——不是迷信，是真的有效。

注意：安裝完成之後，請去你的路由器把主機的 IP 位址固定下來（DHCP 保留 / Static Lease，各家路由器名稱不同）。不然某天路由器重開，主機換了 IP，你所有存成 IP 的書籤、監視器連線、手機 App 設定就全部要重來一次。這件事花五分鐘，省你未來一個晚上。

主機的網路設定與主機名稱可以在 設定 > 系統 > 網路 裡看到與調整。順帶一提，homeassistant.local 這種寫法靠的是 mDNS（多播 DNS），有些路由器或公司網路會擋掉它——真的連不上就用 IP，功能完全一樣。

電源、散熱、UPS：無聊但會救你一命的三件事

電源：不要用手機充電器隨便湊

這是 Raspberry Pi 使用者最經典的災難。症狀是：主機會在你完全沒動它的時候隨機重開機，或是接上 USB 硬碟之後開始不穩。你會以為是系統壞了、SD 卡壞了、記憶體不夠，其實是電不夠。

機型官方電源規格供電不足會怎樣
Raspberry Pi 5官方 27W USB-C PD 電源，5.1V / 5A降頻、USB 裝置供電被限制、隨機重開
Raspberry Pi 4官方 USB-C 電源，5.1V / 3A（15W）畫面出現閃電符號、隨機重開
Home Assistant Green盒裝附的 12V 電源用附的就對了，不要自己換
迷你電腦原廠變壓器同上

Pi 5 特別要注意：它要求的是 5A 的 USB-C PD 電源，這不是一般手機充電器會給的規格。你拿一個「看起來一樣是 USB-C、瓦數也夠」的充電器來接，很可能仍然餵不飽它，而且症狀會非常隱晦。這裡真的建議直接買原廠電源，這是整套系統裡最不值得省的一環。

危險：供電不足造成的隨機重開，最可怕的不是「重開」本身，是重開的瞬間如果正在寫資料庫，檔案就可能損毀。累積幾次之後，你的資料庫就會壞掉，然後歷史紀錄全部消失。這是很多人「莫名其妙資料庫壞掉」的真正原因。

散熱：不會燒掉，但會變慢

ARM 晶片過熱不會爆炸，它會降頻保護自己——反應在你身上就是儀表板變卡、更新變慢。Raspberry Pi 4 與 5 在密閉塑膠殼裡長時間跑，是真的會熱。做法很簡單：買有散熱片的金屬外殼，或加一顆小風扇。Home Assistant Green 用的是鋁製散熱片被動散熱，不用風扇，這也是官方硬體省事的地方之一。

擺放位置也算散熱：不要塞在電視櫃最裡面、不要跟路由器疊在一起、不要壓在一堆線材底下。找個通風、你伸手就摸得到的地方。

UPS：跳電時的保險

台灣夏天跳電、施工停電都不算罕見。你的主機正在寫入時被硬斷電，就是前面講的資料庫損毀風險。一台便宜的不斷電系統（UPS）能撐個十幾分鐘就很夠了——重點不是讓它繼續跑，是讓它有機會好好地關機，或撐過那種幾秒鐘的瞬斷。

提示：如果預算不允許買 UPS，退而求其次的做法是：把自動備份設好，並且讓備份自動上傳到主機以外的地方。硬體終究會壞，備份才是你真正的保險。第 9 章整章都在講這件事。

裝好之後的頭三件事

系統跑起來了，先別急著買一堆燈泡。照這個順序做，你之後會少很多痛苦。

  1. 去路由器把 IP 固定住

    前面網路那節講過的 DHCP 保留。這是唯一一件要在 Home Assistant 以外做的事，先做完。

  2. 設定自動備份，並且讓它離開這台機器

    備份如果只存在主機自己的儲存裝置上，那張卡壞掉時備份也一起陪葬，等於沒備份。第 9 章會帶你設定自動備份與把它送到主機以外的地方。

  3. 檢查更新，然後養成更新前先備份的習慣

    Home Assistant Core 大約每月一版（版本號長得像 2026.8，就是「2026 年 8 月那版」），作業系統 HAOS 則是完全獨立的一條版本號，數字小很多（撰稿時官方文件用的例子與最新釋出都是 18.2）。看到「Core 2026.8」跟「作業系統 18.2」同時出現不要嚇到，那是兩個不同的東西。更新很值得跟，但永遠先備份再更新。

  4. 然後就去第 1 章吧

    硬體的部分到這裡就結束了。接下來的旅程從第 1 章開始：認識介面、裝手機 App、設定時區與區域、命名規則，一路到你的第一條自動化。

觀念：你可能會在舊教學裡看到「進階模式（Advanced Mode）」這個開關，被叫去打開它才能看到某些功能。這個開關在 2026.6 已經被移除了，原本藏起來的功能現在預設就都看得到。另外 2026.8 把「開發者工具（Developer Tools）」直接改名成「工具（Tools）」，因為官方覺得那本來就是每個人都用得到的地方。看到名字對不上的教學，先想想是不是版本差異。

常見卡關

  1. 瀏覽器打 homeassistant.local 完全沒反應

    這幾乎都是 mDNS 的問題，不是主機掛了。依序試：(1) 改打 homeassistant.local:8123——2026.8 之前安裝的機器需要帶通訊埠。(2) 去路由器的管理頁面找「已連線裝置」清單，找一台名字像 homeassistant 的，把它的 IP 抄下來，改打 http://那個IP:8123。(3) 確認你的手機或電腦跟主機在同一個網段——很多路由器的訪客網路（Guest Wi-Fi）或 2.4G／5G 分開的 SSID 會互相隔離，這時候怎麼試都連不到。(4) 公司或學校網路常會擋 mDNS，用 IP 就好。

  2. 燒錄成功了，但插電之後完全沒動靜

    先確認燒錯機型沒有——Raspberry Pi 4 的映像放進 Pi 5、或反過來，都會安靜地開不了機，這是第一名的原因。第二個原因是燒錄工具寫失敗（尤其用便宜讀卡機時），把卡重新燒一次。第三，接個 HDMI 螢幕看看有沒有畫面：完全沒訊號通常是開機媒體的問題，有跑文字但停住則是別的問題。x86 機器則要回去檢查 BIOS 有沒有設成 UEFI、Secure Boot 有沒有關掉。

  3. 開機之後卡在「Preparing Home Assistant」很久

    這一頁是正常的，它在下載最新版本。官方沒有公布這一步該花多久，只說「可能需要一段時間」；經驗上十幾二十分鐘都算合理，用 SD 卡的話更慢。這時候絕對不要拔電。但如果超過一小時還在轉，去確認網路線有沒有真的通、路由器有沒有給它 IP、對外網路是不是正常——這一步一定要能連上網才過得去。

  4. 主機會自己重開機，而且找不到規律

    第一個懷疑對象是電源，不是軟體。特別是 Raspberry Pi 5 沒用 27W／5A 規格的原廠電源、或 Pi 4 用了手機充電器、或你在 USB 埠上又插了一顆沒有獨立供電的硬碟。換原廠電源試一週。第二個懷疑對象是過熱，摸摸看外殼燙不燙，加散熱片或風扇。第三才是儲存媒體開始壞了。

  5. 用了幾個月，儀表板變得很卡、更新常失敗

    這是 SD 卡開始壞掉的典型徵兆。立刻做一份完整備份並下載到你自己的電腦，然後準備換成 SSD。可以用 設定 > 系統 > 儲存空間 裡的「Move data disk」把資料搬到 SSD，或者直接拿備份在新媒體上重裝再還原。不要抱著僥倖心態拖，壞到底就救不回來了。

  6. 裝好之後發現找不到「附加元件」在哪裡

    因為它改名了。2026.2 之後叫做 Apps，路徑是 設定 > Apps。另外要注意：Container 安裝真的沒有這個面板，官方文件白紙黑字寫「Container 安裝無法使用 Apps」，不是你找不到。現在還買得到、還在支援的安裝方式裡，只有 HAOS 有 Apps（舊的 Supervised 也有，但它 2025.12 就終止支援了，不要為了這個去裝）。

常見問題

我可以先用舊筆電或家裡的 Raspberry Pi 試看看，之後再換好一點的機器嗎？
完全可以，而且是很推薦的做法。Home Assistant 的備份機制讓「換機器」變得相對輕鬆：在舊機器上做一份完整備份下載下來，新機器裝好 HAOS 之後，在 Onboarding 的第一步選「還原備份」而不是「建立新的」，你的所有設定、自動化、裝置就會回來。這也是為什麼第 9 章值得在你還沒累積太多東西的時候就先看完。
Home Assistant Green 跟自己配一台 Raspberry Pi，到底差在哪？
差在你要花的是錢還是時間。Green 是官方硬體，盒裝就附電源與網路線、用 32GB eMMC 而不是 SD 卡、鋁製散熱片被動散熱不用風扇，插上去就跑，沒有選錯映像檔或電源不足這些坑。Raspberry Pi 則是彈性大、零件好買、之後想升級成 SSD 很自由，但每一個環節都要你自己判斷。如果你完全不想研究硬體，Green；如果你享受折騰或手上剛好有 Pi，Pi。兩者跑的是同一套 HAOS，軟體體驗一模一樣。
我想買 Home Assistant Yellow，因為它內建 Zigbee，這樣好嗎？
不建議。官方頁面已經明確標示 Yellow 不再生產，只是繼續提供軟體更新，並且建議新買家改買 Green。內建無線電確實方便，但你完全可以買 Green（或任何主機）再插一根 Connect ZBT-2 這類 USB 無線電棒達到一樣的效果，而且棒子壞了可以單獨換、還能擺遠一點避開干擾（ZBT-2 盒裝就附一條 1.5 公尺的 USB 線，本來就是給你拉遠用的）。為了一個停產品去追二手，划不來。
我已經有 NAS 了，直接裝在 NAS 上不是最省？
要看你怎麼裝。Synology 與 QNAP 的官方文件走的是 Docker 路線，那屬於 Container 安裝，會少掉整個 Apps 生態，而且官方明講 Thread 與 Z-Wave 這類靠 Apps 支撐的整合在 Container 上沒有現成支援。想要完整體驗，要在 NAS 的虛擬機管理程式裡開一台 VM 跑 HAOS（官方有提供 .qcow2、.vdi、.ova 等格式，最低配置建議 2GB 記憶體、2 顆 vCPU）。另外要有心理準備：NAS 重開機或更新的時候，你家的自動化會整個停擺，而 NAS 更新的頻率通常比你想像的高。USB 無線電棒要穿透虛擬機也常常出狀況。
32GB 的 SD 卡官方說可以，那我就用 32GB 就好了吧？
32GB 是官方文件寫的最低要求，不是建議值。系統本身加上一般家庭的資料庫，32GB 撐得住，但你只要開始留幾份備份、裝幾個 Apps、或存一點攝影機片段，就會開始擠。更重要的是媒體種類的問題：SD 卡在 24 小時不停寫入的情境下壽命很短，這才是真正該解決的事。能買 SSD 就買 SSD，容量抓 128GB 以上，價差不大又省掉未來搬家的功夫。真的要用 SD 卡，官方安裝文件建議挑有 A2 標示的卡。
網路上的教學說要打 homeassistant.local:8123，但我的機器不用打通訊埠也連得到，是我裝錯了嗎？
沒錯，你是對的。從 2026.8 版開始，新安裝的 HAOS 預設改用不帶通訊埠號的一般網址；既有的安裝則維持原樣不變，所以還是要打 :8123。兩種畫面都正常，差別只在你是什麼時候裝的。網路上大量教學是舊版時期寫的，看到不一致時以你自己瀏覽器網址列上實際跑出來的位址為準就好。
我看到有人說 Supervised 安裝比較彈性，我要不要走那條路？
不要。官方在 2025 年 5 月公告棄用 Core 與 Supervised 兩種安裝方式（同時被砍的還有 i386、armhf、armv7 這些 32 位元架構），時程是從 2025.6 開始跳提醒、2025.12 版正式終止支援，之後官方不再為這些方式建置發行版、也不受理問題回報。官方給的搬家建議是：Supervised 改用 HAOS（實體機或虛擬機皆可）、Core 改用 Container。你現在看到的「Supervised 教學」多半是那之前寫的。
首次設定時那個「分享分析資料」，送出去會不會有隱私問題？
官方文件說得很清楚：這項預設是關閉的，是否開啟完全由你決定，不影響任何功能。送出去的是匿名的統計資料，官方用它來判斷該優先支援哪些裝置與整合。想支持專案就打開，介意就維持關閉，兩種都沒問題。這個選項之後在系統設定裡也還能改，不是一次性的決定。
那個「擁有者」帳號可以之後改掉或多開幾個嗎？
官方文件講明的是這幾件事：擁有者（Owner）是第一次啟動時建立的那個帳號、永遠同時是管理員、擁有最高權限，而且擁有者帳號不能被刪除（你也不能刪掉自己正在登入的帳號）。至於「能不能把擁有者身分轉給別人」「能不能有第二個擁有者」，官方文件沒有明講，介面上也沒有現成的開關，所以實務上請把第一個帳號當成永久的來對待：帳密記牢、密碼認真設。萬一擁有者密碼真的忘了，官方的救援程序是把系統打回可以重新 onboarding 的狀態，代價不小。你之後當然可以在系統裡新增其他使用者（含管理員權限）。使用者、權限、以及跟「人（Person）」的關係，第 5 章講得很完整。
